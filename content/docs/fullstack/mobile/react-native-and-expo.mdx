React Native lets a React developer build real iOS and Android apps. Components and hooks work the same; the difference is that `<View>` and `<Text>` become native `UIView` and `android.view.View`, not DOM elements.

---

## The plain-language version

JavaScript runs in an engine (Hermes) inside the app. React computes the UI tree; React Native turns it into native views. **Expo** is the recommended framework on top: it handles builds, native modules, routing, and updates so most apps never open Xcode or Android Studio.

| Word             | Plain meaning                                                             |
| :--------------- | :------------------------------------------------------------------------ |
| **Hermes**       | JS engine optimised for React Native.                                     |
| **JSI**          | JavaScript Interface: direct calls between JS and native, no JSON bridge. |
| **Fabric**       | The new native renderer.                                                  |
| **TurboModules** | Lazily loaded native modules over JSI.                                    |
| **EAS**          | Expo Application Services: cloud builds, submissions, updates.            |
| **dev build**    | A custom debug app containing the project's native modules.               |

---

## Architecture

The original architecture passed serialised JSON messages over an async bridge, which caused lag for gestures and lists. The **New Architecture** (default since React Native 0.76) uses JSI for synchronous calls, Fabric for rendering with concurrent React support, and TurboModules for native code.

## Expo app basics

```bash
npx create-expo-app@latest my-app
npx expo start          # scan the QR code with a device or open a simulator
```

```tsx title="app/(tabs)/index.tsx"
import { View, Text, Pressable, StyleSheet } from 'react-native';
import { Link } from 'expo-router';

export default function Home() {
  return (
    <View style={styles.container}>
      <Text style={styles.title}>Orders</Text>
      <Link href="/orders/981" asChild>
        <Pressable>
          <Text>Open order</Text>
        </Pressable>
      </Link>
    </View>
  );
}
const styles = StyleSheet.create({
  container: { flex: 1, padding: 16 },
  title: { fontSize: 24, fontWeight: '600' },
});
```

**Expo Router** uses file-based routing like Next.js. Styling uses Flexbox with `flexDirection: 'column'` as the default; NativeWind brings Tailwind classes.

## Differences from web React

- No DOM, no CSS cascade; all text must be inside `<Text>`.
- Lists use `FlatList` / FlashList (virtualised) instead of `map` into a scroll view.
- Navigation is a stack with native transitions.
- Storage: `expo-secure-store` (Keychain / Keystore) for tokens, never `AsyncStorage` for secrets.
- Auth with OAuth uses the system browser and deep links (`expo-auth-session`).

## Building and shipping

- `eas build` produces signed iOS and Android binaries in the cloud.
- `eas submit` uploads to App Store Connect and Google Play.
- `eas update` ships JS-only changes over the air. Native code changes still need a store release.
- App review: Apple's guidelines restrict OTA updates that change an app's core purpose.
