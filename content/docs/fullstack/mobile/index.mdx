A web team needs an iOS and Android app. The options range from wrapping the website to writing two native apps, and the right one depends on how much the app needs from the device and how much team time is available.

---

## The plain-language version

| Approach                         | How it works                               | Examples                                  |
| :------------------------------- | :----------------------------------------- | :---------------------------------------- |
| **Native**                       | Platform languages and UI kits             | Swift + SwiftUI, Kotlin + Jetpack Compose |
| **Cross-platform, native UI**    | One codebase rendering real native views   | React Native, Expo                        |
| **Cross-platform, own renderer** | One codebase drawing every pixel itself    | Flutter (Dart), Compose Multiplatform     |
| **Hybrid (WebView)**             | Web app inside a native shell with plugins | Capacitor, Ionic                          |
| **PWA**                          | Installable website                        | [PWAs](/fullstack/pwas)                   |

| Word              | Plain meaning                                      |
| :---------------- | :------------------------------------------------- |
| **native module** | Platform code exposed to JS (camera, Bluetooth).   |
| **OTA update**    | Shipping a new JS bundle without app store review. |
| **WebView**       | An embedded browser view inside a native app.      |

---

## Choosing

| Need                                        | Lean towards        |
| :------------------------------------------ | :------------------ |
| Team knows React, wants native feel         | React Native + Expo |
| Pixel-identical custom UI on every platform | Flutter             |
| Existing web app, modest device needs       | Capacitor or PWA    |
| Heavy platform features, best performance   | Native              |
| Content or tools, no store needed           | PWA                 |
