Systems at scale fail partially and constantly: a dependency slows down, a region has a bad hour, a deploy goes wrong, traffic triples. Building for scale means two things: **seeing** what is happening (observability) and **containing** failures so a problem in one place does not take down everything (resilience).

| Term                | Plain meaning                                                                                      |
| :------------------ | :------------------------------------------------------------------------------------------------- |
| **observability**   | Ability to understand internal state from outputs, including for questions not planned in advance. |
| **instrumentation** | Code that emits telemetry.                                                                         |
| **telemetry**       | The emitted data: logs, metrics, traces, profiles.                                                 |
| **monitoring**      | Watching known signals and alerting on known failure conditions.                                   |
| **SLO**             | Service level objective: target reliability, such as 99.9 percent of requests under 300 ms.        |
