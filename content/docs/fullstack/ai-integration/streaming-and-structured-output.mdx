A response that takes 20 seconds to generate feels broken if the screen stays empty for 20 seconds, and fine if words start appearing after half a second. Separately, a feature that asks the model to "reply in JSON" breaks the first time the model adds a friendly sentence before the brace. Streaming fixes the first problem; structured outputs fix the second.

## Streaming to the browser

<Tabs items={['Express', 'FastAPI']}>
<Tab value="Express">

```ts
app.post('/api/chat', requireUser, async (req, res) => {
  const { messages } = ChatInput.parse(req.body);
  res.set({
    'Content-Type': 'text/event-stream',
    'Cache-Control': 'no-cache',
    'X-Accel-Buffering': 'no',
  });
  res.flushHeaders();

  const stream = client.messages.stream({ model: 'claude-opus-5-5', max_tokens: 64000, messages });
  req.on('close', () => stream.abort()); // user navigated away: stop paying for tokens

  stream.on('text', (text) => res.write(`data: ${JSON.stringify({ text })}\n\n`));
  try {
    const final = await stream.finalMessage();
    res.write(
      `event: done\ndata: ${JSON.stringify({ usage: final.usage, stop: final.stop_reason })}\n\n`,
    );
  } catch (err) {
    res.write(`event: error\ndata: ${JSON.stringify({ message: 'Generation failed' })}\n\n`);
  }
  res.end();
});
```

</Tab>
<Tab value="FastAPI">

```python
from fastapi.responses import StreamingResponse
import json

@app.post("/api/chat")
async def chat(body: ChatIn, user: CurrentUser):
    async def events():
        async with client.messages.stream(
            model="claude-opus-5-5", max_tokens=64000, messages=body.messages,
        ) as stream:
            async for text in stream.text_stream:
                yield f"data: {json.dumps({'text': text})}\n\n"
            final = await stream.get_final_message()
            yield f"event: done\ndata: {json.dumps({'stop': final.stop_reason})}\n\n"
    return StreamingResponse(events(), media_type="text/event-stream",
                             headers={"Cache-Control": "no-cache", "X-Accel-Buffering": "no"})
```

</Tab>
</Tabs>

Client side, `EventSource` only supports `GET`, so chat UIs read the `POST` response body as a stream (see [streamed responses](/fullstack/performance/streamed-responses)) and append text to state, aborting with an `AbortController` when the user presses stop. Once headers are sent the status code is fixed, so errors mid-stream travel as events.

### Vercel AI SDK

The AI SDK (`ai` package) packages this pattern: `streamText` on the server, `useChat` in React, a standard stream protocol between them, tool-call rendering, and provider adapters (`@ai-sdk/anthropic`, OpenAI, Google, and others). It saves boilerplate in React and Next.js apps; the hand-written version above shows what it does underneath.

## Structured output

Free-form text is for humans. When code consumes the result (extraction, classification, form filling, routing), constrain the output to a schema.

<Tabs items={['TypeScript (Zod)', 'Python (Pydantic)']}>
<Tab value="TypeScript (Zod)">

```ts
import { z } from 'zod';
import { zodOutputFormat } from '@anthropic-ai/sdk/helpers/zod';

const Ticket = z.object({
  category: z.enum(['billing', 'bug', 'feature_request', 'other']),
  priority: z.enum(['low', 'medium', 'high']),
  summary: z.string(),
});

const response = await client.messages.parse({
  model: 'claude-opus-5-5',
  max_tokens: 16000,
  messages: [{ role: 'user', content: `Classify this ticket:\n\n${ticketText}` }],
  output_config: { format: zodOutputFormat(Ticket) },
});
const ticket = response.parsed_output; // typed; null if parsing failed
```

</Tab>
<Tab value="Python (Pydantic)">

```python
from typing import Literal
from pydantic import BaseModel

class Ticket(BaseModel):
    category: Literal["billing", "bug", "feature_request", "other"]
    priority: Literal["low", "medium", "high"]
    summary: str

response = await client.messages.parse(
    model="claude-opus-5-5",
    max_tokens=16000,
    messages=[{"role": "user", "content": f"Classify this ticket:\n\n{ticket_text}"}],
    output_format=Ticket,
)
ticket = response.parsed_output   # validated Ticket instance
```

</Tab>
</Tabs>

The provider constrains generation to the schema, and the SDK validates the result. Business rules (the summary under 200 characters, the category allowed for this customer) still need checks in code, and the schema is the same kind of trust boundary as any [runtime validation](/fullstack/typescript/runtime-validation).

<Callout type="warn">
  Never `eval` or execute model output, and never pass it unescaped into HTML, SQL, or shell
  commands. Treat it like user input, because a prompt-injected document can shape it.
</Callout>
