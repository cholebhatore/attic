A company runs React, Vue, and Angular apps, and wants one shared date picker. A framework component works in one of them; a **web component** works in all three, because it is a native browser element.

---

## The plain-language version

Web components are three browser standards used together:

1. **Custom elements**: define a new HTML tag with a class (`<date-picker>`).
2. **Shadow DOM**: a private DOM and style scope inside the element.
3. **Templates and slots**: markup to clone, and placeholders for content passed in.

| Word                       | Plain meaning                                                            |
| :------------------------- | :----------------------------------------------------------------------- |
| **custom element**         | A tag backed by a JS class extending `HTMLElement`.                      |
| **shadow root**            | The private subtree attached to an element.                              |
| **slot**                   | Where the element's children appear inside the shadow DOM.               |
| **lifecycle callbacks**    | `connectedCallback`, `disconnectedCallback`, `attributeChangedCallback`. |
| **declarative shadow DOM** | `<template shadowrootmode="open">` so shadow DOM can be server-rendered. |

---

## Where they fit

| Good fit                                          | Weaker fit                                              |
| :------------------------------------------------ | :------------------------------------------------------ |
| Design systems shared across frameworks           | Whole applications with complex state                   |
| Embeddable widgets on third-party sites           | SSR-heavy apps (improving with declarative shadow DOM)  |
| Long-lived UI that should outlive framework churn | Forms (needs `ElementInternals` for form participation) |

Examples in the wild: GitHub's UI elements, Adobe Spectrum Web Components, Shoelace / Web Awesome, Salesforce Lightning.
