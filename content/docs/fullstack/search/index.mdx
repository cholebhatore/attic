`WHERE name ILIKE '%running shoe%'` scans every row, misses "shoes for running", cannot rank results, and fails on the typo "runing". Search engines solve a different problem from databases: finding the most relevant documents for loosely phrased text, fast.

---

## The plain-language version

A search engine builds an **inverted index**: for each word, the list of documents containing it, like the index at the back of a textbook. A query looks up its words, combines the lists, and **ranks** documents by how well they match.

| Word               | Plain meaning                                                              |
| :----------------- | :------------------------------------------------------------------------- |
| **inverted index** | Term → list of documents (postings) containing it.                         |
| **tokenisation**   | Splitting text into terms.                                                 |
| **stemming**       | Reducing words to a root: "running" → "run".                               |
| **stop words**     | Very common words often ignored: "the", "a".                               |
| **BM25**           | Standard relevance score from term frequency, rarity, and document length. |
| **facet**          | Count of results per attribute (brand, price band).                        |
| **embedding**      | Vector representing meaning, used for semantic search.                     |

---

## Choosing a level

| Need                                                            | Start with                                                    |
| :-------------------------------------------------------------- | :------------------------------------------------------------ |
| Search a few columns in an existing Postgres app                | Postgres full-text search + `pg_trgm`                         |
| Instant, typo-tolerant product or docs search with little setup | Meilisearch or Typesense                                      |
| Large-scale search, complex relevance, logs and analytics       | Elasticsearch or OpenSearch                                   |
| "Find things that mean the same", RAG                           | Vector search (pgvector, Qdrant), usually hybrid with keyword |
| No infrastructure                                               | Algolia (hosted)                                              |
