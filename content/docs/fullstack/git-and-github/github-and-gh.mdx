Git is the version control tool; GitHub is a hosting and collaboration platform around it. Most team workflow lives in pull requests, and the `gh` CLI brings that workflow into the terminal.

---

## The plain-language version

A **pull request** asks to merge one branch into another and gives a place for review, discussion, and automated checks. **Branch protection** stops anyone pushing straight to `main` or merging without green checks.

| Word                  | Plain meaning                                               |
| :-------------------- | :---------------------------------------------------------- |
| **fork**              | A personal copy of someone else's repository.               |
| **pull request (PR)** | A proposal to merge a branch, with review and checks.       |
| **ruleset**           | Repository rules: required reviews, checks, linear history. |
| **CODEOWNERS**        | File mapping paths to required reviewers.                   |
| **Dependabot**        | Bot that opens PRs for dependency and security updates.     |

---

## A good pull request

- Small and focused; one concern per PR.
- Description says what changed, why, and how it was tested. Link the issue (`Closes #123` auto-closes it).
- Screenshots for UI changes.
- Draft PRs for early feedback.

Reviewers look for correctness first, then design, then style (style should be the linter's job).

---

## Conventional commits

```text
feat(auth): add refresh token rotation
fix(api): return 409 on duplicate email
docs(readme): add setup steps
chore(deps): bump vite to 7.1
```

The `type(scope): summary` shape lets tools generate changelogs and decide version bumps (`feat` = minor, `fix` = patch, `!` or `BREAKING CHANGE` = major). Commitlint and Husky can enforce it.

---

## Repository hygiene

- Branch rulesets on `main`: require PR, required status checks, no force-push.
- `CODEOWNERS` for sensitive paths.
- Dependabot or Renovate for updates; secret scanning and push protection on.
- Issue and PR templates in `.github/`.

## The gh CLI

```bash
gh auth login
gh repo clone owner/repo
gh pr create --fill               # PR from current branch
gh pr checkout 42                 # check out someone's PR locally
gh pr view --web
gh pr checks                      # CI status
gh pr merge --squash --delete-branch
gh issue list --label bug
gh run watch                      # follow an Actions run
gh api repos/owner/repo/pulls     # call the REST API directly
```
