A database dump leaks. If passwords were stored with SHA-256, a single GPU tests billions of guesses per second and most real-world passwords fall within hours. If they were stored with Argon2id, each guess costs tens of milliseconds and a lot of memory, and the same attack becomes impractical for any decent password.

---

## The plain-language version

Store a **hash**, never the password. A hash is a one-way fingerprint: the server hashes the login attempt and compares fingerprints. Password hashes must be **deliberately slow** and **salted** so that leaked hashes are expensive to crack one at a time.

| Word                    | Plain meaning                                                                                                              |
| :---------------------- | :------------------------------------------------------------------------------------------------------------------------- |
| **hash**                | One-way function: easy to compute, infeasible to reverse.                                                                  |
| **salt**                | Random value per password stored with the hash; defeats precomputed tables and makes identical passwords hash differently. |
| **pepper**              | Secret added to all hashes, stored outside the database (in a secrets manager).                                            |
| **work factor**         | Tunable cost: iterations, memory, parallelism.                                                                             |
| **credential stuffing** | Trying username/password pairs leaked from other sites.                                                                    |

## Algorithms

| Algorithm                 | Status                         | Notes                                                                                             |
| :------------------------ | :----------------------------- | :------------------------------------------------------------------------------------------------ |
| **Argon2id**              | First choice                   | Memory-hard (resists GPU/ASIC attacks); OWASP minimum: 19 MiB memory, 2 iterations, parallelism 1 |
| **scrypt**                | Good                           | Memory-hard                                                                                       |
| **bcrypt**                | Good, widely available         | Cost 10 or higher; input truncated at 72 bytes                                                    |
| **PBKDF2**                | Acceptable for FIPS compliance | Needs very high iteration counts (600,000 for SHA-256 per OWASP)                                  |
| MD5, SHA-1, SHA-256 alone | Never for passwords            | Far too fast                                                                                      |
| Encryption (AES)          | Never                          | Reversible: whoever has the key has every password                                                |

Parameters from the [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html). Tune so one hash takes roughly a few hundred milliseconds on the production hardware.

<Tabs items={['Node.js', 'Python']}>
<Tab value="Node.js">

```ts
import argon2 from 'argon2';
const hash = await argon2.hash(password); // argon2id by default, salt included
const ok = await argon2.verify(hash, attempt);
if (ok && argon2.needsRehash(hash)) {
  /* store a fresh hash with current params */
}
```

</Tab>
<Tab value="Python">

```python
from pwdlib import PasswordHash          # or argon2-cffi directly
hasher = PasswordHash.recommended()      # Argon2id
hash_ = hasher.hash(password)
ok, new_hash = hasher.verify_and_update(attempt, hash_)   # new_hash set if params changed
```

</Tab>
</Tabs>

The output string encodes algorithm, parameters, salt, and hash (`$argon2id$v=19$m=19456,t=2,p=1$...`), so parameters can be raised later and old hashes upgraded at the next successful login.

## Policy

Following NIST SP 800-63B:

- Minimum 8 characters (15 recommended when password is the only factor); allow at least 64; allow spaces and all Unicode.
- No composition rules ("one symbol, one digit") and no forced periodic rotation; they produce predictable passwords.
- **Check against breached-password lists** (Have I Been Pwned's k-anonymity API sends only the first five characters of the SHA-1 hash).
- Rate-limit and monitor login attempts; offer [MFA and passkeys](/fullstack/auth/sso-passkeys-mfa).
- Same response and similar timing for "unknown email" and "wrong password", to avoid account enumeration.

## Password reset

1. User submits email; always respond "if the account exists, an email was sent".
2. Generate a random token (32 bytes), store **its hash** with a short expiry (15 to 60 minutes) and single use.
3. Email a link containing the token.
4. On submit, verify hash and expiry, set the new password, delete the token, **revoke all existing sessions and refresh tokens**, and notify the user.

<Callout type="warn">
  Reset tokens in URLs can leak through the `Referer` header to third-party scripts on the reset
  page. Set `Referrer-Policy: no-referrer` on that page, and keep it free of third-party scripts.
</Callout>
