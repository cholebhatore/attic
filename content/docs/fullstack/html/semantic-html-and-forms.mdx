A "button" built from a `div` needs `role`, `tabindex`, Enter and Space handlers, and focus styles to match what `<button>` gives for free. Semantic HTML is the cheapest accessibility and SEO work available.

---

## The plain-language version

**Semantic** elements describe what content is (`nav`, `article`, `button`), not how it looks. Browsers, screen readers, and search engines use that meaning. Forms built with native elements validate, submit, and work with autofill and password managers without JavaScript.

| Word                        | Plain meaning                                                   |
| :-------------------------- | :-------------------------------------------------------------- |
| **semantic element**        | An element whose name carries meaning: `header`, `main`, `nav`. |
| **landmark**                | A region screen readers can jump to.                            |
| **progressive enhancement** | Works with plain HTML; JS improves it.                          |
| **constraint validation**   | Built-in checks: `required`, `type="email"`, `min`, `pattern`.  |

## Document skeleton

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>Orders · Shop</title>
    <link rel="stylesheet" href="/app.css" />
    <script type="module" src="/app.js"></script>
  </head>
  <body>
    <header><nav aria-label="Main">...</nav></header>
    <main>
      <h1>Orders</h1>
      <article>...</article>
    </main>
    <footer>...</footer>
  </body>
</html>
```

One `h1` per page, headings in order without skipping levels. `lang` sets pronunciation for screen readers.

## Picking the element

| Need                   | Use                           | Not                               |
| :--------------------- | :---------------------------- | :-------------------------------- |
| Action on the page     | `<button type="button">`      | `<div onclick>`                   |
| Navigate somewhere     | `<a href>`                    | `<button>` with `location.href`   |
| List of items          | `<ul>` / `<ol>`               | stacked `div`s                    |
| Tabular data           | `<table>` with `<th scope>`   | CSS grid of `div`s                |
| Self-contained content | `<article>`                   | `div class="card"`                |
| Modal                  | `<dialog>` with `showModal()` | custom overlay without focus trap |
| Disclosure             | `<details><summary>`          | custom JS toggle                  |

## Forms

```html
<form action="/signup" method="post">
  <label for="email">Email</label>
  <input id="email" name="email" type="email" autocomplete="email" required />

  <label for="pw">Password</label>
  <input
    id="pw"
    name="password"
    type="password"
    autocomplete="new-password"
    minlength="12"
    required
  />

  <fieldset>
    <legend>Plan</legend>
    <label><input type="radio" name="plan" value="free" checked /> Free</label>
    <label><input type="radio" name="plan" value="pro" /> Pro</label>
  </fieldset>

  <button>Create account</button>
</form>
```

- Every input needs a `<label>`; placeholders are not labels.
- `name` is what gets submitted; `autocomplete` helps autofill and password managers.
- Use `type="email"`, `tel`, `number`, `date` for the right mobile keyboard.
- A `<button>` inside a form defaults to `type="submit"`.
- Native validation is a convenience. The server must validate again, always.

<Callout type="info">
  React 19 and Next.js form actions build on the native `<form action>` model, so forms can submit
  before JavaScript loads. See [React 19](/fullstack/react/react-19-and-patterns).
</Callout>
