A classic Python mistake: `pip install` into the system Python, then two projects need different versions of the same library and one breaks. Virtual environments isolate each project, and **uv** makes creating and managing them nearly invisible.

---

## The plain-language version

**uv** is a fast all-in-one tool (written in Rust) that installs Python versions, creates virtual environments, and manages dependencies. It replaces `pyenv`, `pip`, `venv`, `pip-tools`, and `poetry` for most projects. Its role matches `nvm` + `pnpm` in Node.

| Word                           | Plain meaning                                                                           |
| :----------------------------- | :-------------------------------------------------------------------------------------- |
| **interpreter**                | The `python` program that runs code.                                                    |
| **virtual environment (venv)** | A project-local folder with its own interpreter link and packages, like `node_modules`. |
| **PyPI**                       | The Python package registry, like npmjs.com.                                            |
| **pyproject.toml**             | Project metadata and dependencies, like `package.json`.                                 |
| **uv.lock**                    | Exact resolved versions, like `package-lock.json`.                                      |
| **REPL**                       | Interactive prompt for trying code.                                                     |

## Install and create a project

```bash
# install uv (macOS/Linux); Windows: powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
curl -LsSf https://astral.sh/uv/install.sh | sh

uv python install 3.13          # install a Python version
uv init shop-api                # create a project
cd shop-api
uv add fastapi "uvicorn[standard]" sqlalchemy   # add runtime dependencies
uv add --dev pytest ruff mypy                   # dev dependencies
uv run python main.py           # run inside the project's venv (created automatically)
uv run pytest
uv sync --locked                # install exactly what uv.lock says (CI, Docker)
```

```toml title="pyproject.toml"
[project]
name = "shop-api"
version = "0.1.0"
requires-python = ">=3.13"
dependencies = ["fastapi>=0.115", "uvicorn[standard]>=0.32", "sqlalchemy>=2.0"]

[dependency-groups]
dev = ["pytest>=8", "ruff>=0.7", "mypy>=1.13"]

[tool.ruff]
line-length = 100
```

`uv run` always uses the project's `.venv`, so there is no "activate" step to forget. Activating manually still works: `source .venv/bin/activate` (or `.venv\Scripts\activate` on Windows).

## Running code

```bash
uv run python                   # REPL; exit with exit() or Ctrl+D
uv run python -m app.main       # run a module (package-relative imports work)
uvx ruff check .                # run a tool without adding it (like npx)
```

Editor: VS Code with the Python and Ruff extensions, or PyCharm. Point the editor at `.venv` so it sees installed packages.

<Callout type="warn">
  Never `sudo pip install`. On Linux and macOS the system Python is used by the OS itself, and
  changing its packages can break system tools.
</Callout>

More on uv internals: [Package management with uv](/ai/python/package-management).
