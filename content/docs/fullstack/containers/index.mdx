"It works on my machine" happens because the machine is part of the program: OS packages, runtime versions, environment variables. A container packages the app together with its runtime environment, so the same image runs on a laptop, in CI, and in production.

---

## The plain-language version

A **container** is a normal process that the Linux kernel isolates: it sees its own filesystem, process list, and network, and has limits on CPU and memory. An **image** is the read-only template a container starts from. Unlike a virtual machine, a container shares the host's kernel, so it starts in milliseconds and uses little overhead.

| Word                     | Plain meaning                                                                        |
| :----------------------- | :----------------------------------------------------------------------------------- |
| **image**                | Layered, read-only filesystem snapshot plus metadata (command, env, ports).          |
| **container**            | A running instance of an image.                                                      |
| **layer**                | One filesystem change from a Dockerfile instruction; cached and shared.              |
| **registry**             | Image storage: Docker Hub, GHCR, ECR, Artifact Registry.                             |
| **namespaces / cgroups** | Kernel features for isolation / resource limits.                                     |
| **OCI**                  | Open standard for image and runtime formats (Docker, Podman, containerd all use it). |

|                   | Virtual machine            | Container                                           |
| :---------------- | :------------------------- | :-------------------------------------------------- |
| Isolation         | Own kernel, hardware-level | Shared kernel, process-level                        |
| Start time        | Seconds to minutes         | Milliseconds to seconds                             |
| Size              | GBs                        | MBs                                                 |
| Security boundary | Strong                     | Weaker (hardened with gVisor, Firecracker microVMs) |
