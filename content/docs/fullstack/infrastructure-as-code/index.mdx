A production server was configured by hand three years ago by someone who has left. Nobody knows which packages, firewall rules, or cron jobs it relies on, so nobody dares touch it. Infrastructure as code (IaC) replaces such snowflake servers with files that can be reviewed, versioned, and re-run.

---

## The plain-language version

Two different jobs, two kinds of tools:

| Job                          | Question                                                        | Tools                                             |
| :--------------------------- | :-------------------------------------------------------------- | :------------------------------------------------ |
| **Provisioning**             | Which resources exist? (VMs, networks, databases, DNS, buckets) | Terraform / OpenTofu, Pulumi, CloudFormation, CDK |
| **Configuration management** | What is installed and configured on a server?                   | Ansible, Chef, Puppet, Salt                       |

| Word                         | Plain meaning                                                     |
| :--------------------------- | :---------------------------------------------------------------- |
| **declarative**              | Describe the end state; the tool works out the steps.             |
| **imperative**               | Describe the steps to run.                                        |
| **idempotent**               | Running it again changes nothing if already in the desired state. |
| **drift**                    | Real infrastructure differing from the code (manual changes).     |
| **immutable infrastructure** | Replace servers with new images instead of modifying them.        |

Containers and managed platforms reduce the need for configuration management: an image is already configured, and a PaaS has no server to configure. Provisioning remains.
