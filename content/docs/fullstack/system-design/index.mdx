## A design framework

1. **Requirements**: functional (what it does) and non-functional (scale, latency, availability, consistency, cost). Ask before drawing.
2. **Estimates**: users, requests per second, read/write ratio, storage growth, bandwidth.
3. **API and data model**: endpoints and core entities.
4. **High-level design**: clients, load balancers, services, data stores, caches, queues.
5. **Deep dives**: the two or three hardest parts (hot keys, fan-out, consistency).
6. **Bottlenecks and failures**: what breaks at 10x, single points of failure, how it degrades.
7. **Trade-offs**: state what was given up and why.
