Tests are a tool for changing code without fear. The goal is not coverage numbers; it is confidence that the things users rely on still work after a change.

---

## The plain-language version

Different tests trade speed for realism:

| Level                   | Tests                                                                     | Speed     | Confidence per test | Tools                             |
| :---------------------- | :------------------------------------------------------------------------ | :-------- | :------------------ | :-------------------------------- |
| Static                  | Types, lint                                                               | Instant   | Low                 | TypeScript, ESLint                |
| Unit                    | One function or module                                                    | ms        | Low to medium       | Vitest, Jest, pytest              |
| Component / integration | Several units, a component with its children, an API route with a real DB | 10s of ms | Medium to high      | Testing Library, Supertest, httpx |
| End-to-end              | The whole app in a browser                                                | seconds   | High                | Playwright, Cypress               |

The classic **pyramid** says many unit tests, fewer integration, few E2E. The **testing trophy** (Kent C. Dodds) puts the most weight on integration tests, since they give the best confidence per minute of upkeep. Both agree: few slow E2E tests on critical paths.

| Word                  | Plain meaning                                             |
| :-------------------- | :-------------------------------------------------------- |
| **assertion**         | A check: `expect(x).toBe(3)`.                             |
| **mock / stub / spy** | Fake replacement / fixed-answer fake / recorder of calls. |
| **fixture**           | Prepared data or state a test needs.                      |
| **flaky test**        | Passes or fails without code changes.                     |
| **coverage**          | Share of lines or branches executed by tests.             |
