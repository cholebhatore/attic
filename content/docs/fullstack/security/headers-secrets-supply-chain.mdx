An attacker publishes a package called `reqeusts` to PyPI; a developer mistypes an install command, and a script quietly uploads environment variables. A leaked `.env` in a public repository is found by bots within minutes. Many breaches start outside the application code itself.

## Security headers

| Header                                             | Value                                          | Protects against        |
| :------------------------------------------------- | :--------------------------------------------- | :---------------------- |
| `Content-Security-Policy`                          | See below                                      | XSS, data injection     |
| `Strict-Transport-Security`                        | `max-age=63072000; includeSubDomains; preload` | Downgrade to HTTP       |
| `X-Content-Type-Options`                           | `nosniff`                                      | MIME sniffing attacks   |
| `Referrer-Policy`                                  | `strict-origin-when-cross-origin`              | URL leakage             |
| `Permissions-Policy`                               | `camera=(), geolocation=()`                    | Unwanted feature access |
| `Cross-Origin-Opener-Policy`                       | `same-origin`                                  | Cross-window attacks    |
| CSP `frame-ancestors` (or `X-Frame-Options: DENY`) | `'none'`                                       | Clickjacking            |

`helmet` (Express) and `secure` (Python) set sensible defaults. Check with [securityheaders.com](https://securityheaders.com/) or Mozilla Observatory.

### Content-Security-Policy

```http
Content-Security-Policy:
  default-src 'self';
  script-src 'self' 'nonce-r4nd0m' 'strict-dynamic';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: https://cdn.example.com;
  connect-src 'self' https://api.example.com;
  frame-ancestors 'none';
  base-uri 'none';
  object-src 'none'
```

A fresh **nonce** per response, added to each legitimate `<script nonce="...">`, means injected scripts without it do not run. Roll out with `Content-Security-Policy-Report-Only` first to see what would break.

## Secrets

- Never in code, images, or client bundles. Anything in a frontend bundle (including `NEXT_PUBLIC_*` / `VITE_*` variables) is public.
- Store in a secrets manager (AWS Secrets Manager, GCP Secret Manager, Vault, Doppler, Infisical) or the platform's encrypted variables; inject at runtime.
- Prefer short-lived credentials: OIDC from CI to cloud, IAM roles instead of static keys.
- Rotate on a schedule and immediately on suspected exposure; design for two valid secrets during rotation.
- **Scan**: GitHub secret scanning with push protection, gitleaks or TruffleHog in pre-commit and CI. A secret pushed once must be rotated even after removal, because Git history and forks keep it.

See also [AWS Secrets Manager](/cloud/aws/iam-security/secrets-manager).

## Supply chain

| Risk                  | Example                                            | Defense                                                                                         |
| :-------------------- | :------------------------------------------------- | :---------------------------------------------------------------------------------------------- |
| Known vulnerabilities | Old library with a CVE                             | Dependabot or Renovate, `npm audit`, `pip-audit`, OSV-Scanner                                   |
| Typosquatting         | `reqeusts`, `lodahs`                               | Review new dependencies; copy names from official docs                                          |
| Malicious updates     | Compromised maintainer account publishes a payload | Lockfiles, delayed adoption of brand-new versions, review diffs for critical deps               |
| Install scripts       | `postinstall` runs arbitrary code                  | pnpm and Bun do not run dependency scripts by default; `npm ci --ignore-scripts` where possible |
| Dependency confusion  | Public package with an internal package's name     | Scoped registries, namespace reservation                                                        |
| CI compromise         | Third-party GitHub Action changed                  | Pin actions to commit SHAs, minimal `permissions`                                               |

- **Lockfiles** with integrity hashes make installs reproducible.
- **SBOM** (software bill of materials, CycloneDX or SPDX) lists everything shipped, so a new CVE can be matched to affected services quickly.
- **Provenance**: npm `--provenance` and Sigstore signatures link a package to the source commit and CI run that built it; SLSA levels describe build integrity.
- Fewer dependencies mean less to trust. Check maintenance status and download trends (Socket, Snyk Advisor) before adding one.
