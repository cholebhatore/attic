"Command not found" after installing a tool, a server that keeps running after closing the terminal, a script that works locally and fails in CI: all are shell basics. Every deploy guide on this site assumes them.

---

## The plain-language version

A **shell** (bash, zsh, PowerShell) reads a line, finds the program, and runs it with arguments. Programs read **stdin**, write **stdout** and **stderr**, and exit with a **code** (0 means success). The shell finds programs by searching the directories listed in **PATH**.

| Word                     | Plain meaning                                                     |
| :----------------------- | :---------------------------------------------------------------- |
| **PATH**                 | List of folders searched for commands.                            |
| **environment variable** | Named value inherited by child processes (`NODE_ENV=production`). |
| **pipe** (`\|`)          | Feed one command's output into the next.                          |
| **exit code**            | Number a process returns; `0` is success.                         |
| **signal**               | A message to a process: `SIGINT` (Ctrl+C), `SIGTERM`, `SIGKILL`.  |
| **PID**                  | Process ID.                                                       |

## Everyday commands

```bash
pwd; ls -la; cd ~/projects
mkdir -p a/b; cp -r src dst; mv old new; rm -r dir
cat file; less file; head -n 20 file; tail -f app.log
grep -rn "TODO" src/         # or: rg TODO
find . -name "*.ts"
echo $PATH; export API_URL=http://localhost:3000
which node                    # where a command lives
chmod +x script.sh
```

## Pipes, redirection, exit codes

```bash
cat access.log | grep " 500 " | wc -l   # count 500s
npm test > out.txt 2>&1                   # stdout and stderr to a file
command || echo "failed"                  # run on failure
build && deploy                           # run deploy only if build succeeded
echo $?                                   # last exit code
```

CI marks a step failed when its command exits non-zero. Scripts should use `set -euo pipefail` so a failing line stops the script.

## Processes and signals

```bash
ps aux | grep node
kill -TERM 1234        # ask to stop gracefully
kill -9 1234           # SIGKILL: cannot be caught
lsof -i :3000          # who is using port 3000 (Windows: netstat -ano)
```

Servers should handle `SIGTERM` by finishing in-flight requests and closing connections. Docker and Kubernetes send `SIGTERM` before `SIGKILL`. See [graceful shutdown](/fullstack/backend-fundamentals/request-lifecycle).

## SSH

```bash
ssh-keygen -t ed25519 -C "laptop"
ssh-copy-id user@server
ssh user@server
scp file user@server:/tmp/
```

`~/.ssh/config` stores host aliases. Keys, not passwords, for servers and GitHub.
