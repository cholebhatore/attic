A frontend and an API share TypeScript types for request bodies. In two repositories, a change means publishing a package and bumping versions; in one repository, both change in the same commit.

---

## The plain-language version

A **monorepo** holds many projects in one repository. **Workspaces** let them depend on each other locally. A **task runner** knows the dependency graph, runs only what changed, and caches results.

| Word             | Plain meaning                                                    |
| :--------------- | :--------------------------------------------------------------- |
| **workspace**    | A package inside the monorepo, linked rather than downloaded.    |
| **task graph**   | Which build or test must run before which.                       |
| **remote cache** | Shared build outputs so CI and teammates skip work already done. |
| **affected**     | Only projects touched by a change, plus dependents.              |

```yaml title="pnpm-workspace.yaml"
packages:
  - 'apps/*'
  - 'packages/*'
```

`apps/web` declares `"@acme/schemas": "workspace:*"` and imports the shared Zod schemas the API also uses.

## Task runners

```json title="turbo.json"
{
  "tasks": {
    "build": { "dependsOn": ["^build"], "outputs": ["dist/**", ".next/**"] },
    "test": { "dependsOn": ["^build"] },
    "dev": { "cache": false, "persistent": true }
  }
}
```

`^build` means "build my dependencies first". **Turborepo** is minimal and fast; **Nx** adds generators, a project graph UI, and module boundary rules.

<Callout type="info">
  Monorepos pay off with shared code and coordinated changes. A single app with no shared packages
  gains nothing but configuration.
</Callout>
