A build passes on a laptop and fails in CI because CI installed a newer minor version of a dependency. Lockfiles exist to stop that, and semver ranges explain why it happened.

---

## The plain-language version

A package manager downloads libraries listed in `package.json` from a **registry** (npmjs.com), resolves the full tree of their dependencies, and records exact versions in a **lockfile** so every install is identical.

| Word                      | Plain meaning                                                                          |
| :------------------------ | :------------------------------------------------------------------------------------- |
| **semver**                | `MAJOR.MINOR.PATCH`: breaking, feature, fix.                                           |
| **range**                 | `^1.4.0` allows 1.x.x ≥ 1.4.0; `~1.4.0` allows 1.4.x.                                  |
| **lockfile**              | Exact resolved versions and hashes: `package-lock.json`, `pnpm-lock.yaml`, `bun.lock`. |
| **devDependency**         | Needed only to build or test, not at runtime.                                          |
| **peerDependency**        | A package the host project must provide (a React component library needs React).       |
| **transitive dependency** | A dependency of a dependency.                                                          |

## package.json

```json
{
  "name": "shop-api",
  "type": "module",
  "engines": { "node": ">=22" },
  "scripts": {
    "dev": "tsx watch src/server.ts",
    "build": "tsc -p .",
    "test": "vitest",
    "lint": "eslint ."
  },
  "dependencies": { "express": "^5.1.0" },
  "devDependencies": { "typescript": "^5.9.0", "vitest": "^3.2.0" }
}
```

`"type": "module"` makes `.js` files ES modules. `npm run dev` runs a script with `node_modules/.bin` on PATH. `npx tool` runs a package binary without installing it globally.

## The managers

| Manager      | How it stores packages                    | Notes                                                                              |
| :----------- | :---------------------------------------- | :--------------------------------------------------------------------------------- |
| npm          | Flat `node_modules`                       | Ships with Node. `npm ci` for clean, lockfile-exact installs.                      |
| pnpm         | Global content-addressed store + symlinks | Fast, saves disk, strict: code cannot import undeclared packages. Good workspaces. |
| Yarn (Berry) | Plug'n'Play or `node_modules`             | Less common in new projects.                                                       |
| Bun          | Global cache, `node_modules`              | Very fast installs; also a runtime.                                                |

`corepack` (bundled with Node through v24) or the `packageManager` field pins which manager and version a project uses.

## Dependency hygiene

- Commit the lockfile. Install with `npm ci` / `pnpm install --frozen-lockfile` in CI.
- `npm outdated`, `npm audit`, or Dependabot to stay current.
- Each dependency is code that runs with full access. Check maintenance, size (bundlephobia.com), and whether a few lines would do. See [supply chain security](/fullstack/security/headers-secrets-supply-chain).
- Phantom dependencies: with npm's flat layout, code can import a transitive dependency it never declared, which breaks when that dependency changes. pnpm prevents this.

The Python equivalents (uv, `pyproject.toml`, `uv.lock`) are covered in [Python setup](/fullstack/python-backend/setup-and-uv).
