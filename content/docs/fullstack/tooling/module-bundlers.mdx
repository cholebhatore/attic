A React app imports 900 modules. Shipping 900 separate files, some written in TypeScript and JSX the browser cannot run, would be slow and broken. A bundler turns the source tree into a few optimised files the browser can load.

---

## The plain-language version

A bundler starts at an entry file, follows every `import` to build a **module graph**, converts what the browser cannot read (TS, JSX, Sass), removes unused code, splits the result into **chunks**, and writes files with content **hashes** in their names so they can be cached forever.

Topics: the graph, transforms, tree shaking, code splitting, output, the tools.

| Word               | Plain meaning                                                       |
| :----------------- | :------------------------------------------------------------------ |
| **module graph**   | Every file and the imports between them.                            |
| **transpile**      | Convert syntax (TS to JS, JSX to function calls).                   |
| **tree shaking**   | Dropping exports that nothing imports.                              |
| **code splitting** | Separate chunks loaded on demand (`import()`).                      |
| **minify**         | Shorten names and strip whitespace.                                 |
| **source map**     | File mapping minified code back to the source for debugging.        |
| **HMR**            | Hot module replacement: swap changed modules without a full reload. |

---

## What a bundler does

1. **Resolve**: turn `import x from 'react'` into a file path.
2. **Transform**: TS, JSX, CSS modules, assets.
3. **Tree shake**: works on ES modules because `import`/`export` are static. CommonJS `require` defeats it. Side-effectful modules must be marked in `package.json` (`"sideEffects": false` means safe to drop).
4. **Split**: each dynamic `import()` and route gets its own chunk; shared code goes into common chunks.
5. **Emit**: `app.3f9a1c.js` with hashes. Changing code changes the hash, so files can use `Cache-Control: immutable`.

## The tools

| Tool          | Notes                                                                                                                                             |
| :------------ | :------------------------------------------------------------------------------------------------------------------------------------------------ |
| Vite          | Dev server serves native ES modules with esbuild-powered transforms; production build uses Rollup, moving to Rolldown. Default for most new SPAs. |
| esbuild       | Go-based, extremely fast transforms and bundling. Used inside many tools.                                                                         |
| Rollup        | Library-friendly bundler with clean ES module output.                                                                                             |
| Rolldown      | Rust port of Rollup's API, aimed at unifying Vite's dev and build.                                                                                |
| webpack       | Older, most configurable, large plugin ecosystem. Still in many existing apps.                                                                    |
| Turbopack     | Rust bundler built into Next.js (default for `next dev` and `next build` in recent versions).                                                     |
| Rspack        | Rust, webpack-compatible API.                                                                                                                     |
| tsup / tsdown | Zero-config library bundling.                                                                                                                     |

## Bundle analysis

```bash
npx vite-bundle-visualizer
```

Look for duplicated libraries, whole-library imports (`import _ from 'lodash'` vs `lodash-es` named imports), and large dependencies on the initial route.

<Callout type="warn">
  A bundler is not needed for everything. Node.js servers can run TypeScript directly with `tsx` or
  Node's built-in type stripping, and only libraries and frontends need bundling.
</Callout>
