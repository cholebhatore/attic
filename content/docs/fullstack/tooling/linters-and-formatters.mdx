Code review threads about semicolons and import order waste everyone's time. Formatters settle style automatically; linters catch bugs a compiler misses, such as a missing `await` or a hook called conditionally.

---

## The plain-language version

A **formatter** rewrites code layout (spacing, quotes, line breaks) and has almost no options by design. A **linter** reads code and reports likely bugs or banned patterns. Use both, let the formatter own style, and turn off linter style rules that fight it.

| Word                | Plain meaning                                             |
| :------------------ | :-------------------------------------------------------- |
| **AST**             | Abstract syntax tree: the parsed structure tools inspect. |
| **rule**            | One check, such as `no-unused-vars`.                      |
| **autofix**         | The tool edits the code to satisfy the rule.              |
| **pre-commit hook** | A script Git runs before creating a commit.               |

---

## The tools

| Tool           | Language                    | Role                                                                               |
| :------------- | :-------------------------- | :--------------------------------------------------------------------------------- |
| ESLint         | JS, TS                      | Linter with plugins (`typescript-eslint`, `eslint-plugin-react-hooks`, `jsx-a11y`) |
| Prettier       | JS, TS, CSS, MD, JSON, YAML | Formatter                                                                          |
| Biome          | JS, TS, JSON, CSS           | Linter + formatter in one Rust binary; much faster                                 |
| oxlint         | JS, TS                      | Very fast Rust linter, often run alongside ESLint                                  |
| Ruff           | Python                      | Linter + formatter, replaces Flake8, isort, Black                                  |
| mypy / pyright | Python                      | Type checkers                                                                      |
| Stylelint      | CSS                         | CSS linter                                                                         |

## ESLint flat config

```js title="eslint.config.js"
import js from '@eslint/js';
import tseslint from 'typescript-eslint';
import reactHooks from 'eslint-plugin-react-hooks';

export default tseslint.config(
  js.configs.recommended,
  ...tseslint.configs.recommended,
  { plugins: { 'react-hooks': reactHooks }, rules: reactHooks.configs.recommended.rules },
  { ignores: ['dist/**'] },
);
```

ESLint 9 uses `eslint.config.js` (flat config); `.eslintrc` is the legacy format.

---

## Where they run

1. **Editor**: format on save, lint inline.
2. **Pre-commit**: Husky + lint-staged runs only on staged files.
3. **CI**: `prettier --check .` and `eslint .` fail the build. This is the one that cannot be skipped.

```json title=".lintstagedrc.json"
{ "*.{ts,tsx}": ["eslint --fix", "prettier --write"] }
```

<Callout type="info">
  Python projects: `ruff check --fix` and `ruff format`, configured in `pyproject.toml`, with
  `pre-commit` for hooks.
</Callout>
