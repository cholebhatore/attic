A rebrand changes the primary colour. In a codebase with `#2563eb` hard-coded in 300 places, that is a week of find-and-replace and missed spots. With tokens, it is one line.

---

## The plain-language version

**Tokens** are named design decisions. Components use names (`color-action`), never raw values. **Headless** libraries provide behaviour and accessibility without styles; a styling layer (often Tailwind) gives them the brand.

| Word                      | Plain meaning                                               |
| :------------------------ | :---------------------------------------------------------- |
| **primitive token**       | Raw palette: `blue-600 = #2563eb`.                          |
| **semantic token**        | Role: `color-action = blue-600`.                            |
| **component token**       | Scoped: `button-bg = color-action`.                         |
| **headless component**    | Logic, state, ARIA, keyboard; no styles.                    |
| **polymorphic / asChild** | Rendering a component's behaviour onto a different element. |

---

## Token tiers

```css
:root {
  /* primitive */
  --blue-600: oklch(55% 0.2 260);
  --gray-50: oklch(98% 0 0);
  /* semantic */
  --color-action: var(--blue-600);
  --color-surface: var(--gray-50);
  --radius-md: 0.5rem;
  --space-4: 1rem;
}
[data-theme='dark'] {
  --color-surface: oklch(20% 0 0);
}
```

Tokens are often authored once (Figma variables, the W3C Design Tokens format) and exported to CSS, Tailwind `@theme`, iOS, and Android with Style Dictionary.

## Component libraries

| Kind                | Examples                                           | Trade-off                                                                     |
| :------------------ | :------------------------------------------------- | :---------------------------------------------------------------------------- |
| Headless primitives | Radix UI, React Aria, Base UI, Ark UI, Headless UI | Full styling control; accessibility handled                                   |
| Copy-in components  | shadcn/ui                                          | Code lives in the repo; owned and editable; built on Radix/Base UI + Tailwind |
| Fully styled kits   | MUI, Mantine, Chakra, Ant Design                   | Fast to start; harder to make look custom                                     |

shadcn/ui is a CLI that copies component source into the project (`npx shadcn@latest add dialog`) instead of installing a package. Updates are manual, but nothing is hidden.

---

## Component API design

- Extend native props: `ComponentProps<'button'>` so `disabled`, `type`, `aria-*` work.
- Variants as a small set of named options (`variant`, `size`), not arbitrary style props.
- Composition over configuration: `<Card><Card.Header/></Card>` rather than `<Card headerTitle headerIcon ...>`.
- Forward `className` and merge it last.
- Controlled and uncontrolled modes (`value` + `onChange`, or `defaultValue`).
