A refactor of a shared `Select` breaks its disabled state on one page. Nobody notices for two weeks because that state only appears in one rare flow. A story per state, with visual and accessibility checks in CI, catches it on the PR.

---

## The plain-language version

**Storybook** renders each component on its own, in every state, outside the app. Each state is a **story**. Stories double as documentation, test fixtures, and screenshot baselines.

| Word                  | Plain meaning                                         |
| :-------------------- | :---------------------------------------------------- |
| **story**             | One rendered state of a component.                    |
| **args**              | Props for a story, editable in the UI.                |
| **visual regression** | Comparing screenshots against approved baselines.     |
| **play function**     | Script that interacts with a story to test behaviour. |

---

## A story

```tsx title="Button.stories.tsx"
import type { Meta, StoryObj } from '@storybook/react-vite';
import { expect, fn, userEvent, within } from 'storybook/test';
import { Button } from './Button';

const meta = { component: Button, args: { children: 'Save' } } satisfies Meta<typeof Button>;
export default meta;
type Story = StoryObj<typeof meta>;

export const Primary: Story = {};
export const Disabled: Story = { args: { disabled: true } };
export const Clicks: Story = {
  args: { onClick: fn() },
  play: async ({ canvasElement, args }) => {
    await userEvent.click(within(canvasElement).getByRole('button'));
    await expect(args.onClick).toHaveBeenCalled();
  },
};
```

## Testing layers

- **Interaction tests**: play functions run in a real browser via the Vitest addon.
- **Accessibility**: the a11y addon runs axe on every story.
- **Visual regression**: Chromatic, Playwright screenshots (`toHaveScreenshot`), or Lost Pixel compare renders per PR.

---

## Accessible components checklist

- Correct role and accessible name.
- Full keyboard support per the ARIA Authoring Practices pattern.
- Visible focus; focus trapped and restored for overlays.
- Works at 200 percent zoom and in forced-colours mode.
- Respects reduced motion.
- Announces async changes via `aria-live`.
