Lighthouse shows a score of 98 on a developer's laptop, while Search Console reports the site as "poor" for mobile users. Lab tests run on fast hardware with one simulated network profile; real users have mid-range phones and patchy connections. Core Web Vitals are measured on real users.

---

## The plain-language version

Three metrics capture what users feel:

1. **LCP**: how fast the main content shows up.
2. **INP**: how fast the page responds to clicks and typing.
3. **CLS**: how much the layout jumps around.

Google uses the 75th percentile of real-user data from Chrome (the CrUX dataset) as a search ranking signal.

| Word           | Plain meaning                                                     |
| :------------- | :---------------------------------------------------------------- |
| **p75**        | 75 percent of visits were at least this good.                     |
| **lab data**   | Measured in a controlled test (Lighthouse).                       |
| **field data** | Measured from real users (CrUX, RUM).                             |
| **RUM**        | Real-user monitoring: collecting metrics from visitors' browsers. |
| **long task**  | Main-thread work over 50 ms.                                      |

---

## The three metrics

| Metric                            | Good     | Poor     | Measures                                                  | Common causes                                                                                   |
| :-------------------------------- | :------- | :------- | :-------------------------------------------------------- | :---------------------------------------------------------------------------------------------- |
| **LCP** Largest Contentful Paint  | ≤ 2.5 s  | > 4 s    | When the largest image or text block renders              | Slow TTFB, render-blocking CSS/JS, unoptimised or lazy-loaded hero image, client-side rendering |
| **INP** Interaction to Next Paint | ≤ 200 ms | > 500 ms | Delay from input to the next frame, worst-ish interaction | Long tasks, heavy event handlers, large re-renders, hydration                                   |
| **CLS** Cumulative Layout Shift   | ≤ 0.1    | > 0.25   | Unexpected movement of visible content                    | Images without dimensions, late-loading ads/embeds, web fonts swapping, injected banners        |

Thresholds from [web.dev/articles/vitals](https://web.dev/articles/vitals). INP replaced FID in March 2024.

---

## Supporting metrics

- **TTFB** (time to first byte): server and network time. Target under about 0.8 s.
- **FCP** (first contentful paint): first text or image.
- **TBT** (total blocking time): lab proxy for INP; sum of long-task time beyond 50 ms.

---

## Measuring in the field

```ts
import { onLCP, onINP, onCLS } from 'web-vitals';

function send(metric: { name: string; value: number; id: string }) {
  navigator.sendBeacon('/analytics', JSON.stringify(metric));
}
onLCP(send);
onINP(send);
onCLS(send);
```

Sources: PageSpeed Insights (CrUX + Lighthouse), Search Console's Core Web Vitals report, Vercel Speed Insights, Sentry, Datadog RUM. The `web-vitals` attribution build reports which element or interaction caused a poor score.

<Callout type="info">
  Optimise the p75 of real users on mobile. A perfect lab score with poor field data is still a slow
  site.
</Callout>
