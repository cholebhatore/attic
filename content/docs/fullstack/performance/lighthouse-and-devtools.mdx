Lighthouse says "Reduce unused JavaScript: 420 KB". That is a hint, not a diagnosis. DevTools shows which script, when it loaded, and what it blocked. Lighthouse finds the area; DevTools finds the cause.

---

## The plain-language version

**Lighthouse** loads a page under simulated conditions and scores performance, accessibility, best practices, and SEO. **DevTools** panels record exactly what the browser did: every request, every task on the main thread, every layout.

| Word                       | Plain meaning                                        |
| :------------------------- | :--------------------------------------------------- |
| **throttling**             | Simulated slower CPU and network.                    |
| **waterfall**              | Timeline of network requests and their dependencies. |
| **flame chart**            | Stacked view of function calls over time.            |
| **critical request chain** | Requests that must finish before rendering.          |

---

## Running Lighthouse well

- Use an **incognito** window (extensions skew results) or run from the CLI: `npx lighthouse https://example.com --view`.
- Test the **production build**, not the dev server.
- Run several times; scores vary by a few points.
- Mobile preset applies 4x CPU slowdown and a slow 4G profile.
- **Lighthouse CI** runs on each PR and fails on budget regressions:

```bash
npx @lhci/cli autorun --collect.url=http://localhost:3000 --assert.preset=lighthouse:recommended
```

## Performance panel

1. Record a page load (reload button) or an interaction.
2. Read the **Main** track: yellow is scripting, purple is rendering and layout, green is painting.
3. Red-cornered tasks are **long tasks**; click one and read the bottom-up tab to find the function.
4. **Timings** track shows FCP, LCP marker, and layout shifts.
5. **Insights** sidebar points to LCP breakdown, render-blocking requests, and INP causes.

Set CPU throttling to 4x or 6x; a fast laptop hides problems that mid-range phones have.

---

## Network panel

- Waterfall shows queueing, DNS, connection, TLS, waiting (TTFB), download per request.
- Check `Cache-Control`, `Content-Encoding` (br, gzip), and protocol (`h2`, `h3`) columns.
- **Disable cache** to test first visits; leave it on to verify caching.
- Request blocking simulates a third-party script failing.

---

## Other panels

| Panel                   | Use                                                               |
| :---------------------- | :---------------------------------------------------------------- |
| Coverage                | Unused bytes of JS and CSS on the current page                    |
| Memory                  | Heap snapshots to find leaks (detached DOM nodes, growing arrays) |
| Rendering               | Paint flashing, layout shift regions, core web vitals overlay     |
| Application             | Service workers, cache storage, cookies, storage                  |
| React DevTools Profiler | Which components rendered and why                                 |

<Callout type="info">
  The `performance.mark()` and `performance.measure()` APIs add custom timings that appear in the
  Performance panel, useful for measuring app-specific steps such as "search results rendered".
</Callout>
