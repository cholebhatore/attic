A service worker is a script the browser runs in the background, separate from the page, that can intercept every network request the page makes. It powers offline support, instant repeat visits, push notifications, and background sync, and is the engine of a [PWA](/fullstack/pwas).

---

## The plain-language version

Think of a personal assistant standing between the page and the internet. Every request goes past it; it can answer from its own stash (the **Cache Storage**), go to the network, or both. It needs HTTPS and lives on after the tab closes.

| Word              | Plain meaning                                  |
| :---------------- | :--------------------------------------------- |
| **scope**         | The URL path the worker controls.              |
| **install**       | First event; usually pre-caches the app shell. |
| **activate**      | Worker takes control; clean up old caches.     |
| **fetch event**   | Fires for each request in scope.               |
| **precache**      | Files cached at install time.                  |
| **runtime cache** | Files cached as they are requested.            |

```js title="main.js"
if ('serviceWorker' in navigator) navigator.serviceWorker.register('/sw.js');
```

```js title="sw.js"
const CACHE = 'shell-v3';
self.addEventListener('install', (e) => {
  e.waitUntil(
    caches.open(CACHE).then((c) => c.addAll(['/', '/app.css', '/app.js', '/offline.html'])),
  );
});
self.addEventListener('activate', (e) => {
  e.waitUntil(
    caches
      .keys()
      .then((keys) => Promise.all(keys.filter((k) => k !== CACHE).map((k) => caches.delete(k)))),
  );
});
self.addEventListener('fetch', (e) => {
  if (e.request.mode === 'navigate') {
    e.respondWith(fetch(e.request).catch(() => caches.match('/offline.html')));
  }
});
```

## Caching strategies

| Strategy               | Behaviour                               | Use for                                |
| :--------------------- | :-------------------------------------- | :------------------------------------- |
| Cache first            | Cache, else network                     | Hashed assets, fonts                   |
| Network first          | Network, else cache                     | HTML, API data where freshness matters |
| Stale-while-revalidate | Cache immediately, update in background | Avatars, non-critical API data         |
| Network only           | Never cache                             | Payments, auth                         |
| Cache only             | Never network                           | Precached shell                        |

## Workbox

```js
import { precacheAndRoute } from 'workbox-precaching';
import { registerRoute } from 'workbox-routing';
import { StaleWhileRevalidate, CacheFirst } from 'workbox-strategies';

precacheAndRoute(self.__WB_MANIFEST); // injected by the build
registerRoute(
  ({ request }) => request.destination === 'image',
  new CacheFirst({ cacheName: 'images' }),
);
registerRoute(({ url }) => url.pathname.startsWith('/api/'), new StaleWhileRevalidate());
```

Build integrations: `vite-plugin-pwa`, Serwist for Next.js.

## Pitfalls

- A new worker waits until every tab using the old one closes. Show an "update available" prompt and call `skipWaiting()` on confirm, rather than forcing it mid-session.
- Never cache `sw.js` itself with a long `Cache-Control`.
- A buggy worker can serve a broken app indefinitely. Keep a kill switch: a worker that unregisters itself.
- **Navigation preload** lets the network request start while the worker boots, avoiding added latency on navigations.
