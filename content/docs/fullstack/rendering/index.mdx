The same React component can produce HTML in the browser, on a server per request, once at build time, or in a mix of all three within one page. That choice decides first-load speed, SEO, server cost, how fresh data is, and how much JavaScript users download. These pages cover the mechanics behind each option, so framework features read as applications of a few underlying ideas.

## Afterwards

- Pick a rendering strategy per route and explain its effect on TTFB, LCP, interactivity, freshness, and cost.
- Explain what hydration does, why mismatches happen, and how selective hydration and streaming change the timeline.
- Explain how Server Components differ from SSR, what crosses the client boundary, and why Server Functions must authenticate.
- Find and remove waterfalls, and design cache keys, lifetimes, and tags without leaking personalised data.
