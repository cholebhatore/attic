Most applications should start with PostgreSQL, and most teams never regret it. The other engines exist for real reasons: an existing ecosystem, an embedded use case, enterprise licensing, or a data shape that relational tables handle poorly.

---

## Relational engines at a glance

| Engine     | License                               | Strengths                                                                         | Typical home                              |
| :--------- | :------------------------------------ | :-------------------------------------------------------------------------------- | :---------------------------------------- |
| PostgreSQL | Open source (PostgreSQL license)      | Standards, extensions (PostGIS, pgvector, TimescaleDB), JSONB, strong correctness | Default for new apps                      |
| MySQL      | Open source (GPL) + Oracle commercial | Simple replication, huge install base, fast simple reads                          | WordPress, PHP, large web companies       |
| MariaDB    | Open source (GPL)                     | MySQL fork with extra engines and features                                        | Linux distributions, MySQL replacements   |
| SQLite     | Public domain                         | Embedded file, zero config, fast local reads                                      | Mobile, desktop, edge, tests, small sites |
| SQL Server | Commercial (free Express edition)     | Microsoft tooling, BI, .NET integration                                           | Enterprise Windows/.NET shops             |
| Oracle     | Commercial                            | RAC clustering, decades of enterprise features                                    | Banks, telecom, ERP                       |
