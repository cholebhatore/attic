A sidebar layout's main column refuses to shrink and pushes a horizontal scrollbar onto the page because a long URL inside it has a large minimum size. Three cards with `flex: 1` end up different widths. A grid of product cards leaves an awkward gap on the right at certain widths. Flexbox and Grid are deterministic algorithms; once their sizing rules are clear, these outcomes are predictable.

---

## The plain-language version

**Where this sits:** after [Box Model and Positioning](/fullstack/css/box-model-and-positioning). Both are values of `display` that change how a container lays out its **direct children**.

**Flexbox** arranges items along one line (a row or a column), distributing leftover space or shrinking items to fit, like books on a shelf that can lean or be squeezed. **Grid** defines rows and columns first and places items into the cells, like a spreadsheet. Flexbox is content-out (item sizes drive the layout); Grid is layout-in (the track structure drives item sizes).

| Word                       | Plain meaning                                                                     |
| :------------------------- | :-------------------------------------------------------------------------------- |
| **main axis / cross axis** | Flexbox's direction of flow / the perpendicular direction.                        |
| **flex-basis**             | An item's starting size along the main axis before growing or shrinking.          |
| **free space**             | Container size minus the sum of item bases (positive or negative).                |
| **track**                  | A grid row or column.                                                             |
| **fr**                     | Fraction of the remaining free space in a grid container.                         |
| **grid line**              | The numbered line between tracks.                                                 |
| **implicit track**         | A row or column created automatically for items placed outside the explicit grid. |

## Flexbox: axes and container properties

```css
.toolbar {
  display: flex;
  flex-direction: row; /* main axis: horizontal */
  justify-content: space-between; /* main-axis distribution */
  align-items: center; /* cross-axis alignment */
  gap: 0.5rem;
  flex-wrap: nowrap;
}
```

| `flex-direction`                | Main axis                                   | Cross axis       |
| :------------------------------ | :------------------------------------------ | :--------------- |
| `row` (default)                 | Inline direction (left to right in English) | Block direction  |
| `column`                        | Block direction (top to bottom)             | Inline direction |
| `row-reverse`, `column-reverse` | Reversed visually                           | Same             |

`*-reverse` and `order` change visual order but not DOM order: keyboard tab order and screen readers follow the DOM, so reordering content visually can confuse users.

## The flex sizing algorithm

Each item has three numbers, set together by the `flex` shorthand:

| Shorthand                 | `flex-grow` | `flex-shrink` | `flex-basis` | Meaning                                   |
| :------------------------ | :---------- | :------------ | :----------- | :---------------------------------------- |
| `flex: initial` (default) | 0           | 1             | `auto`       | Content-sized; can shrink, will not grow  |
| `flex: auto`              | 1           | 1             | `auto`       | Grow and shrink from content size         |
| `flex: 1`                 | 1           | 1             | `0%`         | Grow from zero: equal shares of all space |
| `flex: none`              | 0           | 0             | `auto`       | Rigid at content size                     |
| `flex: 0 0 200px`         | 0           | 0             | 200px        | Fixed 200px                               |

Simplified algorithm for a single line:

1. Determine each item's **hypothetical size** from its `flex-basis` (`auto` means use `width`/`height`, or the content size if those are `auto`).
2. Compute **free space** = container's inner main size − sum of hypothetical sizes − gaps.
3. If free space is **positive**, distribute it in proportion to `flex-grow`.
4. If **negative**, shrink items in proportion to `flex-shrink × flex-basis` (larger items give up more).
5. Clamp each item to its `min-*`/`max-*` sizes; if clamping changes things, redistribute among the remaining items.

### Worked example: growing

Container 600px wide, no gap. Three items: A (basis 100px, grow 1), B (basis 100px, grow 2), C (basis 200px, grow 1).

| Step               | Value                       |
| :----------------- | :-------------------------- |
| Sum of bases       | 100 + 100 + 200 = 400       |
| Free space         | 600 − 400 = 200             |
| Total grow factors | 1 + 2 + 1 = 4               |
| A                  | 100 + 200 × 1/4 = **150px** |
| B                  | 100 + 200 × 2/4 = **200px** |
| C                  | 200 + 200 × 1/4 = **250px** |

### Why flex: 1 items can differ

`flex: 1` sets `flex-basis: 0%`, so all space is distributed equally: equal widths. But `flex: auto` (basis `auto`) starts from content size and only shares the leftover, so an item with more text ends up wider. If items with `flex: 1` still differ, their **minimum content size** exceeds the equal share (next section).

### Worked example: shrinking

Container 400px. A (basis 300px, shrink 1), B (basis 200px, shrink 1). Free space = 400 − 500 = −100.

| Item | Scaled shrink factor (shrink × basis) | Share of the 100px deficit | Final size |
| :--- | :------------------------------------ | :------------------------- | :--------- |
| A    | 1 × 300 = 300                         | 100 × 300/500 = 60         | **240px**  |
| B    | 1 × 200 = 200                         | 100 × 200/500 = 40         | **160px**  |

## Minimum sizes and overflow bugs

Flex items have `min-width: auto` (or `min-height: auto` in column layouts), which resolves to their **min-content size**: they will not shrink below their longest word, widest image, or the min-content width of their children (including a `pre` block or a long URL).

```css
.layout {
  display: flex;
}
.sidebar {
  flex: 0 0 240px;
}
.main {
  flex: 1;
  min-width: 0;
} /* without min-width: 0, long content forces overflow */
```

`min-width: 0` (or `overflow: hidden`, which also sets the automatic minimum to zero) lets the item shrink and its content wrap or scroll. The same issue appears in grid as `1fr` tracks with long content; use `minmax(0, 1fr)`.

## Alignment and auto margins

| Property          | Applies to | Axis                                        | Common values                                                           |
| :---------------- | :--------- | :------------------------------------------ | :---------------------------------------------------------------------- |
| `justify-content` | Container  | Main                                        | `flex-start`, `center`, `space-between`, `space-around`, `space-evenly` |
| `align-items`     | Container  | Cross (each item within its line)           | `stretch` (default), `center`, `flex-start`, `baseline`                 |
| `align-self`      | Item       | Cross                                       | Overrides `align-items` for one item                                    |
| `align-content`   | Container  | Cross (distribution of lines when wrapping) | Same as `justify-content`                                               |

The default `align-items: stretch` makes items fill the cross axis, which is why flex items in a row become equal height.

**Auto margins** absorb free space in flex layouts, pushing items apart:

```css
.nav {
  display: flex;
}
.nav .logout {
  margin-left: auto;
} /* pushes logout (and anything after it) to the far end */
.center-me {
  margin: auto;
} /* centres both axes inside a flex container */
```

## Wrapping and gap

With `flex-wrap: wrap`, items that do not fit move to a new line; each line is sized and distributed **independently**, so items on the last line can be wider than those above (a three-item row followed by a one-item row that stretches). When equal columns across rows matter, that is a grid layout.

`gap` (or `row-gap`/`column-gap`) adds space between items without the margin hacks (negative container margins) that flex layouts once needed; gaps are subtracted before distributing free space.

## Grid: tracks and the fr unit

```css
.page {
  display: grid;
  grid-template-columns: 240px 1fr 1fr; /* three column tracks */
  grid-template-rows: auto 1fr auto; /* header, content, footer */
  gap: 1rem;
  min-height: 100dvh;
}
```

The `fr` unit divides **free space** after fixed and content-sized tracks are resolved. Worked example: container 1,000px, columns `240px 1fr 2fr`, gap 20px (two gaps).

| Step             | Value                       |
| :--------------- | :-------------------------- |
| Space for tracks | 1,000 − 2 × 20 = 960        |
| Fixed tracks     | 240                         |
| Free space       | 960 − 240 = 720             |
| 1fr              | 720 / 3 = 240px             |
| Columns          | 240px, **240px**, **480px** |

Track sizing functions:

| Function                     | Meaning                                                                                                                   |
| :--------------------------- | :------------------------------------------------------------------------------------------------------------------------ |
| Length / percentage          | Fixed                                                                                                                     |
| `auto`                       | Fits content, stretches to fill remaining space when no `fr` tracks                                                       |
| `min-content`, `max-content` | Content-based                                                                                                             |
| `fit-content(300px)`         | Content-sized up to a limit                                                                                               |
| `minmax(min, max)`           | Between two bounds                                                                                                        |
| `1fr`                        | Actually `minmax(auto, 1fr)`: the minimum is the content's min size, which is why long content can overflow an "fr" track |

## minmax, repeat, auto-fill, auto-fit

```css
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(min(16rem, 100%), 1fr));
  gap: 1rem;
}
```

This creates as many columns of at least 16rem as fit, sharing remaining space, with no media queries; `min(16rem, 100%)` prevents overflow on screens narrower than 16rem.

|                | `auto-fill`                                         | `auto-fit`                    |
| :------------- | :-------------------------------------------------- | :---------------------------- |
| Creates tracks | As many as fit, even if empty                       | As many as fit                |
| Empty tracks   | Kept (take space)                                   | Collapsed to zero             |
| With few items | Items stay at minimum width; empty space at the end | Items stretch to fill the row |

With three cards in a container that fits five columns: `auto-fill` leaves two empty columns of space; `auto-fit` stretches the three cards across the full width.

## Placing items

```css
.layout {
  display: grid;
  grid-template-columns: 240px 1fr;
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    'header header'
    'sidebar main'
    'footer footer';
}
.header {
  grid-area: header;
}
.sidebar {
  grid-area: sidebar;
}
.main {
  grid-area: main;
}
.footer {
  grid-area: footer;
}

@media (max-width: 48rem) {
  .layout {
    grid-template-columns: 1fr;
    grid-template-areas: 'header' 'main' 'sidebar' 'footer';
  }
}
```

Line-based placement uses line numbers (starting at 1; negative numbers count from the end):

```css
.hero {
  grid-column: 1 / -1;
} /* span all columns */
.feature {
  grid-column: span 2;
  grid-row: 2 / 4;
}
```

Items can overlap by sharing cells (later items paint on top, adjustable with `z-index`), which makes grid useful for layering text over images without absolute positioning.

## Implicit grid and auto-flow

Items placed beyond the defined tracks, or more items than cells, create **implicit** tracks sized by `grid-auto-rows` / `grid-auto-columns` (default `auto`).

```css
.gallery {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  grid-auto-rows: 200px; /* every implicit row is 200px */
  grid-auto-flow: dense; /* backfill holes left by larger items */
}
.gallery .wide {
  grid-column: span 2;
}
```

`grid-auto-flow: dense` fills earlier gaps with later small items, changing visual order relative to DOM order (an accessibility consideration for meaningful sequences).

## Subgrid and alignment

```css
.cards {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
}
.card {
  display: grid;
  grid-row: span 3;
  grid-template-rows: subgrid; /* inherit the parent's row tracks */
}
```

With **subgrid**, each card's title, body, and footer align across cards in the same row, even with different content lengths, which flexbox cannot do because each card would be an independent layout.

Grid alignment uses the same properties as flexbox plus `justify-items`/`justify-self` (aligning items within their cells on the inline axis) and `place-items: center` (both axes). The shortest way to centre anything: `display: grid; place-items: center;`.

## Choosing

| Need                                                                                  | Use                                       |
| :------------------------------------------------------------------------------------ | :---------------------------------------- |
| A row of items whose sizes come from their content (toolbar, nav, button group, tags) | Flexbox                                   |
| Distributing space along one axis, pushing items apart                                | Flexbox (auto margins, `justify-content`) |
| Two-dimensional page layout                                                           | Grid                                      |
| Card grids where columns align across rows                                            | Grid (`auto-fill`/`minmax`)               |
| Aligning nested content across siblings                                               | Subgrid                                   |
| Overlapping layers                                                                    | Grid (shared cells)                       |
| Centring one thing                                                                    | Either (`place-items: center`)            |

They combine naturally: a grid page layout whose header is a flex row.

## Interview questions

<Accordions>
  <Accordion title="What is the difference between flex: 1 and flex: auto?">
    Both grow and shrink. flex: 1 has a basis of 0, so all space is shared equally by grow factor.
    flex: auto has a basis of auto, so items start at their content size and share only the leftover
    space, making content-heavy items wider.
  </Accordion>
  <Accordion title="Why does a flex item overflow instead of shrinking?">
    Flex items default to min-width: auto, which is their min-content size, so long words, URLs, or
    wide children prevent shrinking. Setting min-width: 0 (or minmax(0, 1fr) in grid) allows it.
  </Accordion>
  <Accordion title="auto-fill vs auto-fit?">
    Both create as many tracks as fit. auto-fill keeps empty tracks, leaving space at the end;
    auto-fit collapses empty tracks so existing items stretch to fill the row.
  </Accordion>
  <Accordion title="How does the fr unit work?">
    It divides the free space left after fixed and content-sized tracks and gaps, proportionally to
    the fr values. 1fr is effectively minmax(auto, 1fr), so it will not shrink below content
    minimums.
  </Accordion>
  <Accordion title="When is grid a better choice than flexbox?">
    When layout is two-dimensional or items must align in both rows and columns, such as page
    layouts and card grids. Flexbox suits one-dimensional, content-sized arrangements.
  </Accordion>
</Accordions>
