Express is stable and everywhere, but it predates async/await, TypeScript, and edge runtimes. Newer frameworks address those gaps with schema-based validation, better performance, and portability across runtimes.

---

## Frameworks

| Framework | Model                                                  | Strengths                                                                   | Fits                                              |
| :-------- | :----------------------------------------------------- | :-------------------------------------------------------------------------- | :------------------------------------------------ |
| Express   | Middleware chain                                       | Ubiquitous, huge ecosystem                                                  | Existing apps, simple APIs                        |
| Fastify   | Plugins + JSON Schema per route                        | Fast, built-in validation and serialisation, logging with pino              | Performance-sensitive Node APIs                   |
| Hono      | Web-standard `Request`/`Response`                      | Runs on Node, Bun, Deno, Cloudflare Workers, Lambda; tiny; typed RPC client | Edge and multi-runtime APIs                       |
| NestJS    | Modules, controllers, dependency injection, decorators | Structure for large teams, Angular-like                                     | Large enterprise backends                         |
| Koa       | Async middleware (onion model)                         | Minimal, by Express's authors                                               | Small custom stacks                               |
| tRPC      | Typed procedures, no REST                              | End-to-end types for TS monorepos                                           | Internal APIs where client and server are both TS |

```ts title="Hono"
import { Hono } from 'hono';
import { zValidator } from '@hono/zod-validator';
import { z } from 'zod';

const app = new Hono();
app.post('/orders', zValidator('json', z.object({ productId: z.number() })), (c) => {
  const { productId } = c.req.valid('json');
  return c.json({ id: 1, productId }, 201);
});
export default app;
```

## Runtimes

| Runtime          | Engine         | Notes                                                                                                                     |
| :--------------- | :------------- | :------------------------------------------------------------------------------------------------------------------------ |
| Node.js          | V8             | Default; largest ecosystem; LTS releases                                                                                  |
| Bun              | JavaScriptCore | All-in-one: runtime, package manager, bundler, test runner; fast startup; Node API compatibility is high but not complete |
| Deno             | V8             | Secure by default (explicit permissions), TypeScript built in, npm compatibility, Deno Deploy                             |
| Workers runtimes | V8 isolates    | Cloudflare Workers, Vercel Edge: Web APIs only, no full Node                                                              |

---

## Choosing

- Team already on Express and it works: stay, and upgrade to Express 5.
- New Node API: Fastify for raw Node performance, Hono for runtime portability.
- Large organisation wanting enforced structure: NestJS.
- Full-stack TypeScript monorepo: tRPC or Hono RPC between client and server.
- An ORM choice (Prisma, Drizzle) matters as much as the framework; see [ORMs](/fullstack/databases/migrations-and-orms).
