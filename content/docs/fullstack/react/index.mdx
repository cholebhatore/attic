React's public API is small; its execution model is where engineering decisions live. Infinite effect loops, stale values, lost input focus, laggy typing, and slow lists all come from misunderstanding **when** components render, **what** a render is, and **how** React identifies and schedules work. These pages build that model bottom-up, then apply it.

## Afterwards

- Predict which components render after a state change, and why.
- Explain keys, state preservation by position, and the two reconciliation heuristics.
- Explain what Fiber made possible and how transitions keep input responsive.
- Explain why hooks depend on call order and why state is a snapshot.
- Write effects with correct dependencies and cleanup, and recognise effects that should not exist.
- Diagnose slow renders with the Profiler and fix them structurally before memoising.
- Choose where each kind of state belongs and avoid request waterfalls.
