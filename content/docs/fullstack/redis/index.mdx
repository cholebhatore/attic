Redis is an in-memory data structure server. It started as a cache and became the default place for sessions, rate limits, queues, leaderboards, locks, and real-time fan-out, because its operations are fast, atomic, and work on real data structures rather than opaque blobs.

---

## The plain-language version

Redis keeps data in RAM and answers most commands in well under a millisecond. Keys map to values that can be strings, lists, hashes, sets, sorted sets, streams, and more. Commands run one at a time on a main thread, so each command is **atomic** without locks.

| Word           | Plain meaning                                                    |
| :------------- | :--------------------------------------------------------------- |
| **key**        | Name of a value, conventionally namespaced: `user:19:profile`.   |
| **TTL**        | Time to live: seconds until the key expires.                     |
| **eviction**   | Removing keys when memory is full.                               |
| **RDB / AOF**  | Snapshot persistence / append-only log persistence.              |
| **pipelining** | Sending many commands without waiting for each reply.            |
| **Cluster**    | Redis split across nodes by hash slots.                          |
| **Valkey**     | Open-source fork of Redis maintained under the Linux Foundation. |

---

## Why it is fast

- Data in memory; no disk read on the request path.
- A single main thread executes commands, so no lock overhead; I/O threads handle network reads and writes in recent versions.
- Event loop with non-blocking sockets (the same model as Node.js).
- Purpose-built data structures with known complexity (O(1) hash lookups, O(log N) sorted set inserts).

The flip side: one slow command (`KEYS *`, a huge `SMEMBERS`, a long Lua script) blocks every client.

---

## Licensing and forks

In 2024 Redis moved from the BSD license to source-available licenses, and the Linux Foundation forked the last open version as **Valkey**, now offered by AWS, Google Cloud, and others. Redis 8 added AGPL as an option. Clients and commands are compatible for the features covered here. Other compatible servers: **Dragonfly** (multi-threaded), **KeyDB**, and **Upstash** (serverless, HTTP-based).

## Getting started

```bash
docker run -d --name redis -p 6379:6379 valkey/valkey:8   # or redis:8
docker exec -it redis valkey-cli                          # or redis-cli
```

```text
> SET greeting "hello" EX 60
OK
> GET greeting
"hello"
> TTL greeting
(integer) 57
> INCR page:views
(integer) 1
```

<Tabs items={['Node.js', 'Python']}>
<Tab value="Node.js">

```ts
import { createClient } from 'redis'; // or ioredis
const redis = createClient({ url: process.env.REDIS_URL });
await redis.connect();
await redis.set('user:19:name', 'Ada', { EX: 3600 });
const name = await redis.get('user:19:name');
```

</Tab>
<Tab value="Python">

```python
from redis.asyncio import Redis
redis = Redis.from_url("redis://localhost:6379", decode_responses=True)
await redis.set("user:19:name", "Ada", ex=3600)
name = await redis.get("user:19:name")
```
