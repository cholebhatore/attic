## Request Pipeline

Every incoming request traverses a multi-stage validation, authentication, and execution boundary before results are serialized:

<Mermaid
  chart={`
flowchart LR
    Client["Client App"] --> Gateway["API Gateway"]
    Gateway --> Auth{"Valid Auth?"}
    Auth -- "Yes" --> Engine["Execution Core"]
    Auth -- "No" --> Reject["401 Reject"]
    Engine --> Cache[("Redis Cache")]
    Engine --> DB[("Primary DB")]
    Engine --> EventBus["Event Bus"]
`}
/>

### Pipeline Stages

1. **Ingress & TLS Termination**: The entry gateway normalizes HTTP/2 and WebSocket transport streams into uniform request contexts.
2. **Authentication Gate**: Stateless JWT validation or session token resolution. Failed authorization short-circuits immediately with a standardized 401 response payload.
3. **Execution Core**: Handlers execute with guaranteed context isolation, dispatching asynchronous read/write tasks to cache layers and persistent storage.
4. **Event Bus Propagation**: Mutative actions broadcast event frames asynchronously to decoupled worker queues.

<Callout type="warn" title="Payload Size Enforcement">
  Requests exceeding the configured `maxBodySize` (default: `10MB`) are rejected at the Gateway
  layer prior to memory allocation in the Execution Core.
</Callout>

## State Transition Machine

Internal handler execution follows a strict deterministic finite state machine to guarantee transactional integrity:

<Mermaid
  chart={`
flowchart LR
    Idle["Idle"] --> Ingest["Ingestion"]
    Ingest --> Validate{"Valid Schema?"}
    Validate -- "Valid" --> Execute["Handler Execution"]
    Validate -- "Invalid" --> Abort["400 Abort"]
    Execute --> Commit{"Commit State?"}
    Commit -- "Success" --> Finalize["Response 200"]
    Commit -- "Fail" --> Rollback["Rollback & 500"]
`}
/>

## Quick Setup

Get a complete project running in under two minutes:

<Steps>
  <Step>
    ### Install the Framework

    Install the core runtime and CLI tooling using your preferred package manager:

    <Tabs items={['pnpm', 'npm', 'bun']}>
      <Tab value="pnpm">
        ```bash
        pnpm add @framework/core @framework/router
        pnpm add -D @framework/cli typescript
        ```
      </Tab>
      <Tab value="npm">
        ```bash
        npm install @framework/core @framework/router
        npm install -D @framework/cli typescript
        ```
      </Tab>
      <Tab value="bun">
        ```bash
        bun add @framework/core @framework/router
        bun add -d @framework/cli typescript
        ```
      </Tab>
    </Tabs>

  </Step>

  <Step>
    ### Initialize Application Entrypoint

    Define your server configuration and register basic route handlers:

    ```typescript title="src/server.ts"
    import { createApp, router } from '@framework/core';

    const app = createApp({
      port: 3000,
      telemetry: true,
    });

    const v1 = router()
      .get('/health', (ctx) => ctx.json({ status: 'ok', uptime: process.uptime() }))
      .post('/echo', async (ctx) => {
        const body = await ctx.body();
        return ctx.json({ echoed: body });
      });

    app.use('/api/v1', v1);
    await app.listen();
    ```

  </Step>

  <Step>
    ### Start Development Mode

    Run the hot-reloading development server:

    ```bash
    pnpm dev
    ```

  </Step>
</Steps>

## Frequently Asked Questions

<Accordions>
  <Accordion title="How does the zero-overhead middleware pipeline work?" id="faq-middleware">
    Middleware functions are compiled at startup into a flattened invocation loop. Rather than nesting promises or allocating recursive callback stacks for every request, execution flows through a continuous iterator with pre-allocated context objects.
  </Accordion>

  <Accordion title="Can I use custom validation libraries like Zod or Valibot?" id="faq-validation">
    Yes. The framework provides official adapters for Zod, Valibot, and TypeBox. Simply plug your schema into the route definition:

    ```typescript
    import { z } from 'zod';

    router.post('/login', {
      schema: { body: z.object({ email: z.string().email(), password: z.string() }) },
      handler: async (ctx) => {
        const { email, password } = ctx.validatedBody;
        // ...
      },
    });
    ```

  </Accordion>

  <Accordion title="How does the state rollback mechanism behave during uncaught errors?" id="faq-rollback">
    When an uncaught exception is thrown in a route handler, any open database transaction registered within `ctx.transaction` is automatically rolled back, in-flight background tasks are signalled for cancellation, and a structured 500 error envelope is dispatched.
  </Accordion>
</Accordions>
