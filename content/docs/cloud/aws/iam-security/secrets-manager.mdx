<Callout type="info" title="Core Concept">
  **AWS Secrets Manager** protects secrets needed to access your applications, services, and IT
  resources. It enables you to rotate, manage, and retrieve database credentials, API keys, and
  other secrets throughout their lifecycle. **AWS KMS** provides the underlying encryption key
  management.
</Callout>

## 1. Secrets Management: The Operational Hazard

Baking API keys, database passwords, or private encryption keys into Git repositories, Dockerfiles, or plaintext environment variables creates severe vulnerabilities:

- Source code repositories are widely cloned and easily leaked.
- Secrets can be exposed in build logs or container inspection (`docker inspect`).
- Updating a hardcoded secret requires rebuilding and redeploying the entire application stack.

---

## 2. Secrets Manager vs. SSM Parameter Store

AWS provides two overlapping services for configuration and secret management:

| Dimension                | AWS Secrets Manager                                                            | AWS Systems Manager (SSM) Parameter Store                    |
| :----------------------- | :----------------------------------------------------------------------------- | :----------------------------------------------------------- |
| **Primary Use Case**     | High-value secrets, database passwords, API tokens                             | General configuration parameters, feature flags, simple keys |
| **Automatic Rotation**   | **Built-in native rotation** for Amazon RDS, Aurora, and DocumentDB via Lambda | Requires writing and maintaining custom Lambda functions     |
| **Cross-Account Access** | Native cross-account sharing                                                   | Historically complex (requires RAM or cross-account roles)   |
| **Pricing**              | $0.40 per secret/month + $0.05 per 10,000 API calls                            | **Free** for standard parameters; $0.05/month for Advanced   |

**Rule of Thumb:** Use **SSM Parameter Store** for general non-sensitive configuration values and non-rotating API keys. Use **AWS Secrets Manager** for database credentials requiring automated rotation and mission-critical production secrets.

## 3. AWS Key Management Service (KMS) & Envelope Encryption

AWS KMS protects secrets and database volumes using **Envelope Encryption**:

<Mermaid
  chart={`
flowchart TD
    KMS["AWS KMS (KMS Key / CMK)"] -->|Generates| PlaintextDEK["Plaintext Data Encryption Key (DEK)"]
    KMS -->|Encrypts| EncryptedDEK["Encrypted Data Encryption Key (DEK)"]
    PlaintextDEK -->|Encrypts Payload| EncryptedData["Encrypted Secret Payload"]
    PlaintextDEK -.->|Erased from RAM| Zero["Zero Exposure"]
    EncryptedDEK --- EncryptedData
`}
/>

1. KMS uses a master key (**KMS Key**) to generate a temporary **Data Encryption Key (DEK)**.
2. The plaintext DEK encrypts your sensitive payload locally.
3. The plaintext DEK is immediately erased from memory.
4. The encrypted DEK is stored alongside the encrypted payload.
5. To decrypt, KMS decrypts the DEK, which then decrypts your data.

### Customer Managed Keys (CMK) vs. AWS Managed Keys

- **AWS Managed Keys (Default):** Created and rotated automatically by AWS (e.g., `aws/secretsmanager`, `aws/s3`). Free, but you cannot modify key policies or track key rotation policies manually.
- **Customer Managed Keys (CMK):** Full control over IAM key policies, automatic annual rotation, and cross-account access grants.

## 4. Injecting Secrets into Containers at Runtime

Instead of storing secrets in application code, Amazon ECS automatically retrieves secrets from Secrets Manager at container launch and injects them as standard environment variables:

```json
{
  "name": "api",
  "image": "123456789012.dkr.ecr.us-east-1.amazonaws.com/api:latest",
  "secrets": [
    {
      "name": "DATABASE_URL",
      "valueFrom": "arn:aws:secretsmanager:us-east-1:123456789012:secret:prod/db/credentials-xYz123"
    },
    {
      "name": "STRIPE_SECRET_KEY",
      "valueFrom": "arn:aws:secretsmanager:us-east-1:123456789012:secret:prod/stripe/key-AbCdEf"
    }
  ]
}
```

<Callout type="warn" title="Required IAM Permissions for Secret Injection">
  For ECS to inject secrets, the **Task Execution Role** must possess explicit
  `secretsmanager:GetSecretValue` permissions on the secret ARN, plus `kms:Decrypt` on the KMS key
  used to encrypt it.
</Callout>

## Practical Implementation: Managing and Retrieving Secrets

<Steps>
  <Step>
    ### Create a customer-managed KMS key

    ```bash
    KMS_KEY_ARN=$(aws kms create-key \
      --description "Key for production application secrets" \
      --query 'KeyMetadata.Arn' --output text)

    aws kms create-alias \
      --alias-name alias/production-app-key \
      --target-key-id $KMS_KEY_ARN
    ```

  </Step>
  <Step>
    ### Store a structured JSON secret in Secrets Manager

    ```bash
    SECRET_ARN=$(aws secretsmanager create-secret \
      --name "prod/app/database" \
      --description "PostgreSQL database credentials" \
      --kms-key-id $KMS_KEY_ARN \
      --secret-string '{"username":"dbadmin","password":"SuperSecurePassword2026!","host":"mydb.cluster-xyz.us-east-1.rds.amazonaws.com","port":5432}' \
      --query 'ARN' --output text)
    ```

  </Step>
  <Step>
    ### Grant Task Execution Role permission to decrypt the secret

    Attach an inline policy to the ECS Task Execution Role:

    ```bash
    aws iam put-role-policy \
      --role-name ecsTaskExecutionRole \
      --policy-name AllowSecretRetrieval \
      --policy-document "{
        \"Version\": \"2012-10-17\",
        \"Statement\": [
          {
            \"Effect\": \"Allow\",
            \"Action\": [\"secretsmanager:GetSecretValue\"],
            \"Resource\": [\"$SECRET_ARN\"]
          },
          {
            \"Effect\": \"Allow\",
            \"Action\": [\"kms:Decrypt\"],
            \"Resource\": [\"$KMS_KEY_ARN\"]
          }
        ]
      }"
    ```

  </Step>
  <Step>
    ### Verify secret retrieval from CLI / application

    ```bash
    aws secretsmanager get-secret-value \
      --secret-id prod/app/database \
      --query 'SecretString' --output text
    ```

  </Step>
</Steps>
