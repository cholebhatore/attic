<Callout type="info" title="Core Concept">
  **OpenID Connect (OIDC)** allows GitHub Actions workflows to authenticate directly with AWS using
  short-lived tokens issued by GitHub. This eliminates the operational security liability of storing
  permanent `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` secrets in code repositories.
</Callout>

## 1. The Threat of Static Long-Lived Credentials

In legacy CI/CD pipelines, engineers generated an IAM User access key pair and saved them as repository secrets in GitHub. This approach carries severe vulnerabilities:

- **No Inherent Expiration:** A leaked access key remains active until an administrator notices and manually revokes it.
- **Accidental Leakage:** Keys are frequently leaked into commit history, print statements, or public CI build logs.
- **Compliance Violations:** Modern security standards (SOC 2, ISO 27001) forbid storing long-lived master cloud credentials in third-party SaaS systems.

## 2. How AWS OIDC Authentication Works

<Mermaid chart={`
sequenceDiagram
    autonumber
    participant GHA as GitHub Actions Runner
    participant GH_OIDC as GitHub OIDC Provider
    participant STS as AWS Security Token Service (STS)
    participant AWS as Amazon ECR / ECS

    GHA->>GH_OIDC: Request signed OIDC JSON Web Token (JWT)
    GH_OIDC-->>GHA: Return JWT containing claims (repo, branch, commit)
    GHA->>STS: AssumeRoleWithWebIdentity (passes JWT + Role ARN)
    STS->>GH_OIDC: Cryptographically verify JWT signature
    STS->>STS: Validate Trust Policy condition (matches repository & branch)
    STS-->>GHA: Return 1-hour temporary AWS credentials (AccessKey, SecretKey, SessionToken)
    GHA->>AWS: Authenticated API calls (push to ECR, deploy to ECS)

`} />

1. **GitHub Issues a Signed JWT:** Before any deployment step, GitHub Actions requests an OIDC token signed by GitHub's private key.
2. **AWS STS Validates Claims:** AWS STS verifies the token signature against GitHub's public OIDC endpoint (`https://token.actions.githubusercontent.com`).
3. **Role Assumed:** If the repository name and Git branch match the IAM role's trust policy, STS issues temporary credentials valid for 1 hour.

## 3. The IAM Trust Policy: Securing the Subject Claim

The security of your AWS account depends on the trust policy's `Condition` block:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::123456789012:oidc-provider/token.actions.githubusercontent.com"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "token.actions.githubusercontent.com:aud": "sts.amazonaws.com",
          "token.actions.githubusercontent.com:sub": "repo:your-org/your-repo:ref:refs/heads/main"
        }
      }
    }
  ]
}
```

<Callout type="warn" title="Always Restrict the Subject Claim">
  The `token.actions.githubusercontent.com:sub` condition specifies the exact repository and branch
  allowed to assume the role. If omitted or wildcarded to `*`, **any user on GitHub** could trigger
  an Actions workflow in their own private repository and assume your AWS role.
</Callout>

## 4. Production GitHub Actions Workflow

Create `.github/workflows/deploy.yml`:

```yaml
name: Deploy to Amazon ECS

on:
  push:
    branches:
      - main

permissions:
  id-token: write # Mandatory for requesting the OIDC token from GitHub
  contents: read # Required for actions/checkout

env:
  AWS_REGION: us-east-1
  ROLE_TO_ASSUME: arn:aws:iam::123456789012:role/GitHubActionsECSDeployRole
  ECR_REPOSITORY: production-api
  ECS_CLUSTER: production-cluster
  ECS_SERVICE: api-service

jobs:
  deploy:
    name: Build & Ship
    runs-on: ubuntu-latest

    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Authenticate to AWS via OIDC
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ env.ROLE_TO_ASSUME }}
          aws-region: ${{ env.AWS_REGION }}
          audience: sts.amazonaws.com

      - name: Log in to Amazon ECR
        id: login-ecr
        uses: aws-actions/amazon-ecr-login@v2

      - name: Set up Docker Buildx (Layer Caching)
        uses: docker/setup-buildx-action@v3

      - name: Build, Tag, and Push Container
        uses: docker/build-push-action@v5
        with:
          context: .
          push: true
          tags: |
            ${{ steps.login-ecr.outputs.registry }}/${{ env.ECR_REPOSITORY }}:${{ github.sha }}
            ${{ steps.login-ecr.outputs.registry }}/${{ env.ECR_REPOSITORY }}:latest
          cache-from: type=gha
          cache-to: type=gha,mode=max

      - name: Trigger ECS Rolling Deployment
        run: |
          aws ecs update-service \
            --cluster $ECS_CLUSTER \
            --service $ECS_SERVICE \
            --force-new-deployment
```

## Practical Implementation: Configuring AWS OIDC Setup

<Steps>
  <Step>
    ### Create IAM OIDC Identity Provider

    ```bash
    aws iam create-open-id-connect-provider \
      --url "https://token.actions.githubusercontent.com" \
      --client-id-list "sts.amazonaws.com" \
      --thumbprint-list "6938fd4d98bab03faadb97b34396831e3780aea1" \
      --thumbprint-list "1c58a3a8518e8759bf075b76b750d4f8d440873f"
    ```

  </Step>
  <Step>
    ### Create the IAM Deploy Role with Trust Policy

    Save the trust policy from section 3 as `github-trust-policy.json` (substituting your GitHub username/repository) and create the role:

    ```bash
    aws iam create-role \
      --role-name GitHubActionsECSDeployRole \
      --assume-role-policy-document file://github-trust-policy.json
    ```

  </Step>
  <Step>
    ### Attach Scoped Permissions Policy

    Attach a policy allowing push access to ECR and deployment triggers on your ECS service:

    ```bash
    aws iam put-role-policy \
      --role-name GitHubActionsECSDeployRole \
      --policy-name ECRAndECSDeployPolicy \
      --policy-document '{
        "Version": "2012-10-17",
        "Statement": [
          {
            "Effect": "Allow",
            "Action": "ecr:GetAuthorizationToken",
            "Resource": "*"
          },
          {
            "Effect": "Allow",
            "Action": [
              "ecr:BatchCheckLayerAvailability",
              "ecr:GetDownloadUrlForLayer",
              "ecr:BatchGetImage",
              "ecr:PutImage",
              "ecr:InitiateLayerUpload",
              "ecr:UploadLayerPart",
              "ecr:CompleteLayerUpload"
            ],
            "Resource": "arn:aws:ecr:us-east-1:123456789012:repository/production-api"
          },
          {
            "Effect": "Allow",
            "Action": [
              "ecs:DescribeServices",
              "ecs:UpdateService"
            ],
            "Resource": "arn:aws:ecs:us-east-1:123456789012:service/production-cluster/api-service"
          }
        ]
      }'
    ```

  </Step>
</Steps>
