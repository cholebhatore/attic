**Backpropagation** is the algorithm that computes the gradient of the loss with respect to every parameter in a network, in a single backward sweep that costs about as much as one extra forward pass. [Gradient descent](/ai/neural-networks/gradient-descent) needs those gradients at every step; backpropagation is how they are obtained. It was popularized for neural networks by Rumelhart, Hinton and Williams in 1986, and every deep learning framework's `backward()` is an implementation of it.

This page starts with the chain rule on a network of two neurons, computed by hand, then extracts the four rules that cover any multi-layer perceptron, then builds and trains a complete MLP in NumPy with no autograd at all, and verifies it.

**Builds on:** [Gradient Descent](/ai/neural-networks/gradient-descent), [Loss Functions](/ai/neural-networks/loss-functions#categorical-cross-entropy) for the softmax cross-entropy gradient, and [Derivatives and Gradients](/ai/math-foundations/derivatives-and-gradients) for the chain rule. [Backprop from Scratch](/ai/math-foundations/backprop-from-scratch) builds the same idea as a general scalar autograd engine.

## Why a special algorithm is needed

The obvious way to get a gradient is **numerical differentiation**: nudge one parameter by a tiny $h$, rerun the network, and see how the loss changes:

$$
\frac{\partial L}{\partial \theta_j} \approx \frac{L(\theta_j + h) - L(\theta_j - h)}{2h}
$$

That costs two forward passes **per parameter**. A network with 10 million parameters would need 20 million forward passes for one gradient step. Backpropagation gets all 10 million partial derivatives from one forward pass and one backward pass, roughly three times the cost of a forward pass alone. Without it, training neural networks would be impossible.

The trick is to reuse work. Every parameter's gradient shares most of its chain-rule product with its neighbours', and backpropagation computes each shared piece exactly once.

## The chain rule, worked on two neurons

A tiny network with one input, one hidden ReLU neuron, and one output, trained with squared error:

$$
z_1 = w_1 x, \qquad a_1 = \text{ReLU}(z_1), \qquad z_2 = w_2 a_1, \qquad L = (z_2 - y)^2
$$

With $x = 2$, $y = 1$, $w_1 = 0.5$, $w_2 = -1.5$:

### Forward pass: compute and store every intermediate value

| Quantity | Computation        | Value |
| :------- | :----------------- | ----: |
| $z_1$    | $0.5 \times 2$     |   1.0 |
| $a_1$    | $\text{ReLU}(1.0)$ |   1.0 |
| $z_2$    | $-1.5 \times 1.0$  |  −1.5 |
| $L$      | $(-1.5 - 1)^2$     |  6.25 |

### Backward pass: from the loss back to each weight

Work in reverse. At each node, multiply the gradient arriving from above (the **upstream gradient**) by the node's own derivative (the **local gradient**):

| Gradient                    | Upstream × local                                                  | Value |
| :-------------------------- | :---------------------------------------------------------------- | ----: |
| $\partial L / \partial z_2$ | $2(z_2 - y) = 2(-2.5)$                                            |  −5.0 |
| $\partial L / \partial w_2$ | $\partial L/\partial z_2 \times a_1 = -5.0 \times 1.0$            |  −5.0 |
| $\partial L / \partial a_1$ | $\partial L/\partial z_2 \times w_2 = -5.0 \times (-1.5)$         |   7.5 |
| $\partial L / \partial z_1$ | $\partial L/\partial a_1 \times \text{ReLU}'(z_1) = 7.5 \times 1$ |   7.5 |
| $\partial L / \partial w_1$ | $\partial L/\partial z_1 \times x = 7.5 \times 2$                 |  15.0 |

Checking with numerical differentiation gives $15.000$ and $-5.000$. A gradient step with $\eta = 0.01$ moves $w_1 \to 0.35$ and $w_2 \to -1.45$, and the loss drops from 6.25 to 4.06.

Three things to see in this table:

1. **Each step uses only local information.** A node needs the upstream gradient and its own derivative, nothing else. That makes the algorithm modular: any operation can join the network if it knows its local derivative.
2. **Shared work is reused.** $\partial L/\partial z_2$ was computed once and used twice — for $w_2$ and for passing back to $a_1$. In a large network, every layer's upstream gradient is reused by all the parameters below it.
3. **The forward pass must be stored.** The backward pass needed $a_1$, $z_1$, and $x$ from the forward pass. This is why training uses far more memory than inference: every intermediate activation is kept until the backward pass consumes it.

The local derivative of ReLU, $\text{ReLU}'(z_1)$, was 1 here because $z_1 > 0$. Had $z_1$ been negative, it would have been 0 and $w_1$ would have received no gradient — the [dead neuron](/ai/neural-networks/neurons-and-activations#the-dead-neuron-problem) effect, visible in one line.

## Why backward and not forward

The chain rule can be evaluated in either direction. **Forward-mode** differentiation pushes derivatives from one input forward through the network and yields the derivative of every output with respect to **that one input**. **Reverse-mode**, which is backpropagation, pulls derivatives from one output backward and yields the derivative of **that one output** with respect to every input.

Training has one output (the scalar loss) and millions of inputs (the parameters). Reverse mode gets every needed derivative in one sweep; forward mode would need one sweep per parameter. That asymmetry is the whole reason backpropagation is the algorithm of deep learning.

---

## The four local rules

A multi-layer perceptron is built from four kinds of operation, and each has a simple local backward rule. With a batch of $N$ examples as rows, and an incoming gradient $\mathbf{G}$ with the same shape as the operation's output:

| Operation (forward)                                  | Backward: gradient for each input                                                                                               |
| :--------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------ |
| Matrix multiply $\mathbf{Z} = \mathbf{A}\mathbf{W}$  | $\partial L/\partial \mathbf{W} = \mathbf{A}^\top \mathbf{G}$, and $\partial L/\partial \mathbf{A} = \mathbf{G}\mathbf{W}^\top$ |
| Add a bias broadcast over the batch                  | $\partial L/\partial \mathbf{b} = $ sum of $\mathbf{G}$ over the batch axis                                                     |
| Element-wise activation $\mathbf{A} = f(\mathbf{Z})$ | $\partial L/\partial \mathbf{Z} = \mathbf{G} \odot f'(\mathbf{Z})$ (for ReLU, a 0/1 mask)                                       |
| Softmax followed by cross-entropy                    | $\partial L/\partial \mathbf{Z} = (\mathbf{P} - \mathbf{Y}) / N$, with $\mathbf{Y}$ one-hot                                     |

Each rule is forced by shapes. A weight of shape $(H, C)$ must receive a gradient of shape $(H, C)$; the only product of an $(N, H)$ activation and an $(N, C)$ incoming gradient with that shape is $\mathbf{A}^\top\mathbf{G}$. The sum over the batch in the weight and bias rules is where the per-example gradients are combined into one averaged gradient.

The last rule is the [softmax cross-entropy gradient](/ai/neural-networks/loss-functions#categorical-cross-entropy) divided by the batch size, because the loss is a mean over $N$ examples.

## A complete MLP from scratch

The network: inputs of $D$ features, one hidden ReLU layer of width $H$, and $C$ output classes, trained with softmax cross-entropy:

```text
x    (N, D)            input batch
z1 = x @ W1 + b1       (N, H)   hidden pre-activation
a1 = relu(z1)          (N, H)   hidden activation
z2 = a1 @ W2 + b2      (N, C)   logits
p  = softmax(z2)       (N, C)   probabilities
L  = mean(-log p[i, y_i])       cross-entropy
```

Here weights multiply on the right, so $\mathbf{W}_1$ is $(D, H)$ — the transpose of how `nn.Linear` stores it.

### The data and the initialization

Three Gaussian clusters in four dimensions: $N = 300$, $D = 4$, $C = 3$, with $H = 16$ hidden units. The model has $4 \cdot 16 + 16 + 16 \cdot 3 + 3 = 131$ parameters. Weights start from He initialization, standard deviation $\sqrt{2/\text{fan-in}}$, the scale [Weight Initialization](/ai/neural-networks/layers-and-initialization) derives for ReLU.

```python title="mlp_setup.py"
import numpy as np

def make_data(seed=0, N=300, D=4, C=3):
    rng = np.random.default_rng(seed)
    centroids = rng.standard_normal((C, D)) * 2.0
    y = rng.integers(0, C, N)
    return centroids[y] + rng.standard_normal((N, D)) * 0.7, y

def init_params(D, H, C, seed=1):
    rng = np.random.default_rng(seed)
    return (rng.standard_normal((D, H)) * np.sqrt(2 / D), np.zeros(H),
            rng.standard_normal((H, C)) * np.sqrt(2 / H), np.zeros(C))
```

### Forward pass, with a cache

```python title="forward.py"
def softmax(z):
    z = z - z.max(axis=1, keepdims=True)        # stability: shift so the max exponent is e^0
    e = np.exp(z)
    return e / e.sum(axis=1, keepdims=True)

def forward(x, y, W1, b1, W2, b2):
    z1 = x @ W1 + b1
    a1 = np.maximum(0.0, z1)
    p = softmax(a1 @ W2 + b2)
    N = x.shape[0]
    loss = -np.log(p[np.arange(N), y]).mean()
    return loss, (x, y, z1, a1, p, N)            # everything the backward pass needs
```

The cache holds exactly what the backward rules consume: `x` and `a1` for the weight gradients, `z1` for the ReLU mask, `p` and `y` for the output gradient.

### Backward pass: the seven gradients

Applying the four rules from the loss back to the input, one layer at a time:

| Step | Gradient                    | Rule applied          | Expression                 | Shape            |
| ---: | :-------------------------- | :-------------------- | :------------------------- | :--------------- |
|    1 | logits `dz2`                | softmax cross-entropy | `(p - onehot(y)) / N`      | `(N, C)`         |
|    2 | `dW2`, `db2`                | matmul weight; bias   | `a1.T @ dz2`; `dz2.sum(0)` | `(H, C)`, `(C,)` |
|    3 | hidden activation `da1`     | matmul input          | `dz2 @ W2.T`               | `(N, H)`         |
|    4 | hidden pre-activation `dz1` | element-wise ReLU     | `da1 * (z1 > 0)`           | `(N, H)`         |
|    5 | `dW1`, `db1`                | matmul weight; bias   | `x.T @ dz1`; `dz1.sum(0)`  | `(D, H)`, `(H,)` |

Steps 2 and 5 are the same rule applied to different layers. A deeper network just repeats steps 3 to 5 once per extra layer. In code:

```python title="backward.py"
def backward(cache, W2):
    x, y, z1, a1, p, N = cache
    dz2 = (p - np.eye(p.shape[1])[y]) / N       # step 1
    dW2, db2 = a1.T @ dz2, dz2.sum(axis=0)      # step 2
    da1 = dz2 @ W2.T                            # step 3
    dz1 = da1 * (z1 > 0)                        # step 4
    dW1, db1 = x.T @ dz1, dz1.sum(axis=0)       # step 5
    return dW1, db1, dW2, db2
```

`np.eye(C)[y]` is the one-hot encoding: indexing the identity matrix by label picks one row per example.

### Training

```python title="train.py"
x, y = make_data()
W1, b1, W2, b2 = init_params(4, 16, 3)
for epoch in range(200):
    loss, cache = forward(x, y, W1, b1, W2, b2)
    dW1, db1, dW2, db2 = backward(cache, W2)
    W1 -= 0.5 * dW1; b1 -= 0.5 * db1; W2 -= 0.5 * dW2; b2 -= 0.5 * db2
```

| Epoch    |     0 |    25 |    50 |   100 |   199 |
| :------- | ----: | ----: | ----: | ----: | ----: |
| Loss     | 2.194 | 0.099 | 0.068 | 0.046 | 0.034 |
| Accuracy | 84.7% | 97.7% | 97.7% | 97.7% | 99.0% |

The initial loss, 2.194, is above the uniform-guess value $\ln 3 = 1.099$: the random network makes confident wrong predictions on some examples. Loss falls by a factor of 22 in the first 25 epochs, then slowly — the network is mostly growing more confident on examples it already classifies correctly.

## Gradient checking

A hand-written backward pass that is slightly wrong still trains, just badly, and the loss curve can look healthy. The only reliable test is **gradient checking**: compare every analytical gradient against the numerical estimate from the central difference above, parameter by parameter.

On the network above, with $h = 10^{-5}$ in `float64`, the maximum relative error for all four parameter arrays is about $10^{-10}$:

| Relative error         | Interpretation                                                           |
| :--------------------- | :----------------------------------------------------------------------- |
| below $10^{-7}$        | Correct                                                                  |
| $10^{-5}$ to $10^{-3}$ | Probably correct but in low precision; recheck in `float64`              |
| above $10^{-2}$        | A bug: usually a missing transpose, a wrong sum axis, or a missing $1/N$ |

The central difference has error proportional to $h^2$, versus $h$ for a one-sided difference, so it is the one to use. The check must run in `float64`, because in `float32` subtracting two nearly equal losses loses most of the significant digits. It costs two forward passes per parameter, so it is run once on a small model during development, never during training. PyTorch provides it as `torch.autograd.gradcheck` for custom operations.

## The shape contract

**Every parameter's gradient has exactly the parameter's shape**, and every activation's gradient has the activation's shape. Checking that after deriving a backward pass catches most errors before any number is examined:

| Tensor      | Shape    | Gradient shape | Keeps the batch axis?  |
| :---------- | :------- | :------------- | :--------------------- |
| `W1`        | `(D, H)` | `(D, H)`       | No — summed over batch |
| `a1`, `z1`  | `(N, H)` | `(N, H)`       | Yes                    |
| `W2`        | `(H, C)` | `(H, C)`       | No                     |
| logits `z2` | `(N, C)` | `(N, C)`       | Yes                    |

Activation gradients keep one row per example; parameter gradients sum over the batch. That sum is the content of mini-batch training: $N$ examples contribute one averaged gradient.

Shapes do not catch everything. When a weight matrix is square, the wrong expression `dz2.T @ a1` has the same shape as the correct `a1.T @ dz2`, and the update runs without complaint. Gradient checking catches what shapes cannot.

### The missing-1/N bug

The $1/N$ enters once, at step 1, and every other gradient inherits it by multiplication. Dropping it makes every gradient exactly $N$ times too large — on this network, 300 times — so the effective learning rate is $N$ times the intended one. Every shape is still correct. The bug often goes unnoticed, because lowering the learning rate "fixes" training; it resurfaces when the batch size changes and the tuned learning rate suddenly stops working. The same bug appears with gradient accumulation if the summed micro-batch gradients are not divided by the number of micro-batches.

## What autograd automates

The same network in PyTorch:

```python
import torch
from torch import nn

model = nn.Sequential(nn.Linear(4, 16), nn.ReLU(), nn.Linear(16, 3))
optimizer = torch.optim.SGD(model.parameters(), lr=0.5)
loss = nn.CrossEntropyLoss()(model(x_t), y_t)   # x_t, y_t: the data as tensors
optimizer.zero_grad(); loss.backward(); optimizer.step()
```

During the forward pass, PyTorch records every operation in a graph. `loss.backward()` walks that graph in reverse, applying each operation's local backward rule — exactly the five steps above, for every operation in any architecture. [Autograd Engine](/ai/pytorch/autograd-engine) covers how the graph is recorded. Writing the NumPy version once is what makes autograd debuggable: when a gradient is wrong or `NaN`, it is one of a small number of local rules that broke.

| Concern             | NumPy version          | PyTorch                                        |
| :------------------ | :--------------------- | :--------------------------------------------- |
| Deriving gradients  | By hand, per operation | Recorded automatically                         |
| Batch averaging     | Manual $1/N$           | `reduction="mean"` by default                  |
| Numerical stability | Manual max subtraction | Fused `log_softmax`                            |
| Memory              | Whole cache kept       | Each node freed after its backward step        |
| Weight layout       | `(in, out)`            | `(out, in)`, so `nn.Linear` computes `x @ W.T` |

## Key terms

| Term                            | Meaning                                                                                    |
| :------------------------------ | :----------------------------------------------------------------------------------------- |
| **backpropagation**             | Reverse-mode application of the chain rule, giving every parameter's gradient in one sweep |
| **upstream gradient**           | The gradient of the loss with respect to an operation's output, arriving from above        |
| **local gradient**              | The derivative of an operation's output with respect to its own input                      |
| **forward cache**               | Intermediate values saved in the forward pass for use in the backward pass                 |
| **reverse mode / forward mode** | Differentiating from the output back / from one input forward                              |
| **gradient checking**           | Comparing analytical gradients with central-difference estimates                           |
| **shape contract**              | A gradient always has the shape of the tensor it belongs to                                |

## Interview questions

<Accordions>
  <Accordion title="Why is backpropagation used instead of numerical differentiation?">

    Numerical differentiation needs two forward passes per parameter, so 20 million passes for a 10-million-parameter network, for a single step. Backpropagation computes all partial derivatives with one forward and one backward pass, about three times the cost of a forward pass, by computing each shared piece of the chain-rule product once and reusing it.

  </Accordion>
  <Accordion title="Backpropagate by hand: z1 = w1·x, a1 = ReLU(z1), z2 = w2·a1, L = (z2 − y)², with x = 2, y = 1, w1 = 0.5, w2 = −1.5.">

    Forward: $z_1 = 1$, $a_1 = 1$, $z_2 = -1.5$, $L = 6.25$. Backward: $\partial L/\partial z_2 = 2(z_2 - y) = -5$; $\partial L/\partial w_2 = -5 \cdot a_1 = -5$; $\partial L/\partial a_1 = -5 \cdot w_2 = 7.5$; ReLU passes it because $z_1 > 0$, so $\partial L/\partial z_1 = 7.5$; $\partial L/\partial w_1 = 7.5 \cdot x = 15$.

  </Accordion>
  <Accordion title="Why is reverse mode the right choice for neural networks?">

    Reverse mode gives the derivatives of one output with respect to all inputs in one sweep; forward mode gives the derivatives of all outputs with respect to one input. Training has a single scalar output, the loss, and millions of parameters, so reverse mode needs one sweep while forward mode would need one per parameter.

  </Accordion>
  <Accordion title="Why does training use more memory than inference?">

    The backward pass needs the forward pass's intermediate values — inputs to each matrix multiply, pre-activations for activation derivatives — so all of them are kept until backward consumes them. Inference can discard each activation as soon as the next layer has used it. Activation memory grows with depth and batch size, which is what gradient checkpointing trades compute to reduce.

  </Accordion>
  <Accordion title="Give the backward rules for Z = A W + b and for A = ReLU(Z).">

    With incoming gradient $\mathbf{G}$: $\partial L/\partial \mathbf{W} = \mathbf{A}^\top\mathbf{G}$, $\partial L/\partial \mathbf{A} = \mathbf{G}\mathbf{W}^\top$, and $\partial L/\partial \mathbf{b} = \mathbf{G}$ summed over the batch. For ReLU, $\partial L/\partial \mathbf{Z} = \mathbf{G} \odot (\mathbf{Z} > 0)$, an element-wise mask.

  </Accordion>
  <Accordion title="What does gradient checking test, and how should its result be read?">

    It compares each analytical gradient with the central difference $(L(\theta + h) - L(\theta - h))/2h$. In `float64`, relative errors below $10^{-7}$ mean correct, and above $10^{-2}$ mean a bug, typically a transpose, a wrong reduction axis, or a missing $1/N$. It must run in double precision because subtracting nearly equal losses in `float32` destroys the significant digits.

  </Accordion>
  <Accordion title="What happens if the 1/N is dropped from the output gradient?">

    Every gradient becomes exactly $N$ times larger, because all of them inherit that factor by multiplication, so the effective learning rate is $N$ times too high. Shapes are unaffected and nothing errors. Lowering the learning rate hides it, and it reappears whenever the batch size changes.

  </Accordion>
