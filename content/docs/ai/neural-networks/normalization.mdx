A **normalization layer** rescales the activations passing through a network so that, within some group of values, they have mean 0 and standard deviation 1, then applies a learned scale and shift. Normalization keeps every layer's input at a predictable scale throughout training — not just at initialization, which [Weight Initialization](/ai/neural-networks/layers-and-initialization) arranges, but after thousands of weight updates have changed every layer. Networks with normalization train faster, tolerate higher learning rates, and are far less sensitive to initialization. Nearly every modern architecture uses it.

The layers differ in one thing only: **which values are averaged together** to compute the mean and standard deviation. This page computes normalization by hand, then compares the groupings.

**Builds on:** [Weight Initialization](/ai/neural-networks/layers-and-initialization) for why activation scale matters, and [Descriptive Statistics](/ai/math-foundations/descriptive-statistics) for mean and variance.

## Normalization, by hand

Take three numbers, $x = [1, 2, 3]$:

1. **Mean:** $\mu = (1 + 2 + 3)/3 = 2$.
2. **Centre:** subtract the mean: $[-1, 0, 1]$.
3. **Variance:** average the squared deviations: $(1 + 0 + 1)/3 = 0.667$, so the standard deviation is $\sqrt{0.667} = 0.816$.
4. **Scale:** divide by the standard deviation: $\hat{x} = [-1.225, 0, 1.225]$, which has mean 0 and standard deviation 1.
5. **Learned scale and shift:** multiply by $\gamma$ and add $\beta$. With $\gamma = 2$, $\beta = 1$: $[-1.449, 1, 3.449]$.

As one formula:

$$
y = \gamma \cdot \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} + \beta
$$

$\epsilon$ (typically $10^{-5}$) prevents division by zero when a group has no spread. $\gamma$ and $\beta$ are **learned parameters**, one per feature, initialized to 1 and 0. They matter: forcing every layer's input to exactly mean 0 and variance 1 could remove information the network needs, so it is given the freedom to choose any scale and offset — including undoing the normalization entirely if that turns out best. The difference is that the scale is now controlled by two explicit parameters rather than emerging from the interaction of every weight below.

## The one choice: which values to average

An activation tensor has several axes: batch, features (or channels), and for images, height and width. Each normalization layer computes $\mu$ and $\sigma$ over a different subset. With a batch of 2 samples and 3 features:

```text
             feature 0   feature 1   feature 2
sample 0         1           2           3
sample 1         5           4           7
```

- **BatchNorm** averages **down each column**, across the batch: groups $(1, 5)$, $(2, 4)$, $(3, 7)$. Each feature is normalized using all samples in the batch.
- **LayerNorm** averages **along each row**, across features: groups $(1, 2, 3)$ and $(5, 4, 7)$. Each sample is normalized using only its own values.

| Layer            | Statistics computed over                               | Depends on other samples in the batch? |
| :--------------- | :----------------------------------------------------- | :------------------------------------- |
| **BatchNorm**    | The batch (and spatial positions), per channel         | Yes                                    |
| **LayerNorm**    | All features of one sample                             | No                                     |
| **RMSNorm**      | All features of one sample, without centring           | No                                     |
| **InstanceNorm** | Spatial positions of one channel of one sample         | No                                     |
| **GroupNorm**    | A group of channels plus spatial positions, per sample | No                                     |

Everything about how these layers behave — and fail — follows from the last column.

## BatchNorm

**Batch normalization** (Ioffe and Szegedy, 2015) normalizes each feature (each channel, in a CNN) over the examples in the current mini-batch, and over all spatial positions for images. It was the first normalization layer and it made very deep CNNs much easier to train.

### Training and evaluation behave differently

During training, $\mu$ and $\sigma$ come from the current batch. At evaluation there may be no batch — a single image arrives at a time — and predictions must not depend on which other examples happen to be processed alongside. So BatchNorm also keeps **running statistics**, exponential moving averages of the batch statistics updated at every training step:

$$
\text{running} \leftarrow (1 - m)\cdot\text{running} + m \cdot \text{batch statistic}, \qquad m = 0.1
$$

At evaluation, the running averages replace the batch statistics. Starting from 0 with a constant batch mean of 4.0, the running mean goes $0.4,\ 0.76,\ 1.08,\ 1.38,\ 1.64, \dots$, closing a tenth of the remaining gap per step, so it reflects roughly the last 10 to 20 batches.

This is why `model.train()` and `model.eval()` matter: forgetting `model.eval()` at test time makes predictions depend on the test batch, and leaving a frozen backbone in train mode silently updates its running statistics. (PyTorch's `momentum` argument is the weight on the **new** value; many other libraries use the opposite convention.)

### Why batch size matters

Batch statistics are **estimates** of the true statistics, and an estimate from $N$ samples has error proportional to $1/\sqrt{N}$:

| Batch size                                               |    2 |    4 |   16 |   64 |  256 |
| :------------------------------------------------------- | ---: | ---: | ---: | ---: | ---: |
| Typical error in the batch mean (in standard deviations) | 0.71 | 0.50 | 0.25 | 0.13 | 0.06 |

At batch size 2, the mean used in training differs from the running mean used at evaluation by about 0.7 standard deviations, so the network is trained on one distribution and tested on another. The limiting case is stark: with 2 samples, every normalized feature is just $\pm 1$, whatever the values. BatchNorm needs batches of roughly 16 or more per device, which rules it out for large detection and segmentation models whose images are big enough that only 1 or 2 fit on each GPU.

### Why BatchNorm helps

The original paper explained it as reducing **internal covariate shift**, the drift of each layer's input distribution as earlier layers update. Santurkar et al. (2018) showed this explanation does not hold up: BatchNorm can even increase that drift while still helping. What it does is make the loss surface smoother, so gradients are more reliable from one step to the next and larger learning rates are stable. Its noise — each example's normalization depends on random batch-mates — also acts as a mild regularizer.

## LayerNorm

**Layer normalization** (Ba, Kiros and Hinton, 2016) normalizes each sample independently, over its own features. Nothing crosses the batch boundary, so:

- **Training and evaluation are identical.** There are no running statistics.
- **Batch size 1 works**, as does any batch size.
- **Variable-length sequences work.** Each token is normalized on its own, so padding in other sequences cannot contaminate it.
- **One-token-at-a-time generation works**, because each new token is normalized without reference to anything else.

These properties make LayerNorm the standard in RNNs and transformers. The cost is that it averages across features that may mean unrelated things. In a CNN, averaging over all channels at once mixes "edge detector" with "red detector" statistics, which is why CNNs kept BatchNorm.

## RMSNorm

**RMSNorm** (Zhang and Sennrich, 2019) simplifies LayerNorm by dropping the mean subtraction and the shift $\beta$, dividing only by the root mean square:

$$
y = \gamma \cdot \frac{x}{\sqrt{\tfrac{1}{C}\sum_i x_i^2 + \epsilon}}
$$

The insight is that LayerNorm's benefit comes from fixing the **scale**, not the centre. Since mean square $=$ mean$^2$ $+$ variance, the two layers are identical when the input is already centred, which transformer activations approximately are. RMSNorm saves one reduction and one parameter vector per layer, and is used by LLaMA, Mistral, Qwen, Gemma, and most recent language models.

## GroupNorm and InstanceNorm

**GroupNorm** (Wu and He, 2018) splits the channels into $G$ groups (often 32) and normalizes each group over its channels and all spatial positions, per sample. It is independent of batch size, like LayerNorm, but averages only over related channels, so it suits CNNs. It is the standard replacement for BatchNorm in detection and segmentation models trained with small batches. Its two extremes are the other layers: $G = 1$ (all channels in one group) is LayerNorm, and $G = C$ (one channel per group) is **InstanceNorm**, which normalizes each channel of each image separately. InstanceNorm removes per-image contrast and colour statistics, which is exactly what style transfer wants.

## Where normalization goes: pre-norm and post-norm

In a network with [residual connections](/ai/classical-deep-learning/vision-architectures#resnet-the-residual-connection), the normalization can sit after the residual addition or inside the residual branch:

```text
post-norm:  h = Norm(h + Block(h))        the original 2017 Transformer
pre-norm:   h = h + Block(Norm(h))        GPT-2 and almost everything since
```

In **pre-norm**, the residual path from input to output is a clean chain of additions with nothing in the way, so gradients reach early layers easily. Training is stable without careful tuning. In **post-norm**, every path back passes through a normalization layer; Xiong et al. (2020) showed this gives large gradients near the output at initialization, so post-norm training diverges without a learning-rate **warmup**. Post-norm can reach slightly better final quality when tuned, but pre-norm is the default because it is robust. Measured on 40 residual blocks, pre-norm's parameter gradients grow toward the input by a factor of about $\sqrt{L}$, a mild and manageable drift.

## Choosing

| Model                                                | Normalization                              |
| :--------------------------------------------------- | :----------------------------------------- |
| CNN for classification, batch ≥ 16 per device        | BatchNorm                                  |
| CNN for detection or segmentation with small batches | GroupNorm (32 groups)                      |
| Style transfer                                       | InstanceNorm                               |
| Transformer                                          | RMSNorm or LayerNorm, in pre-norm position |
| RNN or LSTM                                          | LayerNorm                                  |
| Batch size 1 or 2, any model                         | Anything except BatchNorm                  |

Three questions decide it: is the batch small? (then not BatchNorm) Are inputs sequences of varying length or generated one token at a time? (then LayerNorm or RMSNorm) Is it a CNN whose channels mean unrelated things? (then GroupNorm rather than LayerNorm).

## Key terms

| Term                         | Meaning                                                                                    |
| :--------------------------- | :----------------------------------------------------------------------------------------- |
| **normalization**            | Rescaling a group of values to mean 0 and standard deviation 1                             |
| **$\gamma$, $\beta$**        | Learned per-feature scale and shift applied after normalizing                              |
| **BatchNorm**                | Normalizes each feature over the batch; uses running statistics at evaluation              |
| **running statistics**       | Moving averages of batch mean and variance, used in evaluation mode                        |
| **LayerNorm**                | Normalizes each sample over its own features                                               |
| **RMSNorm**                  | LayerNorm without mean subtraction or shift                                                |
| **GroupNorm / InstanceNorm** | Per-sample normalization over groups of channels / single channels, plus spatial positions |
| **pre-norm / post-norm**     | Normalization inside the residual branch / after the residual addition                     |

## Interview questions

<Accordions>
  <Accordion title="Normalize [1, 2, 3] by hand.">

    The mean is 2, the deviations are $-1, 0, 1$, the variance is $2/3$, and the standard deviation is 0.816, giving $[-1.225, 0, 1.225]$. A learned $\gamma$ and $\beta$ then rescale and shift it; with $\gamma = 2$ and $\beta = 1$ it becomes $[-1.449, 1, 3.449]$.

  </Accordion>
  <Accordion title="Why do normalization layers have learnable γ and β?">

    Forcing every layer's input to exactly zero mean and unit variance could remove useful information, such as a feature that should be mostly positive. $\gamma$ and $\beta$ let the network choose any scale and offset, including undoing the normalization. The benefit remains because the scale is controlled by two explicit parameters instead of emerging from all the weights below.

  </Accordion>
  <Accordion title="What is the difference between BatchNorm and LayerNorm?">

    BatchNorm normalizes each feature across the examples in a batch; LayerNorm normalizes each example across its own features. BatchNorm therefore depends on the batch, needs running statistics for evaluation, behaves differently in train and eval modes, and fails at small batch sizes. LayerNorm is a per-example function with none of those issues, which suits sequences and generation.

  </Accordion>
  <Accordion title="Why does BatchNorm fail with small batches?">

    The batch mean and variance are estimates whose error scales as $1/\sqrt{N}$: about 0.7 standard deviations at $N = 2$. Training then uses statistics that differ substantially from the running statistics used at evaluation, so the model is evaluated on a different distribution from the one it was trained on. At $N = 2$ each normalized feature is simply $\pm 1$.

  </Accordion>
  <Accordion title="What does forgetting model.eval() do to a network with BatchNorm?">

    Evaluation uses the current batch's statistics instead of the running averages, so predictions depend on which examples are batched together and degrade badly for small or unrepresentative batches. It also keeps updating the running statistics with test data.

  </Accordion>
  <Accordion title="Why did RMSNorm replace LayerNorm in many language models?">

    It drops mean subtraction and the shift parameter, dividing only by the root mean square. Because mean square equals squared mean plus variance, it equals LayerNorm on centred inputs, and transformer activations are close to centred. It is slightly cheaper with no loss in quality, because rescaling rather than recentring is what provides the benefit.

  </Accordion>
  <Accordion title="Why is pre-norm more stable than post-norm?">

    Pre-norm normalizes inside the residual branch, so the skip path from input to output is an uninterrupted chain of additions and gradients reach early layers without passing through normalization. Post-norm puts a normalization on every path, which produces large gradients near the output at initialization and requires learning-rate warmup to avoid divergence.

  </Accordion>
</Accordions>
