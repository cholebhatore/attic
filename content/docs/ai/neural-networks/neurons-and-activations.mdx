An artificial **neuron** is the smallest unit of a neural network. It does two things: it computes a **weighted sum** of its inputs plus a bias, and it passes that sum through a fixed curve called the **activation function**. The first step is linear. The second is not, and the second step is the reason a stack of neurons can learn anything a single straight-line model cannot.

This page builds one neuron, then a layer of them, then shows why the activation function matters, and finally walks through the activation functions in the order they were adopted — each one fixing a problem with the one before.

**Builds on:** [What Is a Neural Network](/ai/neural-networks/neural-network-basics) for the overall picture, and [Vectors and Matrices](/ai/math-foundations/vectors-and-matrices) for dot products and matrix multiplication.

## What one neuron computes

A neuron with $n$ inputs has $n$ **weights** and one **bias**. Given an input vector $\mathbf{x}$:

$$
\begin{aligned}
z &= \mathbf{w} \cdot \mathbf{x} + b = w_1 x_1 + w_2 x_2 + \dots + w_n x_n + b && \text{pre-activation} \\
a &= f(z) && \text{activation (the neuron's output)}
\end{aligned}
$$

- Each **weight** $w_i$ says how much, and in which direction, input $x_i$ influences the neuron. A large positive weight means "this input pushes me up", a negative weight "this input pushes me down", a weight near zero "I ignore this input".
- The **bias** $b$ shifts the result, setting how much input the neuron needs before it responds.
- $z$ is the **pre-activation**: the raw weighted sum.
- $f$ is the **activation function**, and $a$ is the **activation**, the number the neuron passes on.

### Worked example

Weights $\mathbf{w} = [1.0, -2.0]$, bias $b = 0.5$, input $\mathbf{x} = [3.0, 2.0]$:

| Term                              | Value                    |
| :-------------------------------- | :----------------------- |
| $w_1 x_1$                         | $1.0 \times 3.0 = 3.0$   |
| $w_2 x_2$                         | $-2.0 \times 2.0 = -4.0$ |
| $+\, b$                           | $+0.5$                   |
| $z$                               | $3.0 - 4.0 + 0.5 = -0.5$ |
| $a = \text{ReLU}(z) = \max(0, z)$ | $0$                      |

The second input, weighted negatively, outweighed the first, so the pre-activation is negative and ReLU (defined below) outputs 0: this neuron is "off" for this input.

### The geometric view

The dot product $\mathbf{w}\cdot\mathbf{x}$ measures how much $\mathbf{x}$ points in the direction of $\mathbf{w}$ (see [Similarity and Norms](/ai/math-foundations/similarity-and-norms)). The set of inputs where $z = 0$, that is $\mathbf{w}\cdot\mathbf{x} = -b$, is a straight line in 2D (a flat **hyperplane** in higher dimensions). It splits the input space into a side where the neuron is active and a side where it is not. This line is the neuron's **decision boundary**; $\mathbf{w}$ sets its orientation and $b$ slides it away from the origin.

One neuron can therefore only draw one straight boundary. Everything more complex comes from combining many neurons.

## From one neuron to a layer

A **layer** is a set of $m$ neurons that all read the same input. Stacking their weight vectors as the rows of a matrix $\mathbf{W}$ of shape $(m, n)$ and their biases into a vector $\mathbf{b}$ of length $m$ turns $m$ separate dot products into one matrix-vector product:

$$
\mathbf{z} = \mathbf{W}\mathbf{x} + \mathbf{b}, \qquad \mathbf{a} = f(\mathbf{z}) \quad \text{(f applied to each element)}
$$

Worked example with three neurons and two inputs:

$$
\mathbf{W} = \begin{bmatrix} 1.0 & 2.0 \\ 0.5 & -0.5 \\ -1.0 & 0.0 \end{bmatrix}, \quad
\mathbf{b} = \begin{bmatrix} 0 \\ 1 \\ -1 \end{bmatrix}, \quad
\mathbf{x} = \begin{bmatrix} 1 \\ 1 \end{bmatrix}
\quad\Rightarrow\quad
\mathbf{z} = \begin{bmatrix} 3 \\ 1 \\ -2 \end{bmatrix}, \quad
\text{ReLU}(\mathbf{z}) = \begin{bmatrix} 3 \\ 1 \\ 0 \end{bmatrix}
$$

Each row of $\mathbf{W}$ is one neuron: row 1 computes $1 \cdot 1 + 2 \cdot 1 + 0 = 3$, row 3 computes $-1 + 0 - 1 = -2$, which ReLU turns into 0.

For a **batch** of $B$ inputs stored as rows of a matrix $\mathbf{X}$ of shape $(B, n)$, the whole layer for the whole batch is one matrix multiply:

```python
import torch

X = torch.tensor([[1.0, 1.0], [2.0, 0.0]])          # (B=2, n=2)
W = torch.tensor([[1.0, 2.0], [0.5, -0.5], [-1.0, 0.0]])   # (m=3, n=2)
b = torch.tensor([0.0, 1.0, -1.0])

Z = X @ W.T + b              # (2, 3): every neuron, every example
A = torch.relu(Z)
print(A)                      # [[3, 1, 0], [2, 2, 0]]
```

The `W.T` appears because PyTorch's `nn.Linear` stores weights as `(out_features, in_features)`, one row per neuron, and batches as rows. Turning many small dot products into one large matrix multiply is what makes neural networks fast on GPUs, which are built to do exactly that operation.

## Why the activation function is essential

Remove the activation and stack two layers:

$$
\mathbf{y} = \mathbf{W}_2(\mathbf{W}_1\mathbf{x} + \mathbf{b}_1) + \mathbf{b}_2 = \underbrace{(\mathbf{W}_2\mathbf{W}_1)}_{\mathbf{W}'}\mathbf{x} + \underbrace{(\mathbf{W}_2\mathbf{b}_1 + \mathbf{b}_2)}_{\mathbf{b}'}
$$

Two linear layers collapse into **one** linear layer. With scalars: $W_1 = 2, b_1 = 1, W_2 = 3, b_2 = 4$ gives $3(2x + 1) + 4 = 6x + 7$ — the second layer added nothing. The same holds for any depth: a hundred linear layers compute a single linear function and can only draw straight decision boundaries. This is why a linear model cannot solve XOR, as [the basics page](/ai/neural-networks/neural-network-basics#the-perceptron-and-the-xor-problem) shows.

A nonlinear $f$ between layers breaks the collapse. $f(\mathbf{W}_1\mathbf{x} + \mathbf{b}_1)$ cannot be rewritten as a single matrix times $\mathbf{x}$, so each layer adds a genuinely new transformation, and the network can bend its decision boundaries. With ReLU, every neuron contributes one "fold" in the function; stacking layers of folds builds up arbitrarily complex shapes.

Since every gradient in training passes back through $f$, the **derivative** $f'(z)$ matters as much as $f$ itself. When a neuron's weights are updated, the gradient they receive is proportional to $f'(z)$ (shown in [Backpropagation](/ai/neural-networks/mlp-from-scratch)). If $f'(z) = 0$, the neuron does not learn from that input. Every activation function below is best understood through two questions: what shape is it, and what does its derivative do?

## Step, sigmoid, and tanh: the classic curves

### The step function

The original **perceptron** (Rosenblatt, 1958) used a hard step: output 1 if $z > 0$, else 0. It models a neuron that either fires or does not. Its derivative is 0 everywhere except at $z = 0$, where it is undefined, so gradient descent receives no signal at all. Neural networks became trainable by gradient descent only when the step was replaced by smooth curves.

### Sigmoid

$$
\sigma(z) = \frac{1}{1 + e^{-z}} \in (0, 1), \qquad \sigma'(z) = \sigma(z)\,(1 - \sigma(z))
$$

The **sigmoid** (or logistic function) is a smooth step: near 0 for very negative $z$, near 1 for very positive $z$, and 0.5 at $z = 0$. It was the standard activation through the 1990s. Two problems retired it from hidden layers:

1. **Small gradients.** Its derivative is at most $0.25$ (at $z = 0$). Backpropagation multiplies one such factor per layer, so ten sigmoid layers shrink the gradient by at least $0.25^{10} \approx 10^{-6}$.
2. **Not zero-centred.** Its outputs are always positive, so the next layer's inputs are all positive, which makes the gradients of that layer's weights all share one sign and forces zig-zagging updates.

The sigmoid survives where its $(0, 1)$ range is the point: as the output for binary classification, and as a **gate** that scales something between "off" and "on" (see [LSTM](/ai/classical-deep-learning/lstm-and-gru#what-a-gate-is)).

### Tanh

$$
\tanh(z) = \frac{e^z - e^{-z}}{e^z + e^{-z}} \in (-1, 1), \qquad \tanh'(z) = 1 - \tanh^2(z)
$$

**Tanh** is a rescaled sigmoid ($\tanh(z) = 2\sigma(2z) - 1$) that is zero-centred and has a maximum derivative of 1. It fixes problem 2 and improves problem 1, and it replaced the sigmoid as the default hidden activation.

### Saturation: the problem both share

Both curves flatten out at the ends. In those flat regions the neuron is **saturated**: a large change in $z$ barely changes the output, and the derivative is nearly zero.

| $z$          |     0 |     1 |     2 |      3 |
| :----------- | ----: | ----: | ----: | -----: |
| $\tanh(z)$   | 0.000 | 0.762 | 0.964 |  0.995 |
| $\tanh'(z)$  | 1.000 | 0.420 | 0.071 | 0.0099 |
| $\sigma'(z)$ | 0.250 | 0.197 | 0.105 |  0.045 |

A saturated neuron is stuck: it outputs nearly the same value for $z = 3$ and $z = 100$, and it passes back almost no gradient, so it cannot be moved out of saturation. In a deep network, saturated layers multiply gradients by tiny factors one after another, and gradients reaching the early layers **vanish**. This vanishing gradient problem kept deep networks untrainable for two decades.

## ReLU: the modern default

$$
\text{ReLU}(z) = \max(0, z), \qquad \text{ReLU}'(z) = \begin{cases} 1 & z > 0 \\ 0 & z \le 0 \end{cases}
$$

The **rectified linear unit** outputs its input if positive and 0 otherwise. It became standard after AlexNet (2012) showed it trained deep CNNs about six times faster than tanh. Its advantages follow directly from its shape:

- **No saturation on the positive side.** The derivative is exactly 1 for every active neuron, so gradients pass through active units unchanged however deep the network is.
- **Cheap.** One comparison, no exponentials.
- **Sparse.** For a given input, roughly half the neurons output exactly 0, so each input is represented by a subset of active units.

At $z = 0$ the derivative is undefined; frameworks use 0. It never matters in practice because a pre-activation is almost never exactly 0.

### The dead neuron problem

ReLU's derivative is exactly 0 for every negative input. A neuron whose pre-activation is negative for **every** input in the dataset outputs 0 always, receives gradient 0 always, and never changes again. It is **dead**.

Whether neurons die depends on where pre-activations sit. If they are centred at 0, half are inactive on any given input — normal and fine, since a different half fires for a different input. If something pushes them negative, most of the layer dies:

| Pre-activations distributed as | Fraction inactive ($z \le 0$) |
| :----------------------------- | ----------------------------: |
| Normal, mean 0, std 1          |                         50.0% |
| Normal, mean −1, std 1         |                         84.1% |
| Normal, mean −2, std 1         |                         97.7% |

A shift of −2 kills almost the entire layer, and a single over-large gradient step can cause such a shift. That is one reason [initialization](/ai/neural-networks/layers-and-initialization) and [normalization](/ai/neural-networks/normalization) matter: both keep pre-activations centred.

### ReLU variants

| Variant        | Negative side ($z \le 0$)    | Gradient at $z = -1$ | Notes                           |
| :------------- | :--------------------------- | -------------------: | :------------------------------ |
| **ReLU**       | $0$                          |                    0 | Can die                         |
| **Leaky ReLU** | $0.01 z$                     |                 0.01 | Never exactly zero gradient     |
| **PReLU**      | $\alpha z$, $\alpha$ learned |             $\alpha$ | One extra parameter per channel |
| **ELU**        | $e^z - 1$                    |                0.368 | Smooth; bounded below at −1     |

All keep ReLU's positive side and give the negative side a nonzero gradient so a neuron can recover.

## GELU and SiLU: smooth ReLUs

Transformers and most modern architectures use smooth versions of ReLU that let a small amount of negative signal through.

**GELU** (Gaussian Error Linear Unit) multiplies $z$ by the probability that a standard normal variable falls below $z$:

$$
\text{GELU}(z) = z\,\Phi(z)
$$

where $\Phi$ is the standard normal cumulative distribution function. Large positive inputs pass nearly unchanged ($\Phi \to 1$), large negative inputs are suppressed ($\Phi \to 0$), and near zero the input is scaled smoothly. Implementations usually use a fast approximation, $\tfrac{z}{2}\left(1 + \tanh\left(\sqrt{2/\pi}\,(z + 0.044715 z^3)\right)\right)$, which differs from the exact form by at most about $5 \times 10^{-4}$. BERT, GPT-2, GPT-3, and vision transformers use GELU.

**SiLU** (Sigmoid Linear Unit, also published as **Swish**) uses the sigmoid instead of $\Phi$:

$$
\text{SiLU}(z) = z\,\sigma(z)
$$

It is slightly "lazier" than GELU: it passes less of positive inputs and dips further below zero. LLaMA, Mistral, PaLM, and Qwen use it inside SwiGLU, below.

The same inputs through each curve:

| $z$  |     −2 |     −1 |   −0.5 |     0 |   0.5 |     1 |     2 |
| :--- | -----: | -----: | -----: | ----: | ----: | ----: | ----: |
| ReLU |  0.000 |  0.000 |  0.000 | 0.000 | 0.500 | 1.000 | 2.000 |
| GELU | −0.045 | −0.159 | −0.154 | 0.000 | 0.346 | 0.841 | 1.955 |
| SiLU | −0.238 | −0.269 | −0.189 | 0.000 | 0.311 | 0.731 | 1.762 |
| tanh | −0.964 | −0.762 | −0.462 | 0.000 | 0.462 | 0.762 | 0.964 |

Three differences from ReLU stand out:

- **Smoothness.** No corner at zero, so the derivative changes gradually. This tends to make optimization slightly smoother.
- **Nonzero gradient for negative inputs.** At $z = -0.5$, ReLU's derivative is 0, GELU's is 0.13, and SiLU's is 0.26. Neurons keep learning from inputs that would leave a ReLU unit silent, and do not die.
- **Non-monotonic.** Both dip slightly below zero (GELU to −0.17, SiLU to −0.28) before rising, so a single unit can distinguish "slightly negative" from "very negative".

## Gated units and SwiGLU

A **gated linear unit (GLU)** computes two linear projections of the same input and multiplies them element-wise, passing one through an activation so it acts as a learned, input-dependent gate on the other:

$$
\text{SwiGLU}(\mathbf{x}) = \text{SiLU}(\mathbf{W}_g\mathbf{x}) \odot (\mathbf{W}_v\mathbf{x})
$$

$\odot$ is element-wise multiplication. The "value" path $\mathbf{W}_v\mathbf{x}$ carries content; the "gate" path decides, per element, how much of it passes. In transformers, the feed-forward block of every layer is `down(SwiGLU(x))`. Because it has three weight matrices instead of two, the hidden width is usually reduced to about $\frac{2}{3}$ of a plain MLP's ($\frac{8}{3}d$ instead of $4d$) to keep the parameter count equal. Shazeer (2020) found the gated variants consistently improved language-model quality at equal compute. The detailed transformer block is in [Blocks and Positions](/ai/transformers/blocks-and-positions).

## Activations on the output layer

Hidden layers use ReLU-family activations. The **output layer** is different: its activation must match what the network predicts, and it is chosen together with the [loss function](/ai/neural-networks/loss-functions).

| Task                                 | Output activation  | Output meaning                              |
| :----------------------------------- | :----------------- | :------------------------------------------ |
| Regression (predict a number)        | None (identity)    | Any real number                             |
| Binary classification                | Sigmoid            | Probability of the positive class           |
| Multi-class (one label of $C$)       | Softmax            | A probability distribution over $C$ classes |
| Multi-label (several labels at once) | Sigmoid per output | An independent probability per label        |

**Softmax** turns a vector of raw scores, called **logits**, into probabilities that are positive and sum to 1: $\operatorname{softmax}(\mathbf{z})_i = e^{z_i} / \sum_j e^{z_j}$. It is covered in [Softmax and Logits](/ai/math-foundations/softmax-and-logits). In PyTorch the softmax or sigmoid is usually folded into the loss function for numerical stability, so the model itself outputs raw logits.

## Choosing an activation

| Situation                                | Choice                                         |
| :--------------------------------------- | :--------------------------------------------- |
| Hidden layers of an MLP or CNN           | ReLU; Leaky ReLU if many units die             |
| Transformers                             | GELU (BERT, GPT-style) or SwiGLU (LLaMA-style) |
| Gates (LSTM, GRU, attention-like gating) | Sigmoid                                        |
| Bounded hidden state (classic RNN)       | Tanh                                           |
| Output layer                             | Determined by the task, per the table above    |

Among ReLU, GELU, and SiLU, the differences in final accuracy are usually a fraction of a percent. Initialization, normalization, and learning rate matter far more. The choice that matters most is to avoid sigmoid and tanh in deep stacks of hidden layers, because of saturation.

## Key terms

| Term                    | Meaning                                                                              |
| :---------------------- | :----------------------------------------------------------------------------------- |
| **neuron**              | A weighted sum plus bias, passed through an activation function                      |
| **weight / bias**       | How much each input matters / an offset setting how readily the neuron responds      |
| **pre-activation $z$**  | The weighted sum before the activation function                                      |
| **activation function** | The fixed nonlinear curve applied to $z$                                             |
| **decision boundary**   | The hyperplane $\mathbf{w}\cdot\mathbf{x} + b = 0$ where a neuron switches on        |
| **layer**               | Many neurons reading the same input, computed as $\mathbf{W}\mathbf{x} + \mathbf{b}$ |
| **saturation**          | The flat region of a curve, where the derivative is near zero and learning stalls    |
| **vanishing gradient**  | Gradients shrinking toward zero as they pass back through many layers                |
| **dead neuron**         | A ReLU unit inactive on every input, so it never receives gradient                   |
| **logits**              | Raw output scores before softmax or sigmoid                                          |
| **gated unit**          | A unit where one projection, through an activation, multiplies another element-wise  |

## Interview questions

<Accordions>
  <Accordion title="What does a single neuron compute? Work one example.">

    $z = \mathbf{w}\cdot\mathbf{x} + b$, then $a = f(z)$. With $\mathbf{w} = [1, -2]$, $b = 0.5$ and $\mathbf{x} = [3, 2]$: $z = 3 - 4 + 0.5 = -0.5$, and ReLU gives $a = 0$. Geometrically, the neuron is active on one side of the hyperplane $\mathbf{w}\cdot\mathbf{x} = -b$.

  </Accordion>
  <Accordion title="Why does a deep network without activation functions collapse to one layer?">

    Each layer is $\mathbf{W}\mathbf{x} + \mathbf{b}$, and composing two gives $(\mathbf{W}_2\mathbf{W}_1)\mathbf{x} + (\mathbf{W}_2\mathbf{b}_1 + \mathbf{b}_2)$, another affine map. By induction any depth is one affine map, which can only draw straight decision boundaries. A nonlinearity between layers prevents the matrices from multiplying together.

  </Accordion>
  <Accordion title="Why were sigmoid and tanh replaced by ReLU in hidden layers?">

    Both saturate: for large $|z|$ their derivatives approach zero ($\tanh'(3) = 0.0099$, and the sigmoid's derivative never exceeds 0.25), so gradients shrink at every layer and vanish in deep networks. The sigmoid is also not zero-centred. ReLU has derivative exactly 1 for every active unit, so gradients pass through deep stacks undiminished, and it is cheaper to compute.

  </Accordion>
  <Accordion title="What is a dead ReLU, and how is it prevented?">

    A unit whose pre-activation is negative for every input: it always outputs 0, its gradient is always 0, and it never updates. It is caused by pre-activations drifting negative, for example after a too-large step. Prevention: good initialization, normalization, a moderate learning rate, or variants like Leaky ReLU, ELU, GELU, and SiLU that have a nonzero gradient for negative inputs.

  </Accordion>
  <Accordion title="How do GELU and SiLU differ from ReLU?">

    Both multiply $z$ by a smooth gate — the normal CDF for GELU, the sigmoid for SiLU — instead of hard-thresholding it. They are smooth at zero, have a nonzero gradient for moderately negative inputs (so units do not die), and dip slightly below zero, making them non-monotonic. In practice they give small, consistent gains in transformers.

  </Accordion>
  <Accordion title="What is SwiGLU, and why is the hidden width reduced to 8/3 d?">

    $\text{SiLU}(\mathbf{W}_g\mathbf{x}) \odot (\mathbf{W}_v\mathbf{x})$: a learned gate multiplied element-wise into a value projection, used in the transformer feed-forward block. It has three weight matrices (gate, value, down) instead of two, so shrinking the hidden width from $4d$ to $\frac{8}{3}d$ keeps the parameter count the same as a standard MLP block.

  </Accordion>
  <Accordion title="Which activation goes on the output layer for regression, binary, multi-class, and multi-label tasks?">

    Regression: none, so any real value is possible. Binary: sigmoid, giving one probability. Multi-class with exactly one correct label: softmax, giving a distribution over classes. Multi-label: an independent sigmoid per label. In PyTorch the sigmoid or softmax is usually folded into the loss, so the model outputs logits.

  </Accordion>
