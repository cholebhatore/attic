Phase 8 ended with a model that can reason and follow instructions. It still does not know your documents. Everything it answers from is in its weights, which means it is confident about a private codebase it has never seen and silent about a policy that changed last week.

This phase is the outer box. It covers how the full runtime context gets assembled, how a corpus becomes something searchable, how a query becomes something retrievable, and what breaks once the system is in front of users. Phase 9 is the most heavily tested AI Engineering interview domain, so the pages lean toward naming and comparing techniques rather than deriving them.

The phase follows the RAG pipeline in the order data flows through it. **Indexing** turns documents into a searchable index: load them from their sources, parse them into structured text, clean and enrich them, chunk, embed, and store. **Querying** answers a question from that index: retrieve, rerank, transform the query, assemble the context, and generate a grounded answer with citations. Advanced paradigms and production debugging come last.

New to RAG? Start with [RAG Basics](/ai/rag/rag-basics). It defines every term, walks through every stage, builds a RAG system in 40 lines, and maps the tech stack, before any page goes deep. Every page after it also opens with a **plain-language version**: where the page sits in the pipeline, a short explanation with an analogy, the page's topics in order, and a table of the words it uses.

<Callout type="info">
  ### Every number here is either published or arithmetic

The cost-per-query figures, the KV cache sizes, the storage multipliers for chunk overlap and quantization, and the indexing token budgets are all derived on the page from stated inputs. Where a figure comes from a paper, the arXiv id is next to it. Where a figure would depend on hardware you have not measured, it is given as a range with an instruction to measure your own.

Read RAG Basics first: it is the map for everything else. Then follow the data. The indexing pages come first because most RAG quality problems are created there, at load, parse, and chunk time, and cannot be repaired by a better retriever later. Read the retrieval pages in order, because reranking assumes hybrid search and query transformation assumes both. The context and generation block turns retrieved chunks into a grounded, cited answer. Do not skip it in a hurry to tune the index: half of the projects that reach for a bigger index should have fixed how the context is assembled. It ends with RAG against long context, the decision of whether to retrieve at all, which is easiest to judge once you know what retrieval costs and buys.

## Prerequisites

- [Similarity and Norms](/ai/math-foundations/similarity-and-norms) for cosine similarity, dot products and the `L2^2 = 2 - 2*cos` relationship every embedding page assumes
- [Vectors and Matrices](/ai/math-foundations/vectors-and-matrices) for the dimension arithmetic behind embeddings and product quantization
- [Information Theory and Loss](/ai/math-foundations/information-the-and-loss) for cross-entropy and KL, which appear in the contrastive embedding loss and in judge metrics
- [Matrix Multiplication](/ai/pytorch/matrix-multiplication) for the `O(N*d)` exact-scan cost that motivates approximate nearest neighbour search
- [Classical NLP](/ai/classical-deep-learning/classical-nlp) for word vectors, TF-IDF and the lineage BM25 and dense retrieval both descend from
- [What is an LLM](/ai/llm/what-is-an-llm) for the memory-footprint arithmetic reused for index sizing
- [Tokenization](/ai/llm/tokenization) because tokens are the unit every context budget here is counted in
- [Context Windows](/ai/llm/context-windows) for window limits and the KV cache cost behind RAG against long context
- [Attention Variants](/ai/llm/attention-variants) for GQA and MLA, which set the per-token cache cost of stuffing a window
- [Inference Lifecycle](/ai/llm/inference-lifecycle) for prefill against decode, and where time to first token comes from
- [Decoding Strategies](/ai/llm/decoding) for temperature, which grounded generation pins near zero
- [Why Fine-Tune](/ai/fine-tuning/why-fine-tune) for the prompting-retrieval-fine-tuning ladder that decides whether retrieval is the right lever
- [RLVR and Reasoning](/ai/reinforcement-learning/rlvr-and-reasoning) for test-time compute, which agentic RAG spends freely

No new packages, and nothing here needs a GPU to read. The code samples use `pydantic`, `numpy`, and the client libraries named on each page.

## What you should be able to do afterwards

- Draw the indexing and query pipelines from memory, name every stage, and name a tool for each

- Write a grounded prompt with a refusal path, and verify citations with an entailment check
- Distinguish prompt engineering from context engineering, and list the six components of a runtime context with a rough token share for each
- Explain lost in the middle and length degradation, and state where to place a critical instruction as a result
- Order a context for prompt cache hits, and compute the saving from a stated provider's cache pricing
- Decide between retrieval and a long context for a stated corpus size, query rate and latency target, with the arithmetic
- Compare fixed-size, recursive, semantic, parent-child, proposition and late chunking, and pick one for a stated document type
- Explain contextual retrieval and quote the failure-rate reduction each stage buys
- Describe HNSW, IVF and product quantization, name which parameters are build-time against query-time, and compute the memory a quantization level saves
- Derive a BM25 score, explain what `k1` and `b` each control, and compute a reciprocal rank fusion ordering by hand
- Compare cross-encoders, LLM rerankers and ColBERT on where the computation happens, latency, and indexability
- Write ColBERT's MaxSim score and explain why late interaction is a middle ground
- Choose among rewriting, multi-query, HyDE, decomposition and step-back prompting from a symptom
- Explain Self-RAG's reflection tokens, CRAG's three confidence bands, and what Adaptive-RAG routes on
- Name the four guardrails an agentic retrieval loop needs and what each prevents
- Walk through the GraphRAG indexing pipeline, contrast Local with Global search, and estimate the indexing token cost of a stated corpus
- Build a text-to-SQL pipeline with schema linking, value retrieval and a sandbox, and compare execution accuracy against exact set match
- Say what layout-aware PDF parsing recovers that naive extraction loses, and the two chunking rules that follow
- Localize a RAG failure to retrieval or generation from a chunk dump, and name the metric that proves it
- Fix ungrounded answers, duplicate chunks, slow retrieval, per-user access control and stale documents, in that order of diagnosis
- Explain why access control must be a pre-filter, and name four leak paths that are not the vector index
