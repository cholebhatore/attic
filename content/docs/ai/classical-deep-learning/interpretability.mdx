A trained CNN is a differentiable function from pixels to class scores, and you can query it in two directions. Push an image forward and read what each layer computes. Push a class score backward and read which pixels and which units were responsible for it. Both directions use the same mechanism: hooks.

---

## The plain-language version

A trained network gives an answer but not a reason. **Interpretability** is the set of techniques for looking inside to see **why** it answered the way it did: which parts of the image mattered, and what each internal unit has learned to detect.

There are two directions to look:

- **Forward**: run an image through and inspect what each layer produced. The **feature maps** of early layers show edges; later ones respond to eyes, wheels, or fur.
- **Backward**: start from the model's score for a class and compute its gradient with respect to the input pixels. Pixels with large gradients are the ones that, if changed, would change the answer most. Painting those gradients as an image gives a **heatmap** of where the model was "looking".

Both use **hooks**: small functions you attach to a layer so PyTorch calls them automatically whenever data (forward) or gradients (backward) pass through that layer.

Why it matters: a model that correctly labels "wolf" because of the snow in the background will fail on a wolf on grass. A heatmap exposes that before users do.

| Word                                  | Plain meaning                                                                                                                                                           |
| :------------------------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **interpretability / explainability** | Understanding why a model produced its output.                                                                                                                          |
| **hook**                              | A function registered on a layer that runs automatically during the forward pass (`register_forward_hook`) or backward pass.                                            |
| **feature map / activation map**      | The output grid of one convolution filter. Shows where in the image that filter's pattern appears.                                                                      |
| **unit / channel**                    | One filter in a layer and its feature map. "What a unit responds to" means which image patterns make it fire strongly.                                                  |
| **saliency map**                      | A heatmap of the gradient of a class score with respect to each input pixel.                                                                                            |
| **Grad-CAM**                          | Gradient-weighted Class Activation Mapping: weight a late conv layer's feature maps by how much each one affects the class score, giving a coarse but reliable heatmap. |
| **Guided Grad-CAM**                   | Grad-CAM multiplied by a sharper pixel-level gradient map, for heatmaps that are both class-specific and detailed.                                                      |
| **attribution**                       | Assigning credit for the output to each input feature (pixel, word).                                                                                                    |
| **integrated gradients**              | An attribution method that averages gradients along a path from a blank image to the real one, to fix the noise of plain gradients.                                     |
| **`captum`**                          | PyTorch's library of ready-made attribution methods.                                                                                                                    |
| **spurious correlation**              | A pattern that predicts the label in training data but is not the real cause, like snow for "wolf". Interpretability tools help catch them.                             |

## Hooks

A hook is a callback PyTorch invokes during a module's forward or backward pass. You register it on a module and it fires every time that module runs, with no change to the model's source.

| Registration                   | Signature                                    | Fires                 |
| :----------------------------- | :------------------------------------------- | :-------------------- |
| `register_forward_pre_hook`    | `(module, args) -> None or modified args`    | Before `forward`      |
| `register_forward_hook`        | `(module, args, output) -> None or new out`  | After `forward`       |
| `register_full_backward_hook`  | `(module, grad_input, grad_output) -> tuple` | During `backward`     |
| `register_module_forward_hook` | Global, every module                         | After every `forward` |

```python
handles = []
acts = {}

def fwd(module, args, output):
    acts[module] = output.detach()

handles.append(model.layer4.register_forward_hook(fwd))
model(x)
print(acts[model.layer4].shape)   # (B, 2048, 7, 7)

for h in handles:
    h.remove()
```

Four things worth knowing:

- Returning a value from a forward hook replaces the module's output. This is how you patch a layer without editing the model.
- Returning a tuple from a backward hook replaces `grad_input`. This is how guided backprop works.
- `register_full_backward_hook` is the current API. `register_backward_hook` is deprecated and mishandles modules with multiple outputs.
- Hooks hold references to what they capture. Remove the handles, or your activations stay on the GPU for the lifetime of the process.

If you need the gradient of a tensor that is not a module output, `retain_grad()` is simpler than a hook:

```python
mid = model.features[:6](x)
mid.retain_grad()
logits = model.features[6:](mid)
logits.sum().backward()
print(mid.grad.shape)
```

## Inspecting feature maps

The cheapest useful audit is a forward hook that records activation statistics per layer. It catches dead units, saturation, and scale drift in a few lines.

```python title="activation_stats.py"
stats = {}

def record(name):
    def hook(module, args, output):
        o = output.detach().float()
        stats[name] = {
            "mean": o.mean().item(),
            "std": o.std().item(),
            "frac_zero": (o == 0).float().mean().item(),
            "max": o.amax().item(),
        }
    return hook

for name, module in model.named_modules():
    if isinstance(module, nn.ReLU):
        module.register_forward_hook(record(name))
```

`frac_zero` after a ReLU is the dead-unit rate. A layer where it exceeds about 0.8 has collapsed and is contributing nothing; see [Neurons and Activations](/ai/neural-networks/neurons-and-activations).

### Finding what a unit responds to

For a given channel `k` in a feature map, score every image in the dataset by its maximum activation and look at the top ten. This is the standard manual version of feature visualization, and on ImageNet-pretrained models the results are interpretable: early channels fire on colours and edges, mid channels on textures like fur and grille, late channels on object parts.

```python title="max_activating.py"
best = []

def hook(module, args, output):
    score = output[:, channel].flatten(1).amax(1)     # (B,)
    for i, s in enumerate(score.tolist()):
        best.append((s, i))

model.layer4[2].register_forward_hook(hook)
with torch.no_grad():
    for batch, _ in loader:
        model(batch.to(device))
best.sort(reverse=True)
```

Activating a single channel maximally by gradient ascent on the input, starting from noise or a blurred image, is Deep Dream and activation maximization. That is on the next page.

## Saliency maps

Saliency answers: which pixels most influence this class score? Take the gradient of the score with respect to the input image.

```python title="saliency.py"
import torch

def saliency(model, x, class_idx=None):
    model.eval()
    x = x.unsqueeze(0).requires_grad_(True)
    logits = model(x)
    idx = logits.argmax(-1).item() if class_idx is None else class_idx

    model.zero_grad()
    logits[0, idx].backward()

    grad = x.grad[0].abs()              # (3, H, W)
    return grad.amax(0)                 # (H, W), max over colour channels
```

Setting `requires_grad_(True)` on the input rather than the weights is the whole trick, and it is the same mechanism as every attack and visualization method on the next page. `model.zero_grad()` stops weight gradients from accumulating across calls, but the parameters still allocate gradient buffers. Free them first if memory is tight:

```python
for p in model.parameters():
    p.requires_grad_(False)
```

The result is noisy. Three common cleanups:

| Variant              | Modification                                | Effect                        |
| :------------------- | :------------------------------------------ | :---------------------------- |
| Vanilla gradient     | `abs(grad)`                                 | Noisy, shows local edges      |
| Gradient times input | `grad * x`                                  | Suppresses low-value pixels   |
| SmoothGrad           | Average `grad` over `n` noisy copies of `x` | Much smoother, `n` times cost |
| Guided backprop      | Block negative gradients at every ReLU      | Sharp, high-contrast          |

Guided backprop needs a backward hook on each ReLU that zeroes the negative part of the incoming gradient:

```python
def guided_relu(module, grad_input, grad_output):
    return (grad_output[0].clamp(min=0),)

for m in model.modules():
    if isinstance(m, nn.ReLU):
        m.register_full_backward_hook(guided_relu)
```

Returning a one-element tuple replaces `grad_input`. The result is visually far cleaner than vanilla saliency, and it is also less faithful, since it drops the negative evidence that pushed the score down.

## Grad-CAM

Saliency gives pixel-level detail and no semantic locality. Grad-CAM gives a coarse heatmap over the last convolutional feature map that says which region of the image the class score came from.

For class `c` and the last conv layer's activation `A` with channels `A^1 ... A^K`:

```text
alpha_k = (1/Z) * sum over i,j of  dY^c / dA^k_ij
L_Grad-CAM = ReLU( sum_k  alpha_k * A^k )
```

`alpha_k` is the global-average-pooled gradient of the class score with respect to channel `k`. It measures how much channel `k` matters for class `c`. The weighted sum of channels is then passed through a ReLU so only positive evidence shows, and upsampled to the input resolution.

```python title="gradcam.py"
import torch
import torch.nn.functional as F

def grad_cam(model, target_layer, x, class_idx=None):
    acts, grads = {}, {}

    def fwd(module, args, output):
        acts["a"] = output

    def bwd(module, grad_input, grad_output):
        grads["g"] = grad_output[0]

    hf = target_layer.register_forward_hook(fwd)
    hb = target_layer.register_full_backward_hook(bwd)

    x = x.unsqueeze(0)
    logits = model(x)
    idx = logits.argmax(-1).item() if class_idx is None else class_idx

    model.zero_grad()
    logits[0, idx].backward()
    hf.remove()
    hb.remove()

    A, G = acts["a"][0], grads["g"][0]         # both (K, h, w)
    alpha = G.mean(dim=(1, 2), keepdim=True)   # (K, 1, 1)
    cam = torch.relu((alpha * A).sum(0))       # (h, w)
    cam = cam / cam.amax().clamp(min=1e-8)
    return F.interpolate(
        cam[None, None], size=x.shape[-2:], mode="bilinear", align_corners=False
    )[0, 0]
```

Target the last convolutional layer before global pooling. For a `timm` ResNet-50 that is `model.layer4[-1].conv3`, or more reliably the module whose output feeds `model.avgpool`:

```python
target = [m for m in model.modules() if isinstance(m, nn.Conv2d)][-1]
```

The heatmap will be `7 x 7` for a `224 x 224` input, upsampled by bilinear interpolation. That coarseness is expected and is the reason Grad-CAM is often combined with guided backprop.

### Guided Grad-CAM

Multiply the upsampled Grad-CAM by the guided-backprop saliency map elementwise. Grad-CAM supplies the localization, guided backprop supplies the fine detail.

```python
guided = guided_backprop(model, x, idx)            # (3, H, W)
cam = F.interpolate(grad_cam_out[None, None], guided.shape[-2:])[0, 0]
result = guided * cam
```

<Callout type="warn">
  ### In-place operations break backward hooks

`nn.ReLU(inplace=True)` overwrites its input tensor, and a backward hook registered on the preceding convolution then sees a tensor that has already been freed. PyTorch raises a version-counter error, or the hook silently receives the wrong gradient. When you need Grad-CAM, rebuild the model with `inplace=False`, or register the hook on the ReLU module itself rather than the convolution before it.

</Callout>

## Attribution methods and captum

Grad-CAM and saliency are two points in a large space. [`captum`](https://github.com/pytorch/captum) implements most of them with a common API: each attributor takes a forward function, an input, and a target index, and returns a tensor shaped like the input.

| Method                          | What it computes                                          | Cost                 |
| :------------------------------ | :-------------------------------------------------------- | :------------------- |
| `Saliency`                      | Gradient of the score wrt the input                       | One backward         |
| `InputXGradient`                | Gradient times input                                      | One backward         |
| `GuidedBackprop`                | Gradient with positive-only ReLU paths                    | One backward         |
| `IntegratedGradients`           | Path integral of gradients from a baseline to the input   | `m` backward passes  |
| `DeepLift`                      | Single-pass approximation of integrated gradients         | Roughly one backward |
| `GradCam`                       | Gradient-weighted activation of a chosen layer            | One backward         |
| `LayerIntegratedGradients`      | Integrated gradients attributed to a chosen layer         | `m` backward passes  |
| `Occlusion` / `FeatureAblation` | Score change when a patch is masked or replaced           | Many forward passes  |
| `NoiseTunnel`                   | SmoothGrad-style variance reduction over any of the above | Multiplier on top    |
| `ShapleyValueSampling`          | Game-theoretic contribution per feature                   | Very expensive       |

```python
from captum.attr import IntegratedGradients, LayerIntegratedGradients, visualization

ig = IntegratedGradients(model)
attr = ig.attribute(x, target=idx, baselines=torch.zeros_like(x), n_steps=50)
```

Integrated gradients is the one to reach for when you need a defensible answer rather than a pretty picture. It satisfies two axioms that plain gradients violate: a feature that never changes between the baseline and the input gets zero attribution, and attributions sum to the difference between the input's score and the baseline's score. It costs `m` backward passes, usually `m = 50`.

Occlusion methods are model-agnostic and slow, but they measure the quantity you asked about directly: how much does the score change when this patch is gone.

## Hooks for everything else

The same two registration calls cover most model surgery you will ever need without touching a `forward` method.

| Use                                | Hook type       | Notes                                      |
| :--------------------------------- | :-------------- | :----------------------------------------- |
| Shape debugging                    | Forward pre     | Print `args[0].shape` for every module     |
| Embedding extraction for retrieval | Forward         | Capture the pooled feature vector          |
| FLOP and MAC counting              | Forward         | Multiply output elements by kernel weights |
| Quantization calibration           | Forward         | Record min/max or histogram per activation |
| Attention weight extraction        | Forward         | Alternative to `output_attentions=True`    |
| Feature distillation losses        | Both            | Match teacher and student activations      |
| Gradient norm monitoring per layer | Backward        | Detect one layer dominating or dying       |
| Patching a layer's behaviour       | Forward, return | Returned value replaces the module output  |

A global forward pre-hook that prints shapes is the fastest way to debug a new architecture:

```python
import torch.nn.modules.module as nn_module

def shape_probe(module, args):
    t = args[0]
    if torch.is_tensor(t):
        print(f"{module.__class__.__name__:20s} in={tuple(t.shape)}")

handle = nn_module.register_module_forward_pre_hook(shape_probe)
model(torch.randn(1, 3, 224, 224))
handle.remove()
```

## Interview questions

<Accordions>
  <Accordion title="What is the signature of a forward hook, and what happens if it returns a value?">

    `hook(module, args, output)`. Returning a value from a forward hook replaces the module's output, which is how you patch a layer without editing the model; returning `None` leaves it as it is.

  </Accordion>
  <Accordion title={<>Why is <code>register_full_backward_hook</code> preferred over <code>register_backward_hook</code>?</>}>

    `register_backward_hook` is deprecated and mishandles modules with multiple inputs or outputs. `register_full_backward_hook` is given the module's full input and output and does the autograd bookkeeping correctly, so it is the current API for anything with more than one tensor crossing the boundary.

  </Accordion>
  <Accordion title="How do you get the gradient of an intermediate tensor that is not a module's output?">

    Call `tensor.retain_grad()` before the backward pass and read `tensor.grad` afterwards. Hooks are the right tool at module boundaries; for an intermediate tensor produced inside a chain of calls, `retain_grad` avoids registering and removing anything.

  </Accordion>
  <Accordion title={<>Write the Grad-CAM formula and explain what <code>alpha_k</code> measures.</>}>

    `alpha_k` is the global-average-pooled gradient of the class score with respect to channel `k`, computed as `(1/Z) * sum over i,j of dY^c / dA^k_ij`, and the map is `ReLU(sum_k alpha_k * A^k)` upsampled to the input size. `alpha_k` measures how much channel `k` matters for class `c`: a channel whose gradients point at the class contributes, one that argues against it is zeroed out by the ReLU.

  </Accordion>
  <Accordion title="Which layer should Grad-CAM target, and why not an earlier one?">

    The last convolutional feature map. Channels there correspond to object parts, so the weighting localizes the thing the network recognized. Earlier maps have finer spatial resolution but their channels encode edges and textures, so the heatmap points at low-level pattern rather than the object. The final map is coarse, `7 x 7` for a `224 x 224` input, which is why Grad-CAM is often combined with guided backprop.

  </Accordion>
  <Accordion title="What breaks when a backward hook is registered on a module followed by an in-place ReLU?">

    `nn.ReLU(inplace=True)` overwrites the tensor the convolution just produced, so the hook registered on that convolution references memory already freed. PyTorch raises a version-counter error, or worse, the hook silently receives the wrong gradient. Rebuild the model with `inplace=False`, or register the hook on the ReLU module itself instead of the convolution before it.

  </Accordion>
  <Accordion title="How does guided backprop modify the backward pass, and what does that cost in faithfulness?">

    It clamps the gradient to non-negative at every ReLU by returning `(grad_output[0].clamp(min=0),)` from a backward hook, so only paths that increased the score survive and the saliency map is a single clean object instead of a positive-negative mess. The cost is faithfulness: it discards the negative evidence that pushed the score down, so the picture is more legible than it is true.

  </Accordion>
  <Accordion title="What two axioms do integrated gradients satisfy that vanilla gradients do not?">

    Sensitivity of the input, meaning a feature identical to the baseline receives exactly zero attribution, and completeness, meaning the attributions sum to the difference between the score at the input and the score at the baseline. Plain gradients violate both: a saturated unit can have a gradient of zero while being entirely responsible for the prediction.

  </Accordion>
  <Accordion title="When would you use occlusion over a gradient method?">

    When the model is not differentiable, when you distrust its gradients because gradient masking is suspected, or when you want the literal counterfactual rather than a linearization: how much does the score fall with this patch removed. It costs many forward passes, and being model-agnostic is also what makes the answer defensible to a skeptic.

  </Accordion>
  <Accordion title={<>How do you extract embeddings from a pretrained backbone without editing its <code>forward</code>?</>}>

    Create the model with `num_classes=0`, which drops the classifier head and returns the pooled feature vector, or call `forward_features` and pool the map yourself. Either way the checkpoint's code is untouched and no `forward` is edited.

  </Accordion>
  <Accordion title="What does a high dead-unit fraction in a layer's activations tell you?">

    It is the dead-unit rate: `frac_zero` after a ReLU. Above roughly 0.8 the layer has collapsed and contributes nothing for most inputs, usually from a learning rate too high, a missing normalization layer, or a bias pushed negative enough that the unit never activates.

  </Accordion>
  <Accordion title="Why do hooks cause memory leaks, and how do you avoid it?">

    The hook's closure keeps a reference to everything it captures, so those activations stay alive, and if they were stored without `.detach()` they keep the graph alive too — on the GPU, for the lifetime of the process. Call `remove()` on the returned handles when the inspection is finished, and `.detach()` before storing.

  </Accordion>
</Accordions>
