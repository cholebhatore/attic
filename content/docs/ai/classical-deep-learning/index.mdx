Phase 3 built networks out of dense layers. Every weight in those layers connects to every input, so they treat an input as a flat vector and they relearn the same feature at every position in an image. Convolutions fix both problems by sharing weights across space.

This phase covers what came after that fix and before transformers took over: vision architectures, reusing pretrained backbones, reading gradients out of a trained model, and recurrent networks for sequences. The last page ends at the fixed-vector bottleneck that motivated attention, which is where Phase 5 starts.

New to computer vision or NLP? Start with [Vision and Sequence Basics](/ai/classical-deep-learning/vision-and-sequence-basics). It explains how images and text become tensors, what the main tasks and datasets are, what an inductive bias is, and how CNNs, RNNs, and transformers relate, before any page goes deep. Every page after it also opens with a **plain-language version**: a short explanation with an analogy and a table of the words the page uses.

## The whole phase, topic by topic

Every heading in this phase, in reading order, with the one detail that makes each worth remembering. Read it first as a preview, or afterwards as a revision sheet.

<Accordions>
  <Accordion title="Vision and Sequence Basics">

    - **Why dense layers are not enough** — about 9.6 million position-tied weights for one small image layer; no way to handle variable length or order
    - **Images as tensors** — pixels, channels, `(B, C, H, W)`, scaling to 0..1, and per-channel normalization
    - **Computer vision tasks and datasets** — classification, detection, segmentation, captioning; MNIST, CIFAR-10, ImageNet
    - **Sequences as tensors** — `(B, T, F)`; text, audio, and time series; what NLP is
    - **Inductive bias** — locality and translation equivariance for convolutions, order for recurrence
    - **The three families** — CNNs for space, RNNs for time, transformers for both
    - **Pretrain, then adapt** — backbone, head, transfer learning, fine-tuning
    - **Where each idea is covered** — which page answers which question

  </Accordion>
  <Accordion title="Convolutions">

    - **The plain-language version** — a small filter slid over the image like a magnifying glass; pixel, channel, feature map, stride, padding, pooling, receptive field
    - **Kernels, filters, and channels** — a filter spans every input channel; one filter makes one output channel
    - **The output size formula** — `floor((H + 2*padding - dilation*(kernel - 1) - 1) / stride) + 1`
    - **Stride** — the jump between positions; stride 2 halves height and width
    - **Padding** — border pixels so edges are covered and size is kept
    - **Pooling** — summarize each window by its max or mean
    - **Receptive field progression** — each layer's window is measured in the previous layer's coordinates, so it grows faster than the kernel suggests
    - **Convolutions are matrix multiplies** — `im2col` turns patches into columns, then one GEMM
    - **Grouped and depthwise convolutions** — filter channel groups separately to cut compute
    - **A minimal CNN** — conv, activation, pool, repeat, then a classifier

  </Accordion>
  <Accordion title="Vision Architectures">

    - **The plain-language version** — augmentation for too little data, residuals for too much depth, multi-scale blocks for wasted compute
    - **A CIFAR-10 pipeline** — augmentation choices and the training loop
    - **Residual connections** — `x + f(x)`; the bottleneck block and pre-activation ordering
    - **Inception and multi-scale blocks** — parallel filter sizes, with 1 by 1 convolutions to keep the cost down
    - **Navigating timm** — finding and loading pretrained architectures
    - **A short architecture timeline** — GoogLeNet beats VGG with about a twentieth of the parameters

  </Accordion>
  <Accordion title="Transfer, Ensembles, Video">

    - **The plain-language version** — reuse a pretrained backbone, replace the head; average several models; video adds a time axis
    - **Transfer learning** — linear probing, fine-tuning, and how the domain gap decides between them
    - **Ensembles** — logit versus probability averaging, bagging, and evaluating many models at once with `vmap`
    - **Video data** — 3D convolutions, factorized (2+1)D convolutions, temporal sampling and transforms

  </Accordion>
  <Accordion title="Interpretability">

    - **The plain-language version** — read forward to see what layers compute, backward to see which pixels mattered; hooks do both
    - **Hooks** — callbacks on a layer's forward or backward pass
    - **Inspecting feature maps** — and finding what a unit responds to from its top-activating images
    - **Saliency maps** — the gradient of a class score with respect to each pixel
    - **Grad-CAM** — feature maps weighted by their gradient; Guided Grad-CAM adds pixel detail
    - **Attribution methods and captum** — integrated gradients and other ready-made methods
    - **Hooks for everything else** — the same two registration calls cover most model surgery

  </Accordion>
  <Accordion title="Gradient Manipulation">

    - **The plain-language version** — freeze the model and change the image instead: adversarial examples, Deep Dream, style transfer
    - **Adversarial examples** — invisible perturbations that flip predictions, explained by near-linearity in high dimensions
    - **FGSM** — one step of size `eps` along the sign of the input gradient; choosing `eps`
    - **PGD** — many small steps projected back into the budget; the attack taxonomy
    - **Adversarial training** — training on perturbed examples, the only defense that has held up
    - **Deep Dream** — gradient ascent on an intermediate layer's activations
    - **Style transfer** — content from deep features, style from Gram matrices, optimized with L-BFGS

  </Accordion>
  <Accordion title="Recurrent Networks">

    - **The plain-language version** — read a sequence one step at a time and keep notes in a hidden state; gates fix forgetting
    - **The recurrent cell** — new input plus previous hidden state in, new hidden state out, same weights every step
    - **Backpropagation through time** — backprop over the unrolled network; gradients vanish or explode
    - **Clipping exploding gradients** — cap the gradient norm; truncated BPTT
    - **LSTM** — a cell state with forget, input, and output gates
    - **GRU** — two gates and one state vector
    - **Bidirectional, stacked, and variable length** — reading both ways, layering, padding and packing
    - **Time series prediction** — sliding-window autoregression, multi-horizon strategies, and what matters more than the architecture
    - **When recurrent networks still make sense** — where transformers did not replace them

  </Accordion>
  <Accordion title="Classical NLP and Seq2Seq">

    - **The plain-language version** — what NLP is, its main tasks, and the vocabulary from corpus to beam search
    - **Before neural NLP: counting words** — bag of words, n-grams, TF-IDF, and n-gram language models
    - **From one-hot to embeddings** — a learned `(V, d)` lookup table replaces orthogonal one-hot vectors
    - **Word2Vec** — skip-gram and CBOW, negative sampling, and analogy arithmetic
    - **GloVe** — fit vectors to the log of global co-occurrence counts; Word2Vec against GloVe
    - **The limits of static embeddings** — one vector per word, whatever the sentence
    - **Seq2Seq** — encoder-decoder, teacher forcing, greedy and beam search decoding
    - **The fixed-vector bottleneck** — BLEU falls off on long sentences because everything squeezes through one vector
    - **Image captioning** — swap the RNN encoder for a CNN
    - **Evaluation** — perplexity, BLEU, METEOR, and what each misses

  </Accordion>
</Accordions>

## Prerequisites

- [Neurons and Activations](/ai/neural-networks/neurons-and-activations) for ReLU and its variants, which every conv block uses
- [Normalization](/ai/neural-networks/normalization) for BatchNorm and GroupNorm, which appear in ResNet blocks and in small-batch detection models
- [Matrix Multiplication](/ai/pytorch/matrix-multiplication) for `einsum`, which is how a convolution is written when you want to see what it computes
- [Autograd Engine](/ai/pytorch/autograd-engine) for `requires_grad`, `backward()`, and `no_grad()`, which the whole gradient track runs on

Install the vision extras:

```bash
uv add torchvision timm captum
```

`torchvision` supplies datasets and transforms, `timm` supplies pretrained backbones, and `captum` supplies attribution methods you can compare your own hooks against.

## What you should be able to do afterwards

- Compute the output size of any conv layer from its input size, kernel, stride, padding, and dilation, and state the receptive field of a given depth
- Explain what a residual connection does to the gradient, and why it let networks go from 8 layers to 150
- Freeze a backbone and train only a new head, then say when unfreezing is worth the cost
- Pull a Grad-CAM heatmap out of a model with `register_forward_hook` and a backward hook, without `captum`
- Generate a PGD adversarial example and state why it is stronger than FGSM
- Unroll an LSTM over a sliding window, and explain why its gradient does not vanish the way a vanilla RNN's does
- Describe the Seq2Seq bottleneck precisely enough to explain why attention was invented

## Canonical resources

- [`huggingface/pytorch-image-models`](https://github.com/huggingface/pytorch-image-models) (`timm`) — pretrained backbones, augmentations, and training scripts covering most published vision architectures
- [`pytorch/captum`](https://github.com/pytorch/captum) — feature attribution methods including Grad-CAM, integrated gradients, and saliency, useful as a reference implementation
- [`Harry24k/adversarial-attacks-pytorch`](https://github.com/Harry24k/adversarial-attacks-pytorch) — FGSM, PGD, and C&W attacks in a few hundred readable lines
- Stanford CS231n, _Deep Learning for Computer Vision_ — the derivation of backprop through conv layers, receptive fields, and the visual analysis material
- Chris Olah, [_Feature Visualization_](https://distill.pub/2017/feature-visualization) — activation maximization, and what individual units respond to
- _Deep Residual Learning for Image Recognition_ (He et al., arXiv:1512.03385) — the residual connection and the 152-layer network it enabled
- _Going Deeper with Convolutions_ (Szegedy et al., arXiv:1409.4842) — Inception and the multi-scale block
- _Visualizing and Understanding Convolutional Networks_ (Zeiler and Fergus, arXiv:1311.2901) — deconvnets, the origin of most feature-map visualization
- _Long Short-Term Memory_ (Hochreiter and Schmidhuber, 1997) — the gated cell and the constant error carousel
- _Gradient-Based Learning Applied to Document Recognition_ (LeCun et al., 1998) — LeNet, and the first statement of why weight sharing beats dense layers on images
- _Distributed Representations of Words and Phrases_ (Mikolov et al., arXiv:1310.4546) — Word2Vec and negative sampling
- _Sequence to Sequence Learning with Neural Networks_ (Sutskever et al., arXiv:1409.3215) — the encoder-decoder that created the bottleneck problem
- _Deep Visual-Semantic Alignments for Generating Image Descriptions_ (Karpathy and Fei-Fei, arXiv:1412.2306) — CNN-to-RNN captioning
- _A Neural Algorithm of Artistic Style_ (Gatys et al., arXiv:1508.06576) — the Gram-matrix style loss and L-BFGS optimization
