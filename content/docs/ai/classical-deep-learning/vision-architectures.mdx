An **architecture** is a network design: which layers, how many, in what arrangement. [Convolutions](/ai/classical-deep-learning/convolutions) supply the building block; this page follows how researchers learned to stack it. Each landmark architecture solved one specific problem that blocked the previous one, and the problems arrive in a natural order:

| Year | Architecture | Problem it solved                                                               |
| ---: | :----------- | :------------------------------------------------------------------------------ |
| 1998 | LeNet-5      | Showed convolution plus pooling can learn to recognize images                   |
| 2012 | AlexNet      | Scaled CNNs to large, real photographs with GPUs, ReLU, and dropout             |
| 2014 | VGG          | Showed depth matters, built from uniform small kernels                          |
| 2014 | GoogLeNet    | Spent compute efficiently with multi-scale blocks and $1 \times 1$ convolutions |
| 2015 | ResNet       | Made very deep networks trainable with residual connections                     |

Most of these were measured on **ImageNet**: the ImageNet Large Scale Visual Recognition Challenge (ILSVRC) classification task, with about 1.28 million training images in 1,000 classes. Results are reported as **top-5 error**: the fraction of test images whose true class is not among the model's five highest-scoring guesses.

**Builds on:** [Convolutions](/ai/classical-deep-learning/convolutions), and [Normalization](/ai/neural-networks/normalization) for BatchNorm. **Dropout**, used by AlexNet below, randomly sets a fraction of activations to zero at each training step so the network cannot rely on any single unit; it is switched off at inference.

## LeNet-5: the template

LeCun et al. (1998) built LeNet-5 to read handwritten digits on bank cheques. On a $32 \times 32$ grayscale input it alternates convolution and downsampling, then finishes with dense layers:

```text
input 1x32x32 -> conv 5x5 (6) -> pool -> conv 5x5 (16) -> pool -> dense 120 -> dense 84 -> 10 classes
```

It has about 60,000 parameters and established the template every later CNN follows: **convolution layers extract features at decreasing resolution and increasing channel count, then a classifier reads them.** Its paper also gave the first clear argument for why weight sharing beats dense layers on images. CNNs then stayed niche for over a decade, because large labelled datasets and the compute to train big networks did not exist yet.

---

## AlexNet: deep learning arrives

In 2012, Krizhevsky, Sutskever and Hinton's AlexNet won ILSVRC with **15.3%** top-5 error. The runner-up, built on hand-engineered features, had 26.2%. That gap ended the hand-engineered era of computer vision almost overnight.

AlexNet is LeNet's template scaled up — five convolution layers and three dense layers, about 61 million parameters — plus four changes that made the scale trainable:

| Change                          | Problem it solved                                                                                                             |
| :------------------------------ | :---------------------------------------------------------------------------------------------------------------------------- |
| **ReLU** instead of `tanh`      | `tanh` saturates and its gradient vanishes; ReLU has gradient 1 for positive inputs. AlexNet trained about 6× faster with it. |
| **GPU training**                | Split across two GTX 580 GPUs with 3 GB each, for five to six days. CPU training at this scale was impractical.               |
| **Dropout** in the dense layers | 61 million parameters overfit badly; randomly zeroing half the dense activations during training reduced it.                  |
| **Data augmentation**           | Random crops and horizontal flips multiplied the effective dataset size.                                                      |

The lesson was not any single trick. It was that a large CNN, given enough data and compute, learns better features than humans can design.

## VGG: depth from small kernels

Simonyan and Zisserman's VGG (2014) asked one question: what happens if the network gets deeper while everything else stays simple? VGG uses only $3 \times 3$ convolutions at stride 1 with padding 1, and $2 \times 2$ max pooling, stacked into 16 or 19 weight layers:

```text
[conv3-64] x2 -> pool -> [conv3-128] x2 -> pool -> [conv3-256] x3 -> pool
-> [conv3-512] x3 -> pool -> [conv3-512] x3 -> pool -> dense 4096 -> dense 4096 -> 1000
```

The design rule: **channels double each time resolution halves**, keeping the compute per layer roughly constant. The reason for small kernels is the [receptive-field argument](/ai/classical-deep-learning/convolutions#receptive-fields): two $3 \times 3$ layers see the same $5 \times 5$ region as one $5 \times 5$ layer with fewer weights and an extra nonlinearity.

VGG-16 reached 7.3% top-5 error, confirming that depth was the main lever. Its weakness is size: **138 million parameters**, and about 124 million of them sit in the three dense layers at the end (the first alone maps $512 \times 7 \times 7 = 25{,}088$ inputs to 4,096 outputs: 103 million weights). The convolutional part, which does the actual seeing, holds only about 14 million.

## GoogLeNet and Inception: spending compute wisely

Szegedy et al.'s GoogLeNet (2014) won ILSVRC with 6.7% top-5 error using about **7 million** parameters, a twentieth of VGG's. Two ideas made that possible.

### Multi-scale blocks

Choosing a kernel size is a guess about how large the important patterns are, and the right answer varies: an object can be 10 pixels wide in one image and 200 in another. The **Inception module** avoids the guess by running several kernel sizes in parallel on the same input and concatenating the results along the channel axis:

| Branch | Operation                               | Output channels |
| :----- | :-------------------------------------- | --------------: |
| 1      | $1 \times 1$ conv                       |              64 |
| 2      | $1 \times 1$ then $3 \times 3$          |             128 |
| 3      | $1 \times 1$ then $5 \times 5$          |              32 |
| 4      | $3 \times 3$ max pool then $1 \times 1$ |              32 |

All branches keep the same spatial size, so their outputs stack into $64 + 128 + 32 + 32 = 256$ channels, and the next layer learns which scales were useful.

### 1x1 convolutions as cheap reducers

Run naively, the $5 \times 5$ branch on 256 input channels with 32 outputs costs $32 \times 256 \times 25 = 204{,}800$ multiply-adds per spatial position. Inception first applies a $1 \times 1$ convolution that reduces 256 channels to 16 — costing $256 \times 16 = 4{,}096$ — and the $5 \times 5$ then costs $32 \times 16 \times 25 = 12{,}800$. Total: 16,896, about **twelve times cheaper**.

A $1 \times 1$ convolution is a dense layer applied independently at every pixel: it mixes channels without looking at neighbours. Because channels in a deep layer are highly redundant, compressing them first loses little and saves a great deal. This "squeeze, then do the expensive thing" pattern reappears in ResNet's bottleneck blocks and nearly every efficient architecture since.

GoogLeNet also replaced the giant dense head with **global average pooling**, removing the source of most of VGG's parameters.

## ResNet: the residual connection

### The degradation problem

If depth helps, more depth should help more. He et al. (arXiv:1512.03385) found that it did not. On CIFAR-10, a plain 56-layer CNN had **higher training error** than a 20-layer one.

This was surprising for a precise reason. A deeper network can represent everything a shallower one can: copy the 20-layer network and make the extra 36 layers compute the identity. So the 56-layer network's best possible training error is at most the 20-layer one's. Getting a **worse training** error is therefore not overfitting (which would show as worse **test** error with better training error); it is an **optimization failure**. Gradient descent could not find the good solution — in particular, stacks of nonlinear layers find it surprisingly hard to learn the identity. Vanishing gradients were not the main cause; BatchNorm and careful initialization already kept gradients at a healthy scale.

### The fix: learn the change, not the whole mapping

A **residual block** adds its input back to its output:

$$
\text{plain block: } \mathbf{y} = F(\mathbf{x}) \qquad\qquad \text{residual block: } \mathbf{y} = F(\mathbf{x}) + \mathbf{x}
$$

$F$ is two or three convolution layers; the $+\mathbf{x}$ path is the **skip** or **shortcut** connection. Two consequences:

1. **The identity is the default.** If extra layers are not useful, the block only needs $F(\mathbf{x}) = 0$, which is easy (weights near zero), instead of learning an identity mapping through nonlinear layers, which is hard. Adding blocks can no longer make the network worse in principle. Each block learns a **residual** — a correction to its input.
2. **Gradients get a direct path.** Differentiating gives

$$
\frac{\partial \mathbf{y}}{\partial \mathbf{x}} = \frac{\partial F}{\partial \mathbf{x}} + \mathbf{I}
$$

The identity term means the gradient always reaches earlier layers at least unchanged, through a chain of additions rather than only through a long product of weight matrices. A 100-block network has a 100-deep multiplicative path **and** an unbroken additive highway. This is the same principle as the [LSTM cell state](/ai/classical-deep-learning/lstm-and-gru#why-the-gradient-survives), applied across layers instead of time.

The result: ResNet-152, with 152 layers, won ILSVRC 2015 with **3.57%** top-5 error (an ensemble), below the roughly 5% often quoted for human performance on this task. Residual networks of over 1,000 layers were later trained successfully.

### Block designs

**Basic block** (ResNet-18 and ResNet-34): two $3 \times 3$ convolutions on the residual branch.

**Bottleneck block** (ResNet-50 and deeper): $1 \times 1$ to reduce channels, $3 \times 3$ at the reduced width, $1 \times 1$ to expand back — the Inception reduction trick. At the first stage this runs $256 \to 64 \to 64 \to 256$ channels, and the $3 \times 3$ costs $64 \times 64 \times 9 = 36{,}864$ weights instead of $256 \times 256 \times 9 = 589{,}824$.

```python title="bottleneck.py"
import torch.nn as nn

class Bottleneck(nn.Module):
    def __init__(self, channels: int, width: int):
        super().__init__()
        self.f = nn.Sequential(
            nn.Conv2d(channels, width, 1, bias=False), nn.BatchNorm2d(width), nn.ReLU(),
            nn.Conv2d(width, width, 3, padding=1, bias=False), nn.BatchNorm2d(width), nn.ReLU(),
            nn.Conv2d(width, channels, 1, bias=False), nn.BatchNorm2d(channels),
        )
        self.relu = nn.ReLU()

    def forward(self, x):
        return self.relu(self.f(x) + x)      # the residual connection
```

**Projection shortcuts.** The addition requires $F(\mathbf{x})$ and $\mathbf{x}$ to have the same shape. At the start of each stage, where resolution halves and channels double, the shortcut becomes a stride-2 $1 \times 1$ convolution that reshapes $\mathbf{x}$ to match. Everywhere else it is a free identity.

**Pre-activation (ResNet v2).** The original block applies ReLU **after** the addition, so the shortcut signal passes through a nonlinearity at every block. Moving BatchNorm and ReLU to the start of the residual branch leaves the shortcut path a pure chain of additions from the last block to the first:

```text
v1:  x -> conv -> BN -> ReLU -> conv -> BN -> (+x) -> ReLU
v2:  x -> BN -> ReLU -> conv -> BN -> ReLU -> conv -> (+x)
```

This trained a 1,001-layer network where v1 struggled. Transformers use the same arrangement, called **pre-norm**.

<Callout type="info">
  ### Skip connections everywhere after ResNet

U-Net concatenates encoder features into the decoder for segmentation. DenseNet concatenates every earlier layer's output instead of adding it. Every transformer block adds its input to both its attention output and its feed-forward output. All are the same idea: give information and gradients a path that skips the transformation.

</Callout>

## After ResNet

| Year | Model           | Params | Idea                                                                                                                       |
| ---: | :-------------- | -----: | :------------------------------------------------------------------------------------------------------------------------- |
| 2017 | DenseNet        |    8 M | Each layer receives the concatenated outputs of all previous layers                                                        |
| 2017 | MobileNet       |  4.2 M | [Depthwise separable convolutions](/ai/classical-deep-learning/convolutions#grouped-and-depthwise-convolutions) for phones |
| 2018 | SENet           |   28 M | **Squeeze-and-excitation**: learned per-channel weights, a form of channel attention                                       |
| 2019 | EfficientNet-B0 |  5.3 M | Scale depth, width, and resolution together by a fixed ratio                                                               |
| 2020 | ViT-B/16        |   86 M | No convolutions: split the image into patches and use a transformer                                                        |
| 2022 | ConvNeXt-T      |   29 M | A ResNet modernized with transformer-era design choices                                                                    |

ConvNeXt is the instructive entry. Liu et al. took a ResNet-50 and applied changes one at a time: a modern training recipe, $7 \times 7$ depthwise convolutions, GELU instead of ReLU, LayerNorm instead of BatchNorm, and fewer normalization and activation layers. Each was worth roughly a point of accuracy, and the result matched a Swin transformer at the same compute. Much of the transformer's apparent advantage in vision came from its training recipe rather than from attention itself.

## Training a CNN in practice

### Data augmentation

**Data augmentation** generates new training examples by applying random, **label-preserving** transformations to existing ones. A horizontally flipped cat is still a cat; a slightly cropped, rotated, or brightened cat is still a cat. Each transformation encodes an invariance the model should have, and showing many variants teaches it that invariance directly instead of relying on the architecture to supply it. The effect is a larger effective dataset and less memorization.

| Transformation           | Invariance taught                               | Typical use                            |
| :----------------------- | :---------------------------------------------- | :------------------------------------- |
| Random crop with padding | Small translations                              | Always                                 |
| Horizontal flip          | Left-right mirror                               | Natural images (not text or digits)    |
| Colour jitter            | Lighting and camera differences                 | Common                                 |
| RandAugment              | A random mix of colour and geometry distortions | Strong default for classification      |
| Random erasing / Cutout  | Occlusion: parts of the object may be hidden    | Common                                 |
| MixUp / CutMix           | Smoother decision boundaries                    | Blends two images **and their labels** |

An augmentation must actually preserve the label: vertical flips are wrong for street scenes, and rotating a handwritten `6` by 180 degrees turns it into a `9`. **MixUp** blends two images pixel by pixel, $\lambda x_a + (1 - \lambda) x_b$, and uses the same blend of their one-hot labels as a soft target; **CutMix** pastes a patch of one image into another and mixes the labels by area. Because the target is a distribution rather than a class index, these need a soft-target cross-entropy.

### A CIFAR-10 recipe

**CIFAR-10** has 60,000 colour images of $32 \times 32$ pixels in 10 classes, 50,000 for training and 10,000 for testing. It is small enough to train on one GPU in under an hour and small enough that augmentation is essential.

```python title="cifar.py"
import torch
from torchvision.datasets import CIFAR10
from torchvision.transforms import v2

MEAN, STD = (0.4914, 0.4822, 0.4465), (0.2470, 0.2435, 0.2616)

train_tf = v2.Compose([
    v2.ToImage(), v2.ToDtype(torch.float32, scale=True),   # uint8 0..255 -> float 0..1
    v2.RandomCrop(32, padding=4), v2.RandomHorizontalFlip(),
    v2.RandAugment(num_ops=2, magnitude=9),
    v2.Normalize(MEAN, STD),
])
train = CIFAR10("./data", train=True, download=True, transform=train_tf)
```

Order matters: pixel-space augmentations expect values in $[0, 1]$, so normalization comes after them.

A standard recipe: SGD with momentum 0.9 and Nesterov, learning rate 0.1 with a warmup and cosine (or one-cycle) decay, weight decay $5 \times 10^{-4}$, batch size 128, for 100 to 200 epochs. A ResNet-18 trained this way reaches about 95% test accuracy; without augmentation it drops to around 91%, and without weight decay further still. The loop itself is the one from [Training Loop](/ai/pytorch/training-loop).

### Pretrained backbones with timm

Training from scratch on ImageNet takes days of GPU time, so most projects start from a pretrained network ([Transfer Learning and Ensembles](/ai/classical-deep-learning/transfer-and-ensembles) covers how to adapt one). The [`timm`](https://github.com/huggingface/pytorch-image-models) library provides most published architectures with pretrained weights:

```python
import timm, torch

model = timm.create_model("resnet50", pretrained=True, num_classes=10)    # new 10-class head
backbone = timm.create_model("resnet50", pretrained=True, num_classes=0)  # no head: features
print(backbone(torch.randn(2, 3, 224, 224)).shape)                        # (2, 2048)
cfg = timm.data.resolve_model_data_config(backbone)                       # the input size, mean, std it expects
```

`num_classes=0` removes the classifier and returns the globally pooled feature vector. Always use the preprocessing a checkpoint was trained with; a model fed differently normalized images produces no error, only poor accuracy.

## Key terms

| Term                    | Meaning                                                                               |
| :---------------------- | :------------------------------------------------------------------------------------ |
| **ImageNet / ILSVRC**   | The 1.28M-image, 1,000-class benchmark that drove CNN development                     |
| **top-5 error**         | Fraction of images whose true class is not among the model's five top guesses         |
| **Inception module**    | Parallel branches with different kernel sizes, concatenated along channels            |
| **1x1 convolution**     | Per-pixel channel mixing; the cheap way to change channel count                       |
| **degradation problem** | Deeper plain networks reaching higher **training** error than shallower ones          |
| **residual connection** | $\mathbf{y} = F(\mathbf{x}) + \mathbf{x}$: the block learns a correction to its input |
| **bottleneck block**    | $1 \times 1$ reduce, $3 \times 3$, $1 \times 1$ expand, inside a residual block       |
| **projection shortcut** | A $1 \times 1$ convolution on the skip path when shapes change                        |
| **pre-activation**      | Normalization and activation before each convolution, leaving the skip path clean     |
| **data augmentation**   | Random label-preserving transformations of training inputs                            |
| **MixUp / CutMix**      | Blending two images and their labels, pixel-wise or by pasted patch                   |

## Interview questions

<Accordions>
  <Accordion title="What four changes let AlexNet train at a scale LeNet never reached?">

    ReLU, which does not saturate and trained about six times faster than `tanh`; GPU training across two GPUs; dropout in the dense layers to control overfitting of 61 million parameters; and data augmentation with random crops and flips. Combined with ImageNet's 1.28 million labelled images, they produced 15.3% top-5 error against 26.2% for the best hand-engineered system.

  </Accordion>
  <Accordion title="Why did VGG-16 have 138M parameters while GoogLeNet had about 7M at better accuracy?">

    About 124 million of VGG's parameters are in its three dense layers; the first alone maps 25,088 inputs to 4,096 outputs. GoogLeNet uses global average pooling before a small classifier, so it has almost no dense parameters, and its Inception modules put $1 \times 1$ reductions in front of every expensive convolution.

  </Accordion>
  <Accordion title="Why does an Inception module put a 1x1 convolution before its 5x5 convolution?">

    Cost. On 256 input channels with 32 outputs, a direct $5 \times 5$ costs 204,800 multiply-adds per position. Reducing to 16 channels first costs 4,096, and the $5 \times 5$ then costs 12,800, for 16,896 total — about twelve times cheaper — with little loss because deep-layer channels are redundant.

  </Accordion>
  <Accordion title="What is the degradation problem, and why is it not overfitting?">

    Deeper plain networks reaching higher **training** error than shallower ones, such as a 56-layer CNN doing worse than a 20-layer one on CIFAR-10. Overfitting means low training error with high test error. Since a deeper network could copy the shallower one and set its extra layers to the identity, worse training error means optimization failed to find a solution that exists.

  </Accordion>
  <Accordion title="Explain why a residual block trains better than a plain block, in terms of both the function and the gradient.">

    Function: $\mathbf{y} = F(\mathbf{x}) + \mathbf{x}$ makes the identity the default, reached by driving $F$ to zero rather than by learning an identity through nonlinear layers, so extra blocks cannot easily hurt. Gradient: $\partial\mathbf{y}/\partial\mathbf{x} = \partial F/\partial\mathbf{x} + \mathbf{I}$, so gradient always reaches earlier layers through an additive path that bypasses the weights.

  </Accordion>
  <Accordion title="When does a ResNet shortcut need a projection instead of an identity?">

    When the residual branch changes the shape: at the first block of each stage, where resolution halves and channels grow. A stride-2 $1 \times 1$ convolution on the shortcut makes the shapes match so the addition is valid. Elsewhere the shortcut is a parameter-free identity.

  </Accordion>
  <Accordion title="What does pre-activation ordering change, and why does it help very deep ResNets?">

    It moves BatchNorm and ReLU to the start of the residual branch and removes the ReLU after the addition. The skip path then becomes a pure chain of additions from the output back to the input, so both the forward signal and the gradient cross the whole network unchanged. It trained a 1,001-layer network, and transformers use the same pre-norm arrangement.

  </Accordion>
  <Accordion title="Why does data augmentation work, and when is an augmentation wrong?">

    Each random, label-preserving transformation encodes an invariance the model should have, so showing variants enlarges the effective dataset and teaches the invariance directly. An augmentation is wrong when it changes the label or produces impossible inputs: vertical flips on street scenes, horizontal flips on text, or heavy colour changes where colour is the class signal.

  </Accordion>
  <Accordion title="What does MixUp do to the target, and why does plain cross-entropy on class indices not work with it?">

    MixUp blends two images with weight $\lambda$ and uses the same blend of their one-hot labels, so the target is a probability distribution, not a single class index. Cross-entropy must be computed against that soft target, $-\sum_k y_k \log p_k$, which is what soft-target cross-entropy losses implement.

  </Accordion>
  <Accordion title="What did ConvNeXt show about CNNs versus vision transformers?">

    Applying transformer-era choices one by one to a ResNet-50 — a modern training recipe, $7 \times 7$ depthwise convolutions, GELU, LayerNorm, fewer normalization and activation layers — each gained about a point, and the result matched a Swin transformer at equal compute. Much of the transformer's advantage in vision came from training and design details that a CNN can also adopt.

  </Accordion>
</Accordions>
