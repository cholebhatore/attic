A convolution shares weights across space. A recurrent network shares weights across time. That single change lets a model carry information forward over a variable-length sequence, and it creates the gradient problem that dominated sequence modelling for a decade.

---

## The plain-language version

Much data comes as a **sequence**, where order matters: words in a sentence, notes in a song, a stock price minute by minute. Sequences also vary in length. A dense layer wants a fixed-size input, and a CNN looks at nearby positions only, so neither fits well.

A **recurrent neural network (RNN)** reads a sequence one step at a time and keeps a running summary, called the **hidden state**. At each step it combines the new input with the previous hidden state to produce an updated hidden state. It is like reading a book while keeping notes: after each sentence you update your notes, and the notes are all you carry to the next sentence. The same weights are used at every step, which is why it handles any length.

The catch: training sends gradients backwards through every step. Over a long sequence they get multiplied many times, so they shrink toward zero (the network forgets the start) or blow up. The **LSTM** and **GRU** fix this with **gates**, learned switches that decide what to keep, what to forget, and what to output.

| Word                                | Plain meaning                                                                                                                                  |
| :---------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------- |
| **sequence**                        | Ordered data: tokens, audio samples, measurements over time.                                                                                   |
| **time step**                       | One position in the sequence. Step `t` is the `t`-th element.                                                                                  |
| **hidden state (`h_t`)**            | The network's running memory: a vector updated at every step that summarizes everything read so far.                                           |
| **recurrent cell**                  | The small piece of computation applied at every step: new input plus previous hidden state in, new hidden state out.                           |
| **unrolling**                       | Drawing (or computing) the RNN as one copy of the cell per time step, all sharing weights. It turns a loop into an ordinary deep network.      |
| **BPTT**                            | Backpropagation through time: ordinary backpropagation run over the unrolled network.                                                          |
| **truncated BPTT**                  | Only backpropagating through the last `k` steps, to save memory and time on long sequences.                                                    |
| **vanishing / exploding gradients** | Gradients shrinking to nearly zero or growing huge as they pass back through many steps.                                                       |
| **gradient clipping**               | Scaling gradients down whenever their total size exceeds a limit. The standard fix for exploding gradients.                                    |
| **LSTM**                            | Long Short-Term Memory: an RNN cell with a separate **cell state** and three gates (forget, input, output). Keeps information over long spans. |
| **gate**                            | A vector of numbers between 0 and 1 (from a sigmoid) multiplied into another vector, acting as a learned dimmer switch.                        |
| **cell state**                      | The LSTM's long-term memory lane, changed only by gated additions, which lets gradients flow far back.                                         |
| **GRU**                             | Gated Recurrent Unit: a simpler gated cell with two gates and no separate cell state. Often performs about as well as an LSTM.                 |
| **bidirectional RNN**               | Two RNNs, one reading forwards and one backwards, so every position sees context from both sides.                                              |
| **stacked RNN**                     | Several RNN layers, each reading the hidden states of the one below.                                                                           |
| **padding / packing**               | Padding fills short sequences up to a common length; packing tells the RNN to skip the filler.                                                 |
| **time series**                     | Measurements taken at regular intervals over time, such as temperature every hour.                                                             |
| **sliding window / horizon**        | Predict the next `H` values (the horizon) from the previous `W` values (the window), then slide forward.                                       |
| **autoregressive**                  | Predicting the next value from previous values, then feeding predictions back in to predict further ahead.                                     |

## The recurrent cell

One hidden state `h_t` is updated at every timestep from the current input `x_t` and the previous state:

$$
\begin{aligned}
\mathbf{h}_t &= \tanh(\mathbf{W}_{ih} \mathbf{x}_t + \mathbf{b}_{ih} + \mathbf{W}_{hh} \mathbf{h}_{t-1} + \mathbf{b}_{hh}) \\
\mathbf{y}_t &= \mathbf{W}_{hy} \mathbf{h}_t + \mathbf{b}_{hy}
\end{aligned}
$$

`W_hh` is applied at every step, so it is the same matrix multiplied by itself as many times as the sequence is long. That fact explains both what RNNs can do and why they fail.

```python
import torch
import torch.nn as nn

rnn = nn.RNN(input_size=128, hidden_size=256, num_layers=1, batch_first=True)
x = torch.randn(8, 40, 128)              # batch 8, sequence length 40
out, h_n = rnn(x)
print(out.shape)   # (8, 40, 256)  hidden state at every timestep
print(h_n.shape)   # (1, 8, 256)   hidden state at the last timestep only
```

Without `batch_first=True` the input layout is `(T, B, H)`, which is what `nn.LSTM` and `nn.GRU` also default to. This is the most common shape bug in sequence code.

PyTorch keeps two separate biases, `b_ih` and `b_hh`, for CUDA kernel reasons. They are redundant; their sum is what matters.

## Backpropagation through time

Unroll the recurrence over `T` steps and you have a `T`-layer network where every layer shares the same weights. BPTT is ordinary backprop on that unrolled graph.

The gradient of the final state with respect to an earlier state is a product of `T - k` Jacobians:

```text
dh_T / dh_k = product over t=k+1..T of  diag(tanh'(z_t)) W_hh
```

Bounding the norm, with `gamma = max tanh' = 1` and `rho = ||W_hh||_2`:

```text
||dh_T / dh_k|| <= (gamma * rho)^(T-k)
```

That exponent is the whole story.

| `rho`     | Behaviour over 40 steps                      | Symptom                                    |
| :-------- | :------------------------------------------- | :----------------------------------------- |
| `rho > 1` | Grows exponentially                          | `NaN` loss, gradient explosion             |
| `rho = 1` | Stays bounded only if the tanh terms are `1` | Unstable in practice                       |
| `rho < 1` | Decays exponentially                         | Vanishing gradient, no long range learning |

Because the same matrix is reused at every step, there is no value of `rho` that keeps gradients stable for both very long and very short dependencies. A vanilla RNN learns dependencies over roughly ten to twenty steps and not much beyond.

`gamma` makes it worse. `tanh'` is `1` only at zero and falls towards zero as the pre-activation saturates, so a network with large weights has both a large `rho` and small `gamma` terms that fluctuate wildly. This is why ReLU is sometimes used in recurrent cells for the exploding case: `gamma` becomes exactly `1`.

## Clipping exploding gradients

Clipping is a bound, not a fix. It stops `NaN` and lets training continue; it does nothing about the vanishing direction.

```python
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=5.0)
opt.step()
```

`clip_grad_norm_` rescales the whole gradient vector if its global norm exceeds the threshold, which preserves direction:

```text
g <- g * min(1, max_norm / ||g||)
```

`clip_grad_value_` clamps each element independently and distorts direction. Norm clipping is the default choice for RNNs and LSTMs.

<Callout type="warn">
  ### Clipping and mixed precision

With `torch.amp.GradScaler`, gradients are scaled up during `backward()` to avoid FP16 underflow. Clipping the scaled values gives you a meaningless threshold. Call `scaler.unscale_(opt)` first, then clip, then `scaler.step(opt)`.

</Callout>

A typical `max_norm` for an LSTM language model is `5.0`, and for most other recurrent work `1.0`. Monitor the pre-clip norm during training; if it is routinely an order of magnitude above the threshold, the threshold is doing the optimization for you and the learning rate is too high.

### Truncated BPTT

For very long sequences, process the input in chunks of length `L`, detach the hidden state at each chunk boundary, and backpropagate only within a chunk.

```python
h = None
for chunk in sequence.split(L, dim=1):
    out, h = rnn(chunk, h)
    loss = criterion(out, target)
    loss.backward()
    h = tuple(t.detach() for t in h)     # cut the graph between chunks
```

This bounds memory to `O(L)` instead of `O(T)` and caps the gradient chain length. The cost is that dependencies longer than `L` are never learned, which is fine when `L` is chosen above the dependency length you care about.

## LSTM

The Long Short-Term Memory cell adds a second state `c_t`, the cell state, which is updated additively rather than by overwriting:

$$
\begin{aligned}
\mathbf{i}_t &= \sigma(\mathbf{W}_{ii} \mathbf{x}_t + \mathbf{b}_{ii} + \mathbf{W}_{hi} \mathbf{h}_{t-1} + \mathbf{b}_{hi}) && \text{(input gate)} \\
\mathbf{f}_t &= \sigma(\mathbf{W}_{if} \mathbf{x}_t + \mathbf{b}_{if} + \mathbf{W}_{hf} \mathbf{h}_{t-1} + \mathbf{b}_{hf}) && \text{(forget gate)} \\
\mathbf{g}_t &= \tanh(\mathbf{W}_{ig} \mathbf{x}_t + \mathbf{b}_{ig} + \mathbf{W}_{hg} \mathbf{h}_{t-1} + \mathbf{b}_{hg}) && \text{(candidate)} \\
\mathbf{o}_t &= \sigma(\mathbf{W}_{io} \mathbf{x}_t + \mathbf{b}_{io} + \mathbf{W}_{ho} \mathbf{h}_{t-1} + \mathbf{b}_{ho}) && \text{(output gate)} \\
\mathbf{c}_t &= \mathbf{f}_t \odot \mathbf{c}_{t-1} + \mathbf{i}_t \odot \mathbf{g}_t && \text{(additive cell update)} \\
\mathbf{h}_t &= \mathbf{o}_t \odot \tanh(\mathbf{c}_t) && \text{(exposed hidden state)}
\end{aligned}
$$

| Gate   | Range    | Controls                               |
| :----- | :------- | :------------------------------------- |
| Forget | `(0, 1)` | How much of the old cell state to keep |
| Input  | `(0, 1)` | How much of the candidate to write     |
| Output | `(0, 1)` | How much of the cell state to expose   |

The key line is `c_t = f_t * c_(t-1) + i_t * g_t`. Differentiating gives:

$$
\frac{\partial \mathbf{c}_t}{\partial \mathbf{c}_{t-1}} = \mathbf{f}_t \quad \text{(plus terms through gate pre-activations)}
$$

If the forget gate learns to stay near `1`, the gradient passes through almost unchanged for arbitrarily many steps. That is the constant error carousel, and it is why LSTMs learn dependencies over hundreds of timesteps where vanilla RNNs fail at twenty. It replaces the multiplicative `W_hh` chain with an elementwise gate chain.

Two implementation details that matter:

- **Forget gate bias.** Initialize `b_if` to `1` or `2` so the gate starts open. With the default initialization it starts near `sigmoid(0) = 0.5`, and the cell forgets half its state every step before it has learned anything.
- **Peephole connections** let the gates read `c_(t-1)` directly. They help on tasks needing precise timing and are rarely used otherwise. PyTorch's `nn.LSTM` does not implement them.

```python
lstm = nn.LSTM(128, 256, num_layers=2, batch_first=True, bidirectional=True, dropout=0.1)
out, (h_n, c_n) = lstm(torch.randn(8, 40, 128))
print(out.shape)   # (8, 40, 512)      2 directions x 256
print(h_n.shape)   # (4, 8, 256)       2 layers x 2 directions
```

`dropout` between LSTM layers applies to the hidden state passed upward, not to the recurrent connection within a layer. With `num_layers=1` it does nothing.

## GRU

The Gated Recurrent Unit merges the cell and hidden state into one vector and uses two gates instead of three:

$$
\begin{aligned}
\mathbf{r}_t &= \sigma(\mathbf{W}_{ir} \mathbf{x}_t + \mathbf{b}_{ir} + \mathbf{W}_{hr} \mathbf{h}_{t-1} + \mathbf{b}_{hr}) && \text{(reset gate)} \\
\mathbf{z}_t &= \sigma(\mathbf{W}_{iz} \mathbf{x}_t + \mathbf{b}_{iz} + \mathbf{W}_{hz} \mathbf{h}_{t-1} + \mathbf{b}_{hz}) && \text{(update gate)} \\
\mathbf{n}_t &= \tanh(\mathbf{W}_{in} \mathbf{x}_t + \mathbf{b}_{in} + \mathbf{r}_t \odot (\mathbf{W}_{hn} \mathbf{h}_{t-1} + \mathbf{b}_{hn})) && \text{(candidate)} \\
\mathbf{h}_t &= (1 - \mathbf{z}_t) \odot \mathbf{n}_t + \mathbf{z}_t \odot \mathbf{h}_{t-1} && \text{(hidden state)}
\end{aligned}
$$

`z_t` interpolates between the previous state and the new candidate, so it plays the role of both forget and input gates with the constraint `i_t = 1 - f_t`. That constraint is what GRU gives up relative to LSTM: it cannot forget and not write at the same time.

| Property          | RNN                           | GRU                         | LSTM                           |
| :---------------- | :---------------------------- | :-------------------------- | :----------------------------- |
| States            | 1                             | 1                           | 2 (`h` and `c`)                |
| Gates             | 0                             | 2                           | 3                              |
| Weight matrices   | `H_in*H + H*H`                | `3` times that              | `4` times that                 |
| Additive path     | None                          | Via `z_t`                   | Via `c_t`                      |
| Long dependencies | ~20 steps                     | Hundreds                    | Hundreds                       |
| Typical use       | Short sequences, tiny budgets | Default when data is scarce | Default when data is plentiful |

At equal hidden size, an LSTM has roughly `4/3` the parameters of a GRU. Published comparisons are close enough to a tie that the choice is usually made on parameter budget and library support rather than accuracy.

## Bidirectional, stacked, and variable length

A bidirectional layer runs two independent recurrences, one forward and one backward, and concatenates the outputs. It sees the whole sequence at every position, which is what you want for classification and tagging and what you cannot have for autoregressive generation.

```python
from torch.nn.utils.rnn import pack_padded_sequence, pad_packed_sequence

lengths = torch.tensor([40, 31, 27, 19, 12, 8, 5, 2])
packed = pack_padded_sequence(x, lengths.cpu(), batch_first=True, enforce_sorted=False)
out_packed, (h_n, c_n) = lstm(packed)
out, out_lengths = pad_packed_sequence(out_packed, batch_first=True)
```

Packing removes the padded positions from the computation entirely, so short sequences in a batch cost nothing and the final hidden state `h_n` is the state at each sample's true last timestep rather than at the padding. Without packing, `h_n` is garbage for every sequence shorter than the longest.

`enforce_sorted=False` lets PyTorch sort internally. Older versions required the batch to be pre-sorted by length, and a lot of existing code still does that.

## Time series prediction

The setup is sliding-window autoregression: predict the next `H` values from the previous `W` values, and slide the window along the series.

```python title="window.py"
import torch
from torch.utils.data import Dataset

class WindowDataset(Dataset):
    def __init__(self, series: torch.Tensor, window: int = 48, horizon: int = 1):
        n = len(series) - window - horizon + 1
        self.x = torch.stack([series[i : i + window] for i in range(n)])
        self.y = torch.stack([series[i + window : i + window + horizon] for i in range(n)])

    def __len__(self):
        return len(self.x)

    def __getitem__(self, i):
        return self.x[i], self.y[i]

series = torch.randn(5000, 1)
train = WindowDataset(series[:4000], window=48, horizon=1)
test = WindowDataset(series[4000:], window=48, horizon=1)
print(train[0][0].shape, train[0][1].shape)   # (48, 1) (1, 1)
```

### Multi-horizon strategies

| Strategy  | How it works                                   | Failure mode                        |
| :-------- | :--------------------------------------------- | :---------------------------------- |
| One-step  | Predict `t+1` only                             | Cannot forecast                     |
| Recursive | Feed predictions back as inputs                | Errors compound over the horizon    |
| Direct    | One output head per future step                | No cross-step consistency           |
| Seq2seq   | Encoder over history, decoder over the horizon | More parameters, best long horizons |

Recursive multi-step is what "autoregression" usually means in practice, and it is where the error growth shows up: a small bias at step one gets fed back in and amplified. Direct multi-horizon avoids that at the cost of independent predictions per step.

### Things that matter more than the architecture

- **Normalize per feature, fitted on training data only.** A standardization computed over the whole series leaks the future into the training split.
- **Difference non-stationary series.** An LSTM cannot extrapolate a trend it has never seen leave its training range.
- **Split by time, never shuffle.** Random splits on a series produce optimistic numbers that do not survive deployment.
- **Beat a naive baseline first.** Predicting `y_hat = x_t` (persistence) or a seasonal mean is a strong baseline on many real series, and a recurrent model that does not beat it is not learning.

```python title="model.py"
class Forecaster(nn.Module):
    def __init__(self, n_features=1, hidden=128, layers=2, horizon=1):
        super().__init__()
        self.rnn = nn.LSTM(n_features, hidden, layers, batch_first=True)
        self.head = nn.Linear(hidden, horizon)

    def forward(self, x):
        out, _ = self.rnn(x)          # x: (B, W, n_features)
        return self.head(out[:, -1])  # use the final timestep only
```

Using `out[:, -1]` gives the state after the whole window. For multi-step direct forecasting, widen the head to `horizon` outputs. For seq2seq, run a second decoder RNN whose input at each step is the previous prediction.

## When recurrent networks still make sense

Transformers replaced RNNs for language, but the replacement is not universal.

| Situation                                      | Better choice                    |
| :--------------------------------------------- | :------------------------------- |
| Long sequences, plenty of data, parallelizable | Transformer                      |
| Streaming inference, one sample at a time      | RNN or LSTM, constant memory     |
| Very small dataset, short sequences            | GRU or LSTM                      |
| Strictly causal online prediction              | Any recurrent model              |
| Irregularly sampled time series                | RNN with a time-aware decay gate |
| Edge deployment with a tiny memory budget      | GRU                              |

A recurrent model processes a stream in `O(1)` memory per step. A transformer needs the full KV cache, which grows linearly with sequence length. That is why [Phase 10](/ai/inference) spends so much time on KV-cache management: it is the cost of giving up recurrence.

Modern recurrent variants (Mamba, RWKV, RetNet, xLSTM) revisit these trade-offs with linear-time attention-like mechanisms, and as of 2026 they are competitive with transformers on long-context language modelling at lower inference cost.

## Interview questions

<Accordions>
  <Accordion title="Write the LSTM update equations and label each gate.">

    `i_t = sigmoid(W_ix x_t + b_ix + W_ih h_(t-1) + b_ih)` input gate, `f_t` forget gate, `o_t` output gate, same form with their own weights, and `g_t = tanh(...)` the candidate. Then `c_t = f_t * c_(t-1) + i_t * g_t` is the additive cell update and `h_t = o_t * tanh(c_t)` is the exposed hidden state. Every gate reads both `x_t` and `h_(t-1)`.

  </Accordion>
  <Accordion title="Why does an LSTM avoid the vanishing gradient that a vanilla RNN suffers? Point at the specific term.">

    The cell line. `dc_t / dc_(t-1) = f_t` plus terms through the gate pre-activations, whereas the RNN's equivalent factor is `diag(tanh') W_hh` applied once per step. The LSTM replaces that multiplicative `W_hh` chain with an elementwise gate the network can hold near `1`, and then the gradient passes through almost unchanged for hundreds of steps.

  </Accordion>
  <Accordion title="What is the constant error carousel?">

    The additive path `c_t = f_t * c_(t-1) + i_t * g_t`, where the previous state is carried forward by multiplication with a gate value instead of through a saturating nonlinearity and a shared matrix. With the forget gate near 1 the cell is a running sum, so error signals circulate without decaying.

  </Accordion>
  <Accordion title={<>Derive the bound on <code>||dh_T / dh_k||</code> for a vanilla RNN and explain what <code>rho</code> does.</>}>

    Unrolling gives `dh_T / dh_k` as a product of `T - k` Jacobians, each `diag(tanh') W_hh`, so its norm is bounded by `(gamma * rho)^(T-k)` with `gamma = max tanh' = 1` and `rho` the spectral norm of `W_hh`. `rho` decides everything: above 1 the gradient grows exponentially and you get `NaN` loss, below 1 it decays and long dependencies are unreachable, and at 1 stability holds only where the tanh derivatives are near 1. Because one matrix serves every step, no value works for both long and short dependencies; a vanilla RNN learns roughly ten to twenty steps and not much beyond.

  </Accordion>
  <Accordion title={<>Why does gradient clipping preserve direction with <code>clip_grad_norm_</code> but not with <code>clip_grad_value_</code>?</>}>

    `clip_grad_norm_` rescales the whole vector by the single scalar `min(1, max_norm / ||g||)`, so direction is untouched and only magnitude is capped. `clip_grad_value_` clamps each element independently, which changes the relative sizes of coordinates and therefore the direction of the update.

  </Accordion>
  <Accordion title="Where does clipping go in an AMP training step, and why does the order matter?">

    After `scaler.unscale_(opt)` and before `scaler.step(opt)`. GradScaler multiplies gradients by a large constant during backward to keep FP16 values above underflow, so clipping the scaled tensor applies your threshold in the wrong units and the bound means nothing.

  </Accordion>
  <Accordion title="What is truncated BPTT, and what does it cost you?">

    Processing the input in chunks of length `L`, carrying the hidden state across chunk boundaries but detaching it there, and backpropagating only within a chunk. It bounds activation memory and makes long sequences trainable. The cost is gradient flow: the model still sees earlier context through the hidden state, but it cannot learn dependencies that have to be established across the boundary.

  </Accordion>
  <Accordion title="Why initialize the LSTM forget gate bias to a positive value?">

    So the forget gate starts near 1 and the cell remembers by default at the beginning of training. With a zero bias, `sigmoid(0) = 0.5` erases half the cell content at every step, which sends early gradients toward zero and can prevent the network from ever learning to retain anything.

  </Accordion>
  <Accordion title="What does GRU give up relative to LSTM, and how many parameters does each have at equal hidden size?">

    A GRU merges forget and input into one update gate `z_t` that interpolates between the previous state and the new candidate, so `i_t = 1 - f_t`, and it has no separate cell state. The constraint is what it gives up: it cannot forget and not write in the same step. Three gates instead of four gives `3 * (d*h + h*h + h)` against `4 * (d*h + h*h + h)`, so an LSTM holds roughly 4/3 the parameters, and published results are close enough that the choice comes down to parameter budget and library support.

  </Accordion>
  <Accordion title={<>What goes wrong if you feed a padded batch to <code>nn.LSTM</code> without packing, and read <code>h_n</code>?</>}>

    Every padded position is processed as if it were real, so the hidden state accumulates from zero embeddings, and `h_n` is the state at the last timestep of the longest sequence in the batch rather than each sample's own last real step. For every sequence shorter than the maximum, `h_n` is garbage. `pack_padded_sequence` removes padded positions from the computation so the state is read at the true final step.

  </Accordion>
  <Accordion title="Why must time series splits be chronological rather than random?">

    A random split puts observations that come later in time inside the training set, and because neighbouring points are highly correlated the model interpolates rather than forecasts. Metrics look excellent and leak information the deployment will not have. A chronological split keeps the test window strictly after everything used for training.

  </Accordion>
  <Accordion title="Compare recursive and direct multi-step forecasting, and say when each fails.">

    Recursive feeds its own one-step prediction back as input, so it needs only a one-step model and stays coherent, but errors compound and drift accumulates over the horizon. Direct trains a separate output per horizon step, which removes compounding and is better at long horizons, but each step needs enough data and the predictions can disagree with one another at the joins.

  </Accordion>
  <Accordion title="What does a recurrent model give you at inference time that a transformer does not?">

    A constant-size state. The hidden vector summarizes arbitrarily long history at fixed width, so per-step compute and memory do not grow with sequence length. Attention reads the whole context, so both grow with it — the thing a recurrent model does not pay.

  </Accordion>
</Accordions>
