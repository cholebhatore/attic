A **recurrent neural network (RNN)** is a neural network that processes a sequence one element at a time while carrying a vector of memory, the **hidden state**, from each step to the next. At every step the same small network, the **cell**, reads two things, the current input and the previous hidden state, and produces a new hidden state. Because the cell is reused at every position, one set of weights handles sequences of any length.

This page builds the RNN from the problem it solves. The next page, [Vanishing and Exploding Gradients](/ai/classical-deep-learning/vanishing-gradients), explains why a plain RNN cannot remember for long, and [LSTM and GRU](/ai/classical-deep-learning/lstm-and-gru) covers the gated cells built to fix that.

**Builds on:** [Neurons and Activations](/ai/neural-networks/neurons-and-activations) for `tanh` and the sigmoid, and [Vision and Sequence Basics](/ai/classical-deep-learning/vision-and-sequence-basics#sequences-as-tensors) for the `(B, T, F)` sequence shape.

## What makes sequence data different

A **sequence** is an ordered list of items $x_1, x_2, \dots, x_T$ where the order carries meaning. Words in a sentence, characters in a word, audio frames, daily temperatures, and clicks in a session are all sequences. $T$ is the **length**, and each position $t$ is a **time step**, whether or not it has anything to do with clock time.

Three properties separate sequences from the fixed-size feature vectors a dense network handles:

| Property                 | Example                                                                                              | What it demands of a model                              |
| :----------------------- | :--------------------------------------------------------------------------------------------------- | :------------------------------------------------------ |
| **Order matters**        | "dog bites man" and "man bites dog" contain the same words                                           | The model must know which item came first               |
| **Length varies**        | A tweet and a novel are both text                                                                    | The model cannot have one input slot per position       |
| **Long-range relations** | "The keys to the old wooden cabinet **are** on the table" — `are` agrees with `keys`, six words back | Information from early steps must survive to later ones |

### Why the obvious alternatives fail

**A dense network over the whole sequence.** Concatenate all $T$ word vectors into one long vector. This fixes $T$ at design time, and it ties each weight to one position: a pattern learned for "not good" at positions 3 and 4 does not transfer to positions 17 and 18. The same weakness that makes dense layers wasteful on images (see [Why dense layers are not enough](/ai/classical-deep-learning/vision-and-sequence-basics#why-dense-layers-are-not-enough)) appears along the time axis.

**A fixed window.** Feed only the last $k$ items to a dense network, sliding along. This handles any length, but nothing older than $k$ steps can affect the output. Raising $k$ raises the parameter count linearly, and the right $k$ is unknown in advance.

**Bag of words.** Sum or average all the item vectors. This handles any length with few parameters, and throws order away completely.

What is wanted is something that reads one item at a time like the sliding window, shares weights across positions like a convolution, and can in principle carry information from step 1 all the way to step $T$. That is the recurrent design.

## The core idea: a memory updated at every step

Reading a sentence works this way for a person. Nobody holds every previous word verbatim; they keep a running understanding and revise it with each new word. After "The keys to the", the important retained fact is roughly "the subject is plural, something about keys". The next word revises that understanding, and the old words themselves can be forgotten.

An RNN formalizes exactly this. The running understanding is a vector $\mathbf{h}_t$ of fixed width $H$ (for example $H = 256$), and a learned function updates it:

$$
\mathbf{h}_t = f_\theta(\mathbf{h}_{t-1}, \mathbf{x}_t)
$$

- $\mathbf{x}_t$ is the input at step $t$, a vector of width $F$ (for text, the embedding of the $t$-th token).
- $\mathbf{h}_{t-1}$ is the hidden state after the previous step. Before the first step it is set to $\mathbf{h}_0 = \mathbf{0}$ (or learned).
- $f_\theta$ is the **cell**, with parameters $\theta$. The same $\theta$ is used at every step. That reuse is called **weight sharing across time**.

Two consequences follow directly from this one line:

1. **Any length works.** The cell is applied $T$ times for a length-$T$ sequence; nothing in the parameters depends on $T$.
2. **The hidden state is a lossy summary.** All information about $x_1, \dots, x_t$ that the model will ever use later has to be packed into $H$ numbers. The network must learn what to keep. This is both the strength of the design and, as the later pages show, its central limitation.

<Callout type="info">
  ### RNNs are learned state machines

A finite-state machine reads symbols one at a time and moves between a fixed set of states. An RNN is the continuous, differentiable version: the state is a real vector rather than a label, and the transition rule is learned by gradient descent rather than written by hand. With enough hidden units, an RNN can in principle simulate any finite-state machine.

</Callout>

## The vanilla RNN cell

The simplest choice of $f_\theta$, now called the **vanilla** or **Elman** RNN, is one dense layer applied to the concatenation of input and previous state, followed by `tanh`:

$$
\begin{aligned}
\mathbf{h}_t &= \tanh(\mathbf{W}_{xh} \mathbf{x}_t + \mathbf{W}_{hh} \mathbf{h}_{t-1} + \mathbf{b}_h) \\
\mathbf{y}_t &= \mathbf{W}_{hy} \mathbf{h}_t + \mathbf{b}_y
\end{aligned}
$$

| Symbol            | Shape    | Role                                                                         |
| :---------------- | :------- | :--------------------------------------------------------------------------- |
| $\mathbf{x}_t$    | $(F)$    | Input at step $t$                                                            |
| $\mathbf{h}_t$    | $(H)$    | Hidden state after step $t$                                                  |
| $\mathbf{W}_{xh}$ | $(H, F)$ | **Input-to-hidden** weights: how the new input changes the memory            |
| $\mathbf{W}_{hh}$ | $(H, H)$ | **Hidden-to-hidden** (recurrent) weights: how the old memory carries forward |
| $\mathbf{b}_h$    | $(H)$    | Hidden bias                                                                  |
| $\mathbf{W}_{hy}$ | $(O, H)$ | **Hidden-to-output** weights, only when an output is needed at this step     |
| $\mathbf{y}_t$    | $(O)$    | Output at step $t$, for example logits over a vocabulary                     |

Each piece has a reason:

- **The sum $\mathbf{W}_{xh}\mathbf{x}_t + \mathbf{W}_{hh}\mathbf{h}_{t-1}$** mixes new evidence with old memory. It is equivalent to one weight matrix of shape $(H, F + H)$ applied to the concatenated vector $[\mathbf{x}_t; \mathbf{h}_{t-1}]$.
- **`tanh`** keeps every hidden unit in $(-1, 1)$. Without a squashing function, repeatedly multiplying by $\mathbf{W}_{hh}$ would let the state grow without bound over a long sequence. `tanh` is preferred over the sigmoid because it is zero-centred, so a unit can push the state in either direction.
- **The output layer is separate** from the recurrence. The hidden state is the memory; $\mathbf{y}_t$ is a read-out of it for whatever the task needs.

**Parameter count.** The recurrent part has $HF + H^2 + H$ parameters, independent of $T$. With $F = 128$ and $H = 256$ that is $32{,}768 + 65{,}536 + 256 = 98{,}560$ — the same for a 5-step and a 5,000-step sequence.

## A worked example by hand

Shrink everything to one dimension so every number is visible: $F = H = 1$, weights $w_{xh} = 1.0$, $w_{hh} = 0.5$, bias $0$. Feed a single "event" followed by silence: $x = [1, 0, 0, 0, 0]$.

$$
h_t = \tanh(1.0 \cdot x_t + 0.5 \cdot h_{t-1}), \qquad h_0 = 0
$$

| Step $t$ | $x_t$ | Pre-activation $x_t + 0.5\,h_{t-1}$ | $h_t$ |
| -------: | ----: | :---------------------------------- | ----: |
|        1 |     1 | $1 + 0.5 \cdot 0 = 1.000$           | 0.762 |
|        2 |     0 | $0 + 0.5 \cdot 0.762 = 0.381$       | 0.363 |
|        3 |     0 | $0 + 0.5 \cdot 0.363 = 0.182$       | 0.180 |
|        4 |     0 | $0.090$                             | 0.090 |
|        5 |     0 | $0.045$                             | 0.045 |

The event at step 1 is still detectable at step 5, so the network **has** memory: $h_5 \neq 0$ only because $x_1$ was nonzero. But the trace roughly halves every step, because each step multiplies the old state by $w_{hh} = 0.5$ and then `tanh` shrinks it a little more.

Raising the recurrent weight to $w_{hh} = 1.0$ slows the fade: $h = 0.762, 0.642, 0.566, 0.513, 0.472$. It still fades, because `tanh` compresses every value toward zero ($\tanh(z) < z$ for $z > 0$). Raising $w_{hh}$ further makes the state saturate near $\pm 1$ and stop responding to new input at all.

That trade-off — memory that either fades or locks up, controlled by one shared weight — is the vanilla RNN's core weakness in miniature. The [next page](/ai/classical-deep-learning/vanishing-gradients) shows that the gradient used for training suffers from the same repeated multiplication, which is far more damaging.

## Unrolling: an RNN is a deep network with tied weights

The recurrence is a loop. Writing out one copy of the cell per time step, called **unrolling** the network, turns it into an ordinary feed-forward graph:

<Mermaid
  chart={`
flowchart LR
    H0["h0 = 0"] --> C1["cell"]
    X1["x1"] --> C1
    C1 -- "h1" --> C2["cell"]
    X2["x2"] --> C2
    C2 -- "h2" --> C3["cell"]
    X3["x3"] --> C3
    C3 -- "h3" --> C4["cell"]
    X4["x4"] --> C4
    C1 --> Y1["y1"]
    C2 --> Y2["y2"]
    C3 --> Y3["y3"]
    C4 --> Y4["y4"]
`}
/>

Every box labelled `cell` is the **same** weights. Two views follow from the picture:

- **Depth equals sequence length.** The path from $x_1$ to $y_4$ passes through four applications of the cell, so a 100-step sequence is a 100-layer-deep network along the time axis, even with a single RNN layer.
- **Backpropagation works unchanged.** The unrolled graph is a normal computation graph, so autograd can differentiate it. Running backprop over it is called **backpropagation through time (BPTT)**. Because each weight appears once per step, its gradient is the sum of its gradients at every step:

$$
\frac{\partial L}{\partial \mathbf{W}_{hh}} = \sum_{t=1}^{T} \frac{\partial L}{\partial \mathbf{W}_{hh}}\bigg|_{\text{step } t}
$$

The same rule governs any shared weight, including a convolution kernel's gradient summed over spatial positions. What is special about time is the depth: the contribution from an early step must travel back through many copies of the cell, which is the subject of the next page.

## What an RNN can be asked to do

Whether the network reads an input at every step, and whether it emits an output at every step, depends on the task. Five patterns cover nearly every sequence problem:

| Pattern                       | Input → output                        | Example                                        | Where the output is read                                         |
| :---------------------------- | :------------------------------------ | :--------------------------------------------- | :--------------------------------------------------------------- |
| **One-to-one**                | Vector → vector                       | Ordinary classification (no recurrence needed) | n/a                                                              |
| **Many-to-one**               | Sequence → single label               | Sentiment of a review; spam detection          | Only the final hidden state $\mathbf{h}_T$ feeds a classifier    |
| **One-to-many**               | Single vector → sequence              | Image captioning; music generation from a seed | The input sets $\mathbf{h}_0$; outputs are emitted at every step |
| **Many-to-many, aligned**     | Sequence → one label per element      | Part-of-speech tagging; named-entity tagging   | $\mathbf{y}_t$ at every step                                     |
| **Many-to-many, not aligned** | Sequence → sequence of another length | Translation; summarization                     | Two RNNs: an **encoder** reads, a **decoder** writes (Seq2Seq)   |

The last pattern needs a separate architecture because a single RNN emits exactly one output per input step, and a French sentence is not the same length as its English translation. [Seq2Seq and Attention](/ai/classical-deep-learning/seq2seq-and-attention) builds it from two RNNs.

<Callout type="info">
  ### Many-to-one: why the last state works

For sentiment classification, $\mathbf{h}_T$ is the only state that has seen the whole review, so a linear layer on $\mathbf{h}_T$ is the standard classifier. A common, often better, alternative is to pool all hidden states, $\frac{1}{T}\sum_t \mathbf{h}_t$ or $\max_t \mathbf{h}_t$, which gives early words a shorter path to the output.

</Callout>

## Training an RNN: a character-level language model

A **language model** assigns a probability to the next token given all previous ones. It is the cleanest RNN task because the training data labels itself: every text is its own target, shifted by one.

Take the word `hello` with a vocabulary of four characters `{h, e, l, o}`:

| Step $t$ | Input $x_t$ | Target (the next character) |
| -------: | :---------- | :-------------------------- |
|        1 | `h`         | `e`                         |
|        2 | `e`         | `l`                         |
|        3 | `l`         | `l`                         |
|        4 | `l`         | `o`                         |

Steps 3 and 4 show why memory is needed: the input is `l` both times, but the correct next character differs (`l` then `o`). A model that only sees the current character cannot get both right. The hidden state distinguishes "first `l` after `he`" from "second `l` after `hel`".

At each step:

1. Turn the input character into a vector (a one-hot or an [embedding](/ai/classical-deep-learning/word-embeddings)).
2. Update the hidden state with the cell.
3. Compute logits $\mathbf{y}_t$ of width $V = 4$ and a probability distribution $\operatorname{softmax}(\mathbf{y}_t)$ over the next character.
4. Score it with cross-entropy against the true next character: $\ell_t = -\log p_t(\text{target}_t)$.

The sequence loss is the average over steps, $L = \frac{1}{T}\sum_t \ell_t$, and BPTT sends its gradient back through every step. If the model assigns probability $0.6$ to the correct `o` at step 4, that step costs $-\ln 0.6 = 0.51$; a confident wrong answer with $p = 0.01$ costs $4.6$.

**Generation.** After training, the model writes text by feeding its own output back in: give it `h`, sample a character from $\operatorname{softmax}(\mathbf{y}_1)$, feed that character as $x_2$, and repeat. This loop of predicting, sampling, and feeding back is called **autoregressive generation**. It is exactly how modern LLMs generate text; they replace the RNN with a transformer but keep the loop (see [Decoding](/ai/llm/decoding)).

<Callout type="info">
  ### Karpathy's char-RNN

A three-layer character RNN trained on Shakespeare, Linux source code, or LaTeX produces text with correct local syntax: matched brackets, indentation, plausible variable names. Inspecting individual hidden units revealed cells that track whether the text is inside a quotation or how deep the current bracket nesting is — the network learned its own state variables, as the state-machine view predicts.

</Callout>

## Deeper and wider: stacked and bidirectional RNNs

**Stacked (multi-layer) RNNs.** The hidden states of one RNN layer form a sequence $\mathbf{h}^{(1)}_1, \dots, \mathbf{h}^{(1)}_T$, which can be the input to a second RNN layer, and so on. Lower layers tend to capture local patterns (character combinations, short phrases) and upper layers longer-range structure, mirroring the feature hierarchy of a CNN. Two to four layers is typical; beyond that, gains are small and training gets harder.

**Bidirectional RNNs.** A normal RNN's state $\mathbf{h}_t$ knows only the past $x_1 \dots x_t$. For tagging, the future often matters too: in "Apple announced earnings", whether `Apple` is a company is clearer after reading `announced`. A **bidirectional** RNN runs two independent RNNs, one left-to-right and one right-to-left, and concatenates their states at each position:

$$
\mathbf{h}_t = [\overrightarrow{\mathbf{h}}_t \, ; \, \overleftarrow{\mathbf{h}}_t] \qquad \text{width } 2H
$$

The constraint: a bidirectional model needs the whole sequence before producing any output, so it cannot be used for generation or real-time streaming, where the future does not exist yet.

## RNNs in PyTorch

The whole recurrence is a short loop, which is worth writing once to see that nothing is hidden:

```python title="rnn_from_scratch.py"
import torch

F, H, T = 8, 16, 5
W_xh, W_hh, b = torch.randn(H, F) * 0.1, torch.randn(H, H) * 0.1, torch.zeros(H)

x = torch.randn(T, F)        # one sequence of 5 steps
h = torch.zeros(H)           # h_0
for t in range(T):
    h = torch.tanh(W_xh @ x[t] + W_hh @ h + b)
print(h.shape)               # (16,)  the final hidden state h_T
```

`nn.RNN` runs the same loop in an optimized kernel, over a batch:

```python
rnn = torch.nn.RNN(input_size=8, hidden_size=16, num_layers=1, batch_first=True)
out, h_n = rnn(torch.randn(4, 5, 8))   # batch 4, length 5, features 8
print(out.shape)   # (4, 5, 16)  hidden state at every step: use for tagging
print(h_n.shape)   # (1, 4, 16)  final hidden state per layer: use for classification
```

Two details cause most bugs:

- **Layout.** Without `batch_first=True`, PyTorch's recurrent layers expect `(T, B, F)`, time first.
- **Padding.** A batch holds sequences of different lengths padded to the longest. Without care, the RNN keeps updating the state over the padding, and `h_n` for a short sequence is its state after a run of meaningless zeros. `torch.nn.utils.rnn.pack_padded_sequence` tells the layer each sequence's true length so padded steps are skipped and `h_n` is read at the real last step.

PyTorch stores two biases, `b_ih` and `b_hh`, instead of one. Only their sum matters; the split exists for compatibility with cuDNN kernels.

## Where the vanilla RNN breaks

On paper, the hidden state can carry information from step 1 to step $T$. In practice, a vanilla RNN trained by gradient descent learns dependencies over roughly ten to twenty steps and almost nothing beyond. The worked example above hints at why: anything that passes repeatedly through the same multiplication either fades or explodes. The training gradient passes back through that multiplication once per step, so it fades or explodes exponentially with distance.

[Vanishing and Exploding Gradients](/ai/classical-deep-learning/vanishing-gradients) derives that precisely and covers the partial fixes. [LSTM and GRU](/ai/classical-deep-learning/lstm-and-gru) covers the architectural fix that made recurrent networks practical.

## Key terms

| Term                  | Meaning                                                                                           |
| :-------------------- | :------------------------------------------------------------------------------------------------ |
| **RNN**               | A network that applies the same cell at every step of a sequence, carrying a hidden state forward |
| **hidden state**      | The fixed-width vector $\mathbf{h}_t$ summarizing everything read up to step $t$                  |
| **cell**              | The function $f_\theta$ that maps $(\mathbf{h}_{t-1}, \mathbf{x}_t)$ to $\mathbf{h}_t$            |
| **weight sharing**    | Using the same parameters at every time step                                                      |
| **unrolling**         | Drawing the loop as one cell copy per step, giving a deep feed-forward graph with tied weights    |
| **BPTT**              | Backpropagation through time: ordinary backprop on the unrolled graph                             |
| **language model**    | A model of $p(x_t \mid x_1, \dots, x_{t-1})$, trained to predict the next token                   |
| **autoregressive**    | Generating by feeding each output back in as the next input                                       |
| **bidirectional RNN** | A forward and a backward RNN whose states are concatenated at each position                       |
| **stacked RNN**       | RNN layers where each layer reads the hidden-state sequence of the one below                      |

## Interview questions

<Accordions>
  <Accordion title="What problem does a recurrent network solve that a dense network cannot?">

    Variable-length, ordered input with weight sharing across positions. A dense network over a concatenated sequence fixes the length at design time and ties each weight to one position, so a pattern learned at positions 3 and 4 does not transfer to 17 and 18. An RNN applies one cell at every step and carries a hidden state, so the parameter count is independent of length and the same rule is applied everywhere.

  </Accordion>
  <Accordion title="Write the vanilla RNN update and give the shape of every matrix.">

    $\mathbf{h}_t = \tanh(\mathbf{W}_{xh}\mathbf{x}_t + \mathbf{W}_{hh}\mathbf{h}_{t-1} + \mathbf{b}_h)$ and $\mathbf{y}_t = \mathbf{W}_{hy}\mathbf{h}_t + \mathbf{b}_y$. With input width $F$, hidden width $H$, and output width $O$: $\mathbf{W}_{xh}$ is $(H, F)$, $\mathbf{W}_{hh}$ is $(H, H)$, $\mathbf{W}_{hy}$ is $(O, H)$. The recurrent part has $HF + H^2 + H$ parameters, independent of the sequence length.

  </Accordion>
  <Accordion title="Why tanh in the recurrence rather than no activation or ReLU?">

    Without a squashing function, repeated multiplication by $\mathbf{W}_{hh}$ lets the state grow or shrink geometrically with sequence length, and a purely linear recurrence cannot represent nonlinear state updates. `tanh` bounds every unit to $(-1, 1)$ and is zero-centred, so units can move in both directions. ReLU is unbounded, so the state can explode unless $\mathbf{W}_{hh}$ is carefully initialized (the IRNN uses an identity initialization to make it work).

  </Accordion>
  <Accordion title="What does unrolling an RNN mean, and what does it imply about depth?">

    Writing one copy of the cell per time step, all sharing weights, so the loop becomes an ordinary feed-forward computation graph. The depth of that graph along the time axis equals the sequence length, so a single-layer RNN on 100 steps is a 100-layer-deep network for the gradient travelling from the last output back to the first input. That depth is the root of the vanishing gradient problem.

  </Accordion>
  <Accordion title="How is the gradient of a shared weight computed in BPTT?">

    By summing the gradient contributions from every time step at which the weight is used: $\partial L / \partial \mathbf{W}_{hh} = \sum_t \partial L / \partial \mathbf{W}_{hh}|_t$. Each contribution is computed by ordinary backprop through the unrolled graph. The same rule applies to a convolution kernel summed over spatial positions.

  </Accordion>
  <Accordion title="Give the five input-output patterns of sequence tasks with an example of each.">

    One-to-one: ordinary classification. Many-to-one: sentiment from a review, reading only $\mathbf{h}_T$. One-to-many: captioning, where an image sets the initial state and words are emitted every step. Many-to-many aligned: part-of-speech tagging, one output per input step. Many-to-many unaligned: translation, which needs an encoder RNN and a separate decoder RNN because input and output lengths differ.

  </Accordion>
  <Accordion title="In a character-level language model on 'hello', why must the model have memory?">

    The input `l` appears at steps 3 and 4, but the correct next character is `l` the first time and `o` the second. A model that sees only the current character must give the same prediction both times. The hidden state encodes that the model has already seen `hel`, which is what lets it distinguish the two positions.

  </Accordion>
  <Accordion title="When can a bidirectional RNN not be used?">

    Whenever the output at step $t$ must be produced before step $t+1$ is available: autoregressive generation, real-time speech recognition with no lookahead, online forecasting. The backward RNN needs the full sequence before it can produce any state. For tagging and classification of complete inputs it is usually the better choice.

  </Accordion>
  <Accordion title={<>What goes wrong if a padded batch is fed to <code>nn.RNN</code> without packing?</>}>

    The layer processes padded positions as real input, so a short sequence's state keeps changing over a run of padding vectors, and `h_n` is the state at the length of the longest sequence rather than at each sequence's own last real step. `pack_padded_sequence` with the true lengths skips padded steps so `h_n` is correct.

  </Accordion>
</Accordions>
