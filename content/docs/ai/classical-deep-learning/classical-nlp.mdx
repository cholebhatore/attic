**Natural Language Processing (NLP)** is the field of AI concerned with making computers read, interpret, and produce human language. Every NLP system, from a 1990s spam filter to a modern LLM, starts with the same problem: a neural network or statistical model consumes vectors of numbers, while text is a variable-length string of discrete symbols. How text is turned into numbers determines what a model can learn.

This page covers the classical answers, in the order they were developed: splitting text into tokens, encoding tokens as one-hot vectors, representing documents by counts (bag of words, n-grams, TF-IDF), and modelling language with counted probabilities (n-gram language models). Each method is still used — TF-IDF and its refinement BM25 still power search engines — and each one's limitation motivates the next. The last limitation, that counting treats every word as unrelated to every other, is what [Word Embeddings](/ai/classical-deep-learning/word-embeddings) solves.

**Builds on:** [Vision and Sequence Basics](/ai/classical-deep-learning/vision-and-sequence-basics) and, for the vector maths, [Similarity and Norms](/ai/math-foundations/similarity-and-norms).

## What NLP systems are asked to do

| Task                      | Input → output                              | Example                                           |
| :------------------------ | :------------------------------------------ | :------------------------------------------------ |
| **Text classification**   | Text → one label                            | Spam or not spam; positive or negative review     |
| **Sequence labelling**    | Text → one label per token                  | Mark each word as person, place, or neither (NER) |
| **Language modelling**    | Text so far → probability of the next token | Autocomplete; the core of every LLM               |
| **Machine translation**   | Text in one language → text in another      | English to French                                 |
| **Summarization**         | Long text → short text                      | A news article to two sentences                   |
| **Information retrieval** | Query → ranked documents                    | Web search                                        |
| **Question answering**    | Question (+ context) → answer               | "Who wrote Hamlet?" → "Shakespeare"               |

Classification and retrieval need a vector for a whole **document** (any unit of text: a sentence, a review, a web page). Labelling, language modelling, and translation need a vector for each **token**. The methods below supply one or the other.

## Tokens and vocabularies

**Tokenization** is splitting raw text into a sequence of units called **tokens**. The choice of unit is the first modelling decision:

| Level         | `"unhappiness isn't rare"` becomes         | Vocabulary size | Trade-off                                                    |
| :------------ | :----------------------------------------- | :-------------- | :----------------------------------------------------------- |
| **Word**      | `unhappiness`, `is`, `n't`, `rare`         | 100k–1M+        | Short sequences; unseen words are unrepresentable            |
| **Character** | `u`, `n`, `h`, `a`, `p`, …                 | ~100            | Nothing is unseen; sequences become 5–6× longer              |
| **Subword**   | `un`, `happi`, `ness`, `is`, `n't`, `rare` | 30k–200k        | Frequent words stay whole, rare ones split into known pieces |

Classical NLP used word-level tokens, usually after **normalization**: lowercasing, and sometimes **stemming** (crudely cutting suffixes, `running` → `run`) or **lemmatization** (mapping to a dictionary form, `ran` → `run`). Modern systems use subword tokenizers such as byte-pair encoding, covered in [Tokenization](/ai/llm/tokenization).

The **vocabulary** $V$ is the fixed list of tokens a model knows, each assigned an integer **ID**. It is built from the training **corpus** (the collection of training text), typically by keeping tokens that occur at least a minimum number of times. Every other token is replaced by a special **unknown** token `<unk>`; this is the **out-of-vocabulary (OOV)** problem. A few more special tokens are standard: `<pad>` to fill short sequences in a batch, and `<bos>` / `<eos>` to mark the beginning and end of a sequence.

```text
vocabulary:  {<pad>: 0, <unk>: 1, the: 2, cat: 3, sat: 4, on: 5, mat: 6}
"the cat sat on the rug"  ->  [2, 3, 4, 5, 2, 1]        rug is out of vocabulary
```

Token IDs are labels, not quantities. ID 6 is not "twice" ID 3, and feeding raw IDs to a model as numbers would impose a meaningless ordering. They must be turned into vectors.

## One-hot vectors

A **one-hot vector** represents token $i$ as a vector of length $|V|$ with a 1 in position $i$ and 0 everywhere else. With the vocabulary `[cat, dog, mat, sat, the]`:

```text
cat = [1, 0, 0, 0, 0]
dog = [0, 1, 0, 0, 0]
mat = [0, 0, 1, 0, 0]
```

One-hot encoding is an **encoding**, a fixed rule with no learned parameters (see [Encoding versus embedding](/ai/math-foundations/ai-basics#encoding-versus-embedding)). It is lossless — every token gets a distinct vector — but it has two structural flaws:

1. **Every pair of words is equally different.** The dot product of any two distinct one-hot vectors is 0, and the distance between any two is $\sqrt{2}$. `cat` is exactly as far from `dog` as from `mat`. A model that learns something about cats learns nothing about dogs, because their inputs share no component.
2. **Size grows with the vocabulary.** With $|V| = 100{,}000$, each token is a 100,000-dimensional vector with a single nonzero entry.

Both flaws persist in every count-based method below, because they are all built by adding one-hot vectors together.

## Bag of words

A **bag of words (BoW)** represents a document by how many times each vocabulary word appears in it, ignoring order. It is the sum of the one-hot vectors of the document's tokens. Take three documents:

```text
d1: the cat sat on the mat
d2: the dog sat on the log
d3: the cat chased the dog
```

With vocabulary `[cat, chased, dog, log, mat, on, sat, the]`, each document becomes one row of a **document-term matrix**:

| Doc  | cat | chased | dog | log | mat |  on | sat | the |
| :--- | --: | -----: | --: | --: | --: | --: | --: | --: |
| `d1` |   1 |      0 |   0 |   0 |   1 |   1 |   1 |   2 |
| `d2` |   0 |      0 |   1 |   1 |   0 |   1 |   1 |   2 |
| `d3` |   1 |      1 |   1 |   0 |   0 |   0 |   0 |   2 |

Documents can now be compared with **cosine similarity**, the cosine of the angle between two vectors: $\cos(\mathbf{a}, \mathbf{b}) = \frac{\mathbf{a}\cdot\mathbf{b}}{\lVert\mathbf{a}\rVert\,\lVert\mathbf{b}\rVert}$, which ignores document length.

$$
\cos(d_1, d_2) = \frac{1 \cdot 1 + 1 \cdot 1 + 2 \cdot 2}{\sqrt{8}\,\sqrt{8}} = \frac{6}{8} = 0.75, \qquad
\cos(d_1, d_3) = \frac{1 + 4}{\sqrt{8}\,\sqrt{7}} = 0.67
$$

So by this measure `d1` (a cat on a mat) is more similar to `d2` (a dog on a log) than to `d3` (a cat chasing a dog). The similarity comes largely from `the`, `sat`, and `on` — words that say little about meaning — which is the problem TF-IDF addresses.

A bag of words also loses all order: "dog bites man" and "man bites dog" get identical vectors. Even so, a linear classifier on BoW features is a strong baseline for topic and spam classification, because topic is mostly a matter of which words appear.

## N-grams

An **n-gram** is a run of $n$ consecutive tokens. Unigrams ($n = 1$) are single words, bigrams ($n = 2$) pairs, trigrams ($n = 3$) triples. Counting n-grams instead of single words restores **local** order:

```text
d3 bigrams:  "the cat", "cat chased", "chased the", "the dog"
```

Now "dog bites" and "bites dog" are different features, and "not good" can be learned as negative even though "good" alone is positive. The cost is size: the number of possible bigrams is $|V|^2$, and most of them occur rarely, so the feature vectors become even larger and sparser. In practice systems use unigrams plus bigrams, and keep only n-grams above a frequency threshold.

## TF-IDF

Raw counts overweight words that appear everywhere. **TF-IDF** (term frequency × inverse document frequency) reweights each count by how distinctive the word is across the collection. It has two factors:

- **Term frequency** $\text{tf}(w, d)$: how often word $w$ appears in document $d$, either the raw count or the count divided by the document length.
- **Inverse document frequency** $\text{idf}(w) = \log\dfrac{N}{\text{df}(w)}$, where $N$ is the number of documents and $\text{df}(w)$ is the number of documents containing $w$.

$$
\text{tf-idf}(w, d) = \text{tf}(w, d) \times \text{idf}(w)
$$

The IDF factor is 0 for a word in every document and largest for a word in only one. For the three documents above ($N = 3$):

| Word  | In documents | $\text{idf} = \ln(3 / \text{df})$ | Reading                               |
| :---- | :----------- | --------------------------------: | :------------------------------------ |
| `the` | 3            |                             0.000 | Present everywhere; carries no signal |
| `sat` | 2            |                             0.405 | Moderately common                     |
| `cat` | 2            |                             0.405 | Moderately common                     |
| `mat` | 1            |                             1.099 | Unique to `d1`; most distinctive      |

In `d1`, `the` appears twice but scores $2 \times 0 = 0$, while `mat` appears once and scores $1 \times 1.099 = 1.099$. The document's vector is now dominated by the words that set it apart. Libraries differ in small details (adding 1 inside the logarithm to avoid division by zero, normalizing each vector to unit length), so exact values vary.

TF-IDF vectors compared by cosine similarity were the standard for search for decades. **BM25**, the refinement still used in Elasticsearch and as the lexical half of [hybrid search](/ai/rag/hybrid-search), adds two corrections: term frequency saturates (the tenth occurrence of a word matters less than the second), and long documents are penalized so they do not win just by containing more words.

## Language models from counts

A **language model** assigns a probability to a sequence of tokens, or equivalently predicts the next token given the previous ones. By the chain rule of probability, any sequence probability factors into next-token predictions:

$$
P(w_1, w_2, \dots, w_T) = \prod_{t=1}^{T} P(w_t \mid w_1, \dots, w_{t-1})
$$

This is exact, but the conditioning history grows without limit, and most long histories never appear in any corpus. An **n-gram language model** makes the **Markov assumption**: the next word depends only on the previous $n - 1$ words. For a bigram model ($n = 2$):

$$
P(w_t \mid w_1, \dots, w_{t-1}) \approx P(w_t \mid w_{t-1}) = \frac{\text{count}(w_{t-1}, w_t)}{\text{count}(w_{t-1})}
$$

Estimating probabilities by dividing counts like this is the **maximum-likelihood estimate**.

### Worked example

Train a bigram model on three sentences, with `<s>` and `</s>` marking the start and end:

```text
<s> I like cats </s>
<s> I like dogs </s>
<s> I hate cats </s>
```

`I` is followed twice by `like` and once by `hate`, so $P(\text{like} \mid \text{I}) = 2/3$ and $P(\text{hate} \mid \text{I}) = 1/3$. `like` is followed once each by `cats` and `dogs`, so each gets $1/2$. The probability of the sentence "I like cats":

$$
P = \underbrace{P(\text{I} \mid \langle s \rangle)}_{1} \cdot \underbrace{P(\text{like} \mid \text{I})}_{2/3} \cdot \underbrace{P(\text{cats} \mid \text{like})}_{1/2} \cdot \underbrace{P(\langle /s \rangle \mid \text{cats})}_{1} = \frac{1}{3}
$$

Now score "I hate dogs", a perfectly reasonable sentence. `hate` was never followed by `dogs`, so $P(\text{dogs} \mid \text{hate}) = 0$ and the whole sentence gets probability 0. This is the **sparsity problem**: almost every plausible n-gram is missing from any finite corpus, and the problem grows rapidly with $n$.

### Smoothing

**Smoothing** moves a little probability mass from seen n-grams to unseen ones. The simplest form, **add-one (Laplace) smoothing**, adds 1 to every count:

$$
P(w_t \mid w_{t-1}) = \frac{\text{count}(w_{t-1}, w_t) + 1}{\text{count}(w_{t-1}) + |V|}
$$

With 6 possible next tokens (`I`, `like`, `hate`, `cats`, `dogs`, `</s>`), $P(\text{dogs} \mid \text{hate}) = (0 + 1)/(1 + 6) = 1/7$: small but no longer zero. Add-one moves too much mass on large vocabularies; practical systems used **Kneser-Ney smoothing**, which also uses how many different contexts a word appears in, and **backoff**, which falls back to a shorter n-gram when the longer one is unseen.

### Perplexity

Language models are evaluated by **perplexity**: the exponentiated average negative log-probability the model assigns to each token of held-out text.

$$
\text{PPL} = \exp\left(-\frac{1}{T}\sum_{t=1}^{T} \log P(w_t \mid w_{<t})\right)
$$

Perplexity has a concrete reading: it is the number of equally likely choices the model is effectively picking between at each step. A model that assigns probability $1/4$ to every correct token has perplexity exactly 4, as if choosing uniformly among four words. If a model assigns $0.5, 0.25, 0.125, 0.5$ to four tokens, the average log-probability is $-1.75 \ln 2$ and the perplexity is $2^{1.75} = 3.36$. Lower is better. Perplexity is also $e^{\text{cross-entropy}}$, so it is the same quantity neural language models minimize, reported on a more readable scale.

Well-smoothed 5-gram models reached perplexities around 140 on the Penn Treebank benchmark; LSTM language models brought that below 60.

## What counting cannot do

Every method on this page is built from one-hot vectors, so every method inherits their central flaw: **words are atomic symbols with no relationship to each other**.

- Having seen "I like cats" many times, a bigram model learns nothing about "I like kittens", because `kittens` and `cats` share no counts.
- A TF-IDF search for "car" does not match a document that only says "automobile".
- An n-gram model needs to see every word combination separately, which is why it needed enormous corpora and still assigned zero to most plausible sentences.

What is missing is a representation in which **similar words have similar vectors**, so that evidence about one word automatically generalizes to its neighbours. The idea that makes this possible is the **distributional hypothesis**, stated by J. R. Firth in 1957 as "a word is characterized by the company it keeps": words that occur in similar contexts tend to have similar meanings. `cats` and `kittens` both appear near `purr`, `feed`, `cute`, and `the`; `car` and `automobile` both appear near `drive`, `engine`, and `road`.

Turning that hypothesis into dense, learned vectors is the subject of the next page, [Word Embeddings](/ai/classical-deep-learning/word-embeddings).

## Key terms

| Term                          | Meaning                                                                                   |
| :---------------------------- | :---------------------------------------------------------------------------------------- |
| **corpus**                    | The collection of text a model is built from                                              |
| **token / tokenization**      | A unit of text (word, subword, character), and the act of splitting text into them        |
| **vocabulary**                | The fixed list of known tokens, each with an integer ID                                   |
| **OOV / `<unk>`**             | A token not in the vocabulary, and the placeholder that replaces it                       |
| **one-hot vector**            | A vector as long as the vocabulary, with a single 1 at the token's ID                     |
| **bag of words**              | A document as a vector of word counts, order ignored                                      |
| **n-gram**                    | A run of $n$ consecutive tokens                                                           |
| **TF-IDF**                    | Term frequency times inverse document frequency: counts reweighted by distinctiveness     |
| **cosine similarity**         | The cosine of the angle between two vectors; similarity independent of length             |
| **language model**            | A probability distribution over sequences, factored into next-token predictions           |
| **Markov assumption**         | The next token depends only on the previous $n - 1$                                       |
| **smoothing**                 | Reassigning probability mass to unseen n-grams so nothing gets probability 0              |
| **perplexity**                | $\exp$ of the average negative log-probability; the effective number of choices per token |
| **distributional hypothesis** | Words that occur in similar contexts have similar meanings                                |

## Interview questions

<Accordions>
  <Accordion title="Why can token IDs not be fed to a model directly as numbers?">

    IDs are arbitrary labels assigned by the vocabulary. Treating them as quantities imposes a meaningless order and scale: ID 6 would be "twice" ID 3 and "closer" to ID 5 than to ID 100. They must first become vectors, either by a fixed encoding such as one-hot or by a learned embedding lookup.

  </Accordion>
  <Accordion title="What are the two structural flaws of one-hot vectors?">

    Every pair of distinct words has dot product 0 and the same distance, so no similarity is encoded and nothing learned about one word transfers to another. And the vector length equals the vocabulary size, so representations are huge and almost entirely zeros.

  </Accordion>
  <Accordion title="Compute the IDF of a word that appears in every document. Why is that the desired behaviour?">

    $\text{idf} = \log(N / N) = \log 1 = 0$. A word present in every document cannot help distinguish one document from another, so its weight should be zero regardless of how often it appears. Words like `the` and `of` are suppressed automatically without a hand-made stop-word list.

  </Accordion>
  <Accordion title="What does a bag of words lose, and what do n-grams recover?">

    It loses all order: "dog bites man" and "man bites dog" get the same vector, and negation like "not good" is invisible. Counting n-grams recovers local order within a window of $n$ tokens, so "not good" becomes its own feature, at the cost of a feature space that grows roughly as $|V|^n$ and is extremely sparse.

  </Accordion>
  <Accordion title="State the Markov assumption in an n-gram language model and the problem it creates.">

    The next token depends only on the previous $n - 1$ tokens, so $P(w_t \mid w_{<t}) \approx P(w_t \mid w_{t-n+1}, \dots, w_{t-1})$, estimated by counting. It makes estimation possible but caps the context at $n - 1$ words, and it creates sparsity: most plausible n-grams never appear in the corpus and get probability zero, which grows worse as $n$ increases.

  </Accordion>
  <Accordion title="What is smoothing, and why is it necessary?">

    Moving some probability mass from observed n-grams to unobserved ones. Without it, any sentence containing a single unseen n-gram gets probability zero, so perplexity is infinite and the model cannot rank plausible sentences. Add-one smoothing adds 1 to every count; Kneser-Ney and backoff are the practical methods.

  </Accordion>
  <Accordion title="Define perplexity and interpret a perplexity of 4.">

    $\text{PPL} = \exp(-\frac{1}{T}\sum_t \log P(w_t \mid w_{<t}))$, the exponentiated average negative log-likelihood, equal to $e^{\text{cross-entropy}}$. A perplexity of 4 means the model is, on average, as uncertain as if choosing uniformly among four tokens at each step.

  </Accordion>
  <Accordion title="Why does a TF-IDF search for 'car' miss a document about 'automobiles', and what idea fixes it?">

    TF-IDF is built from one-hot word identities, so `car` and `automobile` are unrelated dimensions with no overlap. The distributional hypothesis fixes it: words in similar contexts have similar meanings, so learning vectors from co-occurrence places `car` and `automobile` close together. Dense retrieval with embeddings exploits exactly that.

  </Accordion>
</Accordions>
