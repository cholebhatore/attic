Python backend and AI applications handle persistence across two core paradigms: relational databases (SQL) for structured transactional records and document stores (NoSQL) for unstructured payloads and conversation state.

---

## Persistence architecture

A modern Python database integration consists of four distinct architectural tiers:

1. **Validation Layer (Pydantic)**: Defines strict input and output shapes at the HTTP or RPC boundary.
2. **Mapping Layer (ORMs & ODMs)**: Translates application objects into database queries and rows or documents.
3. **Driver Layer**: Handles network sockets, wire protocol framing, and connection pooling asynchronously.
4. **Migration Layer (Alembic)**: Tracks relational schema delta scripts over time.

## SQL vs NoSQL in AI applications

| Factor                | Relational (SQL)                                                       | Document / Key-Value (NoSQL)                                        |
| :-------------------- | :--------------------------------------------------------------------- | :------------------------------------------------------------------ |
| **Typical Engines**   | PostgreSQL, SQLite                                                     | MongoDB, Redis                                                      |
| **Python Libraries**  | SQLAlchemy, SQLModel, Alembic                                          | Beanie, Motor, redis-py                                             |
| **AI Workloads**      | Vector embeddings (`pgvector`), user auth, API usage metering, billing | Raw prompt/response logs, agent memory transcripts, context caching |
| **Schema Guarantees** | Strict column types, foreign keys, unique constraints                  | Dynamic schemas, nested JSON structures                             |
| **Schema Evolution**  | Requires versioned migrations (Alembic)                                | Handled at the application layer                                    |

## Local vs hosted database environments

### Local development

- **SQLite**: Runs in-process with zero server setup. Useful for fast unit tests and standalone CLI tools. Async driver: `aiosqlite`.
- **Docker Compose (PostgreSQL)**: Runs a local container matching production PostgreSQL versions, extensions, and network configurations.

### Hosted cloud databases

- **Serverless PostgreSQL (Neon, Supabase)**: Scales compute independently from storage. Requires connection pooling settings tuned for serverless functions and mandatory SSL flags (`sslmode=require`).
- **Managed Cloud Instances (AWS RDS, GCP Cloud SQL)**: Traditional dedicated instances requiring VPC peering or private subnets for low-latency database access.
