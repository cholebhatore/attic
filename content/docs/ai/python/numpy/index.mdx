NumPy is the array layer the rest of the Python machine-learning stack sits on. pandas, PyTorch, JAX, and scikit-learn all pass data through `ndarray` objects or through designs copied from them, so the dtype rules, the view-versus-copy behavior, and the broadcasting semantics written here are the rules those libraries inherit, or deliberately break.

Every NumPy array is one flat block of memory plus the metadata needed to read that block as a shape:

- **dtype** — how many bytes each element occupies and how it is encoded
- **shape** — how many elements sit along each axis
- **strides** — how many bytes to skip to advance one element along each axis

Surprising results almost always come from two facts. Views share the buffer they point at, so mutating one array changes another. Operations return a fresh array only when they have to, which is why some of your code copies gigabytes and some of it copies nothing.

## Prerequisites

[Language Fundamentals](/ai/python/fundamentals) covers the list, dict, and class mechanics that
NumPy code leans on: iteration, slicing syntax shared with Python sequences, `is None` checks, and
comprehensions. [Package Management](/ai/python/package-management) covers the `uv` commands used to
install and pin NumPy.

This section is the last pre-requisite before the rest of the curriculum. [Math
Foundations](/ai/math-foundations) implements broadcasting, softmax, and backpropagation in NumPy,
and [PyTorch](/ai/pytorch) keeps the same mental model with a device dimension and an autograd engine
added. The cross-references between the two frameworks run both ways, and
[Pitfalls and Interop](/ai/python/numpy/pitfalls-and-interop) lists where they disagree.

## What you should be able to do afterwards

- Predict the dtype of an expression before running it, including where NumPy 2 promotes a Python scalar and where it refuses to
- Tell whether an indexing expression returned a view or a copy, and check it with `np.shares_memory` instead of guessing
- Rewrite a nested Python loop over a large array into one vectorized expression without materializing an intermediate copy
- Reduce along an axis and keep the dimension aligned for the next operation, using `keepdims` rather than a re-reshape
- Sample the same numbers twice on a machine you control, and explain why a fix applied with `np.random.seed` did not survive a worker process
- Size a dataset in bytes from its shape and dtype, and choose between loading it, memory-mapping it, and downcasting it at read time
- Explain why `a[idx] += v` loses updates when `idx` repeats and what `np.add.at` does differently
- Read a `np.linalg` call and know whether it solved, factored, or inverted, and which of those costs the most
