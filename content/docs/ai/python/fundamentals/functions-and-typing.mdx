Functions are first-class citizens in Python, meaning they can be passed as arguments, assigned to variables, and returned from other functions. Modern Python services combine function signatures with type hints to provide self-documenting code contracts.

---

## 1. Defining functions

Functions are defined using the `def` keyword. Type annotations describe expected input parameter types and the return type.

```python title="functions.py"
def add(a: int, b: int) -> int:
    return a + b

result = add(10, 20)
print(result)  # 30
```

### Default arguments and f-strings

Functions support default argument values. String interpolation is performed using f-strings (prefixing strings with `f` and embedding expressions inside `{}`):

```python title="defaults.py"
def greet(name: str = "Guest", uppercase: bool = False) -> str:
    message = f"Hello, {name}!"
    return message.upper() if uppercase else message

print(greet())                       # "Hello, Guest!"
print(greet("Aditi", uppercase=True))    # "HELLO, ADITI!"
```

## 2. Modern type annotations (Python 3.10+)

Python supports expressive type annotations without requiring the legacy `typing` module for standard collections.

```python title="typing_signatures.py"
from typing import Any

def process_batch(
    records: list[dict[str, Any]],
    user_id: int | None = None,
    tags: set[str] | None = None
) -> list[str]:
    valid_ids: list[str] = []
    for record in records:
        if "id" in record:
            valid_ids.append(str(record["id"]))
    return valid_ids
```

### Type annotation reference

| Type Concept            | Modern Python (3.10+) | TypeScript Equivalent         |
| :---------------------- | :-------------------- | :---------------------------- |
| **Optional / Nullable** | `str \| None`         | `string \| null` or `string?` |
| **Typed List**          | `list[str]`           | `string[]` (`Array<string>`)  |
| **Typed Dictionary**    | `dict[str, int]`      | `Record<string, number>`      |
| **Dynamic Any**         | `Any` (from `typing`) | `any` / `unknown`             |
| **Tuple of Types**      | `tuple[int, str]`     | `[number, string]`            |

<Callout type="info">
  Type hints are ignored by the standard Python runtime and do not enforce type safety on their own.
  Static analyzers (Mypy, Pyright) check them during development, while framework tools (such as
  Pydantic in FastAPI) parse them at runtime to validate request payloads.
</Callout>

## 3. Argument unpacking: `*args` and `**kwargs`

Python allows functions to accept arbitrary numbers of positional and keyword arguments using the `*` and `**` operators.

```python title="unpacking.py"
def log_event(event_name: str, *args, **kwargs):
    # args: tuple containing extra positional arguments
    # kwargs: dict containing extra named keyword arguments
    print(f"Event: {event_name}")
    print(f"Positional details: {args}")
    print(f"Named parameters: {kwargs}")

log_event("user_signup", "tier_1", ip="192.168.1.1", source="organic")
```

### Forwarding arguments to downstream services

```python title="forwarding.py"
def database_query(query: str, *args, **kwargs):
    # Forwards arguments directly to underlying driver
    return execute_raw(query, *args, **kwargs)
```

## 4. Lambda functions

Lambda functions are anonymous, single-expression functions:

```python title="lambdas.py"
users = [
    {"name": "Aditi", "score": 92},
    {"name": "Madhav", "score": 98},
    {"name": "Aryan", "score": 85},
]

# Sort users in place by score using a lambda key
users.sort(key=lambda u: u["score"], reverse=True)
```
