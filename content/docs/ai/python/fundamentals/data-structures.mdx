Python provides four built-in collection types: lists, tuples, sets, and dictionaries. Understanding their mutability, ordering, and performance characteristics is essential for structuring application data and processing JSON payloads.

---

## 1. Lists (`list`)

Lists are ordered, mutable sequences equivalent to arrays in JavaScript and TypeScript.

```python title="lists.py"
users = ["Madhav", "Dhruv", "Keshav"]

# Appending and inserting elements
users.append("Suhani")       # Adds to the end: ['Madhav', 'Dhruv', 'Keshav', 'Suhani']
users.insert(0, "Aryan")     # Inserts at index 0

# Indexing and negative indexing
print(users[0])              # "Aryan" (first element)
print(users[-1])             # "Suhani" (last element)

# Slicing [start:stop] (stop is exclusive)
subset = users[1:3]          # ['Madhav', 'Dhruv']

# Removal
removed_user = users.pop()   # Removes and returns last item
```

---

## 2. Tuples (`tuple`)

Tuples are ordered, immutable sequences. Once created, elements cannot be added, removed, or reassigned.

```python title="tuples.py"
coordinates = (10, 20)
latitude, longitude = coordinates  # Tuple unpacking

print(f"Lat: {latitude}, Long: {longitude}")

# Reassignment triggers a TypeError at runtime:
# coordinates[0] = 30  # TypeError: 'tuple' object does not support item assignment
```

Tuples are used for fixed groupings (such as database coordinate points or multiple return values from a function) where immutability prevents accidental modification.

---

## 3. Sets (`set`)

Sets are unordered collections of unique elements backed by hash tables, providing `O(1)` average membership testing.

```python title="sets.py"
ids = {1, 2, 2, 3, 4}
print(ids)                 # {1, 2, 3, 4} (duplicates stripped automatically)

# Fast membership check
print(3 in ids)            # True (O(1) average lookup)

# Set operations
a = {1, 2, 3}
b = {3, 4, 5}
print(a | b)               # Union: {1, 2, 3, 4, 5}
print(a & b)               # Intersection: {3}
print(a - b)               # Difference: {1, 2}
```

---

## 4. Dictionaries (`dict`)

Dictionaries are key-value hash maps that maintain insertion order. They serve as the standard data representation for configuration and raw JSON payloads.

```python title="dictionaries.py"
user = {
    "name": "Dhruv",
    "role": "systems_engineer",
    "department": "Infrastructure"
}

# Direct access (raises KeyError if key does not exist)
print(user["name"])        # "Dhruv"

# Safe access with .get() (returns None or fallback value)
phone = user.get("phone")             # None
phone_with_default = user.get("phone", "N/A")  # "N/A"

# Key presence check
if "email" in user:
    print(user["email"])

# Dictionary merge operator (Python 3.9+)
metadata = {"verified": True, "org": "core"}
enriched_user = user | metadata
```

## Collections reference

| Collection  | Syntax       | Ordered | Mutable | Duplicates | Lookup Time                | TypeScript Equivalent       |
| :---------- | :----------- | :------ | :------ | :--------- | :------------------------- | :-------------------------- |
| **`list`**  | `[1, 2, 3]`  | Yes     | Yes     | Yes        | `O(1)` index, `O(n)` value | `Array<T>` (`T[]`)          |
| **`tuple`** | `(1, 2, 3)`  | Yes     | No      | Yes        | `O(1)` index               | `readonly [T, U]`           |
| **`set`**   | `{1, 2, 3}`  | No      | Yes     | No         | `O(1)` value               | `Set<T>`                    |
| **`dict`**  | `{"k": "v"}` | Yes     | Yes     | Keys: No   | `O(1)` key                 | `Record<string, T>` / `Map` |

## Backend JSON payload mapping

In web services and AI agents, Python dictionaries and lists map directly to JSON objects and arrays:

```python title="payload_mapping.py"
# Matches JSON payload: {"session_id": "abc", "items": [{"id": 1, "score": 0.95}]}
response_payload = {
    "session_id": "abc",
    "items": [
        {"id": 1, "score": 0.95},
        {"id": 2, "score": 0.88},
    ],
    "total_count": 2
}
```

Libraries like Pydantic validate these nested dictionaries and serialize them into JSON strings over HTTP responses.
