Python organizes state and behavior through classes and structures repositories into modules and packages. Understanding these mechanisms is foundational for working with ORMs like SQLAlchemy and frameworks like FastAPI.

---

## 1. Classes and the object model

Classes encapsulate state and instance methods using the `class` keyword:

```python title="classes.py"
class User:
    # Constructor / initializer
    def __init__(self, name: str, email: str):
        # Instance attributes bound directly to self
        self.name = name
        self.email = email
        self.is_active = True

    # Instance method
    def introduce(self) -> str:
        return f"User: {self.name} ({self.email})"

    # String representation for debugging
    def __repr__(self) -> str:
        return f"<User id={self.name} active={self.is_active}>"

user = User("Keshav", "keshav@example.com")
print(user.introduce())
```

### Key concepts

1. **`__init__`**: The instance initialization method called immediately when a class is instantiated (`User(...)`).
2. **`self`**: The explicit reference to the current instance. Unlike `this` in TypeScript, `self` must be specified as the first argument in all instance methods.
3. **Dynamic Attributes**: Attributes like `self.name` and `self.email` are created directly on `self`. You do not declare field types outside methods unless defining class-level attributes (as in SQLAlchemy models).

## 2. Modules and package organization

Any Python file `.py` acts as a **module**. A folder containing Python files acts as a **package**.

Given this backend project structure:

<Files>
  <Folder name="app" defaultOpen>
    <File name="main.py" />
    <File name="utils.py" />
    <Folder name="services" defaultOpen>
      <File name="auth.py" />
    </Folder>
  </Folder>
</Files>

```python title="app/utils.py"
def calculate_total(price: float, quantity: int) -> float:
    return price * quantity
```

```python title="app/main.py"
# Absolute import from top-level package
from app.utils import calculate_total
from app.services.auth import verify_token

total = calculate_total(49.99, 2)
print(f"Total: ${total:.2f}")
```

<Callout type="info">
  Always prefer absolute imports (`from app.services.auth import ...`) over relative imports (`from
  ..auth import ...`) in backend services to ensure consistent module resolution across CLI scripts,
  tests, and web servers.
</Callout>

## 3. Exception handling

Errors in Python are raised and handled using `try`, `except`, `else`, and `finally` blocks:

```python title="exceptions.py"
def parse_port(port_str: str) -> int:
    try:
        port = int(port_str)
        if port < 1024 or port > 65535:
            raise ValueError(f"Port {port} out of valid non-privileged range.")
    except ValueError as err:
        print(f"Validation failed: {err}")
        return 8000  # Fallback port
    else:
        # Runs only if NO exception occurred in try block
        print("Port parsed successfully.")
        return port
    finally:
        # Always runs, regardless of success or exception
        print("Completed port parsing routine.")
```

### Defining custom domain exceptions

```python title="domain_exceptions.py"
class UserNotFoundError(Exception):
    def __init__(self, user_id: int):
        self.user_id = user_id
        super().__init__(f"User with ID {user_id} was not found.")

# Usage in service layer
def get_user_by_id(user_id: int):
    user = db_lookup(user_id)
    if not user:
        raise UserNotFoundError(user_id)
    return user
```
