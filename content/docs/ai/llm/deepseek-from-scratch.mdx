description: Multi-head Latent Attention, group-limited aux-loss-free DeepSeekMoE, Multi-Token Prediction, and a parameter count that lands on the published 671B.
---

DeepSeek-V3 combines three components that each solve a different problem: MLA cuts the KV cache, aux-loss-free MoE balances 256 experts without a proxy objective, and Multi-Token Prediction adds supervision and enables speculative decoding. The published model is 671B total parameters with 37B active per token, trained on 14.8 trillion tokens.

The architecture paper is arXiv:2412.19437. The values below are from the released `config.json`.

## Multi-head Latent Attention

```python
import torch
import torch.nn as nn
import torch.nn.functional as F


class DeepSeekMLA(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.h = cfg.num_attention_heads              # 128
        self.q_lora = cfg.q_lora_rank                 # 1536
        self.kv_lora = cfg.kv_lora_rank               # 512
        self.d_nope = cfg.qk_nope_head_dim            # 128
        self.d_rope = cfg.qk_rope_head_dim            # 64
        self.d_v = cfg.v_head_dim                     # 128
        self.scaling = (self.d_nope + self.d_rope) ** -0.5

        self.q_a = nn.Linear(cfg.hidden_size, self.q_lora, bias=False)                    # 7168 -> 1536
        self.q_a_norm = RMSNorm(self.q_lora, cfg.rms_norm_eps)
        self.q_b = nn.Linear(self.q_lora, self.h * (self.d_nope + self.d_rope), bias=False)  # 1536 -> 24576
        self.kv_a = nn.Linear(cfg.hidden_size, self.kv_lora + self.d_rope, bias=False)    # 7168 -> 576
        self.kv_a_norm = RMSNorm(self.kv_lora, cfg.rms_norm_eps)
        self.k_b = nn.Linear(self.kv_lora, self.h * self.d_nope, bias=False)              # 512 -> 16384
        self.v_b = nn.Linear(self.kv_lora, self.h * self.d_v, bias=False)                 # 512 -> 16384
        self.o = nn.Linear(self.h * self.d_v, cfg.hidden_size, bias=False)                # 16384 -> 7168

    def forward(self, x, cos, sin):
        B, T, _ = x.shape
        c_q = self.q_a_norm(self.q_a(x))                                    # (B, T, 1536)
        q = self.q_b(c_q).view(B, T, self.h, self.d_nope + self.d_rope).transpose(1, 2)
        q_nope, q_rope = q.split([self.d_nope, self.d_rope], dim=-1)        # (B,128,T,128), (B,128,T,64)

        kv = self.kv_a(x)                                                   # (B, T, 576)
        c_kv, k_rope = kv.split([self.kv_lora, self.d_rope], dim=-1)
        c_kv = self.kv_a_norm(c_kv)                                         # (B, T, 512)  <- CACHED
        k_rope = apply_rope(k_rope.unsqueeze(1), cos, sin)                  # (B, 1, T, 64) <- CACHED

        k_nope = self.k_b(c_kv).view(B, T, self.h, self.d_nope).transpose(1, 2)   # (B,128,T,128)
        v = self.v_b(c_kv).view(B, T, self.h, self.d_v).transpose(1, 2)           # (B,128,T,128)
        q_rope = apply_rope(q_rope, cos, sin)

        scores = torch.matmul(q_nope, k_nope.transpose(-1, -2)) * self.scaling
        scores = scores + torch.matmul(q_rope, k_rope.transpose(-1, -2)) * self.scaling
        mask = torch.ones(T, T, dtype=torch.bool, device=x.device).tril()
        scores = scores.masked_fill(~mask, float("-inf"))
        attn = F.softmax(scores, dim=-1, dtype=torch.float32).to(q_nope.dtype)

        out = torch.matmul(attn, v).transpose(1, 2).reshape(B, T, -1)       # (B, T, 16384)
        return self.o(out)                                                  # (B, T, 7168)
```

The RoPE cache is built for `d_rope = 64`, not for a full head dimension, and `k_rope` has a single head that broadcasts across all 128.

Cached per token per layer: `512 + 64 = 576` elements. The MHA equivalent at 128 heads and 128 dimensions is `2 * 128 * 128 = 32,768`. See [Attention Variants](/ai/llm/attention-variants) for why the up-projections get absorbed at inference and what breaks if you do not.

## DeepSeekMoE

Sigmoid scoring, a learnable per-expert bias that replaces the auxiliary loss, and two-stage group-limited selection.

```python
class DeepSeekMoE(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.n_experts = cfg.n_routed_experts          # 256
        self.n_group = cfg.n_group                     # 8
        self.topk_group = cfg.topk_group               # 4
        self.top_k = cfg.num_experts_per_tok           # 8
        self.group_size = self.n_experts // self.n_group      # 32
        self.scaling = cfg.routed_scaling_factor       # 2.5

        self.gate = nn.Linear(cfg.hidden_size, self.n_experts, bias=False)
        self.e_score_correction_bias = nn.Parameter(torch.zeros(self.n_experts))
        self.experts = nn.ModuleList(
            [SwiGLU(cfg.hidden_size, cfg.moe_intermediate_size) for _ in range(self.n_experts)]
        )
        self.shared = nn.ModuleList(
            [SwiGLU(cfg.hidden_size, cfg.moe_intermediate_size) for _ in range(cfg.n_shared_experts)]
        )

    def select_experts(self, scores):
        # scores: (BT, 256) after sigmoid — the unbiased routing scores
        biased = scores + self.e_score_correction_bias             # (BT, 256)
        grouped = biased.view(-1, self.n_group, self.group_size)   # (BT, 8, 32)
        group_score = grouped.topk(2, dim=-1)[0].sum(-1)           # (BT, 8)
        keep = group_score.topk(self.topk_group, dim=-1)[1]        # (BT, 4)

        mask = torch.zeros_like(grouped, dtype=torch.bool)
        mask.scatter_(-1, keep.unsqueeze(-1).expand(-1, -1, self.group_size), True)
        masked = biased.masked_fill(~mask.reshape_as(biased), float("-inf"))

        idx = masked.topk(self.top_k, dim=-1)[1]                   # (BT, 8)
        weights = scores.gather(-1, idx)                           # unbiased, for the combination
        return idx, weights / weights.sum(-1, keepdim=True)

    def forward(self, x):
        B, T, D = x.shape
        flat = x.reshape(B * T, D)
        scores = torch.sigmoid(self.gate(flat))                    # (BT, 256)
        idx, weights = self.select_experts(scores)

        out = torch.zeros_like(flat)
        for slot in range(self.top_k):
            for e in range(self.n_experts):
                mask = idx[:, slot] == e
                if mask.any():
                    out[mask] += weights[mask, slot].unsqueeze(-1) * self.experts[e](flat[mask])

        for shared in self.shared:
            out = out + shared(flat)
        return (out * self.scaling).reshape(B, T, D)
```

The bias is added for **selection** but the weights come from the unbiased scores. That separation is what makes the mechanism safe: the bias steers which experts get traffic without distorting how much each contributes once chosen.

### The gradient-free update

```python
@torch.no_grad()
def update_correction_bias(module, expert_counts, target_load, gamma=1.0):
    bias = module.e_score_correction_bias.data
    bias += torch.where(expert_counts > target_load, -gamma, gamma)
    bias[expert_counts == 0] += gamma          # revive dead experts faster
```

No loss term, no gradient, no interaction with the main objective. Compare this to the Switch Transformer aux loss in [Mixture of Experts](/ai/llm/mixture-of-experts), which is differentiable and therefore trades routing quality for balance.

## Multi-Token Prediction

The standard objective supervises one position per token. MTP adds a module that predicts the token at `t + 2` from the hidden state at `t`, giving every position two training signals instead of one.

```python
class MultiTokenPrediction(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.enorm = RMSNorm(cfg.hidden_size, cfg.rms_norm_eps)
        self.hnorm = RMSNorm(cfg.hidden_size, cfg.rms_norm_eps)
        self.eh_proj = nn.Linear(2 * cfg.hidden_size, cfg.hidden_size, bias=False)
        self.block = DeepSeekBlock(cfg, layer_idx=cfg.first_k_dense_replace)
        self.head = nn.Linear(cfg.hidden_size, cfg.vocab_size, bias=False)

    def forward(self, hidden, next_embed):
        # hidden: (B, T, 7168) at position t     next_embed: (B, T, 7168) for token t+1
        x = torch.cat([self.enorm(next_embed), self.hnorm(hidden)], dim=-1)   # (B, T, 14336)
        return self.head(self.block(self.eh_proj(x)))                         # (B, T, 129280)
```

`num_nextn_predict_layers = 1`, so there is one such module. The total loss is

```
L = L_next + lambda * L_MTP
```

At inference the same module drafts a token that the main model verifies in a single forward pass. Because the draft comes from the model itself rather than a separate smaller one, there is no second set of weights to load, and verification is exact, so the output distribution is unchanged. The speedup depends on the draft acceptance rate.

## Parameter count

Per layer, no biases except the correction bias:

| Component                  | Formula            | Parameters      |
| :------------------------- | :----------------- | :-------------- |
| `q_a`                      | `7168 * 1536`      | 11,010,048      |
| `q_b`                      | `1536 * 128 * 192` | 37,748,736      |
| `kv_a`                     | `7168 * 576`       | 4,128,768       |
| `k_b`                      | `512 * 128 * 128`  | 8,388,608       |
| `v_b`                      | `512 * 128 * 128`  | 8,388,608       |
| `o`                        | `16384 * 7168`     | 117,440,512     |
| Two latent norms           | `1536 + 512`       | 2,048           |
| **Attention total**        |                    | **187,107,328** |
| One expert                 | `3 * 7168 * 2048`  | 44,040,192      |
| 256 routed experts         | `256 * 44040192`   | 11,274,289,152  |
| Shared expert              | `44,040,192`       | 44,040,192      |
| Router                     | `7168 * 256`       | 1,835,008       |
| Dense FFN (first 3 layers) | `3 * 7168 * 18432` | 396,361,728     |

Rolling that up:

| Part                             | Parameters          |
| :------------------------------- | :------------------ |
| 58 MoE layers at 11,507,286,272  | 667,422,603,776     |
| 3 dense layers at 583,483,392    | 1,750,450,176       |
| Embedding and untied output head | 1,853,358,080       |
| **Total**                        | **671,026,412,032** |

That is 671B, which is the published figure. Counting only what one token touches — 8 routed experts plus the shared one per MoE layer, all three dense layers, and the embeddings — gives about 37.5B against the published 37B active.

Getting a from-scratch implementation to land on the published parameter count is the single best check that the architecture is right. If your total is off by a factor near 256, you built a dense model. If it is off by a factor near 8, you forgot the shared expert or the untied head.

## FP8 block quantization

`quantization_config` sets `quant_method: fp8`, `fmt: e4m3`, `activation_scheme: dynamic`, `weight_block_size: [128, 128]`.

Per-tensor FP8 uses one scale for the whole weight matrix, which is too coarse when a matrix contains both large-magnitude attention projections and small-magnitude expert slices. Block quantization keeps one scale per 128x128 tile. `e4m3` has four exponent bits and three mantissa bits, giving a narrower range but finer resolution than `e5m2`, which suits weights. Activations are quantized dynamically at runtime because their distribution shifts with the input.

This halves the weight footprint to about 671 GB and is what makes the model servable on a cluster rather than a warehouse.
