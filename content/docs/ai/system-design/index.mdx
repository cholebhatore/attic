Every earlier phase teaches one part of an AI product: how retrieval finds facts, how a GPU serves tokens, how an agent calls tools, how a pipeline versions and gates changes. This section puts the parts together. It asks what a product must do, how big it is, which parts it needs, what each part costs, and how each part fails, and it is the format most AI engineering interviews use to test whether you can build something real.

The section is built to grow. The fundamentals come first and are short on purpose; the interview framework compresses them into a sixty-minute structure; and the case studies apply that structure to concrete products, one design per page.

New to the section? Start with [AI System Design Basics](/ai/system-design/system-design-basics). It explains what changes when a system contains an LLM, the reference architecture, the five-step design process, a runnable napkin estimate, the core trade-offs, and the vocabulary. Every page after it opens with a **plain-language version**: where the page sits, a short explanation with an analogy, the page's topics in order, and a table of the words it uses.

<Callout type="info">
  ### The numbers are design inputs

Volumes, prices, and traffic splits throughout this section are assumptions a designer commits to out loud, then does arithmetic on. They are labelled as assumptions rather than measurements. The skill being taught is the arithmetic chain, not the figures; substitute your own traffic and the same structure holds.

</Callout>

## Prerequisites

The fundamentals pages assume nothing beyond basic web services. The framework and case studies lean on the rest of the curriculum:

- [RAG Basics](/ai/rag), [Hybrid Search](/ai/rag/hybrid-search), and [Reranking](/ai/rag/reranking) for the retrieval stages the case designs price and secure
- [Vector Databases](/ai/rag/vector-databases) for filtered ANN, the mechanism behind every access-control claim
- [Context Budgeting](/ai/rag/context-budgeting) for prompt structure, the same ordering that makes vendor prompt caching work
- [Prefill and Decode](/ai/inference/prefill-and-decode) and [Continuous Batching](/ai/inference/continuous-batching) for TTFT, inter-token latency, and KV-cache pressure
- [The Agent Loop](/ai/agents/agent-loop) for step and cost budgets, which the sandbox enforces at three layers
- [Function Calling](/ai/agents/function-calling) for schema-constrained output, the verification layer's cheapest check
- [Agent Security](/ai/agents/agent-security) for prompt injection, the threat that makes the coding sandbox necessary
- [Observability and Guardrails](/ai/agents/observability-guardrails) for traces and rail positions
- [MLOps Basics](/ai/mlops/mlops-basics), [CI/CD for AI Systems](/ai/mlops/ci-cd-for-llms), and [Production Telemetry and Cost Control](/ai/mlops/telemetry-and-cost) for release manifests, evaluation gates, and the cost figures the framework starts from

## What you should be able to do afterwards

- Explain what changes about system design when a component is an LLM, and draw the reference architecture from memory
- Ask the clarifying questions that change an LLM design, and turn every quality word into a metric
- Convert daily users into peak QPS, concurrency, tokens per minute, and monthly cost
- Convert an availability SLO into an error budget, and explain why a single-provider system cannot beat its provider's availability
- Explain why multi-turn chat cost grows quadratically, and name three fixes
- Compute when self-hosting beats a hosted API, including the effect of utilization
- Size a vector index and its HNSW graph from document count and dimensions
- Split an end-to-end latency target into a budget per step, and say which checks may block the stream
- Name every box in an LLM system, what it does inside, and how it fails
- Distinguish exact, semantic, prompt-prefix, and embedding caches
- Choose which errors to retry, and design backoff with jitter, a retry budget, and a total deadline
- Design a fallback ladder and a circuit breaker for a model provider
- Choose between synchronous, streaming, asynchronous, and batch delivery
- Pick the right autoscaling signal for orchestrators, workers, and GPU engines
- Walk the five-stage pipeline and state two failure modes and two mitigations for each, unprompted
- Route traffic across a model cascade and price it, then state the router-error cost honestly
- Decide between per-tenant indexes and a shared filtered index, and defend the choice at 400 tenants
- Explain pre-filter against post-filter retrieval, and why permission data must not be baked into vectors
- Do base-rate arithmetic that turns a 99 percent accurate classifier into more false positives than violations
- Sample video frames and place a multimodal adjudicator so the cost of the uncertain band stays bounded
- Choose between gVisor, Firecracker, and a container for arbitrary generated code, and justify the boundary
- Enumerate what a code-execution sandbox must never reach, including the link-local metadata address
- Explain how a coding agent games its own tests and what mount prevents it
- Distinguish deflection, containment, and resolution, and pick the right denominator for cost per resolved
- Write an escalation summary contract and explain its effect on human handle time
- Structure a prompt so a stable prefix earns the vendor cache, and name the ordering mistake that defeats it

## Canonical resources

- **Books and guides**
  - Chip Huyen, _AI Engineering: Building Applications with Foundation Models_ (O'Reilly, 2025) — the application-architecture chapters are the closest book-length treatment of this section
  - Alex Xu, _System Design Interview_ (volumes 1 and 2) — the classic estimation and building-block vocabulary this section extends
  - Made With ML, _ML Systems Design Interview Guide_ — the structure the four case studies follow
  - Anthropic Engineering, [_Building Effective Agents_](https://www.anthropic.com/research/building-effective-agents) — when a workflow beats an agent, which is a system design decision
  - Google, _Site Reliability Engineering_ — SLOs, error budgets, and load shedding, the source of the reliability vocabulary
- **Repositories**
  - [`BerriAI/litellm`](https://github.com/BerriAI/litellm) — an LLM gateway: one API over providers, with routing, retries, fallbacks, and spend tracking
  - [`vllm-project/vllm`](https://github.com/vllm-project/vllm) — the self-hosted serving engine most designs reach for
  - [`langfuse/langfuse`](https://github.com/langfuse/langfuse) — traces, evaluations, prompt management, and cost metrics
  - [`firecracker-microvm/firecracker`](https://github.com/firecracker-microvm/firecracker) — microVM isolation for untrusted code, the sandbox primitive
  - [`google/gvisor`](https://github.com/google/gvisor) — user-space kernel container sandbox
  - [`kata-containers/kata-containers`](https://github.com/kata-containers/kata-containers) — VM isolation behind a container interface
- **Videos**
  - Outcome School video masterclass: _AI Engineering Explained: LLM, RAG, MCP, Agent, Fine-Tuning, Quantization_
