---
title: 'System Design: Content Moderation'
description: 'Real-time multimodal moderation: tiered detectors, base-rate arithmetic, frame sampling, queue prioritization, reviewer load, and adversarial drift.'
---

Design prompt. A social platform publishes 500 million posts a day across text, images, short video, and audio. Design the pipeline that decides, before or shortly after publication, whether each one violates policy. Automated action for the obvious cases, human review for the rest, and an appeal path that can reverse a wrong decision.

This is a throughput and calibration problem wearing an ML costume. The interesting parts are base rates, queue prioritization, and the cost of a false positive, which is the opposite of the trade-off in most LLM system designs.

---

## Assumptions to commit to

| Question                    | Assumption                                                                            |
| :-------------------------- | :------------------------------------------------------------------------------------ |
| Volume                      | 500M posts a day, 60 percent text, 30 percent image, 8 percent video, 2 percent audio |
| Publish model               | Publish-then-review for most categories, block-then-review for the severe ones        |
| Violation base rate         | About 0.5 percent overall, far lower per category                                     |
| Latency targets             | Text under 500 ms, image under 2 s, video under 30 s                                  |
| Categories                  | Sexual, violence, hate, harassment, self-harm, spam, CSAM, real-world harm            |
| Can a user appeal?          | Yes, and the reversal rate is a first-class metric                                    |
| Who pays for a false block? | The user's reach and the platform's credibility                                       |
| Legal obligations?          | Yes, severe categories require reporting, not just removal                            |

The severe-category row is not an ML decision. CSAM and imminent-harm content go to a dedicated path with its own access controls, its own audit log, and mandatory external reporting. Design it first and mention it first; it is the answer that shows operational maturity.

## Scale arithmetic

| Quantity                    | Derivation                             | Value                        |
| :-------------------------- | :------------------------------------- | :--------------------------- |
| Average posts per second    | 500M divided by 86,400                 | about 5,800                  |
| Peak, factor 3              | Diurnal spike                          | about 17,400                 |
| Images to score per second  | 30 percent of 5,800                    | about 1,750                  |
| GPUs for a batched detector | 1,750 at 500 images per second per GPU | about 4, plus headroom to 12 |
| Violating posts per day     | 0.5 percent of 500M                    | 2.5 million                  |
| Non-violating posts         | The rest                               | 497.5 million                |

Then the arithmetic that defines the design.

```text
a single classifier with 99 percent sensitivity and 99 percent specificity
  true positives   0.99 * 2,500,000      = 2,475,000
  false positives  0.01 * 497,500,000    = 4,975,000
  review queue      7,450,000 items a day

one reviewer clears about 8,000 items a day
  7,450,000 / 8,000 = 931 reviewers, working every day, on everything
```

A model that is 99 percent accurate on both axes produces more false positives than real violations at this base rate. That is not a failure of the model; it is arithmetic, and it is why moderation systems are tiered, why the auto-block threshold sits far out in the tail, and why the metric quoted in a design review is precision at a fixed recall, never accuracy.

| Tier                     | Population it acts on            | Purpose                                    |
| :----------------------- | :------------------------------- | :----------------------------------------- |
| Exact and hash match     | Known-bad content, evasions      | Free, instant, highest precision available |
| Cheap specialized models | Everything                       | Recall, and a confidence band to route on  |
| Expensive adjudicator    | The uncertain 0.1-1 percent      | Precision where the cheap model was unsure |
| Human review             | Auto-block low band, and reports | Judgment, calibration data, appeals        |

| Component     | Contract                                                                    |
| :------------ | :-------------------------------------------------------------------------- |
| Queue         | Partition by content type, separate topics for severe categories            |
| Tier 0        | Milliseconds, no GPU; hashes, blocklists, known-evasion patterns            |
| Tier 1        | Independent detectors, each emits a score plus a version id                 |
| Fusion        | Calibrated combination, per-category thresholds, account history as a prior |
| Tier 2        | Runs only on the band, with a per-item budget and a timeout                 |
| Action engine | Policy table mapping score to remove, limit reach, label, or review         |
| Review        | Prioritized by severity times confidence times predicted reach              |
| Appeals       | Reversal writes a labeled example back into calibration                     |

Detectors run in parallel and their outputs are combined with a calibrated fusion step, because a single per-detector threshold applied independently multiplies false-positive rates across categories. The fusion layer is where the base rate enters as a prior: the same image score means something different for a five-day-old account with a prior strike than for an established one.

## Multimodal specifics

Video is where the budget goes, and the fix is not a better model.

```text
60 second clip
  shot detection            cut points, usually under 20 for a clip
  all shots                 cheap detectors on 1 keyframe per shot
  sampled                   8 frames per clip for the vision classifier
  flagged only              OCR and ASR on the audio track
  uncertain band only       multimodal LLM on the 4 frames with the highest scores
```

| Choice                          | Why                                                     | Cost effect                            |
| :------------------------------ | :------------------------------------------------------ | :------------------------------------- |
| Keyframes over every frame      | A 60-second clip at 30 fps is 1,800 frames              | 100x fewer detector calls              |
| ASR before text models          | Speech-to-text is cheap, text classification is cheaper | Avoids audio-capable models everywhere |
| OCR then the text classifier    | Text-in-image is where a lot of policy lives            | One shared path for all modalities     |
| LLM only on the band            | The band is 0.1-1 percent of items                      | Keeps adjudication affordable          |
| Frames chosen by detector score | Spread evidence, not uniform sampling                   | Better recall per call                 |

Cross-modal context changes the verdict, so the adjudicator receives all of it at once: an image of a medical procedure, the caption, the ASR transcript, and the account's history. Running per-modality decisions independently and ANDing them is how a system blocks a breastfeeding support post because the image model saw skin.

The tier-2 band is the number to control and quote. At 1 percent of 500M items that is 5 million adjudications a day; at 0.1 percent it is 500,000. If an adjudication costs on the order of a fifth of a cent, the difference is 10,000 versus 1,000 a day. Tightening the cheap detectors' calibration shrinks the band, which is why tier-1 calibration is the highest-leverage work on this system.

## Latency versus review depth

| Mode                    | Latency      | User experience                   | When it is right                                                           |
| :---------------------- | :----------- | :-------------------------------- | :------------------------------------------------------------------------- |
| Pre-publish block       | Under 500 ms | Content never appears             | Severe categories, repeat offenders                                        |
| Publish then review     | Seconds      | Visible for minutes               | The bulk of traffic, where a false block is worse than a delayed removal   |
| Publish then un-publish | Milliseconds | Always visible, sometimes briefly | High-reach accounts where speed matters and risk is low                    |
| Reach limiting          | Milliseconds | Visible, not distributed          | The gray zone, where removal is not justified but distribution is not free |

Reach limiting is the underused answer in this design. It converts a binary block-versus-allow decision into a continuous one, which is exactly what a 0.5 percent base rate with uncertain labels needs. Say it before the interviewer does.

## Prioritization, appeals, and reviewers

The review queue is a scheduling problem, and the priority function is the interesting part.

```text
priority = severity_weight * confidence * log(1 + predicted_reach) * age_soon
```

Reach matters more than recency for harm: a post that will be seen by a million people in an hour should be reviewed before a week-old one that will be seen by no one. Predicted reach comes from a small early-engagement model, which is a second ML system inside the first, and it is worth naming explicitly.

| Concern           | Design answer                                                                 |
| :---------------- | :---------------------------------------------------------------------------- |
| Reviewer exposure | Blurring by default, progressive reveal, category opt-in, mandatory breaks    |
| Consistency       | Paired labels for inter-annotator agreement, per-category calibration sets    |
| Throughput        | Batch similar items, keyboard-first triage, no page reloads                   |
| Reversal learning | Every appeal outcome becomes a labeled example with provenance                |
| Backlog           | Age alarms, and a documented degradation policy under overload                |
| Language coverage | Detectors and reviewers per language, or you moderate 10 percent of the world |

The appeal path is a measurement instrument as much as a product feature. A rising reversal rate on auto-blocks is a calibration alarm that fires before users file complaints, and it is the metric to put on the dashboard next to miss rate.

## Evaluation

| Metric                           | Definition                                                 | Why it is the right one                   |
| :------------------------------- | :--------------------------------------------------------- | :---------------------------------------- |
| Precision at the auto-block band | Of auto-blocked items, the share correctly blocked         | False blocks are the expensive error      |
| Proactive detection rate         | Violations removed before any user report                  | Measures the system, not the crowd        |
| Escaped-violation rate           | Violations that reached publication and were never removed | The number the trust and safety team owns |
| Time to action, by category      | Median and p99 from submission to decision                 | Harm is time-sensitive                    |
| Reversal rate on appeals         | Share of blocks overturned                                 | Calibration drift detector                |
| Reviewer agreement               | Cohen or Kappa on paired labels                            | Policy is ambiguous, measure it           |
| Cost per 1,000 items scored      | Full pipeline cost divided by throughput                   | Keeps tiering honest                      |

Two traps. Aggregate accuracy is meaningless at a 0.5 percent base rate, so report per category and at fixed recall. And a static holdout decays fast, because the population is adversarial: the distribution of violating content changes weekly in response to your own filters. Holdout sets must be re-drawn continuously from live traffic, and the eval report should show the age of its own data.

**Adversarial drift** here is not concept drift by accident, it is concept drift by design. Leet speak, homoglyphs, sticker overlays on text, cropped and rotated images, frame-rate tricks in video. Mitigations are structural: hash and embedding similarity instead of exact strings, OCR before text matching, a feedback path from evasion cases into tier-0, and rate-limiting on the account graph rather than on the content alone.

## Failure modes

| Symptom                                   | Cause                                      | Fix                                                    |
| :---------------------------------------- | :----------------------------------------- | :----------------------------------------------------- |
| Queue explodes, accuracy unchanged        | Base-rate arithmetic, thresholds too loose | Raise specificity in tier 1, tighten the band          |
| Safe content blocked after a model update | Uncalibrated scores across versions        | Per-version calibration, shadow mode before any action |
| Moderation works in English only          | Detectors trained on one language          | Per-language coverage measured as a first-class metric |
| Video misses lag by hours                 | Backlog starved by image and text traffic  | Separate topics and quotas per modality                |
| Evasion waves every fortnight             | Static string rules, no provenance loop    | Embedding similarity plus an evasion case pipeline     |
| Appeals backlogged                        | Reversal path shares the review queue      | Dedicated appeal lane with its own SLA                 |
| One account floods the pipeline           | No per-account rate limit                  | Cost-aware admission control, drop lowest-risk tiers   |
| Reviewer error spikes late in shift       | Exposure fatigue                           | Blurring, rotation, and enforced breaks                |
| Legal report missed                       | Severe path shares the general queue       | Hard-segregated topic with its own alerting            |
| Two teams ship conflicting thresholds     | Thresholds live in code                    | Policy table in a config store, versioned and diffable |

## Interview questions

<Accordions>
  <Accordion title="1. 500 million posts a day at a 0.5 percent violation rate, with a classifier at 99 percent sensitivity and 99 percent specificity. What does the review queue look like?">

    2.5 million violations give about 2.48 million true positives, and 497.5 million clean posts give about 4.98 million false positives, so 7.45 million items a day, which is roughly 931 full-time reviewers.

  </Accordion>
  <Accordion title="2. What does that arithmetic prove about the architecture?">

    That a single accurate classifier cannot be the system. Tiering exists to raise effective specificity before anything reaches a human, and thresholds sit far out in the tail for that reason.

  </Accordion>
  <Accordion title="3. Which metric do you report instead of accuracy, and at what fixed condition?">

    Precision at the auto-block band, reported per category at fixed recall, because a false block costs reach and credibility while a miss costs harm.

  </Accordion>
  <Accordion title="4. What is the first thing to design in a moderation prompt?">

    The severe-category path: segregated queue, its own access controls and audit log, and mandatory external reporting. It is a legal obligation, not a model threshold.

  </Accordion>
  <Accordion title="5. Why sample keyframes instead of scoring every frame of a video?">

    A 60-second clip at 30 fps is 1,800 frames. Shot detection plus one keyframe per shot cuts detector calls by two orders of magnitude with little recall loss, since violation content is visible in a single frame.

  </Accordion>
  <Accordion title="6. Where does a multimodal LLM go in this pipeline, and what controls its cost?">

    Only in the uncertain band. The band percentage is the cost knob: 1 percent of 500M is 5M adjudications a day, 0.1 percent is 500,000, and shrinking the band is tier-1 calibration work.

  </Accordion>
  <Accordion title="7. Give two examples where per-modality decisions produce a wrong verdict.">

    Text in an image that only OCR reveals, and an image that is policy-violating out of context but not in it. Both need fused, simultaneous context rather than independent ANDed thresholds.

  </Accordion>
  <Accordion title="8. What is reach limiting and why does this design need it?">

    Reducing distribution without removing content. At a 0.5 percent base rate with ambiguous labels it converts a binary decision into a continuous one, which is the correct shape for the uncertainty.

  </Accordion>
  <Accordion title="9. How do you prioritize a review queue that can never be drained?">

    Severity weighted by confidence times the log of predicted reach, with an age term. Predicted reach comes from a small early-engagement model, and it beats pure FIFO because harm scales with audience.

  </Accordion>
  <Accordion title="10. What is the cheapest drift alarm on this system?">

    The appeal reversal rate on auto-blocks. It rises before users file broad complaints and it is free, since appeals happen anyway.

  </Accordion>
  <Accordion title="11. How does adversarial drift here differ from ordinary concept drift?">

    It is intentional and reactive: evasion in leet speak, homoglyphs, sticker overlays, cropped images. Exact-match and string rules decay fastest, so similarity search plus an evasion feedback path is required.

  </Accordion>
  <Accordion title="12. What happens to a moderation eval set after two years?">

    It becomes obsolete, because the violating population moved in response to your filters. Re-draw from live traffic continuously and report the age of the eval data.

  </Accordion>
  <Accordion title="13. Why do detector outputs need a fusion and calibration layer rather than independent thresholds?">

    Independent thresholds multiply false-positive rates across categories, and only a shared calibrated scale lets account history act as a prior.

  </Accordion>
  <Accordion title="14. What changes in the design if the platform moves to block-then-review for everything?">

    Latency becomes the binding constraint, so you pay for synchronous inference on the whole stream, and false blocks become user-visible incidents instead of queue items.

  </Accordion>
</Accordions>
