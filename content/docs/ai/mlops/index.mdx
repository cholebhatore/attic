Phases 9 through 11 make the answer good. This phase makes it shippable, measurable, and affordable, and it is where most interview candidates discover that knowing architecture is not the same as knowing what breaks at 3 a.m. It covers both halves of the discipline: MLOps for the pipelines that produce models, and LLMOps for the prompt, retrieval, and trace machinery that produces answers.

The work is a pipeline: version the inputs, run the model on hardware someone else scheduled, gate every change against a golden set, and watch cost, latency, quality, and drift in production. Designing the product around that pipeline (requirements, building blocks, reliability, and the interview framework with its case studies) has its own section, [AI System Design](/ai/system-design), which reads naturally after this one.

New to this phase? Start with [MLOps Basics](/ai/mlops/mlops-basics). It explains MLOps and LLMOps, the lifecycle from data to monitoring and back, what must be versioned together, environments and promotion, evaluation-gated CI/CD and safe rollouts, the four production signals, and a cost-per-request calculation with caching. Every page after it also opens with a **plain-language version**: where the page sits, a short explanation with an analogy, the page's topics in order, and a table of the words it uses.

## Prerequisites

- [Function Calling](/ai/agents/function-calling) for schema-constrained output, the verification layer's cheapest check
- [Model Context Protocol](/ai/agents/mcp) for tool boundaries, which is where shadow traffic must stop executing
- [Evaluation Metrics and Benchmarks](/ai/agents/eval-metrics) for the reference metrics a golden-set gate reports
- [Human and Judge Evaluation](/ai/agents/judge-and-human-eval) for judge variance, which sets the tolerance on every regression gate
- [RAG and Agent Evaluation](/ai/agents/rag-and-agent-eval) for retrieval metrics, run as a gate rather than a report
- [Observability and Guardrails](/ai/agents/observability-guardrails) for traces and rail positions, which telemetry extends with cost and drift
- [Context Budgeting](/ai/rag/context-budgeting) for prompt structure, the same ordering that makes vendor prompt caching work
- [Production Debugging](/ai/rag/production-debugging) for trace-driven diagnosis, the input to the dataset loop
- [Prefill and Decode](/ai/inference/prefill-and-decode) for TTFT and inter-token latency, defined here as service-level objectives
- [Continuous Batching](/ai/inference/continuous-batching) for KV block pressure, the saturation signal worth alerting on
- [Quantization Math](/ai/inference/quantization-math) for the int8 vector and weight sizes used in storage arithmetic
- [Serving Engines Compared](/ai/inference/serving-engines) for the engine metrics that populate a GPU dashboard
- [Merging and Deployment](/ai/fine-tuning/merging-and-deployment) for where a fine-tuned adapter enters a registry
- [Data Preparation](/ai/fine-tuning/data-preparation) for corpus hygiene, which is what DVC is versioning

Nothing here requires a GPU or a cluster. Two pages, containers and telemetry, assume you have seen a `Dockerfile` and a `kubectl get pods`.

## What you should be able to do afterwards

- Explain in plain words what MLOps and LLMOps add on top of a working model, list what must be versioned together, and compute cost per request with and without caching
- List the ten fields a reproducible run record must contain, and name the two most often missing
- Use W&B artifacts to query the blast radius of a poisoned dataset version
- Explain why MLflow deprecated registry stages in favor of aliases
- Size a sweep before starting it, and say why random search beats grid in five dimensions
- Write a `dvc.yaml` stage with dependencies, parameters, outputs, and metrics, and predict what `dvc repro` reruns
- Explain why an embedding-model change invalidates every similarity threshold you tuned
- Name the six components of a prompt program, and why versioning only the string is incomplete
- Build a multi-stage CUDA Dockerfile, and explain what the stage boundary removes
- Describe how a container runs CUDA with no `nvidia/cuda` base image, and what breaks when `nvcc` is needed
- Distinguish MIG, time-slicing, and DRA on isolation, sharing, and failure mode
- Explain why `nvidia-smi` utilization is not a saturation measure, and which four counters are
- Compute cold-start time from weight size and source bandwidth, and name four mitigations with their costs
- State when serverless inference beats a dedicated GPU, in duty-cycle terms
- Design a pull-request gate with four checks, and derive its tolerance from measured judge variance
- Compute the sample size for an A/B on a proportion metric, and say why halving the effect quadruples the time
- Explain what a shadow deployment can and cannot measure, and why side effects must stop at the tool boundary
- Derive inter-token latency from TTFT, E2E, and output length, and give the tokens-per-second equivalent
- Decompose a request's API cost into cached input, uncached input, and output terms
- Show the arithmetic behind "prompt caching plus a semantic cache cuts spend by 70 percent"
- Separate data drift from concept drift, and name a detector and a false alarm for each
- Convert an SLO into an error budget, and alert on burn rate rather than on a raw metric

## Canonical resources

- **Repositories**
  - [`GokuMohandas/Made-With-ML`](https://github.com/GokuMohandas/Made-With-ML) — end-to-end MLOps from design through deployment and monitoring, the clearest written pipeline in this space
  - [`langfuse/langfuse`](https://github.com/langfuse/langfuse) — open-source LLM engineering platform: traces, evals, prompt management, cost metrics
  - [`treeverse/dvc`](https://github.com/treeverse/dvc) — dataset and model versioning with content-addressed storage and pipeline stages, formerly Iterative DVC
  - [`wandb/wandb`](https://github.com/wandb/wandb) — experiment tracking, artifacts, sweeps
  - [`mlflow/mlflow`](https://github.com/mlflow/mlflow) — self-hosted tracking, Model Registry with aliases
  - [`NVIDIA/k8s-device-plugin`](https://github.com/NVIDIA/k8s-device-plugin) — GPU advertisement, MIG and time-slicing configuration
  - [`NVIDIA/gpu-operator`](https://github.com/NVIDIA/gpu-operator) — the driver, plugin, DCGM exporter, and MIG stack as one Helm install
  - [`NVIDIA/DCGM`](https://github.com/NVIDIA/DCGM) — the profiling counters behind every honest GPU dashboard
  - [`volcano-sh/volcano`](https://github.com/volcano-sh/volcano) and [`kubernetes-sigs/kueue`](https://github.com/kubernetes-sigs/kueue) — gang scheduling and queueing for accelerator workloads
  - [`coreweave/tensorizer`](https://github.com/coreweave/tensorizer) — streaming tensor serialization for fast model loading
  - [`vllm-project/vllm`](https://github.com/vllm-project/vllm) — the engine whose Prometheus metrics the telemetry page alerts on
  - [`zilliztech/GPTCache`](https://github.com/zilliztech/GPTCache) — semantic response caching with pluggable embedding stores
  - [`promptfoo/promptfoo`](https://github.com/promptfoo/promptfoo) — prompt and RAG assertion suites that run in CI
- **Books and guides**
  - Chip Huyen, _AI Engineering: Building Applications with Foundation Models_ (O'Reilly, 2025) — the production-lifecycle chapters map to this phase almost one to one
  - Chip Huyen, _Designing Machine Learning Systems_ (O'Reilly, 2022) — deployment patterns, monitoring, and the pipeline the classic-MLOps pages assume
  - Kubernetes documentation, _Dynamic Resource Allocation_ and _GPU scheduling_ — the resource model, DRA semantics, and device plugins
  - NVIDIA Container Toolkit documentation — driver, runtime, and `NVIDIA_VISIBLE_DEVICES` behavior
- **Videos**
  - Outcome School video masterclass: _AI Engineering Explained: LLM, RAG, MCP, Agent, Fine-Tuning, Quantization_
