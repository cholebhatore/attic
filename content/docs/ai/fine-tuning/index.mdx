Phase 6 ended with three frontier architectures written out in full and parameter counts that matched their published numbers. Those models arrive as base checkpoints: they predict the next token well and they do not follow instructions. Turning one into something that answers a question in a fixed format, writes correct SQL against your schema, or runs in 40 ms is what this phase covers.

The phase splits in two. The first half decides whether to fine-tune at all, and then how: which lever in the prompting-retrieval-fine-tuning-distillation ladder, which library owns which job, and what the data has to look like. The second half is the mechanics, ending with a merged model behind a serving engine.

New to fine-tuning? Start with [Fine-Tuning Basics](/ai/fine-tuning/fine-tuning-basics). It explains how fine-tuning differs from pretraining, when to use it instead of prompting or RAG, full versus parameter-efficient fine-tuning, the memory arithmetic for full fine-tuning, LoRA, and QLoRA, a LoRA update in NumPy, the workflow, and the tech stack. Every page after it also opens with a **plain-language version**: where the page sits, a short explanation with an analogy, the page's topics in order, and a table of the words it uses.

<Callout type="info">
  ### Every count here is arithmetic you can redo

The LoRA parameter counts, the prefix-tuning totals with the grouped-query correction, and the 16-bytes-per-parameter AdamW budget are all derived on the page from a published `config.json`. Where a number comes from a paper, the arXiv id is next to it. Where a figure would depend on hardware you have not measured, it is given as a range rather than a measurement.

</Callout>

## Prerequisites

- [GPT from Scratch](/ai/transformers/gpt-from-scratch) for the training loop, cross-entropy masking and weight tying that every fine-tune modifies
- [Blocks and Positions](/ai/transformers/blocks-and-positions) for the projection matrices LoRA attaches to
- [What is an LLM](/ai/llm/what-is-an-llm) for the memory-footprint arithmetic that QLoRA and the ZeRO stages build on
- [Tokenization](/ai/llm/tokenization) for why the tokenizer must match between teacher and student, and between training and serving
- [Attention Variants](/ai/llm/attention-variants) for grouped-query attention, which changes the prefix-tuning parameter count
- [Decoding Strategies](/ai/llm/decoding) for temperature, which reappears as the distillation temperature
- [Inference Lifecycle](/ai/llm/inference-lifecycle) for the KV cache that serving engines page and that FlashAttention reshapes
- [Training Loop](/ai/pytorch/training-loop) for optimizers, schedulers and checkpointing in plain PyTorch
- [Devices and Precision](/ai/pytorch/devices-and-precision) for BF16 against FP16 and the loss-scaling argument
- [Schedule and Optimizer](/ai/neural-networks/schedule-and-optimizer) for warmup, cosine decay and Adam's moment estimates
- [Information Theory and Loss](/ai/math-foundations/information-the-and-loss) for KL divergence, which is the distillation objective

No new packages beyond `transformers`, `datasets`, `accelerate`, `peft` and `trl`, none of which require a local GPU to read.

## What you should be able to do afterwards

- Explain in plain words what fine-tuning changes, how it differs from pretraining, and why LoRA and QLoRA fit on small GPUs
- Decide between prompting, retrieval, constrained decoding, fine-tuning and distillation for a stated task, and say what evidence would change the answer
- List the four things fine-tuning changes reliably and the two it does not
- Name what each of `transformers`, `datasets`, `accelerate`, `peft`, `trl` and `unsloth` owns and where their boundaries are
- Write an instruction dataset with the right loss mask, and explain why masking the prompt matters
- Derive the LoRA parameter count for a given rank, target module set and config
- Explain NF4, double quantization and paged optimizers, and compute the memory they save
- Compute trainable parameters for prompt tuning and prefix tuning, including the grouped-query correction
- Write the distillation loss, justify the `T^2` factor, and choose between forward and reverse KL
- Budget memory per parameter for full fine-tuning, LoRA and QLoRA, and name what each ZeRO stage shards
- Read a loss curve and map each failure shape to a cause
- Scope an eval set before training, and build a regression suite that gates a release
- Merge an adapter, export it, and pick a serving engine for a stated latency and tenancy requirement
