A Seq2Seq model compresses its whole input into one vector. Attention removes the compression: the decoder keeps every encoder state and decides, at each step, how much of each one to read. Once that decision is a differentiable weighted average rather than something a recurrent state has to carry, the recurrence stops being necessary.

---

## The plain-language version

**Where this sits:** the first piece of the transformer. [Transformer Basics](/ai/transformers/transformer-basics) shows where attention sits in the whole model; this page opens it up.

Attention lets every token in a sentence look at every other token and pull in the information it needs. To understand "it" in "the animal was tired, so it slept", the model needs to find "animal". Attention does that by comparison: each token asks a question, every token offers a label, and the token reads most from the ones whose labels best match its question.

Think of searching a library catalogue. Your **query** is what you type. Each book has a **key**, the label on its spine. You compare your query with every key, and you read most from the books that match best; what you read is each book's **value**, its contents. Attention is that search, done by every token at once, with the comparison done by dot products and the "read most from the best matches" done by softmax.

This page covers, in order:

1. **Query, key, and value**: the three projections of each token, and why keys and values are separate
2. **The scaled dot-product formula**: `softmax(Q K^T / sqrt(d_k)) V`, with self-attention written from scratch
3. **Why divide by sqrt(d_k)**: the variance argument, and why saturated softmax stops learning
4. **Cross-attention versus self-attention**: reading another sequence versus reading your own
5. **Cost and where it goes**: why attention is quadratic in sequence length

| Word                                 | Plain meaning                                                                                                                       |
| :----------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------- |
| **query (Q)**                        | A vector saying what a token is looking for. Made by multiplying the token's vector by a learned matrix `W_Q`.                      |
| **key (K)**                          | A vector advertising what a token contains, compared against queries. Made with `W_K`.                                              |
| **value (V)**                        | The information a token hands over when it is attended to. Made with `W_V`.                                                         |
| **projection**                       | Multiplying by a learned matrix to turn a vector into a new vector of a chosen size.                                                |
| **dot product / score**              | How well a query matches a key: multiply matching entries and add. Bigger means a better match.                                     |
| **softmax**                          | Turns a row of scores into positive weights that add to 1. [Softmax and Logits](/ai/math-foundations/softmax-and-logits) covers it. |
| **attention weights**                | The softmax output: how much each token reads from each other token.                                                                |
| **`d_k`**                            | The length of the query and key vectors.                                                                                            |
| **scaling factor**                   | The `1 / sqrt(d_k)` that keeps scores from growing with `d_k` and saturating the softmax.                                           |
| **saturation**                       | Softmax putting nearly all weight on one item, where its gradient is almost zero, so learning stalls.                               |
| **self-attention / cross-attention** | Queries, keys, and values from the same sequence, or queries from one sequence and keys and values from another.                    |
| **quadratic cost**                   | Every token compares with every token, so doubling the length quadruples the work.                                                  |

## Query, key, and value

Attention is a soft dictionary lookup. A hard lookup hashes a key and returns exactly one value. Attention scores a query against every key and returns a weighted blend of all the values.

| Projection | Role in the analogy                      | Question it answers                    |
| :--------- | :--------------------------------------- | :------------------------------------- |
| Query `Q`  | What I am looking for                    | What does position `i` need right now? |
| Key `K`    | What each entry advertises itself as     | What does position `j` offer?          |
| Value `V`  | What each entry hands over once selected | If I read position `j`, what do I get? |

All three come from the same input, through three separate learned matrices:

```text
Q = X W_Q      K = X W_K      V = X W_V
```

The geometric reading: `W_Q` and `W_K` map tokens into a space where the dot product measures relevance. That dot product is a cosine similarity scaled by both magnitudes, which is why [Similarity and Norms](/ai/math-foundations/similarity-and-norms) matters here. `W_V` maps into a different space, because what makes two tokens relevant to each other is not the same as what information should be passed between them.

Separating key from value is what makes attention more expressive than a plain similarity lookup. In a one-hot bag-of-words model, `K` and `V` would be the same object and attention would reduce to averaging similar tokens.

## The scaled dot-product formula

```text
Attention(Q, K, V) = softmax( Q K^T / sqrt(d_k) ) V
```

Shapes, for a batch of `B` sequences of length `T` with model width `d_model` and head width `d_k`:

| Tensor         | Shape             | Comes from                           |
| :------------- | :---------------- | :----------------------------------- |
| `X`            | `(B, T, d_model)` | Token embeddings plus positions      |
| `W_Q`          | `(d_model, d_k)`  | Learned                              |
| `Q`            | `(B, T, d_k)`     | `X @ W_Q`                            |
| `Q K^T`        | `(B, T, T)`       | Every query scored against every key |
| `softmax(...)` | `(B, T, T)`       | Attention weights, rows sum to 1     |
| Output         | `(B, T, d_k)`     | Weighted sum of values               |

The `T x T` matrix is the cost. Compute is `O(B T^2 d_k)` and the weight matrix alone is `B T^2` floats per head.

### Self-attention from scratch

```python title="attention.py"
import math

import torch
import torch.nn as nn

def attention(q, k, v, mask=None):
    # q, k: (B, T, d_k)   v: (B, T, d_v)
    scores = q @ k.transpose(-2, -1) / math.sqrt(q.shape[-1])   # (B, T, T)
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float("-inf"))
    return scores.softmax(dim=-1) @ v                            # (B, T, d_v)


class SelfAttention(nn.Module):
    def __init__(self, d_model: int, d_k: int) -> None:
        super().__init__()
        self.wq = nn.Linear(d_model, d_k, bias=False)
        self.wk = nn.Linear(d_model, d_k, bias=False)
        self.wv = nn.Linear(d_model, d_k, bias=False)

    def forward(self, x, mask=None):
        q, k, v = self.wq(x), self.wk(x), self.wv(x)
        return attention(q, k, v, mask)
```

`k.transpose(-2, -1)` swaps the last two axes only, so a `(B, T, d_k)` tensor becomes `(B, d_k, T)` and the batched matmul produces `(B, T, T)`. Using `.T` here would fail, because it reverses all dimensions.

The same computation in `einsum`, which names the axes instead of relying on position:

```python
import math

import torch

scale = 1.0 / math.sqrt(q.shape[-1])                        # q, k, v as passed to attention()
scores = torch.einsum("bqd,bkd->bqk", q, k) * scale         # (B, T_q, T_k)
out = torch.einsum("bqk,bkd->bqd", scores.softmax(-1), v)   # (B, T_q, d_v)
```

## Why divide by sqrt(d_k)

Assume the components of `q` and `k` are independent with mean `0` and variance `1`. The dot product is a sum of `d_k` products:

```text
q . k = sum over i=1..d_k of q_i * k_i

E[q_i * k_i]     = E[q_i] * E[k_i] = 0
Var[q_i * k_i]   = Var[q_i] * Var[k_i] = 1
Var[q . k]       = d_k          (sum of d_k independent unit-variance terms)
std[q . k]       = sqrt(d_k)
```

So the logits entering softmax have standard deviation `sqrt(d_k)`, which grows with the head width. Dividing by `sqrt(d_k)` puts them back at unit variance. The scale factor is a variance normalizer, not a tuning knob.

At `d_k = 64` the unscaled logits have standard deviation `8`; at `d_k = 512`, `22.6`. Scaling by `1 / sqrt(d_k)` brings both back to `1`.

| Head width `d_k` | std of `q . k`, unscaled | std after scaling |
| ---------------: | -----------------------: | ----------------: |
|               64 |                    `8.0` |             `1.0` |
|              256 |                   `16.0` |             `1.0` |
|              512 |                   `22.6` |             `1.0` |

What matters is the ratio this creates inside the softmax. A logit gap of `g` becomes a weight ratio of `exp(g)`. With unit-variance logits, a one-standard-deviation gap between the top logit and a competitor is a factor of `e^1 = 2.7`. With `d_k = 64` unscaled, the same one-standard-deviation gap is `8` logits, a factor of `e^8 = 2981`. The row collapses onto its maximum and every other position stops contributing.

### Why saturation kills learning

The Jacobian of softmax is `dp_i / dz_j = p_i (delta_ij - p_j)`. Its diagonal terms are `p_i (1 - p_i)`, which peak at `0.25` when `p_i = 0.5` and go to zero at both ends.

| Top weight `p` | `p (1 - p)` | Gradient scale relative to `p = 0.5` |
| -------------: | ----------: | -----------------------------------: |
|         `0.50` |     `0.250` |                                 `1x` |
|         `0.90` |     `0.090` |                              `0.36x` |
|         `0.99` |    `0.0099` |                              `0.04x` |
|        `0.999` |  `0.000999` |                             `0.004x` |

At `p = 0.999` the gradient is 250 times smaller than at `p = 0.5`. In float16, where the smallest normal value is around `6e-5`, gradients that small underflow to zero. The attention weights stop being learnable and the layer becomes a fixed lookup.

<Callout type="info">
  ### Why `sqrt(d_k)` and not `d_k`

Dividing by `d_k` would make the logit variance `1 / d_k`, shrinking towards zero as the head widens. All logits would become nearly equal, softmax would approach a uniform average, and the layer would lose the ability to select. Dividing by the standard deviation is the unique choice that holds logit variance at `1` regardless of `d_k`.

</Callout>

The variance assumption is not exactly true of a trained network, which is why some architectures add a learned temperature on top of the fixed `1 / sqrt(d_k)`. QK-Norm, used in Qwen 3 and covered in [Phase 6](/ai/llm), normalizes `q` and `k` with RMSNorm before the dot product so the variance holds by construction rather than by assumption.

## Cross-attention versus self-attention

The computation is identical. The only difference is where `Q`, `K`, and `V` come from.

| Variant               | `Q` from          | `K`, `V` from                | Where it appears                         |
| :-------------------- | :---------------- | :--------------------------- | :--------------------------------------- |
| Self-attention        | The same sequence | The same sequence            | Every encoder layer, every decoder layer |
| Cross-attention       | The decoder       | The encoder output           | The middle sublayer of a decoder block   |
| Masked self-attention | The decoder       | The decoder, causally masked | Decoder self-attention                   |

```python title="cross_attention.py"
import torch.nn as nn

class CrossAttention(nn.Module):
    def __init__(self, d_model: int, d_k: int) -> None:
        super().__init__()
        self.wq = nn.Linear(d_model, d_k, bias=False)   # reads the decoder
        self.wk = nn.Linear(d_model, d_k, bias=False)   # reads the encoder
        self.wv = nn.Linear(d_model, d_k, bias=False)   # reads the encoder

    def forward(self, decoder_x, encoder_out):
        q = self.wq(decoder_x)          # (B, T_dec, d_k)
        k = self.wk(encoder_out)        # (B, T_enc, d_k)
        v = self.wv(encoder_out)        # (B, T_enc, d_k)
        return attention(q, k, v)       # (B, T_dec, d_k); attention() is from above
```

Note the output shape. Cross-attention produces one vector per `decoder` position, but the attention matrix is `(T_dec, T_enc)`, so the two sequence lengths need not match. That is what makes translation between languages of different lengths work.

A decoder block therefore has three weight sets: self-attention, cross-attention, and the feed-forward network. With `d_ff = 4 d_model`, an encoder block is `4 d^2` of attention plus `8 d^2` of feed-forward, and a decoder block adds another `4 d^2` for cross-attention. Dropping cross-attention removes about a fifth of the parameters per block, which is one reason encoder-only and decoder-only models are cheaper per layer than a full encoder-decoder.

Cross-attention is also the mechanism behind text-to-image diffusion models, where image latent features query a text encoder's output. The `T_dec` positions are pixel patches and the `T_enc` positions are prompt tokens.

## Cost and where it goes

| Quantity                       | Scaling                  | At `B=1, T=8192, heads=32, d_head=128` |
| :----------------------------- | :----------------------- | :------------------------------------- |
| Projections `Q`, `K`, `V`, `O` | `O(T d_model^2)`         | 4 matmuls of `8192 x 4096 x 4096`      |
| Score matrix `Q K^T`           | `O(T^2 d_head)` per head | `32 x 8192 x 8192 x 128` MACs          |
| Attention weights in memory    | `O(B heads T^2)`         | `32 * 8192^2 * 4 bytes = 8 GB` in fp32 |
| Feed-forward network           | `O(T d_model d_ff)`      | 3 matmuls through `11008` (SwiGLU)     |

The quadratic term is what bounds context length. At `T = 8192` the score matrix alone needs 8 GB in float32 for a single sequence, and it grows fourfold at `T = 16384`.

FlashAttention gets rid of the memory cost by never materializing the full matrix, recomputing attention block by block against the running softmax statistics. That is a [Phase 10](/ai/inference) topic. The `O(T^2)` compute stays.

## Interview questions

<Accordions>
  <Accordion title={<>Write the attention formula and give the shape of every tensor in it for a batch of <code>B</code> sequences of length <code>T</code>.</>}>

    `Attention(Q, K, V) = softmax(QK^T / sqrt(d_k)) V`. With `h` heads and `d_head = d_model / h`: `q` and `k` are `(B, h, T, d_head)`, `k.transpose(-2, -1)` is `(B, h, d_head, T)`, the score matrix and the softmax weights are `(B, h, T, T)`, `v` is `(B, h, T, d_head)`, and the output is `(B, h, T, d_head)` before the head merge restores `(B, T, d_model)`.

  </Accordion>
  <Accordion title="What is the difference between a key and a value, and why does attention need both?">

    A key is an address and a value is a payload. The key is what a query is compared against, the value is what gets copied into the output. They need to be separate projections because the information that makes a token matchable is not the information you want to read out of it: one token may be retrieved for its syntactic role while contributing its semantic content. Sharing a single matrix would force the score and the payload to be the same vector, which caps what the attention pattern can express.

  </Accordion>
  <Accordion title={<>Derive the variance of <code>q . k</code> under the standard assumptions, and show why the scale factor is <code>1 / sqrt(d_k)</code>.</>}>

    For independent `q_i, k_i` with mean 0 and variance 1, each product `q_i * k_i` has variance 1 and the terms are uncorrelated, so `Var(q . k) = sum_i Var(q_i k_i) = d_k`. The standard deviation is `sqrt(d_k)`. Dividing by `sqrt(d_k)` normalizes the logits back to unit variance, which keeps softmax in its responsive region instead of saturating as `d_k` grows.

  </Accordion>
  <Accordion title={<>What happens to the softmax gradient when the logits are unscaled at <code>d_k = 512</code>?</>}>

    The logits have standard deviation `sqrt(512)` is about 22.6, so softmax returns an almost exact one-hot vector. The Jacobian entries are `p(1 - p)`, and both are near zero at the ends, so the gradient that flows back through the attention weights vanishes. Only the winning position keeps signal, and the model stops learning where to attend.

  </Accordion>
  <Accordion title={<>Why is dividing by <code>d_k</code> instead of <code>sqrt(d_k)</code> wrong in the other direction?</>}>

    Dividing by `d_k` overshoots. Variance becomes `d_k / d_k^2 = 1 / d_k`, so logits sit within about `+/-0.04` of each other at `d_k = 512` and softmax returns an almost uniform distribution. The output collapses toward the mean of the values, which is exactly the selectivity attention exists to provide.

  </Accordion>
  <Accordion title="Write the softmax Jacobian and say where its diagonal terms are maximized.">

    `J_ij = p_i * (delta_ij - p_j)`, so the diagonal is `J_ii = p_i(1 - p_i)`. It peaks at `p_i = 0.5` and goes to zero at both ends: a saturated row (one-hot) and a uniform row (`p_i = 1/n`) both have vanishing diagonal gradient. Sensitivity to a logit perturbation is largest for a moderately spread distribution.

  </Accordion>
  <Accordion title="In cross-attention, which sequence length determines the output shape and which determines the width of the attention matrix?">

    The query length sets the output shape, because every query position produces one output row. The key and value length sets the width of the attention matrix, because that is how many positions each query can look at. The two are independent, which is why cross-attention can decode one token at a time against a source sequence of any length.

  </Accordion>
  <Accordion title="Why does a decoder block have more parameters than an encoder block?">

    A decoder block runs self-attention, then cross-attention, then the FFN, while an encoder block runs self-attention and the FFN. Cross-attention adds its own `W_Q`, `W_K`, `W_V` and `W_O`, four matrices of about `d_model^2` each, so roughly `4 * d_model^2` more parameters per layer, plus the extra LayerNorm.

  </Accordion>
  <Accordion title={<>What does attention cost in compute and in memory as a function of <code>T</code>, and which one does FlashAttention fix?</>}>

    Compute is `O(T^2 * d)` per head, because every query scores against every key, and memory is `O(T^2)` because the score matrix for each head is materialized. FlashAttention fixes the memory term, not the arithmetic: it tiles the computation and keeps a running softmax so the `T x T` matrix is never written out, bringing peak memory to `O(T)`. The `T^2` FLOPs remain.

  </Accordion>
  <Accordion title={<>Why does <code>k.transpose(-2, -1)</code> work on a batched tensor where <code>k.T</code> does not?</>}>

    `k.T` only reverses dimensions, and on a tensor with more than two axes it either transposes the wrong pair or raises. On `(B, h, T, d_head)` you need the last two axes swapped while the batch axes stay put, which is exactly `k.transpose(-2, -1)`.

  </Accordion>
  <Accordion title="What does QK-Norm change about the scaling argument?">

    QK-Norm puts a LayerNorm or RMSNorm on `q` and `k` per head before the dot product, so the norms are fixed and only the angles between them vary. Scores then stay inside a bounded range regardless of `d_k` or training drift, which removes the logit-growth failure mode in large-`d_k` and long-training regimes. The `1 / sqrt(d_k)` factor becomes a matter of convention rather than stability.

  </Accordion>
  <Accordion title={<>If <code>q</code> and <code>k</code> were drawn from a distribution with variance <code>4</code> instead of <code>1</code>, what scale factor would you need?</>}>

    Each product has variance `4 * 4 = 16`, so `Var(q . k) = 16 * d_k` and the standard deviation is `4 * sqrt(d_k)`. The scale factor needs to be `1 / (4 * sqrt(d_k))`, or generally `1 / (sigma_q * sigma_k * sqrt(d_k))`. This is why normalizing before the dot product is cleaner than tuning a constant.

  </Accordion>
</Accordions>
