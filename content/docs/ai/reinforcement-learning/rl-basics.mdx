Supervised learning needs the right answer for every example. Often you do not have it, but you can tell whether an attempt was good: the game was won, the code passed its tests, the person preferred this reply over that one. **Reinforcement learning (RL)** learns from that kind of signal. The learner tries something, receives a **reward**, and shifts toward whatever earned more reward.

Think of training a dog. You cannot show the dog the correct muscle movements for "sit". You wait for it to try things, and reward it when it sits. Over many tries, sitting becomes more likely. RL is that loop, made mathematical: a **policy** chooses **actions**, the **environment** returns **rewards**, and the policy is adjusted to make high-reward actions more probable.

For LLMs, RL is the stage after supervised fine-tuning. It is how chat models learn which of two answers people prefer (RLHF) and how reasoning models learn to solve problems whose answers can be checked (RLVR).

## Supervised learning versus reinforcement learning

|                          | Supervised learning                          | Reinforcement learning                                                      |
| :----------------------- | :------------------------------------------- | :-------------------------------------------------------------------------- |
| **Feedback**             | The correct answer for every input           | A score (reward) for what the learner did, often only at the end            |
| **Data**                 | A fixed dataset collected beforehand         | Generated by the learner itself as it acts                                  |
| **Question answered**    | "What is the right output?"                  | "Which of my behaviours lead to good outcomes?"                             |
| **Can exceed the data?** | No: the best it can do is imitate the labels | Yes: it can find strategies better than any example it was shown            |
| **Main difficulty**      | Getting labels                               | Noisy, delayed, sparse rewards; exploring enough; rewards that can be gamed |

## The vocabulary

| Word                            | Plain meaning                                                                                                                                                   |
| :------------------------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **agent**                       | The learner that acts. For LLMs, the model.                                                                                                                     |
| **environment**                 | Everything outside the agent that responds to its actions and hands out rewards.                                                                                |
| **state (`s`)**                 | What the agent can see at a moment.                                                                                                                             |
| **action (`a`)**                | What the agent chooses to do.                                                                                                                                   |
| **reward (`r`)**                | A number saying how good the immediate result was.                                                                                                              |
| **policy (`π`)**                | The agent's rule for choosing actions, usually a probability for each action in each state.                                                                     |
| **episode / trajectory**        | One complete run, from start to finish, as a sequence of states, actions, and rewards.                                                                          |
| **return (`G`)**                | The total reward of an episode, often with later rewards discounted by a factor `γ` (gamma).                                                                    |
| **value (`V`) / Q-value (`Q`)** | The expected return from a state, or from taking a particular action in a state.                                                                                |
| **advantage (`A`)**             | How much better an action was than the average action in that state. Positive means "do more of this".                                                          |
| **exploration / exploitation**  | Trying new actions to learn more, versus repeating what already works.                                                                                          |
| **on-policy / off-policy**      | Learning only from data the current policy produced, versus also from older or other data.                                                                      |
| **MDP**                         | Markov decision process: the formal model of states, actions, transitions, and rewards. [RL Foundations](/ai/reinforcement-learning/rl-foundations) defines it. |
| **reward model**                | A neural network trained to predict how much a person would like an answer, used as the reward in RLHF.                                                         |
| **reference model**             | A frozen copy of the starting model; training is penalized for drifting too far from it.                                                                        |

## A policy-gradient learner in 20 lines

A **bandit** is the simplest RL problem: one state, a few actions, a random reward. Here an agent chooses between three answer styles, each with a hidden chance of getting a thumbs-up. It never sees those chances, only its own rewards.

```python title="bandit_reinforce.py"
import numpy as np

rng = np.random.default_rng(0)
true_reward = np.array([0.2, 0.5, 0.8])     # chance each answer style gets a thumbs-up; unknown to the agent
logits = np.zeros(3)                         # the policy's parameters
lr, baseline = 0.1, 0.0

for step in range(2000):
    p = np.exp(logits) / np.exp(logits).sum()          # policy: probability of each action
    a = rng.choice(3, p=p)                             # sample an action
    r = float(rng.random() < true_reward[a])           # environment returns reward 1 or 0
    baseline += 0.01 * (r - baseline)                  # running average reward
    grad = -p
    grad[a] += 1                                       # gradient of log p(a) with respect to the logits
    logits += lr * (r - baseline) * grad               # REINFORCE with a baseline

p = np.exp(logits) / np.exp(logits).sum()
print(p.round(2).tolist())                             # [0.0, 0.01, 0.99]
```

The policy starts uniform (one third each) and ends choosing the best style 99% of the time. Each line is a piece of every algorithm in this phase:

- **Sample, then score**: the agent generates its own data, the defining feature of RL.
- **`r - baseline`** is an **advantage**: was this reward better or worse than usual? Rewards above average push the action up, below average push it down. Without the baseline, every rewarded action is pushed up, and learning is far noisier. [Policy Gradients](/ai/reinforcement-learning/policy-gradients) proves the baseline does not bias the gradient.
- **`grad` of `log p(a)`** is the **log-derivative trick** behind REINFORCE, PPO, and GRPO.

GRPO, the algorithm behind DeepSeek-R1, does exactly this with a language model: sample several answers to one prompt, score them, and use each answer's reward minus the group's average as its advantage.

## Why LLMs need RL after SFT

Supervised fine-tuning teaches by imitation: here is a good answer, make yours look like it. That has limits:

- **It optimizes resemblance, not outcome.** A response can look like the training data and still be wrong.
- **It cannot exceed its examples.** If the demonstrations are mediocre, so is the model.
- **Good answers are hard to write but easy to judge.** People can reliably say which of two answers is better long before they can write the perfect one; a checker can say whether code passes its tests without anyone writing the solution.

RL uses exactly that cheaper signal, a comparison or a check, and optimizes the outcome directly. The standard post-training pipeline is therefore: pretraining, then SFT, then RL ([LLM Basics](/ai/llm/llm-basics#the-lifecycle-of-an-llm)).

## The language model as an agent

| RL term         | For a language model                                                                                                      |
| :-------------- | :------------------------------------------------------------------------------------------------------------------------ |
| **State**       | The prompt plus every token generated so far                                                                              |
| **Action**      | The next token, one of the whole vocabulary                                                                               |
| **Policy**      | The model itself: its softmax over the vocabulary is the action distribution                                              |
| **Episode**     | Generating one complete response                                                                                          |
| **Reward**      | Usually one number at the end of the response: a reward model's score, a person's preference, or a checker's pass or fail |
| **Environment** | Mostly trivial (appending the token is the transition), plus the reward source; for agents, also tools and sandboxes      |

The unusual parts compared with games and robots: the action space is the whole vocabulary (tens of thousands of actions per step), the transitions are deterministic, and the reward arrives only at the end, so the algorithm must work out which of hundreds of tokens deserved the credit. [RL Foundations](/ai/reinforcement-learning/rl-foundations#mapping-the-mdp-onto-a-language-model) works through the mapping.

## RLHF versus RLVR

|                        | RLHF (reinforcement learning from human feedback)       | RLVR (reinforcement learning with verifiable rewards)     |
| :--------------------- | :------------------------------------------------------ | :-------------------------------------------------------- |
| **Reward comes from**  | A reward model trained on human preference comparisons  | A program: an answer checker, a unit test, a compiler     |
| **Good for**           | Helpfulness, tone, safety: things only people can judge | Math, code, and anything with a checkable answer          |
| **Main risk**          | The policy exploits flaws in the learned reward model   | Gaming the checker (for example, a test that is too weak) |
| **Typical algorithms** | PPO, or DPO without explicit RL                         | GRPO and its variants                                     |
| **Produced**           | Instruction-following chat models                       | Reasoning models that think step by step before answering |

## Reward hacking and the KL leash

A reward is only a stand-in for what you actually want, and an optimizer pushes on whatever the stand-in measures. A reward model that slightly favours long answers produces a policy that writes very long answers; a checker that only looks at the final line produces a policy that guesses. This is **reward hacking**, an instance of Goodhart's law: when a measure becomes a target, it ceases to be a good measure.

The standard guard is a **KL penalty**: a cost for moving the policy's token probabilities too far from the reference model (the frozen starting point). It keeps the model fluent and stops it drifting into strange text that happens to score well. PPO, DPO, and GRPO all contain some form of this leash, and its strength (the coefficient `β`) is one of the most important settings in every method. [Reward Models](/ai/reinforcement-learning/reward-models#reward-hacking-and-overoptimization) shows how overoptimization grows with training.

## Interview questions

<Accordions>
  <Accordion title="How does reinforcement learning differ from supervised learning?">

    Supervised learning is given the correct output for every input and learns to imitate it. RL is given only a reward for what it did, generates its own data by acting, and learns which behaviours lead to higher reward, so it can exceed the quality of any demonstration.

  </Accordion>
  <Accordion title="Why fine-tune an LLM with RL after SFT?">

    SFT optimizes resemblance to examples and cannot exceed them. Many qualities are easier to judge than to demonstrate, by preference comparisons or automatic checks, and RL optimizes those judgments directly. That is how chat models are aligned (RLHF, DPO) and how reasoning models are trained (RLVR).

  </Accordion>
  <Accordion title="Map the RL vocabulary onto a language model.">

    State: the prompt plus the tokens so far. Action: the next token. Policy: the model's distribution over the vocabulary. Episode: one full response. Reward: usually a single score at the end from a reward model, a preference, or a checker.

  </Accordion>
  <Accordion title="What is an advantage, and why subtract a baseline?">

    How much better an action did than expected. Subtracting a baseline (an average or a learned value) leaves the expected gradient unchanged but greatly reduces its variance, because only better-than-usual actions are pushed up.

  </Accordion>
  <Accordion title="RLHF versus RLVR?">

    RLHF uses a reward model trained on human preferences, suited to helpfulness and tone but vulnerable to reward hacking. RLVR uses programmatic checkers, suited to math and code, giving exact rewards and producing reasoning models.

  </Accordion>
  <Accordion title="What is reward hacking and how is it controlled?">

    The policy exploiting flaws in the reward instead of improving the real goal, such as writing longer answers because the reward model favours length. A KL penalty against a frozen reference model, better reward models, and held-out evaluation limit it.

  </Accordion>
</Accordions>
