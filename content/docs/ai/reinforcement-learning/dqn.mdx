Value-based RL learns a function that scores actions and picks the best one, rather than parameterising the choice directly. DQN is the version of that idea which works, and the two mechanisms that make it work, replay and a frozen target, are the answer to a specific failure: combining Q-learning with a neural network diverges.

---

## Tabular Q-learning

The Bellman optimality equation for `Q*` gives an update rule. Observe a transition, compare what you got against what you expected, and move the estimate toward the difference.

```text
Q(s,a) <- Q(s,a) + lr * [ r + gamma * max_a' Q(s',a') - Q(s,a) ]
                              \___________________________/
                                        TD target
TD error   delta = r + gamma * max_a' Q(s',a') - Q(s,a)
```

The TD error is the whole algorithm. Positive means the action turned out better than expected, so raise its estimate; negative means lower it. Watkins and Dayan proved in 1992 that with a table, a decaying learning rate and enough visits to every state-action pair, this converges to `Q*`.

Q-learning is off-policy. The `max_a'` inside the target uses the greedy action regardless of what the behaviour policy chose, so the update learns about the optimal policy from data collected by an exploratory one, usually epsilon-greedy.

---

## Why a table stops working

A table has one entry per state-action pair. Two things break it.

| Problem                   | Atari                        | Language model                |
| :------------------------ | :--------------------------- | :---------------------------- |
| State space               | `210 x 160 x 3` pixel frames | Every possible token sequence |
| Action space              | ~18 buttons                  | 32,000 to 152,000 tokens      |
| Similarity between states | Unused by a table            | Critical                      |

The second row is the killer for LLMs. A Q table indexed by (sequence, next token) is not merely large, it is meaningless, because two sequences differing by one word are unrelated keys despite being nearly the same situation.

DQN replaces the table with a network `Q(s, a; theta)`. For Atari, the input is four stacked frames and the output is one value per action, so a single forward pass scores all 18 buttons. That trick does not survive a 150,000-way vocabulary, which is one reason the LLM path went policy-gradient instead.

---

## The loss

With a network the update becomes regression against the Bellman target:

```text
L(theta) = E[ ( r + gamma * max_a' Q(s', a'; theta^-) - Q(s, a; theta) )^2 ]
```

`theta^-` is a frozen copy, discussed below. The gradient is

```text
dL/dtheta = E[ -2 * delta * dQ(s,a;theta)/dtheta ]
```

which has the same shape as the tabular update, with the network's gradient replacing the table's one-hot entry.

---

## Why it diverges

Naive Q-learning with a neural network was known to be unstable long before DQN fixed it. Three properties combine badly.

| Source of instability | What goes wrong                                                                                                       |
| :-------------------- | :-------------------------------------------------------------------------------------------------------------------- |
| Correlated samples    | Consecutive frames are near-identical, so gradient steps are not independent and the network overfits the recent past |
| Non-stationary target | The target contains `Q(s', a'; theta)`, which moves whenever `theta` moves, so you chase a moving goal                |
| The `max` operator    | Amplifies estimation error; the max of noisy values is biased upward                                                  |

Together these form a feedback loop. An overestimate raises the target, which raises the estimate, which raises the target. Supervised learning has none of this, because its labels are fixed.

## Experience replay

Store every transition in a circular buffer and sample uniformly from it.

```python
import random
from collections import deque

class ReplayBuffer:
    def __init__(self, capacity: int = 1_000_000):
        self.buf = deque(maxlen=capacity)          # Nature 2015 used 1e6 transitions

    def push(self, s, a, r, s_next, done):
        self.buf.append((s, a, r, s_next, done))

    def sample(self, batch_size: int = 32):
        return random.sample(self.buf, batch_size)

    def __len__(self) -> int:
        return len(self.buf)
```

This fixes the first instability in two ways at once. Sampling breaks the correlation between consecutive gradients, and each transition is reused many times, which is what makes the method sample-efficient. Off-policy learning is what permits the reuse at all: because Q-learning learns about the greedy policy rather than the one that collected the data, old transitions stay valid.

Two practical details. The buffer has to be large enough to hold a diverse set of situations, or the agent forgets early lessons; 1 million transitions is the published Atari setting. And uniform sampling wastes effort on uninformative transitions, which prioritised experience replay (Schaul et al., arXiv:1511.05952) addresses by sampling proportional to `|delta|^alpha` and correcting the resulting bias with importance weights.

## The target network

Keep a second copy of the weights `theta^-` used only to compute the target, and refresh it periodically.

| Update rule                                    | Name          | Typical setting      |
| :--------------------------------------------- | :------------ | :------------------- |
| `theta^- <- theta` every `C` steps             | Hard          | `C = 10,000` (Atari) |
| `theta^- <- tau * theta + (1 - tau) * theta^-` | Soft (Polyak) | `tau = 0.005`        |

The target is now constant between refreshes, so the regression problem is stationary for `C` steps and behaves like ordinary supervised learning. When the copy is refreshed the target jumps, which is why hard updates can produce visible sawtooth in the loss curve.

<Callout type="info">
  ### The same idea appears everywhere in LLM training

A frozen reference model in RLHF, the frozen teacher in distillation, and the EMA weights in diffusion training all serve the target network's role: hold one side of the objective still while the other side moves. If you understand why DQN needs `theta^-`, the KL penalty against a reference model in PPO is the same instinct applied to a policy rather than a value function.

</Callout>

## A minimal implementation

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class QNet(nn.Module):
    def __init__(self, state_dim: int, n_actions: int):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(state_dim, 256), nn.ReLU(),
            nn.Linear(256, 256), nn.ReLU(),
            nn.Linear(256, n_actions),
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return self.net(x)                          # (B, n_actions)


def dqn_loss(
    q: QNet, q_target: QNet, batch, gamma: float = 0.99, double: bool = True
) -> torch.Tensor:
    s, a, r, s_next, done = [torch.as_tensor(x, dtype=torch.float32) for x in batch]
    a = a.long()
    done = done.bool()

    qsa = q(s).gather(1, a.unsqueeze(1)).squeeze(1)          # (B,)

    with torch.no_grad():
        if double:
            # action chosen by the online net, evaluated by the target net
            a_next = q(s_next).argmax(1, keepdim=True)       # (B, 1)
            target = q_target(s_next).gather(1, a_next).squeeze(1)
        else:
            target = q_target(s_next).max(1).values          # (B,)
        td_target = r + gamma * target * (~done).float()     # (B,)

    return F.smooth_l1_loss(qsa, td_target)                  # Huber, as in the Nature paper
```

`gather` is how you pick one action's value out of a row of `n_actions` values. `smooth_l1_loss` is Huber loss, which the Nature paper used because TD targets contain occasional outliers that squared error over-weights.

## Results and variants

DQN (Mnih et al., arXiv:1312.5602, then Nature 2015 vol. 518) learned to play 49 Atari games from raw pixels with a single architecture and no per-game tuning, exceeding a professional human games tester's score on 29 of them. One network, one set of hyperparameters, 49 tasks was the result that made deep RL a field.

| Variant            | Change                                                                  | Source           |
| :----------------- | :---------------------------------------------------------------------- | :--------------- | ---------------------------------------- | ---------------- |
| Double DQN         | Select the action with the online net, evaluate it with the target net  | arXiv:1509.06461 |
| Dueling DQN        | Split the head into `V(s)` and `A(s,a)`, recombine as `V + A - mean(A)` | arXiv:1511.06581 |
| Prioritised replay | Sample proportional to `                                                | delta            | ^alpha`, correct with importance weights | arXiv:1511.05952 |
| Multi-step returns | Bootstrap from `n` steps ahead instead of one                           | Sutton and Barto |
| Distributional     | Predict the whole return distribution, not its mean                     | arXiv:1707.06887 |
| Noisy Nets         | Parameter-space noise instead of epsilon-greedy                         | arXiv:1706.10295 |
| Rainbow            | Combines the six above                                                  | arXiv:1710.02298 |

Double DQN is worth understanding precisely, because the fix is one line and the diagnosis is a common interview question. The `max` in the target picks the action with the highest estimated value, and estimation noise makes that action more likely to be an overestimate. Selecting with one network and evaluating with another decorrelates the error. In the code above it is the difference between `argmax` on `q` and `max` on `q_target`.

Dueling's decomposition matters because many states have the same value regardless of which action you take. Learning `V(s)` separately lets the network capture that without touching every action's estimate. The `mean(A)` subtraction is there to make the split identifiable, since `V + A` and `V + c + (A - c)` give the same Q.

## Why DQN does not carry over to LLM alignment

| Obstacle                   | Detail                                                                          |
| :------------------------- | :------------------------------------------------------------------------------ |
| Action space               | 150,000 outputs per position, so the value head is a full vocabulary projection |
| Replay invalidity          | Responses from a stale policy are off-distribution for text quality             |
| Sparse terminal reward     | One scalar per multi-thousand-token episode                                     |
| Stochastic policy required | Greedy decoding is worse than sampling for generation quality                   |
| Exploration                | Epsilon-greedy over a vocabulary produces gibberish                             |

The decisive one is that a value-based method picks `argmax_a Q(s,a)`, which is greedy decoding. Generation needs a distribution. Policy-gradient methods parameterise `pi(a|s)` directly and keep sampling, which is why RLHF, PPO and GRPO all sit on that side of the split.

DQN is not irrelevant to LLMs. It is the cleanest place to learn replay, target networks, and the TD error, all of which reappear: the critic in PPO regresses a value function with a bootstrapped target, and GAE is a weighted combination of multi-step TD errors.

## Interview questions

1. Write the Q-learning update and identify the TD error.

   `Q(s,a) <- Q(s,a) + lr * [r + gamma * max_a' Q(s',a') - Q(s,a)]`. The bracketed quantity is the TD error: the observed return `r + gamma * max Q(s', .)` minus the current estimate `Q(s,a)`. Positive means the action outperformed its estimate.

2. Why is Q-learning off-policy?

   The target uses `max_a'` over the greedy action, so the update learns about the optimal policy regardless of which policy collected the transition. That is also what permits experience replay, since old data from a stale behaviour policy remains valid for the target.

3. Name the three sources of instability in combining Q-learning with a neural network.

   Correlated consecutive samples, which make gradient steps non-independent; a non-stationary target, because the target contains the same weights being updated; and the `max` operator, which biases the target upward under estimation noise. Together they form a feedback loop that drives divergence.

4. What does experience replay fix, and what does the target network fix?

   Replay breaks sample correlation and lets each transition be reused, addressing both instability and sample efficiency. The target network freezes one side of the regression so the objective is stationary between refreshes, addressing the moving-target problem. They are independent mechanisms and DQN needs both.

5. What is maximisation bias and how does Double DQN remove it?

   Taking the max over noisy value estimates selects actions whose errors happen to be positive, so the target is systematically too high. Double DQN selects the action with the online network and evaluates it with the target network, decorrelating selection from evaluation. In code it is `argmax` on one network and `gather` from the other instead of a single `max`.

6. Why does the dueling architecture subtract the mean advantage?

   Without a constraint the split is unidentifiable, since adding a constant to `V` and subtracting it from every `A` leaves `Q` unchanged. Subtracting `mean_a A(s,a)` forces the advantage to average zero at each state, which pins `V(s)` to the true state value and lets the network learn it directly.

7. Why use Huber loss rather than squared error for the TD target?

   Bootstrapped targets contain occasional large errors, especially early in training, and squared error weights them quadratically, so a single outlier dominates the gradient. Huber is quadratic near zero and linear beyond a threshold, which caps that influence. The Nature DQN paper used it for this reason.

8. Why is prioritised replay biased, and how is the bias corrected?

   Sampling proportional to `|delta|^alpha` over-represents surprising transitions, so the empirical distribution no longer matches the one the value function should be fit to. The correction multiplies each sample's gradient by an importance weight `(N * P(i))^(-beta)`, with `beta` annealed toward 1 so the bias vanishes by the end of training.

9. What did DQN achieve on Atari, and why was the setup the point?

   The Nature 2015 version played 49 games from raw pixels with one architecture and one set of hyperparameters, exceeding a professional human games tester on 29 of them. The generality mattered more than any single score, because prior RL results required per-task engineering.

10. Why is DQN a poor fit for aligning a language model?

    A value-based policy is greedy by construction, `argmax_a Q(s,a)`, while generation needs a sampled distribution. The action space is the vocabulary, replay from a stale policy produces off-distribution text, the reward is a single terminal scalar for thousands of tokens, and epsilon-greedy exploration over a vocabulary yields gibberish. Policy-gradient methods avoid all of this by parameterising the policy directly.
