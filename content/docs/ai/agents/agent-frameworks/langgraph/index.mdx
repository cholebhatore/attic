LangGraph is an execution engine. A graph is built from a state type, a set of functions, and the edges between them; the engine then runs those functions until the graph says stop. Everything an agent needs that one forward pass cannot give it, which means looping, branching, pausing, and surviving a restart, happens here.

The layer above it is [LangChain](/ai/agents/agent-frameworks/langchain). `create_agent` compiles to a graph with a model node, a tool node, and an edge back, so the middleware hooks mark the places where hand-written nodes would otherwise sit. Learning the runtime first makes that layer legible; learning it second means trusting a black box that holds the production state.

## Outcomes

- Draw a graph as state, nodes, and edges, and say which of the three a given bug lives in
- Declare a state schema and pick the right reducer per key, including why parallel writes need one
- Route on model output, bound a loop, and fan out to a number of branches known only at run time
- Resume a run that died mid-task, and replay it from an earlier state to test a fix
- Put an approval gate on a destructive tool in a way that survives a deploy and an on-call handover
- Say whether a given job needs a graph at all, and what it costs when it does not
