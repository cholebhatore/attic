LangSmith is where an LLM application's evidence lives. Every run becomes a record with its inputs, the prompt that was actually sent, each model and tool call, token counts, latency, and cost. On top of those records sit versioned prompts, datasets, experiments, and dashboards.

The reason it earns a place in this curriculum is that an agent is not one model call. A run with nine tool calls and two retries has nine ways to be wrong, and a log line does not identify the failing step. Tracing is the minimum viable observability for this class of system, and LangSmith is the option that is already wired into the two frameworks around it.

## Outcomes

- Explain what a run, a trace, a thread, and an experiment are, and which one a bug report belongs in
- Instrument a chain, an agent, and plain Python functions so every step is visible
- Say which prompt version produced a given answer, and roll it back without a deploy
- Turn production failures into a dataset and gate merges on it
- Write an evaluator that is a function, not a feeling, and know its limits
- Read a dashboard that gives cost per request and the fallback rate, and alert on both
