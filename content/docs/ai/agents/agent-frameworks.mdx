A framework is a loop you did not write, plus the state, retries, and serialization that make the loop survive production. That is the whole value proposition, and it is also the whole risk: the abstraction is someone else's opinion about what your agent needs.

The field sorted itself into two layers. **Runtimes** own execution: state, checkpointing, replay, resume. **Abstractions** sit on a runtime and hand you a prebuilt agent with sensible defaults. LangChain and LangGraph are the clearest example of that split, and the 1.0 releases made it explicit: LangChain 1.0's `create_agent` is a thin layer on the LangGraph runtime.

---

## The two shapes

LangChain's original model was a pipeline. In the expression language, a chain is composed with the pipe operator:

```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_anthropic import ChatAnthropic
from langchain_core.output_parsers import StrOutputParser

prompt = ChatPromptTemplate.from_messages(
    [("system", "You summarize incident reports in 3 bullets."),
     ("user", "{report}")]
)
model = ChatAnthropic(model="claude-sonnet-4-5", max_tokens=512)

chain = prompt | model | StrOutputParser()
bullets = chain.invoke({"report": raw_text})  # str
```

`prompt | model | StrOutputParser()` is the whole architecture: `Prompt | LLM | Parser`. Each piece is a `Runnable` with the same four methods, `invoke`, `batch`, `stream`, and their async twins, so composition works because every stage has an identical interface. Data flows left to right, once, and the chain terminates.

A graph drops both the linearity and the single pass.

|                           | Chain (LCEL)                         | Graph (LangGraph)                                  |
| :------------------------ | :----------------------------------- | :------------------------------------------------- |
| Topology                  | Directed acyclic, left to right      | Cyclic; edges may point backward                   |
| State                     | Passed as the value between stages   | Accumulates in a typed object every node can read  |
| Control                   | Fixed at composition time            | Conditional edges chosen at run time               |
| Termination               | End of the pipeline                  | A node routes to `END`, or a recursion limit trips |
| Persistence               | None; a failure means starting over  | Checkpointer writes state at every super-step      |
| Pause for a human         | Not expressible                      | `interrupt()` inside a node, resume later          |
| Who decides the next step | The developer, when writing the code | The model, at run time                             |

The last row is the difference that matters for agents. A workflow is control flow you wrote with an LLM inside it. An agent is control flow the model wrote at run time, which means the graph has to be able to visit the same node twice.

## Why pipelines break on agents

Each failure below is a chain that cannot express the loop, not a chain that is merely awkward.

| Requirement          | What it looks like                                       | Why `A \| B \| C` cannot do it             |
| :------------------- | :------------------------------------------------------- | :----------------------------------------- |
| Iterate until done   | Retrieve, judge sufficiency, re-query, retrieve again    | The pipeline length is fixed when composed |
| Act on tool results  | Call a tool, feed the output back, decide again          | Feedback needs an edge to an earlier node  |
| Budget a run         | Stop at 25 steps or 2 USD                                | No notion of a step count                  |
| Recover from failure | Retry with a modified prompt after a bad parse           | Parser errors propagate, they do not route |
| Resume a long job    | Rebuild after a deploy, from step 9                      | Nothing is stored between runs             |
| Wait for approval    | Hold before a destructive action until a human signs off | No suspension semantics                    |
| Parallel fan-out     | One subtask per document, unknown count                  | Static structure, no dynamic dispatch      |

Anthropic's _Building Effective Agents_ (December 2024) made the same argument from the other direction: most production needs are met by composable workflows of five patterns, and an agent loop should be written directly when you need it, because a framework's agent abstraction hides the loop you are responsible for.

## LangGraph

A low-level runtime for stateful, cyclical execution. MIT licensed, at 1.x since October 2025, and the execution model has not changed since 0.1.

```python
from typing import Annotated, TypedDict
from operator import add
from langgraph.graph import StateGraph, START, END
from langgraph.prebuilt import ToolNode
from langgraph.checkpoint.memory import MemorySaver
from langchain_core.runnables import RunnableConfig

class State(TypedDict):
    messages: Annotated[list, add]      # append-only reducer
    attempts: int                        # last write wins
    findings: Annotated[list, add]

def think(state: State, config: RunnableConfig):
    resp = model.invoke(state["messages"], config)
    return {"messages": [resp], "attempts": state["attempts"] + 1}

def decide(state: State) -> str:
    last = state["messages"][-1]
    if getattr(last, "tool_calls", None):
        return "act"
    if state["attempts"] >= 25:
        return "give_up"
    return "finish"

g = StateGraph(State)
g.add_node("think", think)
g.add_node("act", ToolNode(tools))
g.add_node("give_up", give_up_node)
g.add_edge(START, "think")
g.add_conditional_edges("think", decide,
                        {"act": "act", "finish": END, "give_up": "give_up"})
g.add_edge("act", "think")             # the cycle

app = g.compile(checkpointer=MemorySaver())
out = app.invoke(
    {"messages": [human(task)], "attempts": 0, "findings": []},
    {"configurable": {"thread_id": "incident-4821"}, "recursion_limit": 50},
)
```

Four things are doing real work here.

**State with reducers.** The typed dict is not a bag of variables; each key declares how updates merge. `Annotated[list, add]` appends, a bare `int` overwrites. Without reducers, parallel branches writing the same key is undefined behavior; with them, it is a merge.

**Conditional edges.** `decide` is a plain function returning a route name. This is where a deterministic router lives, and where the loop-engineering guards from [The Agent Loop](/ai/agents/agent-loop) attach.

**The cycle.** `act -> think` is an edge back to an already-visited node. `recursion_limit` is the guard rail, and tripping it raises rather than returning a partial answer, which is a design decision you should be aware of before relying on the budget.

**`thread_id`.** One identifier turns a stateless invocation into a conversation, and it is the same identifier used by every other persistence feature below.

## Checkpointing and durable execution

A checkpointer snapshots the full graph state at the end of each super-step (one round of node execution, including parallel branches), keyed by thread.

| Checkpointer        | Backend        | Use                                             |
| :------------------ | :------------- | :---------------------------------------------- |
| `MemorySaver`       | Process memory | Tests and single-process demos. Gone on restart |
| `SqliteSaver`       | A file         | Local tools, low concurrency                    |
| `PostgresSaver`     | Postgres       | Production default; queryable, survives deploys |
| Redis / third-party | Cache store    | High write throughput, short retention          |

What the snapshot buys you:

```python
# Resume after a crash, same thread, no input needed
out = app.invoke(None, {"configurable": {"thread_id": "incident-4821"}})

# Inspect history: every state, every node, every timestamp
for snap in app.get_state_history(config):
    print(snap.next, snap.created_at, len(snap.values["messages"]))

# Time-travel: fork from a checkpoint with a corrected field
fork = app.update_state(config, {"attempts": 0}, as_node="think")
app.invoke(None, config)   # re-runs forward from the fork
```

`invoke(None, ...)` is the resume call. Passing `None` means "continue this thread from its last checkpoint" rather than "start over". Time travel is the same mechanism pointed at an older snapshot, which makes it the debugging tool for agents: replay a failed incident, patch the state at step 6, see whether step 7 now succeeds.

Retention is your problem. A long-lived agent thread accumulates a checkpoint per step, and the state carries the message list, so an unpruned table grows quadratically in the worst case. Set a TTL or prune finished threads.

## Human-in-the-loop

Two mechanisms, for two different needs.

| Mechanism                                              | Semantics                                                | Use for                                                   |
| :----------------------------------------------------- | :------------------------------------------------------- | :-------------------------------------------------------- |
| `interrupt(payload)` in a node                         | Suspend, persist, wait indefinitely, resume with a value | Approval gates, editing proposed arguments, clarification |
| `interrupt_before` / `interrupt_after` at compile time | Halt at named nodes, state visible from outside          | Audit trails, step-by-step review of a whole run          |

```python
from langgraph.types import interrupt, Command

def execute(state: State) -> dict:
    call = state["messages"][-1].tool_calls[0]
    if call["name"] in DESTRUCTIVE:
        decision = interrupt({          # graph state is checkpointed here
            "tool": call["name"],
            "args": call["args"],
            "reason": "drops a production table",
        })
        if not decision["approved"]:
            return {"messages": [tool_refused(call)]}
    return {"messages": [run_tool(call)]}

# Somewhere else entirely: a worker, an hour later, after a human clicked Approve
result = app.invoke(Command(resume={"approved": True}), config)
```

`interrupt()` is not an exception and not a callback. The graph stops, its state is written to the checkpointer, and the process is free to exit. `Command(resume=...)` re-enters that thread with the value that `interrupt()` appears to return. That is what makes an approval gate survive a deploy, an on-call rotation, or a human who answers the next morning.

One trap: code before the `interrupt()` in the same node re-runs on resume, because the node restarts. Put side effects after it, or in a separate node.

## Parallelism and subgraphs

`Send` dispatches a variable number of parallel branch runs, which is what fan-out with an unknown count looks like.

```python
from langgraph.types import Send

def route(state: State):
    return [Send("per_doc", {"doc": d, "q": state["query"]}) for d in state["docs"]]

g.add_conditional_edges("split", route, "per_doc")
```

Each `Send` payload is its own local state; results converge back through the parent's reducers. A subgraph is the other unit of composition: compile a graph, then add it as a single node in another graph. Subagents in [Multi-Agent Topologies](/ai/agents/multi-agent) are subgraphs, which is how a supervisor gets one node whose internal steps still checkpoint independently.

`langgraph-supervisor` and `langgraph-swarm` package the two dominant topologies as prebuilt libraries, so a supervisor hand-off does not have to be written from scratch.

## LangChain 1.0

GA on 22 October 2025, same day as LangGraph 1.0, after an alpha announced 2 September 2025. The release is a narrowing, not an expansion.

| Change                       | Detail                                                                                                                                                                                  |
| :--------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| One agent entry point        | `create_agent(model, tools, system_prompt=..., middleware=[...], response_format=..., checkpointer=...)`, built on the LangGraph runtime                                                |
| Prebuilt agents consolidated | LangGraph's `create_react_agent` is deprecated in favour of LangChain's `create_agent`                                                                                                  |
| Middleware                   | Hooks around the model and tool calls: `before_model`, `after_model`, wrap-style around tool execution. Shipped as `SummarizationMiddleware`, `HumanInTheLoopMiddleware`, PII redaction |
| Standard content blocks      | Provider responses normalize to typed blocks (text, reasoning, tool use, image) instead of provider-specific dicts                                                                      |
| Structured output by default | `response_format` returns validated output or raises, rather than a free-text parse                                                                                                     |
| Integrations moved           | Provider and vector-store packages moved out of the core into `langchain-community` and standalone provider packages such as `langchain-anthropic`                                      |
| Retired surface              | The old `AgentExecutor`, `initialize_agent`, and the string-keyed memory objects are gone from the 1.0 path                                                                             |

```python
from langchain.agents import create_agent
from langchain.agents.middleware import SummarizationMiddleware, HumanInTheLoopMiddleware

agent = create_agent(
    model="claude-sonnet-4-5",
    tools=tools,
    system_prompt="You triage production incidents.",
    middleware=[
        SummarizationMiddleware(model="claude-haiku-4-5", trigger=("tokens", 100_000)),
        HumanInTheLoopMiddleware(interrupt_on={"drop_table": True}),
    ],
    checkpointer=PostgresSaver(pool),
)
```

The honest read of 1.0: LangChain stopped competing with itself. It is now the high-level layer, LangGraph is the runtime under it, and the things people complained about, `AgentExecutor` and deeply nested abstraction, are out of the 1.0 path.

## The rest of the field

| Framework                     | Core abstraction                                                                                    | Origin and status                                                                      | Reach for it when                                                       |
| :---------------------------- | :-------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------- | :---------------------------------------------------------------------- |
| **OpenAI Agents SDK**         | Agent, handoffs, guardrails, sessions; tracing built in                                             | March 2025, the production successor to the experimental Swarm                         | OpenAI-first, and handoffs are the topology you want                    |
| **Google ADK**                | Hierarchical agents, `LlmAgent`, workflow agents, tools                                             | April 2025, launched alongside the A2A protocol                                        | Multi-agent on GCP, or peer-to-peer across vendors                      |
| **Pydantic AI**               | Typed `Agent`, validated structured output, dependency injection                                    | From the Pydantic team                                                                 | Output shape is contractual and Python typing carries the design        |
| **CrewAI**                    | Role/goal/backstory agents grouped into a Crew with sequential or hierarchical process              | Independent of LangChain                                                               | Role-shaped teams and fast prototypes of a fixed collaborative pipeline |
| **Microsoft Agent Framework** | Graph-based agents, workflows, resume and affinity; Azure AI Foundry integration                    | Public preview 1 October 2025, 1.0 on 3 April 2026; merges AutoGen and Semantic Kernel | .NET/Azure shops, or a converged AutoGen codebase                       |
| **Claude Agent SDK**          | The harness extracted from Claude Code: loop, file and shell tools, subagents, MCP, hooks, sessions | September 2025, renamed from the Claude Code SDK                                       | Building a coding or file-operating agent rather than a chat one        |
| **Smolagents**                | Code-as-action: the agent writes Python as its tool calls instead of JSON                           | Hugging Face, December 2024                                                            | Small action space, open-weight models, minimal abstraction             |
| **LlamaIndex Workflows**      | Event-driven steps with typed events, not a graph definition                                        | Successor to the older query engines                                                   | The agent is retrieval-shaped and indexing is the hard part             |
| **MCP servers + your loop**   | The ~150-line controller in [The Agent Loop](/ai/agents/agent-loop)                                 | Always available                                                                       | One model, a dozen tools, no checkpointing need                         |

`A2A` is a protocol, not a framework, and it now sits beside MCP under the Agentic AI Foundation, whose hosted projects are MCP, A2A, goose, AGENTS.md, agentgateway and Agent Router. Frameworks adopt these; they do not compete with them.

## Choosing

| Constraint                                                       | Choice                    |
| :--------------------------------------------------------------- | :------------------------ |
| Need durable execution, resume, or time travel                   | LangGraph                 |
| Need an agent today, on OpenAI, with tracing                     | OpenAI Agents SDK         |
| Need approval gates and standard block types, no graph authoring | LangChain `create_agent`  |
| Typed I/O matters more than orchestration features               | Pydantic AI               |
| .NET or Azure AI Foundry                                         | Microsoft Agent Framework |
| The agent operates on files and a shell                          | Claude Agent SDK          |
| Single model, few tools, no long jobs                            | Your own loop             |

Ordering by abstraction depth from least to most: smolagents, own loop, Pydantic AI, OpenAI Agents SDK, LangChain, LangGraph, CrewAI. Deeper is not better; it is just more of someone else's semantics between your prompt and your behavior.

## What no framework provides

These are the reasons a framework adoption fails after the demo, and none of them are in scope for any of them.

| Gap                                  | Who owns it                        | Where covered                                                |
| :----------------------------------- | :--------------------------------- | :----------------------------------------------------------- |
| Whether the agent works              | Your eval harness                  | [Evaluation Metrics and Benchmarks](/ai/agents/eval-metrics) |
| What is in the context window        | Context engineering                | [Context Budgeting](/ai/rag/context-budgeting)               |
| Cost per run                         | Budgets, caching, model routing    | Phase 10 inference pages                                     |
| Prompt injection through tool output | Host policy and confirmation gates | [Agent Security](/ai/agents/agent-security)                  |
| Tool description quality             | Whoever writes the schema          | [Function Calling](/ai/agents/function-calling)              |
| Latency at p99                       | Serving and batching               | [Serving Engines](/ai/inference/serving-engines)             |

A framework gives you the loop and the state. It gives you no evidence that the loop produces correct answers, which is why [Human and Judge Evaluation](/ai/agents/judge-and-human-eval) is the phase that follows this one rather than a footnote in it.

## Interview questions

<Accordions>
  <Accordion title="1. Describe the classic LangChain chain and why an agent outgrows it.">

    `Prompt | LLM | Parser`, composed with the pipe operator over objects that all implement the `Runnable` interface, so data flows left to right once and terminates. An agent needs a cycle: call a tool, feed the result back, decide again. A pipeline's length is fixed at composition time, so the loop cannot be expressed.

  </Accordion>
  <Accordion title="2. What exactly does LangGraph add?">

    A stateful runtime: a typed state object with per-key reducers, nodes, conditional edges, cycles, a checkpointer that snapshots state every super-step, `interrupt()` for suspension, `Send` for dynamic parallelism, and streaming over execution. The model, not the developer, picks the next node at run time.

  </Accordion>
  <Accordion title="3. Why are reducers necessary?">

    Because parallel branches can write the same key. `Annotated[list, add]` declares append semantics, a bare scalar declares last-write-wins, and without that declaration a concurrent write is undefined rather than merged.

  </Accordion>
  <Accordion title="4. What is a super-step?">

    One round of node execution, including all branches that run in parallel within it. The checkpointer writes a snapshot at the end of each super-step, which is the granularity of resume and time travel.

  </Accordion>
  <Accordion title="5. How do you resume an interrupted agent run?">

    Invoke with `None` as input and the same `thread_id`. `None` means continue from the thread's last checkpoint instead of starting a new run.

  </Accordion>
  <Accordion title={<>6. Contrast <code>interrupt()</code> with <code>interrupt_before</code>.</>}>

    `interrupt(payload)` is called inside a node, suspends the graph, and resumes with a value delivered by `Command(resume=...)`; it is for approval gates and clarification. `interrupt_before` and `interrupt_after` are compile-time lists of node names that halt execution at those points so state can be inspected from outside; they suit auditing a whole run.

  </Accordion>
  <Accordion title="7. Which code in a node re-runs after a resume, and why does that matter?">

    Everything in the node before the `interrupt()` call, because the node restarts rather than continuing. Side effects must be placed after the interrupt or in a separate node.

  </Accordion>
  <Accordion title="8. What changed in LangChain 1.0?">

    It became a high-level layer on the LangGraph runtime: a single `create_agent` entry point, middleware hooks around the model and tool calls, standard typed content blocks across providers, structured output by default, integrations moved to `langchain-community`, and the old `AgentExecutor` path retired. LangGraph's `create_react_agent` was deprecated in favour of `create_agent`.

  </Accordion>
  <Accordion title="9. Is a workflow or an agent the right primitive here?">

    If you can enumerate the steps, use a workflow: deterministic, cheaper, testable. Use an agent when the number and identity of steps depends on what the model finds. Anthropic's _Building Effective Agents_ argues most needs are composable workflows of five patterns.

  </Accordion>
  <Accordion title="10. Name the AAIF-hosted projects and what the foundation changed for MCP.">

    Model Context Protocol, Agent2Agent, goose, AGENTS.md, agentgateway and Agent Router. MCP was donated to it by Anthropic on 9 December 2025, moving governance from a single vendor to a Linux Foundation directed fund co-founded with Block and OpenAI.

  </Accordion>
  <Accordion title="11. Which framework would you pick for a file-and-shell coding agent, and why?">

    The Claude Agent SDK, because it is the harness extracted from Claude Code: the loop plus filesystem and shell tools, subagents, MCP, hooks and sessions are already built. Writing that from scratch is re-implementing a coding agent's hardest half.

  </Accordion>
  <Accordion title="12. When is building your own loop the right call?">

    One model, a dozen or fewer tools, no need for durable execution or resume, and a team that will read the controller. Around 150 lines plus the guards in the agent-loop pattern; a framework earns its abstraction when you need checkpointing, streaming, or parallel dispatch.

  </Accordion>
  <Accordion title="13. What does a framework not solve for you?">

    Evidence the agent is correct (evals), what goes into the context window, cost per run, prompt-injection defense through tool output, tool description quality, and p99 latency. Those are owned by your harness, context engineering, policy, and serving layer.

  </Accordion>
  <Accordion title="14. How would you debug an agent that failed on step 9 of a 40-step run?">

    With a checkpointer, read `get_state_history` for the per-step states, fork from the step-6 checkpoint with `update_state`, and re-run forward to test the fix. Without a checkpointer, you are reproducing the whole run blind, which is the argument for durable execution as a debugging feature rather than only a reliability one.

  </Accordion>
  <Accordion title="15. What is lock-in risk when adopting a graph framework, and how do you limit it?">

    Your control flow becomes a DSL in that framework's terms. Limit it by keeping node bodies as plain functions against provider SDKs, by putting tool definitions in MCP servers, and by keeping state a typed dict you could serialize yourself. The runtime is replaceable if the nodes are not clever.

  </Accordion>
</Accordions>
