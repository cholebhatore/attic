A vector is an ordered list of numbers. A matrix is a function that maps one vector to another. Those two statements cover almost everything a neural network does with data: it stores meaning as vectors and transforms them with matrices.

---

## Vectors as data and as geometry

A vector `v` in `n` dimensions is written `v = [v1, v2, ..., vn]`. It has two readings that you need to hold at the same time.

**Algebraic reading.** A row of features. A house described by `[bedrooms, sqft, balconies]` is the vector `[3, 1625, 2]`.

**Geometric reading.** An arrow from the origin to the point `(v1, v2, ..., vn)`. Its length is its magnitude and its orientation is its direction.

Machine learning uses the geometric reading constantly. A word embedding is a 4096-dimensional arrow, and semantic similarity is a claim about the angle between two arrows rather than about their individual coordinates.

```python title="vectors.py"
import numpy as np

house = np.array([3.0, 1625.0, 2.0])
embedding = np.array([0.12, -0.83, 0.44, 0.07])

print(house.shape)      # (3,)  - a 1D array of length 3
print(embedding.ndim)   # 1
print(len(embedding))   # 4
```

A vector's **magnitude** (length) comes from the Pythagorean theorem generalized to `n` dimensions:

```python title="magnitude.py"
v = np.array([3.0, 4.0])
magnitude = np.sqrt(np.sum(v ** 2))   # 5.0
same = np.linalg.norm(v)              # 5.0, the L2 norm
```

## Unit vectors and basis vectors

A **unit vector** has magnitude 1. You get one by dividing a vector by its own norm, an operation called normalization:

```
u = v / ||v||
```

```python title="normalize.py"
v = np.array([3.0, 4.0])
u = v / np.linalg.norm(v)     # [0.6, 0.8]
np.linalg.norm(u)             # 1.0
```

Normalization strips magnitude and keeps direction. Vector databases do this at index time so that retrieval ranks by direction alone, which is why cosine similarity collapses into a plain dot product.

A **basis** is a set of vectors that is linearly independent (none is a combination of the others) and spans the space (any vector can be written as a combination of them). The **standard basis** in 3D is:

```
e1 = [1, 0, 0]
e2 = [0, 1, 0]
e3 = [0, 0, 1]
```

Any vector `[a, b, c]` equals `a*e1 + b*e2 + c*e3`. The coordinates you write down are the coefficients of that combination, and the basis is usually implicit.

<Callout type="info">
  Changing the basis changes the coordinates but not the vector. Eigen-decomposition and SVD are
  both searches for a basis in which a transformation becomes simple, meaning diagonal. That is the
  entire reason they matter.
</Callout>

## Dimensionality

Dimensionality is the count of values in a vector, and it is the number that dominates cost calculations in every later phase.

| Where it appears          | Symbol    | Typical value     |
| :------------------------ | :-------- | :---------------- |
| Token embedding width     | `d_model` | 768 to 16384      |
| Attention head dimension  | `d_k`     | 64 to 128         |
| Feed-forward hidden width | `d_ff`    | 4 times `d_model` |
| Vocabulary size           | `V`       | 32k to 200k       |
| Sequence length           | `N`       | 2k to 1M          |

A 70B parameter model stores roughly 70 billion floats. Nearly all of them are entries in weight matrices whose shapes are built from the numbers above.

High dimensionality has one consequence worth internalizing early: in high-dimensional space, randomly sampled vectors are almost always nearly orthogonal. Cosine similarity between random 4096-dimensional embeddings concentrates near zero, so a measured similarity of 0.7 is meaningful signal rather than coincidence.

## Matrices as linear transformations

A matrix `A` of shape `(m, n)` maps an `n`-dimensional input vector to an `m`-dimensional output vector:

```
y = A @ x        # A is (m, n), x is (n,), y is (m,)
```

The map is **linear**, meaning it satisfies both of these for all vectors `x`, `z` and all scalars `c`:

```
A @ (x + z) == A @ x + A @ z
A @ (c * x) == c * (A @ x)
```

Geometrically, a linear transformation rotates, scales, shears, or projects space. It never bends it, and it always keeps the origin fixed.

```python title="transform.py"
A = np.array([[2.0, 0.0],
              [0.0, 3.0]])          # scales x by 2, y by 3
x = np.array([1.0, 1.0])
print(A @ x)                        # [2. 3.]

R = np.array([[0.0, -1.0],
              [1.0,  0.0]])          # 90 degree rotation
print(R @ x)                        # [-1.  1.]
```

The columns of `A` are where the standard basis vectors land. Column `j` of `A` is `A @ e_j`.

### The affine layer

Neural network layers add a bias, which makes them **affine** rather than purely linear:

```
y = x @ W.T + b
```

The bias translates the output, so the origin is no longer fixed. This is the exact formula behind every `nn.Linear` in PyTorch, and the `W` and `b` here are the weights and biases from the LLM foundations module.

```python title="linear_layer.py"
batch = np.random.randn(8, 512)      # 8 tokens, d_model = 512
W = np.random.randn(256, 512)        # projects 512 -> 256
b = np.zeros(256)

out = batch @ W.T + b                # shape (8, 256)
```

## Rank and invertibility

The **rank** of a matrix is the number of linearly independent columns, which equals the dimension of the output space it can reach. A `(5, 3)` matrix has rank at most 3, so its outputs live in a 3-dimensional subspace of 5-dimensional space.

A matrix is **invertible** (non-singular) when all of these hold:

- It is square, shape `(n, n)`
- It has full rank `n`
- Its determinant is non-zero
- Its columns are linearly independent

The inverse `A^-1` undoes the transformation: `A^-1 @ A @ x == x`.

```python title="inverse.py"
A = np.array([[4.0, 7.0],
              [2.0, 6.0]])
print(np.linalg.matrix_rank(A))     # 2
print(np.linalg.det(A))             # 10.0
A_inv = np.linalg.inv(A)
print(A_inv @ A)                    # identity, up to float error
```

<Callout type="warn">
  Weight matrices in real networks are almost never square and almost never invertible. A `(4096,
  11008)` feed-forward matrix compresses and expands, destroying information in one direction. Do
  not reach for `np.linalg.inv` in model code; it is a diagnostic tool, and it is numerically
  unstable on ill-conditioned matrices.
</Callout>

**Rank deficiency** is the useful case. When a large matrix has much lower rank than its shape allows, a low-rank approximation captures most of its behavior with far fewer numbers. LoRA in Phase 7 exploits exactly this by training a rank-16 update instead of a full `4096 x 4096` matrix.

## Eigen-decomposition

An **eigenvector** of a square matrix `A` is a non-zero vector that `A` only scales, never rotates:

```
A @ v = lambda * v
```

`lambda` is the **eigenvalue** paired with `v`. Every direction except the eigenvectors gets rotated by `A`; the eigenvectors are the directions that survive the transformation intact.

If `A` has `n` linearly independent eigenvectors, it can be factored as:

```
A = V @ diag(lambda) @ V^-1
```

where the columns of `V` are the eigenvectors and `lambda` holds the eigenvalues. Read from right to left: change into the eigenbasis, scale each axis independently, change back.

```python title="eigen.py"
A = np.array([[2.0, 1.0],
              [1.0, 2.0]])
eigenvalues, eigenvectors = np.linalg.eig(A)
print(eigenvalues)                  # [3. 1.]
print(eigenvectors)

# verify A @ v == lambda * v
v = eigenvectors[:, 0]
print(np.allclose(A @ v, eigenvalues[0] * v))   # True
```

Eigenvalues also describe conditioning. The ratio of the largest to smallest eigenvalue magnitude tells you how much a matrix stretches space unevenly, and that ratio drives both numerical instability and slow gradient descent.

## Singular value decomposition

Eigen-decomposition needs a square matrix. **SVD** works on any shape, which is why it is the workhorse of applied linear algebra.

Any matrix `A` of shape `(m, n)` factors as:

```
A = U @ Sigma @ V.T
```

| Factor  | Shape    | Contents                                                      |
| :------ | :------- | :------------------------------------------------------------ |
| `U`     | `(m, m)` | Orthonormal left singular vectors, output-space directions    |
| `Sigma` | `(m, n)` | Diagonal, singular values sorted descending, all non-negative |
| `V.T`   | `(n, n)` | Orthonormal right singular vectors, input-space directions    |

The singular values `sigma_i` are the square roots of the eigenvalues of `A.T @ A`. Each one measures how much `A` stretches space along the matching direction in `V`.

```python title="svd.py"
A = np.random.randn(6, 4)
U, S, Vt = np.linalg.svd(A, full_matrices=False)
print(U.shape, S.shape, Vt.shape)   # (6, 4) (4,) (4, 4)

reconstructed = U @ np.diag(S) @ Vt
print(np.allclose(A, reconstructed))            # True
```

### Low-rank approximation

Keep only the top `k` singular values and you get the best possible rank-`k` approximation of `A` in the least-squares sense. This is the Eckart-Young theorem.

```python title="low_rank.py"
k = 2
S_k = np.zeros_like(S)
S_k[:k] = S[:k]
A_approx = U @ np.diag(S_k) @ Vt

error = np.linalg.norm(A - A_approx) / np.linalg.norm(A)
print(f"relative error with rank {k}: {error:.4f}")
```

The storage saving is the reason this matters. A full `(m, n)` matrix needs `m * n` numbers. A rank-`k` factorization needs `k * (m + n)`. For `m = n = 4096` and `k = 16`, that is 16.7 million numbers down to 131 thousand.

<Callout type="info">
  Hold this shape in mind: `dW = B @ A` where `B` is `(4096, 16)` and `A` is `(16, 4096)`. It is
  exactly a rank-16 approximation of an update matrix, and it is the whole of LoRA. Phase 7 builds
  on it directly.
</Callout>

## Interview questions

<Accordions>
  <Accordion title="1. What are the two readings of a vector, and which one does machine learning use?">

    Algebraically a vector is a row of features, like a house described by `[3, 1625, 2]`. Geometrically it is an arrow from the origin with a length and a direction. Retrieval, attention, and normalization all depend on the geometric reading, because it is what makes an angle between two vectors mean something.

  </Accordion>
  <Accordion title="2. Why does a linear layer add a bias term?">

    `y = x @ W` alone always maps the zero vector to zero, so every decision boundary it can express passes through the origin. Adding `b` makes the layer affine instead of linear, which lets the hyperplane sit anywhere in space.

  </Accordion>
  <Accordion title="3. What does it mean for a square matrix to be full rank?">

    Its columns are linearly independent, so the transform preserves dimensionality and is invertible. A rank-deficient square matrix collapses space onto a subspace and has no inverse.

  </Accordion>
  <Accordion title="4. Rank deficiency looks like a defect. Why is it the most useful property in model compression?">

    When a large matrix has much lower rank than its shape allows, a low-rank approximation captures most of its behavior with far fewer numbers. LoRA is exactly this: it trains a rank-16 update rather than a full `4096 x 4096` matrix.

  </Accordion>
  <Accordion title="5. When would you use SVD instead of eigendecomposition?">

    Eigendecomposition needs a square matrix and behaves badly on non-symmetric ones. SVD works on any `m x n` matrix, gives non-negative singular values that already order importance, and produces the optimal low-rank approximation at any target rank.

  </Accordion>
  <Accordion title="6. What do the largest and smallest singular values of a weight matrix tell you?">

    The largest is the spectral norm, the maximum stretch the transform applies to a unit vector. The ratio `sigma_max / sigma_min` is the condition number: a large one means gradients scale differently along different directions, so plain gradient descent zigzags, which is why adaptive optimizers and preconditioning exist.

  </Accordion>
</Accordions>
