---
title: Tensor Broadcasting
description: Implicit dimension expansion rules, strides and contiguity, zero-copy views, and writing vectorized array code instead of Python loops.
---

Broadcasting lets arrays of different shapes combine element-wise without copying data. Every bias addition, positional encoding injection, and attention mask in a transformer depends on it. Misreading a broadcast rule is the single most common source of silent shape bugs in numerical code.

---

## The problem broadcasting solves

You have a batch of 8 token vectors, each 512 wide, and one shared bias vector of length 512. You want to add the bias to every row.

The naive version writes a loop:

```python title="loop_version.py"
import numpy as np

X = np.random.randn(8, 512)
b = np.random.randn(512)

out = np.empty_like(X)
for i in range(X.shape[0]):
    for j in range(X.shape[1]):
        out[i, j] = X[i, j] + b[j]
```

The broadcast version writes one expression:

```python title="broadcast_version.py"
out = X + b        # (8, 512) + (512,) -> (8, 512)
```

Both produce identical results. The broadcast version runs in compiled C over contiguous memory, typically one to two orders of magnitude faster, and it states the intent in six characters instead of five lines.

---

## The three rules

Broadcasting aligns shapes from the **trailing** dimension forward and checks each pair:

1. **Right-align the shapes.** Pad the shorter shape with leading 1s.
2. **Each dimension pair must match, or one of them must be 1.** A dimension of size 1 is stretched (virtually) to match the other.
3. **Missing leading dimensions count as 1.**

```
X.shape = (8, 512)
b.shape = (   512)     -> padded to (1, 512)

dim 1: 512 vs 512   match
dim 0:    8 vs   1   one of them is 1, stretch to 8

result: (8, 512)
```

No memory is allocated for the stretch. NumPy and PyTorch adjust the stride so the same 512 floats are read repeatedly.

### Worked shape examples

| A shape       | B shape    | Result        | Valid | Reason                                |
| :------------ | :--------- | :------------ | :---- | :------------------------------------ |
| `(8, 512)`    | `(512,)`   | `(8, 512)`    | Yes   | B padded to `(1, 512)`                |
| `(8, 512)`    | `(8, 1)`   | `(8, 512)`    | Yes   | Column vector stretched across        |
| `(8, 1)`      | `(1, 512)` | `(8, 512)`    | Yes   | Outer-product style expansion         |
| `(4, 8, 512)` | `(512,)`   | `(4, 8, 512)` | Yes   | B padded to `(1, 1, 512)`             |
| `(8, 512)`    | `(8,)`     | error         | No    | Trailing `512` vs `8` mismatch        |
| `(8, 512)`    | `(256,)`   | error         | No    | Trailing `512` vs `256`, neither is 1 |

The two failures are the ones that surprise people. `(8, 512)` and `(8,)` look compatible because they share the value 8, but broadcasting compares the **last** dimensions first: `512` against `8`. It fails rather than guessing.

To add an `(8,)` vector down the columns of an `(8, 512)` matrix, you must make the axis explicit:

```python title="explicit_axis.py"
X = np.random.randn(8, 512)
col = np.random.randn(8)

# X + col                     # ValueError
X + col[:, None]              # (8, 1) + (8, 512) -> (8, 512)
X + col.reshape(-1, 1)        # identical
# X + np.expand_dims(col, 0)  # (1, 8) vs (8, 512): trailing 8 vs 512, ValueError
```

`col[:, None]` inserts a new axis, turning `(8,)` into `(8, 1)`. Now the trailing dimensions are `1` vs `512`, which broadcasts correctly.

## The unsqueeze idiom

`None` in an index (equivalently `np.newaxis` or `torch.unsqueeze`) inserts a length-1 axis. This is how you choose which dimension broadcasts.

```python title="unsqueeze.py"
v = np.arange(6)          # shape (6,)

v[None, :]                # shape (1, 6)  - a row
v[:, None]                # shape (6, 1)  - a column
v[None, None, :]          # shape (1, 1, 6)

# pairwise difference matrix without a loop
diff = v[:, None] - v[None, :]     # (6, 6)
print(diff.shape)                  # (6, 6)
```

That last line builds a full `6 x 6` difference matrix in one operation. The same idiom at scale is how attention computes all pairwise query-key scores.

## Strides, contiguity, and views

A tensor in memory is a flat buffer plus a **shape** and a **stride**. The stride says how many elements to skip in the buffer to advance one step along each axis.

For a contiguous `(3, 4)` float array holding `[0..11]`:

```
shape  = (3, 4)
stride = (4, 1)      # skip 4 elements to move one row, 1 element to move one column
```

Element `(i, j)` sits at flat offset `i * 4 + j * 1`.

```python title="strides.py"
a = np.arange(12).reshape(3, 4)
print(a.strides)        # (32, 8) in bytes for int64 -> (4, 1) elements

t = a.T                 # transpose
print(t.shape)          # (4, 3)
print(t.strides)        # (8, 32) -> strides swapped
print(t.flags['C_CONTIGUOUS'])   # False
```

The transpose did not move any data. It swapped the strides, producing a **view** onto the same buffer. That is why it is free, and also why the result is no longer contiguous: walking down a column now jumps backwards through memory.

### When views are impossible

`reshape` returns a view when the stride math allows it and a copy when it does not. `view` in PyTorch refuses instead of silently copying:

```python title="reshape_vs_view.py"
import torch

x = torch.arange(12).reshape(3, 4)
y = x.t()                      # non-contiguous view, shape (4, 3)

z = y.reshape(12)              # works, silently copies
# w = y.view(12)               # RuntimeError: view size is not compatible

y2 = y.contiguous()            # explicit copy into contiguous layout
w = y2.view(12)                # now works, no further copy
```

<Callout type="warn">
  Prefer `.reshape()` in PyTorch when you do not care about aliasing, and `.view()` when you want an
  error instead of an unexpected allocation. A silent copy inside a training loop shows up as a
  mysterious memory and throughput regression, and it is easy to miss because the numbers stay
  correct.
</Callout>

### Broadcasting reads with zero stride

Broadcasting a length-1 dimension works by giving that axis a stride of 0. Advancing along it never moves in memory, so the same value is read repeatedly with no copy. That is the mechanism behind `X + b` costing no more memory than `X`.

## Broadcasting in transformer code

Four places this appears constantly.

**Bias addition.** A `(batch, seq, d_model)` activation plus a `(d_model,)` bias:

```python title="bias_add.py"
act = np.random.randn(2, 128, 512)     # batch 2, 128 tokens, d_model 512
bias = np.random.randn(512)
out = act + bias                       # (2, 128, 512)
```

**Positional encoding.** Adding a `(seq, d_model)` table to a `(batch, seq, d_model)` activation:

```python title="positional.py"
pos = np.random.randn(128, 512)        # one position table shared by the batch
out = act + pos                        # (2, 128, 512)
```

**Attention masking.** A causal mask of shape `(seq, seq)` applied to scores of shape `(batch, heads, seq, seq)`:

```python title="causal_mask.py"
seq = 8
scores = np.random.randn(2, 4, seq, seq)          # batch 2, 4 heads
mask = np.triu(np.full((seq, seq), -np.inf), k=1) # upper triangle is -inf

masked = scores + mask                            # broadcasts to (2, 4, 8, 8)
```

The mask has no batch or head dimension, so one `(8, 8)` matrix serves all 8 attention planes. Phase 5 builds exactly this.

**Normalization.** RMSNorm divides each vector by its own root-mean-square, computed per row with `keepdims`:

```python title="rmsnorm.py"
x = np.random.randn(2, 128, 512)
rms = np.sqrt(np.mean(x ** 2, axis=-1, keepdims=True))   # (2, 128, 1)
out = x / rms                                            # (2, 128, 512)
```

`keepdims=True` is what makes this work. Without it, `np.mean(..., axis=-1)` returns shape `(2, 128)` and the division fails the trailing-dimension check. Keeping the reduced axis as length 1 leaves it ready to broadcast back.

<Callout type="info">
  `keepdims=True` on any reduction is the standard trick for broadcasting a statistic back against
  the tensor it came from. Batch statistics, softmax denominators, and attention normalizers all
  rely on it.
</Callout>

## Vectorization and performance

Broadcasting is not only shorter, it is faster, for three reasons:

1. **The loop runs in compiled code** rather than in the Python interpreter, which costs tens of nanoseconds per iteration.
2. **Memory access stays contiguous**, so CPU caches and GPU memory coalescing work as designed.
3. **No intermediate Python objects** are created per element.

A rough measurement on a `(1024, 1024)` matrix:

```python title="timing.py"
import time
import numpy as np

X = np.random.randn(1024, 1024)
b = np.random.randn(1024)

start = time.perf_counter()
loop_out = np.empty_like(X)
for i in range(X.shape[0]):
    for j in range(X.shape[1]):
        loop_out[i, j] = X[i, j] + b[j]
loop_time = time.perf_counter() - start

start = time.perf_counter()
vec_out = X + b
vec_time = time.perf_counter() - start

print(f"loop: {loop_time*1e3:.2f} ms   vectorized: {vec_time*1e3:.2f} ms")
print(np.allclose(loop_out, vec_out))
```

The scalar double loop is roughly 100x to 500x slower on typical hardware, because it runs a million Python interpreter iterations instead of one compiled pass. Even a partially vectorized row loop (`loop_out[i] = X[i] + b`) is measurably slower than the single expression. On a GPU the gap widens further, since a Python loop forces per-element kernel launches or a transfer back to host memory.

### Accidental memory blowups

Broadcasting can also allocate more than you expect. `(1000, 1)` against `(1, 1000)` produces a `(1000, 1000)` result, a million elements from two thousand inputs:

```python title="outer_product.py"
a = np.random.randn(1000, 1)
b = np.random.randn(1, 1000)
c = a * b
print(c.nbytes / 1e6)     # 8.0 MB for float64
```

That is legitimate when you want an outer product. In attention, the same expansion over `(batch, heads, seq, seq)` is the reason attention memory grows as `O(N^2)` and why Phase 6 discusses context window limits. FlashAttention exists specifically to avoid materializing that broadcast result.

## Interview questions

<Accordions>
  <Accordion title="1. State the broadcasting algorithm in two sentences.">

    Align the two shapes by their trailing dimensions, and every position must either be equal or have one of the two entries equal to 1. Any operand with fewer dimensions is padded with 1s on the left, then the output takes the non-1 size at each position.

  </Accordion>
  <Accordion title="2. Why does adding a shape `(3, 1)` to a shape `(1, 4)` produce `(3, 4)` instead of an error?">

    Both positions are compatible because each operand has a 1 where the other has a real size. The output takes 3 from the first and 4 from the second, so the addition computes every row-column pair: an outer product.

  </Accordion>
  <Accordion title="3. Which of `(4, 3)` plus `(4,)`, and `(4, 3)` plus `(3,)`, broadcasts?">

    Only the second. A 1-D operand aligns against the trailing axis, so `(4,)` is compared to 3 and fails because 4 is neither 3 nor 1, while `(3,)` matches. This is why `X.T @ w` errors on a 1-D bias but `X @ w` succeeds.

  </Accordion>
  <Accordion title="4. Why is `keepdims=True` load-bearing in a softmax or RMSNorm implementation?">

    A plain reduction returns `(B, S)` and the thing it must divide, `(B, S, V)`, is left unaligned. Keeping the reduced axis as 1 preserves a shape that broadcasts back over the array being normalized. Forgetting it is one of the most common shape bugs in hand-written layers.

  </Accordion>
  <Accordion title="5. How do you tell whether an operation returned a view or a copy, and why does it matter?">

    `reshape` and `permute` return views that share storage, `clone`, `contiguous` and `einsum` outputs are fresh allocations. Views alias, so writing through one changes the other and in-place ops corrupt an operand, which is why PyTorch raises rather than guess when a view's base has been edited.

  </Accordion>
  <Accordion title="6. Why does `X.transpose(0, 1).view(X.shape[1], X.shape[0])` throw when the transpose clearly has the right shape?">

    The transposed tensor has strides `[1, 256]`, and a `view` only relabels dimensions; it cannot express that layout in row-major order without physically moving elements. The fix is `contiguous()`, which pays for a real copy.

  </Accordion>
  <Accordion title="7. A broadcast has a stride of 0 on an axis. What does that mean?">

    Repeated elements cost no memory: every position along that axis indexes the same value. `X[0, None, :].stride()` returns `(1280, 0, 1)`, where the 0 is the size-1 axis being stretched.

  </Accordion>
  <Accordion title="8. What is the difference in cost between `(N, 1) * (1, N)` and a bias addition?">

    Both broadcast, but the first materializes `N * N` elements from `2N` inputs, which is 50x at N = 1000 and 2500x at N = 5000, while a bias adds `(d,)` to `(B, S, d)` and leaves the output at `(B, S, d)`. Self-attention is the legitimate quadratic case; a similarity grid built only to feed a threshold is usually the mistake.

  </Accordion>
  <Accordion title="9. Why does doubling the context length quadruple attention memory while the feed-forward layer only doubles?">

    Scores are one number per token pair, so the array is `S x S` for every batch and head. A projection scales `S * d * d`, which is linear in `S` because `d` is fixed. That gap is what FlashAttention closes by never materializing the score matrix.

  </Accordion>
</Accordions>
