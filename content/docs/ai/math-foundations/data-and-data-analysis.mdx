Every model learns from data, and every claim about a model is a claim about data: "the loss went down", "accuracy is 94%", "this input looks unusual". Statistics is the language for those claims. It answers three questions: what does this data look like, how sure can we be about it, and is this one value normal or strange?

The rest of the notes lean on this group of pages without saying so. Normalization layers subtract a mean and divide by a standard deviation. Weight initialization picks a variance. Evaluation reports an average over a sample of test questions. Drift monitoring compares two distributions. And outlier detection, covered in the [outlier pages](/ai/math-foundations/outlier-fundamentals), is built directly on the spread measures defined here.

No formula on these pages needs more than arithmetic. Every number in the examples was printed by the code next to it.

This is the first of five pages: this one says what data is and how it is described, then [Descriptive Statistics](/ai/math-foundations/descriptive-statistics), [Probability and Distributions](/ai/math-foundations/probability-and-distributions), [Exploratory Data Analysis](/ai/math-foundations/exploratory-data-analysis), and [Data Preprocessing](/ai/math-foundations/data-preprocessing).

## What is data?

**Data** is recorded observations of the world: numbers, words, categories, images, sounds, clicks, timestamps. One recorded value is a **datum**; the plural is data. A **dataset** is a collection of observations gathered for a purpose.

Most datasets are easiest to picture as a table:

| Term in statistics          | Term in ML                      | Term in databases | Meaning                                                 |
| :-------------------------- | :------------------------------ | :---------------- | :------------------------------------------------------ |
| **Observation**, unit, case | Example, sample, data point     | Row, record       | One thing that was measured: a customer, a transaction  |
| **Variable**, attribute     | Feature (input), label (output) | Column, field     | One property measured on every observation: age, amount |
| **Value**                   | Feature value                   | Cell              | One variable's measurement on one observation           |

So "10,000 transactions with 4 features and a fraud label" is a table of 10,000 rows, 4 input columns, and 1 output column. The same three words cover data that is not a table: in a text corpus each document is an observation, and in an image dataset each pixel's brightness is a value.

**Data versus information.** Data is the raw record: `38.9`. Information is data with context that makes it mean something: "the patient's temperature is 38.9 °C, which is a fever". Analysis is the work of turning the first into the second.

**Where data comes from.** Measurements (sensors, instruments), transactions (purchases, logs), surveys and forms, human labelling, and, for language models, text collected from the web, books, and code. How data was collected decides what it can tell you. A survey answered only by people who chose to answer describes those people, not everyone.

## What is data analysis?

**Data analysis** is inspecting, cleaning, summarizing, and modelling data to answer a question or support a decision. It comes in four kinds, each answering a harder question than the last:

| Kind             | Question it answers         | Example                                         |
| :--------------- | :-------------------------- | :---------------------------------------------- |
| **Descriptive**  | What happened?              | Average order value last month was 42 dollars   |
| **Diagnostic**   | Why did it happen?          | Orders fell because the checkout page was slow  |
| **Predictive**   | What is likely to happen?   | This transaction has a 3% chance of being fraud |
| **Prescriptive** | What should we do about it? | Hold transactions above 2% risk for review      |

Machine learning lives mostly in the predictive row. The other three rows are what you do before and after training a model: describe the data, find out why a model fails, and decide what to do with its outputs.

**The workflow.** Every analysis, from a spreadsheet to an LLM pretraining run, follows the same loop:

<Mermaid
  chart={`
flowchart LR
    Q["1. Ask a question"] --> C["2. Collect data"]
    C --> P["3. Clean and preprocess"]
    P --> E["4. Explore (EDA)"]
    E --> M["5. Model or test"]
    M --> R["6. Communicate the result"]
    R -->|"new question"| Q
    E -->|"data problem found"| P
`}
/>

Steps 3 and 4 usually take most of the time. A model trained on data that was never explored inherits every problem in it.

**Data analysis, data science, and ML.** Data analysis answers questions about data you have. Data science adds programming and modelling at scale. Machine learning is the part where a program learns a function from data so it can make predictions on data it has not seen. The statistics on this page are shared by all three.

## Structured, semi-structured, and unstructured data

| Kind                | Shape                                            | Examples                              | How a model reads it                                    |
| :------------------ | :----------------------------------------------- | :------------------------------------ | :------------------------------------------------------ |
| **Structured**      | Fixed columns, one value per cell                | SQL tables, CSV files, spreadsheets   | Directly, after encoding categories and scaling numbers |
| **Semi-structured** | Labelled fields, but nesting and optional fields | JSON, XML, logs, HTML                 | Flattened into columns, or read as text                 |
| **Unstructured**    | No predefined fields                             | Free text, PDFs, images, audio, video | Converted to vectors by a learned model (an embedding)  |

Classical ML, including most outlier detection, works on structured data. Deep learning made unstructured data usable, because a network learns its own features from pixels or tokens. Most of the world's data is unstructured, which is why language and vision models matter. Turning documents into usable pieces is the subject of [Parsing and Extraction](/ai/rag/parsing-and-extraction) in the RAG phase.

## Population versus sample

The **population** is every item you want to draw a conclusion about: all transactions your bank will ever process, all users of an app, all questions people will ask a chatbot. You almost never have the whole population. You have a **sample**: the subset you actually measured.

| Word          | Describes      | Symbol        | Example                                         |
| :------------ | :------------- | :------------ | :---------------------------------------------- |
| **Parameter** | The population | `mu`, `sigma` | The true average transaction amount (unknown)   |
| **Statistic** | The sample     | `x̄`, `s`      | The average of the 10,000 transactions you have |

The whole point of a sample is to **estimate** the population's parameters. That only works if the sample is **representative**. **Sampling bias** breaks it: training a fraud model only on transactions from one country, or evaluating a chatbot only on questions the team wrote. A train and test split is exactly this idea. The test set is a sample that stands in for future data, and a test score is an estimate, not a fact.

**Why sample variance divides by `n - 1`.** The sample mean is computed from the same data, so the data sits closer to its own mean than to the true population mean. Dividing by `n` therefore underestimates the spread on average. Dividing by `n - 1` (Bessel's correction) removes that bias. In NumPy, `ddof=0` divides by `n` and `ddof=1` divides by `n - 1`. With large `n` the difference disappears.

## Data types

The type of a variable decides which statistics and which encodings make sense.

<Mermaid
  chart={`
flowchart TD
    D["Variable"] --> N["Numerical (quantitative)"]
    D --> C["Categorical (qualitative)"]
    N --> ND["Discrete: counts. 0, 1, 2 children"]
    N --> NC["Continuous: measurements. 72.4 kg"]
    C --> CN["Nominal: no order. red, green, blue"]
    C --> CO["Ordinal: ordered. small, medium, large"]
`}
/>

- **Numerical** values are quantities, so arithmetic on them is meaningful. **Discrete** ones are counts and take whole values. **Continuous** ones are measurements and can take any value in a range.
- **Categorical** values are labels. **Nominal** categories have no order. **Ordinal** categories have an order, but the gaps between them are not equal or known: the step from "poor" to "fair" is not necessarily the same size as "good" to "excellent".
- **Binary** (yes or no) is a categorical variable with two values, often stored as 0 and 1.

**Levels of measurement** refine this into four steps. Each level allows everything the one before it does, plus one more operation:

| Level        | What you can do                      | Example                          | Meaningful center  |
| :----------- | :----------------------------------- | :------------------------------- | :----------------- |
| **Nominal**  | Count, check equal or not            | Country, product ID              | Mode               |
| **Ordinal**  | Also order                           | Ratings 1 to 5, education level  | Median, mode       |
| **Interval** | Also add and subtract                | Temperature in °C, calendar year | Mean, median, mode |
| **Ratio**    | Also multiply and divide (true zero) | Height, price, duration          | All, plus ratios   |

The interval and ratio difference catches people out: 20 °C is not "twice as hot" as 10 °C, because 0 °C is not "no temperature". 20 kg is twice 10 kg, because 0 kg means no mass.

Why this matters for AI: a model multiplies its inputs by weights, so it treats every input as a ratio-level number. Feeding it a nominal category as an integer (`red = 0, green = 1, blue = 2`) tells it that blue is twice green. [Encoding and Decoding](/ai/math-foundations/encoding-and-decoding#encoding-categories) covers the fixes.

## Interview questions

<Accordions>
  <Accordion title="What is the difference between a population and a sample, and a parameter and a statistic?">

    The population is every item you want to draw conclusions about; the sample is the part you measured. A parameter describes the population (the true mean, usually unknown); a statistic is computed from the sample (the sample mean) and estimates the parameter. The estimate is only trustworthy if the sample is representative. A test set is a sample standing in for future data.

  </Accordion>
  <Accordion title="Why does sample variance divide by n - 1?">

    The sample mean is fitted to the same data, so squared distances to it are on average smaller than distances to the true mean. Dividing by `n` underestimates the population variance; dividing by `n - 1` (Bessel's correction) makes the estimate unbiased. The data has `n - 1` degrees of freedom left after estimating the mean.

  </Accordion>
  <Accordion title="What are the levels of measurement, and why do they matter for a model?">

    Nominal (labels, no order), ordinal (ordered, unequal gaps), interval (equal gaps, no true zero, like °C), and ratio (true zero, like kilograms). Each allows more operations than the last. A model multiplies inputs by weights, so it treats every input as ratio-level; a nominal category fed in as an integer gets a fake order and fake distances, which is why categories are one-hot encoded or embedded.

  </Accordion>
</Accordions>
