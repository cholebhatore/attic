## Isolation Forest

**Idea.** Anomalies are few and different, so they are **easy to isolate**. Build random trees: at each node pick a random feature and a random split value between its min and max, and keep splitting until each point is alone. A point in a dense crowd needs many splits to separate. An anomaly is cut off in a few. The **average path length** over many trees is the score: short path, likely anomaly. (Liu, Ting, and Zhou, _Isolation Forest_, ICDM 2008.)

- **Strengths**: fast (each tree uses a small random subsample, 256 rows by default), scales to large data and many features, needs no distance metric and no scaling.
- **Weaknesses**: weaker on **local** outliers that sit just outside a dense cluster, and on anomalies that only differ in a combination of features that axis-aligned cuts struggle with.
- **The go-to first method** for tabular data.

## Local Outlier Factor (LOF)

**Idea.** Compare each point's **local density** with the density of its `k` nearest neighbours. A point in a sparse spot surrounded by dense neighbours has a LOF well above 1; a point as dense as its neighbours has LOF near 1. (Breunig, Kriegel, Ng, and Sander, _LOF_, SIGMOD 2000.)

- **Strengths**: finds **local** outliers in data whose clusters have different densities, the case where a single global threshold fails.
- **Weaknesses**: needs a distance metric and scaled features, is slow on large data (nearest-neighbour search), and is sensitive to `k`.

---

## One-Class SVM

**Idea.** Learn a boundary around the normal data in a kernel feature space, so that most training points are inside. Points outside are anomalies. The parameter `nu` is an upper bound on the fraction of training points left outside. (Schölkopf et al., _Estimating the Support of a High-Dimensional Distribution_, Neural Computation 2001.)

- **Strengths**: flexible curved boundaries; a natural fit for **novelty** detection on clean training data.
- **Weaknesses**: very sensitive to the kernel width `gamma` and to `nu`, needs scaled features, and training scales poorly beyond tens of thousands of rows.

---

## DBSCAN

**Idea.** A clustering algorithm that also labels noise. A **core point** has at least `min_samples` neighbours within distance `eps`. Clusters grow from core points. Points not reachable from any core point are labelled **noise** (`-1`), which serves as the outlier set. (Ester, Kriegel, Sander, and Xu, KDD 1996.)

- **Strengths**: finds clusters of any shape and does not need the number of clusters.
- **Weaknesses**: one `eps` for the whole dataset, so clusters of different densities break it: an `eps` that suits a tight cluster calls the edges of a loose cluster noise. Outputs a label, not a graded score.

---

## Autoencoders

**Idea.** An [autoencoder](/ai/math-foundations/encoding-and-decoding#encoder-and-decoder-networks) compresses each input into a small code and rebuilds it. Train it on normal data only. It learns to rebuild normal patterns well, and rebuilds anything unlike them badly. The **reconstruction error** is the anomaly score.

- **Strengths**: works on images, sequences, logs, and very high-dimensional data; learns non-linear structure.
- **Weaknesses**: needs mostly clean training data and tuning. If it is too powerful, it learns to rebuild anomalies as well (it learns the identity). Errors are hard to explain.
- **The linear case is PCA.** A linear autoencoder trained with squared error spans the same subspace as the top principal components (Baldi and Hornik, 1989). PCA reconstruction error is therefore a cheap baseline, used in the [fraud detection project](/ai/math-foundations/fraud-detection-project).

## Four detectors on the same data

Two clusters, one tight and one loose, plus three planted outliers: two **global** ones far from everything, and one **local** one just outside the tight cluster. Each method gives every point a score, and the code prints where each planted point ranks among all 303 (rank 1 is the most anomalous).

```python
import numpy as np
from sklearn.cluster import DBSCAN
from sklearn.ensemble import IsolationForest
from sklearn.neighbors import LocalOutlierFactor
from sklearn.svm import OneClassSVM

rng = np.random.default_rng(42)
dense = rng.normal([0, 0], 0.3, size=(150, 2))     # a tight cluster
loose = rng.normal([4, 4], 1.2, size=(150, 2))     # a spread-out cluster
planted = np.array([[-2.0, 3.0], [6.0, -1.0],      # global outliers: far from everything
                    [1.5, 0.0]])                   # local outlier: close, but far for the tight cluster
X = np.vstack([dense, loose, planted])              # both axes share one unit, so no scaling


def rank(scores):
    """Rank of each planted point among all 303, where 1 is the most anomalous."""
    order = np.argsort(-scores)
    return [int(np.flatnonzero(order == i)[0]) + 1 for i in range(len(X) - 3, len(X))]


scores = {
    "Isolation Forest": -IsolationForest(random_state=0).fit(X).score_samples(X),
    "Local Outlier Factor": -LocalOutlierFactor(n_neighbors=20).fit(X).negative_outlier_factor_,
    "One-Class SVM": -OneClassSVM(nu=0.05, gamma=0.1).fit(X).decision_function(X),
}
for name, s in scores.items():
    print(f"{name:21s} ranks of [global, global, local]: {rank(s)}")

labels = DBSCAN(eps=0.6, min_samples=5).fit_predict(X)
print(f"DBSCAN                planted points labelled noise: {(labels[-3:] == -1).tolist()}  "
      f"other noise points: {int((labels[:-3] == -1).sum())}")
```

```text
Isolation Forest      ranks of [global, global, local]: [2, 1, 17]
Local Outlier Factor  ranks of [global, global, local]: [1, 3, 2]
One-Class SVM         ranks of [global, global, local]: [2, 1, 14]
DBSCAN                planted points labelled noise: [True, True, True]  other noise points: 14
```

All four find the global outliers. Only LOF ranks the local outlier near the top (2nd). Isolation Forest and One-Class SVM rank it 17th and 14th, behind ordinary points, mostly at the edge of the loose cluster, because by absolute distance the loose cluster's edges look more isolated. DBSCAN catches all three, but also calls 14 normal points noise: its single `eps` suits the tight cluster and treats the loose cluster's edges as outliers. No method wins everywhere, which is why the comparison table matters more than any single result.

## Choosing a method

| Method                   | Defines an outlier as               | Global or local | Scale needed? | Large data | Typical use                                    |
| :----------------------- | :---------------------------------- | :-------------- | :------------ | :--------- | :--------------------------------------------- |
| **Z / modified z / IQR** | Far from center on one feature      | Global          | No            | Yes        | Quick checks per column, data cleaning         |
| **Mahalanobis**          | Far from center, given correlations | Global          | No            | Yes        | Few correlated numeric features, one cluster   |
| **Isolation Forest**     | Quick to isolate with random cuts   | Mostly global   | No            | Yes        | First choice for tabular data, fraud           |
| **LOF**                  | Less dense than its neighbours      | Local           | Yes           | Slow       | Clusters of different densities                |
| **One-Class SVM**        | Outside a learned boundary          | Global          | Yes           | Slow       | Novelty detection on small, clean data         |
| **DBSCAN**               | Not in any dense cluster            | Global          | Yes           | Medium     | When you also want the clusters                |
| **Autoencoder**          | Hard to reconstruct                 | Either          | Yes           | Yes (GPU)  | Images, sequences, logs, high-dimensional data |

When labels exist, even a few hundred, a **supervised** classifier (gradient-boosted trees) usually beats every unsupervised method, because it learns what the anomalies you care about look like rather than what "unusual" means in general. Unsupervised detectors are for when labels are missing, too few, or the anomalies keep changing. Many production systems use both: an unsupervised score becomes one feature of the supervised model.

## Interview questions

<Accordions>
  <Accordion title="How does Isolation Forest work, and why is it fast?">

    It builds random trees that split on a random feature at a random value until points are isolated. Anomalies are few and different, so they are isolated in fewer splits; the average path length across trees is the score. Each tree is built on a small subsample (256 rows by default) and needs no distances, so it is fast and scales to large, high-dimensional data. It is weaker on local outliers.

  </Accordion>
  <Accordion title="When would you use LOF instead of Isolation Forest?">

    When the data has clusters of different densities and the anomalies are local: a point just outside a tight cluster is normal by global distance but sparse relative to its neighbours. LOF compares each point's density with its neighbours' density. In the four-detector example, LOF ranked the local outlier 2nd while Isolation Forest ranked it 17th. LOF needs scaled features and is slower on large data.

  </Accordion>
  <Accordion title="How do you use an autoencoder for anomaly detection?">

    Train it on normal data to compress and reconstruct its input. Normal points are reconstructed well, anomalies poorly, so reconstruction error is the anomaly score; set the threshold on a validation set. Risks: if the training data contains anomalies, or the network is too powerful, it learns to reconstruct them too. PCA reconstruction error is the linear version and a good baseline.

  </Accordion>
</Accordions>
