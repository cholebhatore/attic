## The field map

The names nest inside each other. Most confusion about "is this AI or ML?" goes away once you see them as circles inside circles.

<Mermaid
  chart={`
flowchart TD
    AI["Artificial Intelligence: any system that does tasks we associate with intelligence"] --> ML["Machine Learning: the system learns the rules from data instead of being hand-coded"]
    ML --> DL["Deep Learning: machine learning with many-layered neural networks"]
    DL --> GEN["Generative AI: models that produce new text, images, audio, or code"]
    GEN --> LLM["Large Language Models: very large neural networks trained on text"]
`}

| Term                                  | Plain meaning                                                                                                                                 | Example                                                 |
| :------------------------------------ | :-------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------ |
| **AI** (Artificial Intelligence)      | The broad goal: make computers do things that seem to need intelligence. Includes hand-written rules, not only learning.                      | A chess engine, a spam filter, ChatGPT                  |
| **ML** (Machine Learning)             | The subset of AI where the program **learns its behavior from examples** instead of a person writing every rule.                              | A spam filter trained on 100k labeled emails            |
| **DL** (Deep Learning)                | ML with **neural networks** that stack many layers. "Deep" means many layers, not deep understanding.                                         | Image classifiers, speech recognition, every modern LLM |
| **NLP** (Natural Language Processing) | The field of AI that enables computers to **understand, interpret, and generate human language**, both text and speech.                       | Translation, sentiment analysis, search, chatbots       |
| **CV** (Computer Vision)              | The field of AI that works with images and video.                                                                                             | Face detection, self-driving perception                 |
| **Generative AI**                     | Models whose output is new content rather than a label or a number.                                                                           | Text generation, image generation                       |
| **LLM** (Large Language Model)        | A deep learning model, almost always a **transformer**, trained on a huge amount of text to predict the next token. It is where NLP is today. | GPT-4, Claude, Llama, Qwen                              |

**NLP and CV are fields, organized by the kind of data. ML and DL are methods, organized by how the system learns.** Modern NLP is done with deep learning, but NLP existed before machine learning did: early translation systems were thousands of hand-written grammar rules.

<Callout type="warn">
  ### Interview pitfall

"AI" and "ML" are not synonyms. A rule-based system with no learning at all is still AI. Every ML system is AI; not every AI system is ML. Interviewers ask this to see whether you know where the circles nest.

</Callout>

## Data

Every ML system starts from a **dataset**, a collection of examples to learn from.

| Term                           | Plain meaning                                                                                    | House-price example                              |
| :----------------------------- | :----------------------------------------------------------------------------------------------- | :----------------------------------------------- |
| **example** (sample, instance) | One item in the dataset. One row.                                                                | One house                                        |
| **feature**                    | One measurable input property of an example. The list of features is the example's input vector. | bedrooms, square feet, balconies: `[3, 1625, 2]` |
| **label** (target)             | The correct answer for that example, the thing you want the model to predict.                    | The sale price                                   |
| **prediction**                 | What the model outputs for an example. Training tries to make it match the label.                | The model's price estimate                       |

The house vector `[3, 1625, 2]` on [Vectors and Matrices](/ai/math-foundations/vectors-and-matrices) is exactly a feature vector. Turning real things into feature vectors is the first step of every system, which is why the next pages are all about vectors.

**The three-way split.** You never measure a model on the data it learned from, because it might have memorized it. The dataset is split before training:

| Split          | Typical share | Used for                                                                    |
| :------------- | :------------ | :-------------------------------------------------------------------------- |
| **training**   | ~80%          | The model learns from it. Its weights are adjusted to fit these examples.   |
| **validation** | ~10%          | You check progress and choose settings (learning rate, model size) with it. |
| **test**       | ~10%          | Touched once, at the end, to report how well the model does on unseen data. |

The shares are a common convention, not a rule. Large datasets often hold back far less than 10%.

<Callout type="warn">
  ### Common mistake: data leakage

If any test example (or a near-duplicate) slips into training, the test score measures memory, not skill. The model looks great on paper and fails on real users. Split first, then do anything else.

</Callout>

## Kinds of learning

The kind of learning is decided by **what the labels look like and where they come from**.

| Kind                       | Where the answer comes from                                                                         | Example                                                                     |
| :------------------------- | :-------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------- |
| **Supervised**             | A human attached a label to every example.                                                          | Emails labeled spam or not spam                                             |
| **Unsupervised**           | No labels. The model finds structure on its own.                                                    | Grouping customers into clusters by behavior                                |
| **Self-supervised**        | The labels are **cut out of the data itself**, so no human labeling is needed.                      | Hide the next word of a sentence and predict it. This is how LLMs pretrain. |
| **Reinforcement learning** | No correct answer, only a **reward** after acting. The model learns which actions earn more reward. | A game-playing agent; tuning an LLM toward answers people prefer            |

Supervised problems come in two shapes, and the shape decides the last layer and the loss function later in the phase:

- **Classification**: the label is one of a fixed set of categories. Spam or not spam. Which of 50,000 tokens comes next. The model outputs one score per category, and [Softmax and Logits](/ai/math-foundations/softmax-and-logits) turns those scores into probabilities.
- **Regression**: the label is a number on a continuous scale. A house price. A temperature.

Self-supervised learning is the reason LLMs exist at all. Labeling the internet by hand is impossible, but every sentence on it already contains its own answers: each word is the label for the words before it.

## The model

A **model** is a function with adjustable numbers inside it. Data goes in, a prediction comes out, and the adjustable numbers decide which prediction.

| Term                    | Plain meaning                                                                                                                                                      |
| :---------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **parameters**          | The adjustable numbers the model **learns** during training. "A 7B model" has about 7 billion of them.                                                             |
| **weights**             | The parameters that multiply inputs. They decide how much each input matters. Most parameters are weights.                                                         |
| **bias**                | A parameter that is **added** rather than multiplied, letting the output shift away from zero. Nothing to do with social bias.                                     |
| **hyperparameters**     | Settings **you** choose before training, which the model never learns: learning rate, batch size, number of layers.                                                |
| **neuron**              | The smallest unit: multiply each input by a weight, add them up, add a bias, then apply an activation function.                                                    |
| **activation function** | A simple function like ReLU (`max(0, x)`) applied after the weighted sum. It bends the output, which lets the network learn curves instead of only straight lines. |
| **layer**               | Many neurons side by side reading the same inputs. Mathematically one matrix multiply plus a bias: `y = Wx + b`.                                                   |
| **neural network**      | Layers stacked so each one's output is the next one's input. "Deep" when there are many.                                                                           |
| **architecture**        | The design of the network: which layers, in what order, how wide. Transformer, CNN, and RNN are architectures.                                                     |
| **checkpoint**          | The saved parameter values at some point in training. "Downloading a model" means downloading a checkpoint.                                                        |

The **dial analogy** carries through the whole phase: a model is a machine with billions of dials (the parameters), and training is the process of turning every dial to a good position. You set how fast the dials turn and how big the machine is; those are the hyperparameters.

<Callout type="info">
  ### Why the math pages care about layers

A layer is `y = Wx + b`, which is a matrix times a vector plus a vector. That one line is why [Vectors and Matrices](/ai/math-foundations/vectors-and-matrices) comes before anything else: understanding the matrix is understanding the layer.

</Callout>

<Callout type="warn">
  ### Interview pitfall

Parameters versus hyperparameters. The learning rate is a hyperparameter, not a parameter: no gradient ever touches it. "How many parameters does the model have?" never counts the learning rate.

</Callout>

## Training and inference

A model's life has two phases. **Training** adjusts the parameters. **Inference** uses the finished parameters to make predictions. Training happens once (and is expensive); inference happens every time someone uses the model.

Training is one loop, repeated millions of times:

<Steps>
<Step>

**Forward pass.** Feed a batch of examples through the network and get predictions.

</Step>
<Step>

**Loss.** Compare predictions to labels and reduce "how wrong" to one number, the **loss**. Lower is better.

</Step>
<Step>

**Backward pass.** Compute the **gradient**: for every parameter, which direction to move it to lower the loss, and how strongly.

</Step>
<Step>

**Update.** Move every parameter a small step against its gradient. Then repeat with the next batch.

</Step>
</Steps>

| Term                       | Plain meaning                                                                                                                                                                  |
| :------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **loss** (cost, objective) | One number measuring how wrong the predictions are. Training is the search for parameters that make it small.                                                                  |
| **gradient**               | The list of "which way and how much" for every parameter, computed with derivatives.                                                                                           |
| **gradient descent**       | The update rule: `new weight = old weight - learning rate * gradient`. Walk downhill on the loss.                                                                              |
| **learning rate**          | The step size of each update. Too large and training jumps around or blows up; too small and it crawls.                                                                        |
| **optimizer**              | The algorithm that performs the update. Plain gradient descent (SGD) is the simplest; Adam and AdamW are the common defaults.                                                  |
| **backpropagation**        | The algorithm that computes every gradient efficiently in one backward sweep through the network, using the chain rule.                                                        |
| **batch**                  | The group of examples processed together in one step, for speed. Batch size is how many.                                                                                       |
| **step** (iteration)       | One forward pass, backward pass, and update on one batch.                                                                                                                      |
| **epoch**                  | One full pass over the entire training set. 10,000 examples with a batch size of 100 is 100 steps per epoch.                                                                   |
| **overfitting**            | The model memorized the training set, including its noise, and does worse on new data. Training loss keeps falling while validation loss rises.                                |
| **underfitting**           | The model is too simple or trained too little to capture the pattern. Both losses stay high.                                                                                   |
| **generalization**         | How well the model performs on data it never saw. The actual goal of training.                                                                                                 |
| **regularization**         | Any technique that discourages overfitting, such as penalizing large weights. [Similarity and Norms](/ai/math-foundations/similarity-and-norms) covers the L1 and L2 versions. |

Each step of the loop is one page of this phase: the forward pass is matrix math, the loss comes from [Information Theory and Loss](/ai/math-foundations/information-the-and-loss), the gradient from [Derivatives and Gradients](/ai/math-foundations/derivatives-and-gradients), and the backward pass from [Backprop from Scratch](/ai/math-foundations/backprop-from-scratch).

<Callout type="warn">
  ### Common mistake: reading training loss as success

A falling training loss only says the model fits the data it has seen. Always watch validation loss next to it. When the two curves split apart, the model has started memorizing.

</Callout>

## Language: from text to vectors

Neural networks only do arithmetic, so text has to become numbers before a model can touch it. The path is always the same:

```text
"The cat sits"  ->  tokens ["The", " cat", " sits"]  ->  IDs [464, 3797, 10718]  ->  one vector per token
     text              tokenization                      lookup in vocabulary         embedding lookup
```

The IDs above are illustrative. Real values depend on the tokenizer.

| Term                | Plain meaning                                                                                                                                                                                                     |
| :------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **corpus**          | The body of text a model learns from. Plural **corpora**. Wikipedia is a corpus; so is "every email in this inbox".                                                                                               |
| **token**           | The unit a model reads and writes. Usually a word or a piece of one: `"unbelievable"` may split into `"un"`, `"believ"`, `"able"`. About three quarters of an English word on average, by OpenAI's rule of thumb. |
| **tokenization**    | Splitting text into tokens. The tokenizer is fixed before training and never changes afterwards.                                                                                                                  |
| **vocabulary**      | The fixed list of every token the model knows, each with an integer ID. Its size is written `V`: GPT-2's is 50,257 (Radford et al., 2019).                                                                        |
| **one-hot vector**  | A vector of length `V` with a 1 at the token's ID and 0 everywhere else. Identifies a token but says nothing about its meaning.                                                                                   |
| **encoding**        | A fixed, hand-written rule that turns data into numbers, such as UTF-8 bytes, token IDs, or one-hot vectors. Nothing is learned.                                                                                  |
| **embedding**       | A short, dense vector of learned numbers that represents a token (or sentence, or image) so that **similar meanings get similar vectors**.                                                                        |
| **embedding space** | The space all those vectors live in. "Close together in embedding space" means "similar in meaning".                                                                                                              |

**Why one-hot is not enough.** With one-hot vectors every pair of different words is equally unrelated: the dot product of `cat` and `dog` is 0, and so is the dot product of `cat` and `carburetor`. An embedding fixes that by giving `cat` and `dog` nearby vectors. It is also far shorter: a few hundred numbers instead of 50,000.

[Tokenization](/ai/llm/tokenization) in the LLM phase covers how tokenizers are built.

### Encoding versus embedding

Both words describe "turning something into numbers", and they are often mixed up. The difference is **who decides the numbers**.

- An **encoding** is a **fixed rule**, written by a person and never trained. The same input always gives the same numbers, in every model, before and after training. It makes data machine-readable but adds no knowledge about meaning.
- An **embedding** is a **learned vector**. Its numbers are parameters, adjusted by gradient descent during training, and they end up placing related things close together. Two models trained on different data give different embeddings for the same word.

The common encodings you will meet:

| Encoding                           | What the rule does                                                                | Example                                                     |
| :--------------------------------- | :-------------------------------------------------------------------------------- | :---------------------------------------------------------- |
| **character encoding** (UTF-8)     | Maps each character to bytes, so text can be stored at all.                       | `"café"` becomes the bytes `[99, 97, 102, 195, 169]`        |
| **integer (label) encoding**       | Gives each category or token an ID.                                               | `cat = 0`, `dog = 1`, `milk = 2`; the tokenizer's IDs       |
| **ordinal encoding**               | Integer encoding where the order is real.                                         | `small = 0`, `medium = 1`, `large = 2`                      |
| **one-hot encoding**               | A vector of zeros with a 1 at the ID, so no category looks "bigger" than another. | `dog` becomes `[0, 1, 0]`; a city feature becomes 3 columns |
| **sinusoidal positional encoding** | Turns a position number into a fixed pattern of sine and cosine waves.            | Position 5 always gets the same vector, in every model      |

**Integer encoding for categories with no order is a trap.** If `cat = 0`, `dog = 1`, and `milk = 2`, a model that does arithmetic on the input "sees" that milk is twice dog. One-hot removes the fake order, which is why it is the default encoding for unordered categories.

The two are connected: **an embedding lookup is a one-hot encoding multiplied by a learned matrix.** The table `E` has shape `(V, d)`, one row per token. Multiplying a one-hot vector by `E` picks out one row, which is why frameworks skip the multiply and just index the row.

```python title="encoding_vs_embedding.py"
import numpy as np

vocab = ["cat", "dog", "milk"]
ids = {w: i for i, w in enumerate(vocab)}   # integer encoding: cat=0, dog=1, milk=2
onehot = np.eye(len(vocab))                 # one-hot encoding: row i is word i

print(ids["dog"], onehot[ids["dog"]])                 # 1 [0. 1. 0.]
print(onehot[ids["cat"]] @ onehot[ids["dog"]])        # 0.0   cat and dog: unrelated
print(onehot[ids["cat"]] @ onehot[ids["milk"]])       # 0.0   cat and milk: equally unrelated

E = np.array([[0.9, 0.8, 0.1],    # cat    embedding table, shape (V, d) = (3, 3)
              [0.8, 0.9, 0.2],    # dog    values a trained model might reach
              [0.1, 0.2, 0.9]])   # milk

def cos(a, b):
    return a @ b / (np.linalg.norm(a) * np.linalg.norm(b))

print(f"{cos(E[0], E[1]):.2f} {cos(E[0], E[2]):.2f}")   # 0.99 0.30   cat-dog close, cat-milk far
print(onehot[ids["dog"]] @ E, E[ids["dog"]])            # [0.8 0.9 0.2] [0.8 0.9 0.2]   same row
```

The encoding says only "this is word 1". The embedding says "word 1 is a lot like word 0". The values in `E` are written by hand here to show what training produces; in a real model they start random and gradient descent moves them.

| Question                        | Encoding                                       | Embedding                                               |
| :------------------------------ | :--------------------------------------------- | :------------------------------------------------------ |
| Where do the numbers come from? | A fixed rule                                   | Training (gradient descent)                             |
| Does it have parameters?        | No                                             | Yes: a `(V, d)` table, often millions of numbers        |
| Does it capture meaning?        | No. Every pair of one-hot words is equally far | Yes. Similar items get nearby vectors                   |
| Size per item                   | Often as long as the vocabulary (one-hot)      | Short and dense, typically 50 to a few thousand numbers |
| Same in every model?            | Yes                                            | No. Each model learns its own                           |
| Place in the pipeline           | First: make the data numeric                   | Second: turn the IDs into useful vectors                |

So the full path from earlier is **encode, then embed**: text is encoded into token IDs by a fixed tokenizer, and the IDs are embedded by a learned table. Hugging Face tokenizers even name the first step `tokenizer.encode(text)`.

The table above lists only the encodings this page needs. [Encoding and Decoding](/ai/math-foundations/encoding-and-decoding) covers all of them: character encodings, every way to encode a category or a number, positional encodings, encoder and decoder networks, and what decoding means.

<Callout type="warn">
  ### Three names that look alike

**Positional encoding versus positional embedding.** The original transformer added a fixed sinusoidal **encoding** of each position. GPT-2 and BERT instead learn a table of position vectors, which is a positional **embedding**. Both do the same job; one is a rule, the other is trained. [Blocks and Positions](/ai/transformers/blocks-and-positions) covers both, plus RoPE.

**Encoder** is a third, unrelated use of the word. In "encoder-decoder" or "BERT is an encoder", an encoder is a whole neural network that reads an input and outputs contextual embeddings. It is learned, not a fixed rule.

</Callout>

### Where embeddings come from: GloVe

**GloVe** (Global Vectors for Word Representation) is an unsupervised algorithm from Stanford (Pennington, Socher, and Manning, EMNLP 2014) for learning word embeddings. It works from one idea: **words that appear in similar company have similar meanings**. It learns from **global co-occurrence statistics**, meaning counts of how often each pair of words appears near each other across the entire corpus.

Take a four-sentence corpus:

```text
The cat sits on the mat.
The dog sits on the mat.
The cat likes milk.
The dog likes bones.
```

GloVe first builds a **co-occurrence matrix**: one row and one column per word, and each cell counts how often the two words appear together. Here "together" means in the same sentence, with the filler words `the` and `on` dropped to keep the table small:

|          | bones | cat | dog | likes | mat | milk | sits |
| :------- | :---- | :-- | :-- | :---- | :-- | :--- | :--- |
| **cat**  | 0     | 0   | 0   | 1     | 1   | 1    | 1    |
| **dog**  | 1     | 0   | 0   | 1     | 1   | 0    | 1    |
| **milk** | 0     | 1   | 0   | 1     | 0   | 0    | 0    |

`cat` and `dog` never appear in the same sentence, yet their rows share three of four neighbors: `likes`, `mat`, and `sits`. Treat each row as a vector and measure the angle between them with cosine similarity:

```python title="cooccurrence.py"
import numpy as np

sentences = [
    "the cat sits on the mat",
    "the dog sits on the mat",
    "the cat likes milk",
    "the dog likes bones",
]
stop = {"the", "on"}
docs = [[w for w in s.split() if w not in stop] for s in sentences]
vocab = sorted({w for d in docs for w in d})
idx = {w: i for i, w in enumerate(vocab)}

X = np.zeros((len(vocab), len(vocab)), dtype=int)   # (7, 7) co-occurrence matrix
for d in docs:
    for a in d:
        for b in d:
            if a != b:
                X[idx[a], idx[b]] += 1

def cos(a, b):
    return a @ b / (np.linalg.norm(a) * np.linalg.norm(b))

print(vocab)                                         # ['bones', 'cat', 'dog', 'likes', 'mat', 'milk', 'sits']
print(f"cat vs dog  {cos(X[idx['cat']], X[idx['dog']]):.2f}")    # cat vs dog  0.75
print(f"cat vs milk {cos(X[idx['cat']], X[idx['milk']]):.2f}")   # cat vs milk 0.35
```

Check `0.75` by hand: the `cat` and `dog` rows match in three positions, so the dot product is 3; each row has four 1s, so each length is `sqrt(4) = 2`; and `3 / (2 * 2) = 0.75`. **Shared contexts became measured similarity**, with no labels and no human telling the program that cats and dogs are both pets.

The real algorithm goes one step further. A real vocabulary has hundreds of thousands of words, so these raw rows are huge and mostly zeros. GloVe instead **learns** a short vector per word (typically 50 to 300 numbers) whose dot products reproduce the logarithm of the co-occurrence counts. The math is on [Word Embeddings](/ai/classical-deep-learning/word-embeddings#glove); the dot product and cosine are on [Similarity and Norms](/ai/math-foundations/similarity-and-norms).

### Static versus contextual embeddings

GloVe (and Word2Vec, its predecessor) has one important limitation: it generates **static embeddings**. Each word gets exactly one vector, learned once and then looked up forever. The word `bank` gets the same vector whether you are discussing a financial institution or a riverbank, so its vector ends up as a blurred average of both meanings.

Modern transformer models such as **BERT** (Devlin et al., arXiv:1810.04805) generate **contextual embeddings**: the vector for a word is computed fresh each time, from the whole sentence around it.

| Sentence                                 | GloVe vector for `bank`      | BERT vector for `bank`           |
| :--------------------------------------- | :--------------------------- | :------------------------------- |
| "I deposited cash at the **bank**."      | the one fixed `bank` vector  | a vector near `money`, `account` |
| "We had a picnic on the river **bank**." | the same fixed `bank` vector | a vector near `shore`, `water`   |

- **GloVe**: a word has **one fixed embedding**, regardless of context. It is a lookup table.
- **BERT**: a word gets a **different embedding depending on the sentence** it appears in. It is a function of the whole input.

Every modern LLM works the contextual way. Each one still begins with a static lookup table, the **embedding layer**, and then its layers rewrite each token's vector using the surrounding tokens until the vector reflects the meaning in context.

<Callout type="warn">
  ### Interview pitfall

"Do LLMs use static or contextual embeddings?" Both. The input embedding layer is a static lookup table, exactly like GloVe's. The hidden states after the first attention layer are contextual. Answering only one half is the common mistake.

</Callout>

### Language models and transformers

| Term                          | Plain meaning                                                                                                                                                                |
| :---------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **language model**            | A model that assigns probabilities to text. In practice: given the tokens so far, output a probability for every token in the vocabulary as the next one.                    |
| **next-token prediction**     | The self-supervised training task of an LLM: predict token `t+1` from tokens `1..t`. Generating text is just doing it repeatedly.                                            |
| **transformer**               | The neural network architecture behind BERT and every modern LLM (Vaswani et al., arXiv:1706.03762). Built from attention layers and feed-forward layers.                    |
| **attention**                 | The operation that lets each token look at every other token in the input and pull in information from the relevant ones. It is what makes embeddings contextual.            |
| **context window**            | The maximum number of tokens a model can read at once.                                                                                                                       |
| **logits**                    | The raw score the model gives each vocabulary token before turning the scores into probabilities. [Softmax and Logits](/ai/math-foundations/softmax-and-logits) covers them. |
| **pretraining / fine-tuning** | Pretraining is the first, expensive training run on a huge corpus. Fine-tuning is a smaller, later run that adapts the model to a task.                                      |
| **prompt**                    | The input text you give a generative model.                                                                                                                                  |

**BERT versus GPT.** Both are transformers. BERT reads the whole sentence in both directions and is built to understand text (classification, search). GPT-style models read left to right and are built to generate text. "LLM" today usually means the GPT-style generator.

## Interview questions

<Accordions>
  <Accordion title="What is the difference between AI, machine learning, and deep learning?">

    They nest. AI is the broad goal of machines doing intelligent tasks, including hand-written rules. Machine learning is the subset that learns its rules from data. Deep learning is the subset of ML that uses neural networks with many layers.

  </Accordion>
  <Accordion title="What is NLP, and how does it relate to LLMs?">

    Natural Language Processing is the field of AI concerned with computers understanding, interpreting, and generating human language. It is defined by the kind of data, not the method. LLMs are the current dominant method for NLP: very large transformer networks trained on text.

  </Accordion>
  <Accordion title="Parameters versus hyperparameters?">

    Parameters (weights and biases) are learned by training through gradients. Hyperparameters, such as learning rate, batch size, and number of layers, are chosen by a person before training and are never updated by gradients.

  </Accordion>
  <Accordion title="What are an epoch, a batch, and a step?">

    A batch is the group of examples processed together. A step is one forward pass, backward pass, and update on one batch. An epoch is one full pass over the training set, so steps per epoch equals dataset size divided by batch size.

  </Accordion>
  <Accordion title="How do you recognize overfitting?">

    Training loss keeps falling while validation loss stops falling and starts to rise. The model is memorizing training examples instead of learning a pattern that generalizes.

  </Accordion>
  <Accordion title="How is an LLM trained without human labels?">

    Self-supervised learning. Every sentence supplies its own labels: each token is the target for the tokens before it, so next-token prediction turns raw text into billions of training examples for free.

  </Accordion>
  <Accordion title="What is the difference between an encoding and an embedding?">

    An encoding is a fixed rule that makes data numeric, such as UTF-8, integer IDs, one-hot vectors, or sinusoidal positions. It has no parameters and carries no meaning. An embedding is a learned dense vector, part of the model's parameters, trained so similar items land close together. They connect: an embedding lookup equals a one-hot encoding multiplied by the `(V, d)` embedding matrix.

  </Accordion>
  <Accordion title="Why not represent words as one-hot vectors?">

    Every pair of distinct one-hot vectors has dot product 0, so the representation says every word is equally unrelated to every other. The vectors are also as long as the vocabulary. Embeddings are short, dense, and place similar words near each other.

  </Accordion>
  <Accordion title="How does GloVe learn word embeddings?">

    It counts how often each pair of words co-occurs across the whole corpus, then learns a short vector per word whose dot products reproduce the log of those counts. Words with similar neighbors end up with similar vectors.

  </Accordion>
  <Accordion title="Static versus contextual embeddings, with an example?">

    A static embedding (GloVe, Word2Vec) gives a word one vector everywhere, so `bank` is the same in "river bank" and "bank account". A contextual embedding (BERT, any transformer) computes the vector from the surrounding sentence, so the two uses of `bank` get different vectors.

  </Accordion>
  <Accordion title="Does an LLM use static or contextual embeddings?">

    Both. The input embedding layer is a static lookup table, one row per vocabulary token. The attention layers then rewrite each vector using the surrounding tokens, so every hidden state after them is contextual.

  </Accordion>
</Accordions>
