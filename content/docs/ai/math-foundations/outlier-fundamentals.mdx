An **outlier** is a value that does not fit with the rest of the data. Sometimes it is a typo, sometimes a broken sensor, and sometimes it is exactly what you are looking for: the fraudulent transaction, the failing machine, the intrusion. **Anomaly detection** is finding those values on purpose.

These pages build on the [statistics pages](/ai/math-foundations/data-and-data-analysis). Every statistical rule here is one of the spread measures from [Descriptive Statistics](/ai/math-foundations/descriptive-statistics) (standard deviation, IQR, MAD, covariance) turned into a test. The machine learning methods replace "far from the mean" with smarter ideas of "far": easy to isolate, in a sparse neighbourhood, outside a learned boundary, or impossible to reconstruct.

The pages go for breadth, not depth. For each method you get the idea, the assumption it makes, where it works, where it fails, and a small example with real output. Every number was printed by the code next to it.

## What is an outlier?

A standard definition comes from Douglas Hawkins (_Identification of Outliers_, 1980): **an observation that deviates so much from other observations as to arouse suspicion that it was generated by a different mechanism.** The last part is the important one. An outlier is not just a large number; it is a value that probably came from a different process than the rest.

Outliers have three causes, and the cause decides what to do:

| Cause                 | Example                                                       | What to do                                                            |
| :-------------------- | :------------------------------------------------------------ | :-------------------------------------------------------------------- |
| **Error**             | Age 250, a height typed in mm instead of cm, a sensor glitch  | Fix it if you can, otherwise remove it or treat it as missing         |
| **Natural extreme**   | A genuinely tall person, a billionaire in an income survey    | Keep it; use robust statistics or a transform so it does not dominate |
| **Different process** | A fraudulent purchase, a cyberattack, a machine about to fail | This is the signal: detect it, do not delete it                       |

**Should you remove outliers?** Only when you know they are errors. Deleting real extreme values makes the data look tidier than the world is, and a model trained without them is surprised by them in production. In fraud, security, and fault detection the outliers are the whole point. When in doubt, keep them and use methods that are not dominated by them: medians instead of means, robust scaling, log transforms, or tree models.

## Point, contextual, and collective outliers

The three-way split is from the anomaly detection survey by Chandola, Banerjee, and Kumar (_Anomaly Detection: A Survey_, ACM Computing Surveys, 2009).

| Type           | Unusual because…                                                           | Example                                                        |
| :------------- | :------------------------------------------------------------------------- | :------------------------------------------------------------- |
| **Point**      | The single value is unusual compared with all data                         | A 9,000-dollar purchase on a card that usually spends 40       |
| **Contextual** | The value is unusual **in its context** only                               | 30 °C is normal in July and an anomaly in January in Oslo      |
| **Collective** | A **group** of values is unusual together, though each one alone is normal | 50 small logins from one IP in a minute; a flat line in an ECG |

Contextual outliers need the context as an input: the time, the location, the user. A global rule on the raw value misses them, which is why [time-series detection](/ai/math-foundations/anomaly-scores-and-time-series#time-series-anomaly-detection) compares each day with the same weekday, not with the whole series. Collective outliers need a window or a sequence, not single rows.

## Outlier, anomaly, novelty, and noise

These words overlap and are used loosely. The useful distinctions:

| Word        | Meaning                                                                                                               |
| :---------- | :-------------------------------------------------------------------------------------------------------------------- |
| **Outlier** | A data point far from the rest. A statistical description: it says nothing about why.                                 |
| **Anomaly** | A data point produced by a different, usually interesting process: fraud, attack, failure. An outlier you care about. |
| **Novelty** | A new kind of point, not present in the clean training data, seen at prediction time.                                 |
| **Noise**   | Random, uninteresting variation or error. Removed or smoothed, not investigated.                                      |

scikit-learn makes the outlier and novelty split concrete, and interviewers use the same terms:

- **Outlier detection** (unsupervised): the training data **contains** outliers, and the method must find them in that same data. Example: clean a dataset before training.
- **Novelty detection** (semi-supervised): the training data is **clean**, all normal. The method learns what normal looks like, then judges new data. Example: train on a month of verified-good transactions, then score today's.

Novelty detection is easier when you can get clean data, because the model never learns that outliers are normal.

## Univariate versus multivariate outliers

- A **univariate** outlier is unusual in one variable on its own: a salary of 250 thousand among salaries near 40. Box plots and z-scores find these.
- A **multivariate** outlier is unusual only in **combination**. A height of 190 cm is fine. A weight of 52 kg is fine. A 190 cm adult who weighs 52 kg is very unusual. Checking each column alone will never find it.

Real anomalies are usually multivariate: a normal amount, at a normal hour, in a normal country, but never all three together for this customer. That is why, on the next pages, the methods after the IQR rule all look at every feature at once.

  <Accordion title="What is an outlier, and should you remove it?">

    A point that deviates so much from the rest that it was probably produced by a different mechanism. Remove it only if you know it is an error (a typo, a broken sensor). Natural extremes should stay, handled with robust statistics or transforms. In fraud, security, and fault detection the outliers are the signal, so you detect them rather than delete them.

  </Accordion>
  <Accordion title="Name the three types of outliers with an example of each.">

    Point: one value unusual against all data, like a 9,000-dollar purchase on a card that spends 40. Contextual: unusual only in context, like 30 °C in January. Collective: a group unusual together while each member is normal, like 50 small logins from one IP in a minute.

  </Accordion>
  <Accordion title="What is the difference between outlier detection and novelty detection?">

    In outlier detection the training data contains the outliers, and the method must find them in that data (unsupervised). In novelty detection the training data is clean, the method learns normal, and it judges new points (semi-supervised). Novelty detection is easier when clean data exists, because the model never learns the outliers as normal.
